# 本批材料托管与观察权限审查

本审查绑定 raw/batch01 和 raw/continuation01 的实际源码锁、四个新账户及其有限轨迹。单机 Windows OS 用户、R、权威、适配器和测试身份夹具均在可信边界内。密码学辅助线保持 FROZEN。

| 材料/信息 | 实际持有者与存放处 | 代理可见输出 |
|---|---|---|
| AT、RT、ID token | 原生 AS、可信适配器内存、权威 AES-GCM 状态、启用时的加密 operational inbox | rid、状态、来源投影和任务句柄 |
| 用户密码 | 本批 secure 账户配置、加密登录材料、固定 password 请求 | 批准结果和句柄 |
| 应用 client_secret | batch secure profile、受保护 HTTP 证据、可信适配器 | 无原文字段的正常投影 |
| 服务能力凭据和 TLS 私钥 | 每条轨迹 secure 目录，Windows DACL 限定测试用户与 SYSTEM | 代理由可信夹具取得自己的角色能力，正文不能声明 caller |
| 管理 Cookie | 环境/清理专用 CookieJar 的进程内存 | 原生 UserInfo 和运行方法采用 cookie-free 客户端 |
| 原生请求响应证据 | batch secure/http/*.aes，独立 http.key | 公开预算行只记录类别、操作、账户、状态及字节数 |
| 适配器已收到的迟到结果 | M2-02 先写加密 inbox，之后交付 R | 交付前 R 的请求仍为 DISPATCHED_UNKNOWN |
| 适配器未持久接收的结果 | M2-03 仅存于评分私有 HTTP 证据，R 崩溃后 lookup 不读取该通道 | UNKNOWN 和原始 pending 义务 |

## 已执行核对

开发测试验证错误调用者、错误账户/客户端、载荷和 URL 限制、重复来源及秘密投影。真实 M2 经角色能力鉴别的任务句柄入口调用固定 provider；R 在权威内核验来源材料，代理只提交 source_rid。旧批准的新本地放行均被拒绝。

独立评分器扫描实际账户密码、应用 secret、服务能力凭据以及本批原生响应的 AT/RT/ID token，覆盖 R 已知及未知的材料。公开运行日志、异常、管理投影和进程控制记录均通过本批检查。原生 HTTP 响应正文只以密文保存，固定字段白名单控制业务输出。

客户端固定 127.0.0.1:18081，拒绝任意操作名、未登记账户和错误 client，运行方法仅能访问发行、刷新、UserInfo、撤销及内省。环境代理和重定向关闭。AS 侧 HTTP 是已冻结的可信 loopback 实验配置，服务间使用固定信任的 TLS。

本轮临时 R、权威和 provider 为不同进程；实际退出与启动由日志和 wait 结果记录，原生 AS 进程保持运行。secure 目录记录了 Windows DACL，账户、密钥和缓存位于不同目录。故障覆盖控制器进程、缓存文件和本轮权威进程，密钥及权威持久数据保留。

## 证据边界

应用接口角色检查已有开发与有限原生证据。各测试进程使用同一可信 OS 用户，真实恶意代理的独立 OS 身份、文件系统不可读性和沙箱隔离仍待验收。R 中保存密钥的事实不能单独覆盖同 OS 用户任意读文件的攻击。

已有材料外发、浏览器 Cookie/SSO、发送者约束、跨机器 TLS 部署、其他 RP、生产登录流程和真实用户批准 UI 分别保留其前提。ID token 已按实际响应加密登记，本批没有将它作为额外 RP 的接受依据。

M2-03 的额外子代在 B 保留评分之前由评分者看到，但没有交给恢复运行者。账户收尾之后，清理通道使用其私有证据撤销该已知子代并删除本批账户。R 原来的 A1 未知义务仍保存。运行态来源完整性、评分可见性和最终测试收尾分别登记。

本批四个新账户均删除，已观察材料的清理后 UserInfo 接受均为拒绝。映射到本批材料的八条保留 token 行 expires_in 均非正。材料密文及测试密钥按证据保留政策继续保存，物理擦除、备份擦除和任意外部副本没有在本轮核验。
