# Casdoor 持久运行层集成与有限生命周期验收

2026-11-05，Asia/Shanghai。

真实调用链已接通，范围为已冻结 Casdoor 4.25.0 的 password 发行、刷新、cookie-free UserInfo、单材料撤销和内省。代理任务句柄经过当前批准、预算和持久派发后，由可信适配器使用材料。真实 AT/RT 束经过签名/账户/客户端校验并加密登记，旧 schema 和合成字符串兼容路径已验证。

原计划四条均完成，每条只原生采样一次。原始评分为 **3 PASS、1 SAFETY_FAILURE 报警**。唯一报警来自评分器的固定启动次数规则，离线复核证明对应故障进程退出及新进程恢复，修正后四条检查均通过。确认的安全违反为 0，UNKNOWN/INCONCLUSIVE/ABORTED 轨迹判定为 0，未运行为 0。M2-03 仍保留运行态 UNKNOWN 义务，该状态与轨迹是否符合保守合同分别登记。

开发回归包含三次合法启动、缺少故障 PID、缺少后续恢复及重叠启动的正负例。原 M2-03 文件哈希全部保持一致，离线复核在受保护副本中执行，原始评分文件保留。通过校验的复核门随后只消费原计划 M2-04 的未采样槽位，沿用原授权、第四个账户和原预算账本。原生重采次数为 0。

对应工件为 raw/batch01/RESULTS.json、review/SCORER_CORRECTION.json、review/M2-03_recheck.json、raw/continuation01/RESULTS.json。SOURCE_LOCK.json 绑定初始源码，SOURCE_LOCK_v2.json 及两个执行段的源码锁绑定评分修正与续行。

## M2-04 的补充覆盖

收尾时发现原轨迹只直接记录了权威不可达时的 recover 返回 UNKNOWN，未在该时点提交代理接纳。原始轨迹保持原样。运行器已补充这一调用，另在原生状态的受保护副本中启动 R、保持权威不可达，实际提交 B 请求并得到 UNKNOWN，随后恢复权威并核对批准、预算、请求与义务不变。

这项本地补核记录于 supplement/RESULT.json，原生 provider 未启动，原生账本前后均为 114，新增原生 HTTP 为 0。它属于单独的本地覆盖证据，原 M2-04 中断期接纳调用的缺项继续可见。

## 原生 profile 与材料

实际配置核验为 Casdoor 4.25.0、app-l1-0、l1-client-0、l1-study、JWT、password/refresh_token grant、刷新轮换开启、AT/RT 各一小时配置。发行物与当前二进制摘要匹配，源码参照 commit 528a0213f01caf70b9f41009cbf7b2f67bdd67ec，可复现构建未证明。

实际材料为 Bearer，scope 为 openid，expires_in 为 3600，所查 JWT 的 exp−iat 为 3600 秒，返回了 ID token。原生字段、验证后 claims、本地 origin 和推导引用分别保存。RT 在该源码中没有 kid，使用同次 AT 指定公钥完成签名和身份绑定校验。原生单元通过限定新账户的 token 行核对，不凭 token 字符串数推断。

| 轨迹 | 批准实例 | 生命周期观测到的原生单元 G | AT/RT 字符串引用 | 收尾后映射保留行 | 正 expiry 行 |
|---|---:|---:|---:|---:|---:|
| M2-01 | 2 | 2 | 4 | 2 | 0 |
| M2-02 | 2 | 3 | 6 | 2 | 0 |
| M2-03 | 2 | 3 | 6 | 2 | 0 |
| M2-04 | 2 | 2 | 4 | 2 | 0 |

G 是初始与最终观察映射的原生记录单位并集。刷新后父记录可被替换，因此该数与某一时刻仍有效或仍需处置的单位数有不同时间作用域。配对 AT/RT 与原生行的对应另有实际字段检查，账户级清理具有更广的作用范围。

## 本地性质与未知结果

四条检查支持本地撤回的新放行截止、持久来源/预算一致性、B 的独立继续和材料投影边界。返回绑定原 rid、attempt_id、批准实例/代次、请求摘要、账户与 client。已知隔离材料的处置先登记尝试，再保存撤销响应和 AT 的 UserInfo/内省观察。RT 的拒绝由独立测量补充。

M2-02 分别记录 native_response_received、operational_result_durable、交付及权威提交版本。适配器收到并持久保存 A1 后，R 尚未看到结果时提交 A 撤回并让 B 继续，随后补收相同结果并隔离。

M2-03 在关闭 operational inbox 的 profile 下，于控制器收到响应但权威登记之前终止 R。恢复者 lookup 返回 UNKNOWN。独立测量在清理前看到 A1 的 UserInfo 接受及 active=true，同时 B0 仍接受。该额外材料没有回流 R 的恢复输入。已知 A0 被处置，A1 的运行态义务保留。

所有原生 HTTP 有发送前序号、类别、操作及结果密文，事务有提交版本。屏障提供客户端与可信适配器可观察顺序。AS 内部精确线性化时点没有直接观测，相关结论保持源代码支持的调用区间和所有相容解释。

各次失败、查询和负向刷新均纳入对应分母。账本没有未回写 HTTP 行。开发测试的网络调用均为合成 mock，与上述原生分母分开。独立测量另有 12 次按新账户及应用过滤的只读 AS 数据库查询，离线评分与汇总的读取单列。

权威 SQL 调用按轨迹为 91、117、104、98，共 410 次，提交 67 个事务。加密前完整应用状态的累计逻辑写入为 1,644,243 字节。该原型采用整状态行，字段和材料束增加会增加其写入量。原生请求/响应正文长度、各 HTTP 操作分项见 COST_AND_RESULTS.json。HTTP 头、TCP 开销、物理 WAL 累计写入和 fsync 次数未测，代理字节指标均按定义标注。

首次预算文件至最后账户清理的墙钟跨度约 713.1 秒，包含评分规则修复和复核间隔，低于 60 分钟。原始执行段用时 38.531 秒，其余阶段的时间依据各自记录解释。

四个本批账户均已禁用、删除并确认不存在，已观察 AT 的清理后 UserInfo 接受均为拒绝。八条映射保留 token 行的 expiry 字段均非正。原生材料密文及测试密钥继续保存以便核对。原生 AS 保持运行，临时服务进程由本批清理。账户级删除和该范围的最终清理不用于替代清理前 B 保留评分。

## 复现与下一步

开发测试可从新目录执行，设置 PYTHONPATH 指向 auth-lifecycle/src，并将 ONLINE_STATE_TEST_ROOT、NATIVE_TEST_ROOT、TEMP/TMP 指向新证据目录，然后运行 `python -B -m unittest discover -s tests -v`。正常原生批次入口如下，完整原生重采需要独立授权编号和新的预算目录。

```powershell
Set-Location -LiteralPath 'D:\毕业设计\auth-lifecycle'
$env:PYTHONUTF8='1'
$env:PYTHONDONTWRITEBYTECODE='1'
& 'C:\Users\a1887\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' -B scripts/native_casdoor.py `
  --out 'D:\毕业设计\mainline_native_casdoor_v1\raw\另行授权的新批次' `
  --authorization-id '填写新的原生执行授权编号' --allow-native-casdoor
```

默认在线运行层仍使用假 provider。真实配置需显式 profile。预算和账户作用域在首个请求之前持久化，代码不自动重采已采样轨迹。

下一项最影响结论的补证是为未知创建尝试取得可核验的终态/截止依据，并把该依据与原 attempt、批准来源和 B 保留条件连接起来。M2-03 的本地 UNKNOWN 和清理前仍接受的隐藏子代明确显示这一需求。

完整后代关闭仍依赖来源/枚举完整性、发行或派生截止与所有在途终态。本轮只有有限、登记轨迹中的已知单元处置与账户收尾证据。外部效果终结的证据范围为 UserInfo 接受和刷新/内省检查，其他业务 RP、离线 JWT 接受或实际业务提交没有在本批验证。

真实用户批准 UI、恶意 OS 用户隔离、生产 TLS、密钥恢复、跨主机权威容灾及多活仍有独立工程验收项。研究结论按实现符合性、有限原生实测和未决前提登记，密码学候选研究保持 FROZEN。
