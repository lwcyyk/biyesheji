[P2] 2026年11月4日
[P3] 摘要
[P4] 现代密码管理器通过密码生成、加密保管、自动填充、同步与共享，降低用户维护大量账户的负担。随着通行密钥、机器身份和凭据代理的发展，其管理对象逐渐扩展到多种身份凭据与访问能力。AI 智能体进一步把凭据使用带入连续、多步骤和可委托的任务过程。用户既希望代理完成工作，也希望随时收回某项授权，并保留其他代理已经获得批准的任务。这使凭据保管、授权执行、服务原生撤销和业务效果终止形成相互关联的研究问题。
[P5] 本报告沿实际访问链条分析选题依据。凭据保险库、代理身份平台、会话代理和任务执行控制已经分别提供重要能力。登录后形成的远端会话、共享授权关系和结果不明的操作，则要求系统把用户的停止与保留目标映射到具体服务行为。认证语义感知的作用，是取得会改变安全决定的必要证据。可撤销凭据配置的作用，是在已有能力与批准范围内选择访问和处置路径。报告据此比较直接会话方案、已有授权与撤销研究及通用规划，明确本课题的适用条件。结合本地研究基础，工程目标为完整的 AI 智能体凭据管理系统，学术目标优先验证证据不完整条件下的安全补证与配置决定。独立算法优势与密码学原创性通过分离实例和同条件实验建立。

[P30] 1 从账户密码理解现代密码管理器
[P31] 用户最初需要解决什么问题
[P32] 假设一名研究生同时使用邮箱、云盘、论文数据库、代码托管和笔记服务。每个服务都需要确认访问者的身份。采用口令认证时，用户通常提交用户名和密码，由服务验证。账户数量增加后，记忆与输入成本随之增长，重复使用密码又会让一个网站的泄露影响其他账户。密码管理器把大量独立密码的生成、保存和填写交给软件，用户集中保护解锁密码库所需的认证因素。美国国家标准与技术研究院（NIST）的数字身份指南明确要求验证方允许密码管理器和自动填充，并指出带生成器的密码管理器有助于用户选择更强的密码。[R01]
[P33] 因此，理解密码管理器的起点是两个同时存在的目标。用户要方便地使用许多账户，也要减少密码复用、弱口令和错误填写。密码管理器围绕这两个目标形成了密码生成、保险库保管、网站匹配、自动填充和跨设备同步等功能。Oesch 与 Ruoti 对浏览器型密码管理器的研究以生成、存储和自动填充三个阶段展开，也说明安全性需要沿整个使用过程检查。[R04]
[P34] 一个密码库如何工作
[P35] 可以把密码库理解为一组经过加密的账户记录。每条记录包含网站地址、用户名、密码以及必要的备注。客户端根据解锁材料获得用于访问密码库的密钥，再解密需要使用的条目。实际产品通常把口令派生、账户认证、数据加密、密钥保护和恢复流程分开设计。以 Bitwarden 的官方白皮书为例，其架构包含客户端密码库加密、密钥派生和共享密钥保护等机制。具体算法与参数属于产品版本的一部分，应以对应白皮书为准。[R02]
[P36] 这个过程里有两个登录动作。第一个是解锁或登录密码管理器，第二个是使用某条凭据登录目标网站。密码库解锁成功，只说明当前组件可以取得某些保存的数据。目标网站仍然根据自己的认证流程决定是否建立会话。企业单点登录、密码库解密与第三方网站登录也可能分别依赖不同的密钥和信任关系。[R02,R11]
[P37] 当客户端把密码提交给网站后，网站常会生成一个会话，并通过 Cookie 或其他会话材料识别后续请求。此后的操作可能持续使用该会话。由此可见，密码条目、登录过程和登录后的会话属于三个需要关联管理的对象。研究范围一旦扩展到任务停止，就必须进一步了解目标服务怎样处理已经建立的会话。[R01]
[P38] 现代密码管理器管理的对象正在扩展
[P39] 现代凭据管理涉及多种对象，其性质和生命周期有所不同。通行密钥使用公私钥完成网站认证，用户可通过设备解锁操作批准使用。FIDO 文档同时区分可同步和设备绑定的通行密钥。API 密钥、OAuth 访问令牌和刷新令牌则常用于软件调用服务。是否支持这些对象、以何种方式保管和使用，取决于具体产品与集成。[R03,R10]

[P63] 由此得到的第一个研究认识
[P64] 密码管理器为本课题提供了明确的系统起点。它负责安全保管和受控使用凭据，后续研究则沿着“凭据使用之后发生什么”继续展开，包括形成什么会话、获得什么权限、产生什么后代，以及用户撤回授权后这些能力如何结束。这条扩展路径保留了密码管理器的实际用途，也把研究对象从静态条目推进到完整访问生命周期。[R02,R08,R12]
[P65] 2 现代密码管理器和秘密管理系统已经发展到哪里
[P66] 个人密码管理已经形成完整的产品能力
[P67] 密码生成、加密同步、自动填充、团队共享、恢复和通行密钥管理已经形成可复用的产品能力。新的毕业设计可以将这些能力作为基础设施要求，并通过范围明确的原型体现自主设计与集成工作。选题的学术贡献还需要落实到一个具有明确输入、输出和评价指标的问题。[R02,R03]
[P68] 密码管理器的安全研究仍然持续发展。2024年的注入攻击研究考察了攻击者通过共享条目等入口影响受害客户端，再利用受保护状态的变化推断秘密的情况。2026年的云端密码管理器比较研究进一步考察恶意服务器模型下的保护边界。这些工作说明，密码库安全需要结合共享协议、元数据、恢复与同步过程分析。相关论文对应其所测版本，产品后续修复情况应按厂商公告另行核对。[R05,R06]
[P69] 从人的密码库走向机器的秘密管理
[P70] 程序也需要连接数据库、云服务和代码仓库。秘密管理系统由此加入工作负载认证、策略控制、动态凭据、租约和撤销。例如 Vault 为动态秘密及部分令牌维护租约，支持到期处理和主动撤销，令牌撤销还可影响由它创建的租约。其键值秘密存储与动态租约机制具有不同语义。这个例子表明，生命周期管理已经是成熟秘密管理技术的重要组成部分。[R08]
[P71] 截至本次检索，1Password Credential Broker 的官方页面标注为 public preview，支持 GitHub Actions 与自定义 OIDC 连接。其流程根据工作负载身份和策略提供获准凭据，并记录交付审计。该能力说明密码管理产品已经在向机器与 AI 智能体扩展。凭据交付后的使用范围与目标服务中的撤销结果，还需要结合执行方式和目标服务能力评价。[R07]

[P89] 为什么从这些已有能力继续向前研究
[P90] 现有系统已经提供了秘密保存、身份验证和策略执行的技术基础。新的问题来自更具体的组合要求。用户让多个 AI 智能体长期使用同一个账户，希望它们按照各自任务工作，并且可以分别停止。实现这一要求需要同时知道凭据归属、授权依赖、服务端撤销行为和运行中的任务状态。系统设计由此需要把“谁获得了凭据”与“谁仍然能够造成哪些访问和效果”连接起来。[R26,R28,R29]
[P91] 3 真实代理工作流对凭据管理提出了哪些要求
[P92] 从实际产品确认问题已经进入使用阶段
[P93] 把账户访问交给 AI 智能体，已经有明确的产品入口。1Password 的使用文档列举了预订、预约和购物等需要登录的代理任务，提供用户批准后向代理浏览器代填登录信息的流程。AWS AgentCore Identity 则使用包含工作负载与用户身份的访问令牌，控制代理从保险库取得下游凭据。两类入口分别服务于网页操作和接口调用，说明凭据管理需要同时面对浏览器会话与 API 连接。[R35,R38]
[P94] 企业侧也已出现专门的身份和凭据管理能力。Microsoft Entra Agent ID 为代理设置身份对象、负责其用途与生命周期的 sponsor，并提供代理专用审计记录。阿里云 Agent Identity 提供工作负载身份、凭据提供方、Token Vault 和访问审计。这些可查证的功能说明，代理归属、凭据保管和运行权限已经进入实际系统设计。[R39,R40]
[P95] 这些资料支持的结论是，代理执行账户任务需要专门组织身份、凭据和授权关系。产品的存在同时提高了研究门槛。新的系统应说明它如何利用已有能力，以及在什么实际条件下还能改善用户的控制能力。
[P96] 用一个完整任务观察凭据在何处起作用
[P97] 设用户要求代理甲读取项目资料并在笔记系统生成摘要，要求代理乙持续检查同一账户中的资料更新。业务步骤包括选择账户、取得访问能力、读取内容、把必要内容交给模型、提交摘要以及完成后处置访问状态。中途用户可能撤回甲的任务，同时要求乙继续工作。这是本地研究已经采用的双代理场景，其访问需求也可以分别落在网页操作和 API 调用上。[L02]
[P98] 对这一任务，保存一份正确密码只能完成其中一个环节。系统还要知道甲当前使用哪个账户，乙是否依赖相同的连接，摘要允许交给哪个接收方，甲能否继续刷新访问能力，以及撤回时有哪些状态仍在目标服务中有效。这些问题分别对应身份绑定、操作约束、授权依赖和状态处置。
[P99] 为避免混淆，需要沿实际运行链条识别三处位置。模型上下文保存代理用于推理的内容，代理运行时负责浏览器和工具编排，可信凭据执行组件保存秘密并发出获准请求。秘密可以留在执行组件中，浏览器和工具仍然代表用户获得实际操作能力。因此，凭据的保存位置与实际操作的批准条件需要分别设计。[R26,R36,R42]
[P100] AI 相关的变化发生在从输入到动作的过程中
[P101] 普通账户系统能够验证一次请求来自哪个凭据。代理还会根据页面、邮件和工具返回值决定下一次调用。外部数据因此进入了后续操作的选择过程。AgentDojo 使用97个现实任务和629个安全测试案例评估这一问题，覆盖工具返回的不可信数据对代理行为的影响。WASP 则在网页操作中区分代理开始偏离任务与最终完成攻击目标，提示评价应观察实际业务效果。[R34,R43]
[P102] 这类证据说明，合法身份和有效凭据可以与错误任务行为同时出现。比如一个获准读取项目资料的代理，可能被文档内容诱导，把读取结果发送给另一个接收方。风险发生在读取所得数据影响后续调用的环节，整个过程可能始终使用有效凭据。凭据管理系统因此需要把用户批准的任务范围连接到执行动作。[R34,R44,R45]
[P103] 工作流、RPA 和其他自动化系统也会遇到身份委托、状态恢复与撤销问题。AI 智能体把运行时形成的工具选择和参数带入同一链条，使外部内容、任务状态与访问能力需要联合分析。已有自动化控制方法应进入基线，研究对象则限定为实际存在动态选择和持续授权的代理任务。[R27,R28,R34]
[P104] 三项用户要求分别对应什么保证
[P105] 用户希望代理能够完成任务，同时希望长期秘密得到保护、操作保持在批准范围内，以及任务结束后相应访问能力得到处置。这三项要求依赖不同对象。密码保管涉及秘密和密钥，任务约束涉及操作及接收方，访问处置涉及会话、授权根、刷新能力和在途效果。[R26–R29]

[P120] 本课题从这里取得什么研究对象
[P121] 代理接入账户之后，系统必须把任务与实际访问状态关联起来。当一个用户同时使用多个代理、多个服务和不同凭据类型时，这种关联还要能够支持后续调整。由此可以得到一个具体对象，用户批准的任务如何映射到可使用、可解释且能够按目标结束的凭据配置。
[P122] 这个对象同时涉及可用性和安全性。一个配置需要让合法任务完成，也需要保留用户要求的停止路径。后面的调研据此考察现有系统能提供哪些保证，以及哪些组合条件需要额外的语义证据和配置决定。
[P123] 4 现有产品与技术路线的能力及适用边界
[P124] 凭据保险库与代填已经解决了重要的接入问题
[P125] 现代凭据保险库可以集中保管秘密，并通过受控组件完成交付或使用。1Password 的不同代理集成提供了具体例子。其 Claude 集成文档描述本地批准、按代理会话保护的凭据交付，以及填充时暂停代理读取页面等措施。面向托管代理的集成则使用机密计算与浏览器扩展交付链。两种部署需要分别按其安全模型评价。[R37,R36]
[P126] 与本课题直接相关的是官方对保证范围的说明。1Password for Agents 的安全文档把保护范围定位于凭据的存储、批准、交付和填充，登录后的操作由代理自身的防护控制。其使用文档进一步说明，登录成功后的会话按目标网站的规则运行。由此可以把代填成功视为取得访问能力的一个节点，再继续检查任务约束和访问结束条件。[R35,R36]
[P127] 这一边界足以支持系统研究中的一项需求，密码管理器与任务执行组件应交换账户、会话和批准信息，使用户能够知道一次登录为哪个任务产生了什么访问状态。该需求的可实现程度还取决于浏览器和目标网站提供的接口。
[P128] 身份与凭据平台已经支持代理归属和按身份授权
[P129] Microsoft Entra Agent ID 在既有服务主体基础上提供代理身份、蓝图关系、权限分配与日志。AWS AgentCore 的工作负载访问令牌关联代理身份及其代表的用户。阿里云 Agent Identity 通过策略约束工作负载可以访问的凭据提供方，并把身份管理和凭据取得操作写入审计日志。这些功能能够支持“由哪个代理代表哪个用户取得什么凭据”的管理。[R38–R40]
[P130] 因此，为代理增加唯一标识、集中保存凭据、建立审计台账，都应作为系统基础能力。研究若进一步要求“撤回甲时乙继续完成工作”，还要把代理身份映射到目标服务实际承认的授权和会话关系。多个清晰可区分的代理身份可以共享同一项下游访问能力，这种共享关系应进入配置记录。
[P131] 凭据交付位置也需具体分析。阿里云的 API Key 文档明确说明，代理通过出站授权后可以取得明文 API Key。对于这种接口，平台保护了存储和交付资格，应用运行时还要决定是否把密钥留在可信执行组件。把“存储加密”“授权后可取出”“模型接触不到秘密”分别验证，才能准确评价系统边界。[R41]
[P132] 会话代理已经能够限制工具和结束本地访问
[P133] Nango 的官方 Agent Sessions 教程提供了一个范围很明确的邮件摘要示例。它把会话绑定到指定邮箱连接和只读工具，设置有效期，由后端使用提供方凭据，并在任务完成后结束会话。教程还关闭通用代理等间接执行入口，再检查工具限制、会话终止和过期。[R42]
[P134] 这类设计是本课题必须认真对待的强基线。若所有访问都经过受控代理，用户要求是停止甲继续通过该入口调用，同时保留乙的入口，按任务区分会话并检查当前状态就可能满足要求。在这样的场景中，研究评价应确认直接方案的效果与成本，再决定额外补证和更复杂配置是否有价值。
[P135] 任务和信息流约束已有独立执行机制
[P136] CaMeL 从可信任务提取控制与数据流，并通过能力和策略约束工具使用。Microsoft Agent Framework 的 FIDES 给内容附加完整性与保密性标签，在敏感工具执行前检查策略。PAuth 则研究从任务要求得到具体操作约束。这些方案已经把部分安全责任放到可检查的执行层，为本系统提供可复用机制和强对照。[R25,R44,R45]
[P137] 执行覆盖范围会影响保证。例如，FIDES 的官方文档明确列出部分 CodeAct 提供方中的嵌套工具调用绕过其逐工具中间件路径，需要宿主工具自行落实授权和目的地控制。这是特定集成的覆盖条件，说明评价一个策略层时，要列出所有实际调用路径并逐一核对。[R45]

[P158] 密码 通行密钥 API Key 和令牌作为接入基础
[P159] 本系统可以通过密码或通行密钥形成网站会话，通过 API Key 调用接口，也可以使用 OAuth 等标准化授权机制取得和更新令牌。OAuth、OIDC 及相关撤销、内省、交换、发送方约束和细粒度授权标准，提供可复用的凭据与身份基础。研究模型从具体接入方式中提取主体、权限、有效期、依赖关系和处置操作，再据此作出配置决定。[R03,R10–R17]
[P160] MCP 与 A2A 承担工具和代理交互，AuthZEN 为策略判定与执行提供通信接口，GNAP 等协议提供其他授权委托方式。它们按照系统需要接入适配层。选题论证的中心是任务访问能力如何建立、约束与结束，相关协议为这些环节提供实施能力。[R20–R23]
[P161] 现有方案共同指向的组合问题
[P162] 上述方案已经分别推进了安全接入、代理身份、任务会话和执行约束。把它们用于同一个长期任务时，系统仍需核对这些层之间的状态是否一致。任务批准、保险库交付资格、工具会话、远端会话和服务端效果分别由不同组件维护。用户的一次撤回需要说明应改变其中哪些对象，以及用什么证据确认结果。
[P163] 由此产生的研究需求可以表述为，依据具体服务和执行路径的能力，把用户目标转换为可检查的凭据配置与状态处置计划。第5章通过可复现的情形说明这项转换在哪些地方会出错。
[P164] 5 认证语义缺失如何导致配置与撤销错误
[P165] 把控制目标写成能够验证的结果
[P166] 用户说“停止代理甲”，可能要求受控入口停止接受甲的新请求，也可能要求甲关联的远端会话和令牌失效，或者要求已经排队的操作停止产生后续效果。本地方案用 L、R、E 分别记录这些目标。目标不同，系统需要操作和检查的对象也不同。[L02,R27,R28]

[P180] 同一用户可以只要求其中一项，也可以要求其组合。系统应记录作用范围和时间边界，再选择实现方式。已经发生的读取或写入属于历史效果，后续补偿需要单独的业务决定。[L02,R27,R28]
[P181] 情形一 关闭凭据入口之后 已有访问状态如何处理
[P182] 考虑代理甲通过代填登录网站，网站已建立会话 s甲。用户随后断开代理与密码管理器的连接。密码管理器处理了自己的连接和批准，网站仍按自身规则管理已经建立的会话。1Password 的官方使用与安全文档明确区分了这两个职责。[R35,R36]
[P183] 这个场景应分目标验收。如果用户只要求阻止后续代填，断开连接可以完成相应控制。如果用户还要求 s甲 在网站端失效，就要调用和核验网站支持的会话处置操作。在受控浏览器始终隔离、甲已经停止、且用户只要求 L 的配置中，系统可以采用较低成本的本地停止方案。R 的额外步骤由明确需求触发。
[P184] 秘密管理服务也存在类似的生命周期分层。Bitwarden Secrets Manager 文档说明，访问令牌撤销后会阻止新的认证，已经认证的机器仍可能在原会话到期前取得并解密秘密，最长可达一小时。这个例子提供了可查证的实际行为，凭据入口失效与已有会话结束需要分别记录。[R09]
[P185] 由此推导的模型要求是，系统至少要区分访问的来源、已经形成的会话、续期能力和接受方。只记录“连接已删除”或“密钥已移除”，还缺少与用户 R 目标相对应的状态证据。
[P186] 情形二 独立代理身份可能共享下游撤销范围
[P187] 设甲乙在代理平台中有独立身份与任务记录，分别使用 t甲、t乙 访问同一账户。后端可能允许分别处置这两份材料，也可能把它们关联到同一授权范围。Google 的官方撤销说明给出了较大范围关联的实例，其程序化撤销会影响此前授予相应项目的权限及相关客户端令牌。Microsoft Graph 的 revokeSignInSessions 又提供了用户刷新令牌与浏览器会话 Cookie 的处置接口。[R18,R19]
[P188] 因此，“每个代理一个身份”和“每份材料可独立撤销”需要各自的证据。前者可以改善归因，后者取决于下游服务的实际关系。若甲乙共享同一原生撤销范围，直接撤销甲所依赖的根可能同时影响乙。此时系统应在配置阶段选择受支持的独立路径，或者明确采用本地停止目标，并向用户说明相应保证。
[P189] 已有会话代理可以在共同下游连接上分别控制甲乙的本地入口。对于所有请求均被中介且目标仅为 L 的场景，这正是合理的直接方案。需要研究配置的情形，应额外说明用户为何要求 R、哪些接受路径被纳入目标，以及服务是否允许在既定批准下取得更合适的原生授权。[R42,L02]
[P190] 情形三 请求结果不明时 重新操作会改变风险与成本
[P191] 假设系统发送一次创建会话、刷新或业务提交请求，服务端执行了操作，但返回消息丢失。此时本地记录只知道请求发出，远端可能已经产生新材料或业务效果。若把超时直接当作未执行，后续重试和清理就可能遗漏已有状态。AID-Guard 将这种不确定性纳入保留预约、效果确认和恢复规则，说明它已有直接研究基础。[R27]
[P192] 凭据配置还会受这些状态影响。例如，首次登录可能已经形成会话，再次登录则可能生成第二个会话。两个会话是否独立、能否查询、退出一个是否影响另一个，都由具体服务决定。安全补证因此需要描述允许结果和处置责任，避免把所有查询都当作免费、无副作用的信息读取。[L02]
[P193] 在完整任务中，甲的停止、乙的保留和新会话的清理可能竞争同一操作预算。某个核验步骤单独看能够增加信息，放到全流程却可能消耗结束任务所需的资源。研究必须把取得证据和证据取得后的状态变化一起计算。
[P194] 认证语义是这些行为关系的可检查描述
[P195] 本报告所说的认证语义，具体指服务对账户、凭据、会话、授权依赖和处置操作的行为约定。它需要回答一次动作作用于哪个对象，可能产生什么结果，哪些其他对象会随之变化，以及系统能观察到什么。语义描述可以来自标准、版本化文档、可信配置和获准的运行观察。[L02]

[P219] 异构性与不确定性分别带来什么工作
[P220] 若网站甲和乙的规则不同，但每项规则都已可靠掌握，版本化适配表和普通规划就可以处理。值得引入主动感知的条件，是某个尚未确定的事实会改变安全动作、可行配置或完整成本，而且存在合法、可承担后果的补证方式。[L02,R30]
[P221] 这类不确定性可能来自当前连接的实际账户绑定、历史材料与现行配置的对应关系、响应丢失后的远端状态，或文档与当前部署的适用性。它应作为具体事实登记。对于缺少有效观察路径的事实，系统保持受限结论，并通过已有安全配置、补充批准或人工核验处理。
[P222] 因此，认证语义感知需要以决定为目标。它要说明当前缺少哪项事实，这项事实会改变什么选择，以及补证本身是否保持合法完成和清理的可能性。这个要求将第4章的产品能力与后续 A/B/AB 的输入连接起来。
[P223] 6 从真实缺口到本课题的研究问题
[P224] 先把需求落到一个可以验收的问题
[P225] 给定用户的任务批准、代理身份、已有凭据和目标服务，系统需要产出一项可执行决定。它应说明采用哪个账户和访问路径，允许哪些操作，用户撤回时怎样处置目标范围，其他任务依靠什么继续工作，以及每项判断由什么证据支持。[L02]
[P226] 以双代理场景为例，可验收要求可以写为甲和乙均能完成各自获准的读取，用户撤回甲后，甲满足事先声明的 L 或 R，乙继续保持已批准的访问。若任务包含异步写入，再按服务能力单独加入 E。这样得到的成功条件同时包含合法工作、选择性停止和证据范围。
[P227] 为什么只增加一个保险库还不足以完成该目标
[P228] 保险库可以正确保护并交付凭据。在第5章的情形一中，后续需要处置的对象却已经变成网站会话。系统要把这项状态与任务、执行环境和停止目标关联起来，才能继续判断。因而，凭据保管是必要模块，完整管理还需要一份面向使用过程的状态与依赖记录。[R35,R36,L02]
[P229] 类似地，给甲乙分配不同代理身份可以明确归因，在情形二中仍需要检查它们下游是否共享同一撤销范围。上述分析把研究对象收敛为任务、凭据和服务行为之间的关系，也为系统应保存什么状态给出了具体理由。[R39,R29]
[P230] 用已知关系与未知关系构造两个对照场景
[P231] 场景甲中，可信适配配置已经说明甲乙均通过同一网关访问，秘密留在网关，用户只要求 L。系统创建两个任务入口，撤回时仅关闭甲的入口。该场景验证直接共享方案的可用性，也作为额外探测应当为零的负控制。Nango 的会话与工具范围控制提供了相应技术基线。[R42,L02]
[P232] 场景乙中，用户要求覆盖明确远端材料的 R，并持续保留乙。现有证据只表明 t甲、t乙 当前可用，尚未确认它们的原生撤销关系。系统可以直接处置甲、先安全补证，或在获准且原生支持的情况下建立新的独立路径。选择哪条路线取决于真实关系、补证成本和新配置的成立条件。
[P233] 这两个场景同时存在，才能检验所谓感知是否有用。若两者都执行相同的大量探测，方法增加了原本可以避免的开销。若两者都依据令牌表面差异执行撤销，方法可能遗漏场景乙中的关联影响。评价应观察证据是否改变了最终决定。
[P234] 一个更具体的可区分性例子
[P235] 构造具有相同初始观察的两个服务状态。状态一中，t甲、t乙 分别依赖 g甲、g乙，处置 g甲 可以保留乙。状态二中，t甲、t乙 均依赖 g共同，处置该根会影响二者。暂且假设账户查询与当前访问测试的返回相同，并且这两个状态都符合现有证据。此例是用于问题分析的构造，服务是否允许这样的关系和查询，需要在实际后端中验证。
[P236] 只依据这些共同观察，系统会对两个状态作出同样的决定。直接处置原生根在状态二中损害乙。总是取得额外独立路径可以作为保守方案，但其成立仍需要服务支持和用户批准，并可能在状态一增加授权、交互和清理成本。如果存在能够区分两种关系的获准查询，系统就有机会根据结果选择更合适的路径。
[P237] 这个构造建立的是信息与决定的依赖。如果最强通用规划器获得同样的可能状态、查询和代价，它也能够作出相应策略。新的学术贡献需要进一步说明，所提出的表示、证据处理或求解机制相对该通用方法的具体增量。[R30–R33,L06]
[P238] 由此依次得到 A B 和 AB 的职责
[P239] 第一，配置之前需要掌握足以支撑当前决定的服务事实。A 因而承担认证语义的证据组织与安全补证，包括区分已知、待决和观察冲突，并记录核验带来的新状态与义务。[L02]
[P240] 第二，获得语义后仍需选择访问路径。B 根据用户的停止与保留目标，在服务支持和批准允许的配置中比较成本。共享连接、隔离执行和独立原生授权都属于候选选择，其可行性由适用条件决定。[L02,L04]
[P241] 第三，应该补什么证据又取决于配置缺少什么事实。AB 把配置可行性和成本的差异反馈给 A，让核验围绕当前决定展开。核验产生的新状态随后重新进入配置与停止规划，形成联合问题。[L02,R30]

[P259] 为什么选择这一范围开展硕士研究
[P260] 这项范围具有三个可具体检验的条件。需求能够落到用户可理解的停甲留乙和任务结束目标。失败情形能够用会话、授权关系和响应丢失构造，并在受控后端中复现。项目已经具有有限模型、独立参考和后端校准，可以用来检查机制是否真正带来增量。[L02,L05,L06]
[P261] 在此范围内，完整凭据管理系统负责把账户连接、批准、执行、撤回和审计组织成可用闭环。学术研究优先处理不完整证据如何影响安全配置以及补证策略。其他任务语义和信息流控制能力可以采用现有方法，再检查它们与凭据生命周期的组合条件。[R25–R29,R44,R45]
[P262] 研究成立的条件和收敛标准
[P263] 如果固定适配表加会话网关已经以可接受成本满足全部目标，相关场景应作为基线成功记录。若实际服务提供完整语义，也应直接使用。主动感知的价值，需要由真实缺证场景中的配置改变、合法任务保留、错误保证减少或完整成本改善体现。
[P264] 同样，支持 R 的目标需要原生处置能力，支持 E 的目标需要覆盖对应业务效果路径。模型应反映能力边界。新候选机制进入实现前，继续遵循具体输入族、度量指标、最强通用方法和预测差距组成的分离声明，并先形成至少一个通用方法付出更高代价的可复查实例。[L02,L06及项目研究规则]
[P265] 因此，选择该方向的依据可以落到一条完整论证上，代理已经实际使用账户，既有安全组件各有明确保证范围，跨组件的访问状态影响用户的停止与保留要求，证据不足又会影响配置决定，而这些关系可以通过有限模型和真实后端共同验证。
[P266] 7 相关研究对本课题的覆盖与约束
[P267] 比较应从安全问题和前提开始
[P268] 把论文按“代理安全”“凭据管理”或“撤销”贴上主题标签，还不足以判断本课题的空间。需要逐项比较研究假设谁可信、已知哪些服务事实、控制哪些调用路径、输出什么保证，以及怎样计量成本。下面按实际问题组织直接近邻，并把已确认能力与后续比较任务对应起来。
[P269] 秘密代用已经有明确的协议研究
[P270] SUDP 让请求者提出规范化操作，由用户批准，再由保管者完成限定的秘密使用。它把不可信请求者与可重复使用的秘密权限分开，并列出对应安全性质。该研究与本系统的保险库和可信执行者直接重合，构成秘密代用的比较基础。[R26]
[P271] 因此，本题需要额外验证的是，这类代用流程接入某个网站后，形成的访问状态怎样对应本地任务，以及多项委托的配置能否满足后续停止与保留。若现有协议及其适配已经完整覆盖目标，系统应复用其能力。新的贡献需要给出具体新增条件和证据。[L02]
[P272] 任务约束与信息流执行已有较强方案
[P273] PAuth 研究任务到具体操作及其参数来源的关联，CaMeL 通过控制流、数据流和能力限制工具行为。FIDES 的工程文档则提供内容标签与调用前策略执行。这些工作直接约束“在模型之外设置执行检查”作为原创主张的范围。任务绑定授权还见于 OAuth Mission 个人草案，其版本状态与适用保证需单独记录。[R24,R25,R44,R45]
[P274] 它们也说明本系统需要把两类问题组合评价。一类是某项调用是否符合任务和数据流策略，另一类是支持该调用的账户与访问状态是否仍然满足生命周期条件。一个完整实验可以先复用已成立的操作约束，再加入共享会话、撤回和响应丢失，观察新增管理机制究竟改善了什么。
[P275] 从批准到业务效果的闭合已有直接先例
[P276] AID-Guard 研究执行前批准如何持续关联到提交、结果不明、重试和恢复。在其声明的提供方契约下，保留同一预约并限制后继执行，使一次批准与业务效果建立可检查关系。本课题中的非原子执行和恢复应以这些机制作为直接近邻。[R27]
[P277] 它对本题的进一步启发是，计划成立依赖提供方契约。系统需要知道幂等标识、结果查询、效果终结和围栏能力在哪些路径上适用。若这些事实已经给定，已有协议可以直接发挥作用。若它们存在影响决定的缺口，研究才继续进入契约证据和配置选择问题。
[P278] 长任务撤销和独立支持保留与本题高度重合
[P279] Root-Scoped Quiescence 已研究授权撤回后的委托、队列、回调与服务端操作，并明确保留其他独立授权支持的活动。它使用登记的路径、支持关系、围栏和证据组合建立限定范围的撤销结论，也保留证据不足时的未定状态。这与本课题的共享授权和停甲留乙需求具有直接重合。[R28]
[P280] 因此，后续比较应把其支持关系和保证前提逐项写入本题的模型。可继续验证的差异是，在调用其执行能力之前，如何依据已有或可取得的证据选择满足目标的访问配置，以及安全补证会怎样改变该选择。仅增加一个 UNKNOWN 状态或采用类似授权图，已经有明确的先例约束。
[P281] ResidualAuth 进一步分析授权历史需要保存什么信息，以区分未来相同撤销操作下的不同许可结果。这为本题的持久状态提出要求，必须保留与后续决定有关的授权依赖。新的状态表示需要比较其能够保持的未来行为与代价，不能只用当前权限表作为较弱对照。[R29]

[P303] DRD 以最终决定需要什么信息组织测试选择，shielding 根据部分可观测状态约束安全动作，多成本受限 POMDP 研究多维资源条件下的目标可达性。账户访问图及其状态转换扩展则刻画凭据、账户和访问路径的变化。它们与 A、B、AB 的思路直接相关。[R30–R33]
[P304] 认证核验包含副作用，可以要求重新检查静态测试模型的适用条件，但通用有状态规划本身也能表示副作用。后续比较必须给通用方法相同的状态、动作、观察、预算和清理义务，再考察特定表示或求解机制的差距。项目已有通用精确参考、SMT 和 GENERIC_REPLAY，应继续作为主要对照。[L06]
[P305] 由覆盖分析得到的研究定位
[P306] 当前可优先研究的对象，是证据不完整、核验有状态变化、多代理同时提出停止与保留要求时的凭据配置决定。它把产品中真实存在的访问链条与已有规划方法连接起来。可以形成的贡献包括版本化语义模型、模型到真实服务的保持条件、可复查反例，以及经过强基线分离验证的方法与端到端结果。[L02,L04–L06]
[P307] 这一定位给出了继续投入的依据，也给出了能够推翻候选路线的检查。若通用方法获得相同语义与结构后复现全部收益，结果就按领域模型或工程优化评价。若候选在明确输入族上保留安全与合法可用性，并形成可证明或可复现的代价差距，才进一步提出方法创新。第8章据此给出 A、B、AB 的准确职责。
[P308] 8 把研究问题具体化为 A B 和 AB
[P309] 核心研究问题
[P310] 在多个 AI 智能体共享用户账户、服务原生认证与撤销关系存在不确定性、核验受到批准与预算限制的条件下，系统如何获取足以支持决定的证据，并选择满足指定停止和其他任务保留目标的凭据配置，同时控制端到端成本。
[P311] 这个问题至少包含输入、约束、输出和代价。输入是账户与任务、用户批准、已有凭据、候选服务契约和可用操作。约束是当前访问合法性、停止目标、保留目标、预算和后续清理责任。输出是可执行策略或具有明确原因的其他结论。代价同时包括原生授权单元、请求、用户交互和计算开销。[L02]
[P312] A 认证语义感知
[P313] A 维护与现有证据相容的可能状态集合 K。每次核验之后，根据允许的状态变化和观察结果更新 K，并保存新形成的义务。一个动作只有在模型覆盖的可能状态中都符合批准和安全条件，并且保留合法结束路径时，才进入可执行集合。已有项目把这类有限有界判定作为 A 的安全内核。[L02,L05]
[P314] 例如，系统需要确认当前连接实际属于哪个账户。若有获准的详情查询，可以先检查身份与范围。若需要新的登录尝试才能确认，就必须考虑新会话创建与清理成本。查询到的账户信息可用于更新对应事实，原生撤销独立性仍由其自己的证据支持。这种按事实类型和作用域更新的方式有助于防止结论扩张。[L02]
[P315] B 可撤销凭据配置
[P316] B 根据任务需求和认证契约，选择哪些凭据、授权单元和支持路径供各代理使用。它需要检查任务开始时能够完成获准工作，未来执行指定停止时能够满足目标，并在要求保留的路径上维持乙的合法访问。[L02,L04]
[P317] 本地 B 的历史目标以原生效果单元数量 G 为主，配置字典序用于同值选择。新增批准、隔离资源、请求和计算时间应分别记录。G 的含义需要依据服务的效果关系定义，不能直接用令牌字符串数替代。对于已经按同目标精确求解的基线，候选方法的价值可以体现为更低求解成本、更清晰的证据或更广的可处理结构。[L02,L06]
[P318] AB 配置反馈驱动的安全补证
[P319] AB 把配置器遇到的具体缺口反馈给 A。例如，B 发现停甲留乙是否可行取决于两个凭据是否共享撤销范围，就可以把这一事实标记为补证目标。A 再判断可用查询能否获得相关信息，以及查询之后是否仍能完成整个任务和清理责任。[L02]
[P320] 在贯穿场景中，如果现有证据已支持共享连接满足 L，AB 可以直接进入配置。如果 R 需要独立性证据，AB 才考虑相应补证。当证据表明原生授权不可分、且现有批准中没有其他可行路径时，系统应给出明确的受限结论，并说明需要何种新的能力或用户决定才能继续。[L02]
[P321] 状态结论与保证边界
[P322] 表9  有限模型的结果状态

[P334] 9 完整凭据管理系统应如何承载研究
[P335] 工程交付范围
[P336] 完整系统可以围绕一个用户、两个代理、两个服务和少量明确任务形成可演示闭环。用户能够建立账户连接、保管凭据、确认任务、查看使用记录、撤回单项任务，并观察其他任务是否保留。研究方法通过这个闭环接受真实后端与故障情形的检验。该范围与本地需求规格和三个贯穿场景相衔接。[L01,L02]
[P337] 系统的逻辑顺序可以描述为用户批准任务，代理提交操作，A 与 AB 根据必要性取得证据，B 提出配置，独立检查器核验适用条件，可信执行者落实真实调用，持久协调器记录结果、撤回和清理责任。已有证据足够时，流程直接使用现有契约。各模块承担逻辑职责，部署时可以组合成少量进程。[L02]

[P367] 用三个场景展示系统的研究作用
[P368] 场景一是已知契约下完成正常任务。代理甲读取并生成摘要，代理乙继续监测，系统测量合法完成与凭据暴露边界。该场景也用于检查 A 和 AB 是否产生了多余核验。[L02]
[P369] 场景二是配置所需证据不足。系统显示具体缺口，执行获准补证，更新证据后重新决定配置。评价重点是证据是否真正改变配置，以及全流程增加了多少请求、授权和清理成本。[L02]
[P370] 场景三是用户停止代理甲并保留代理乙。系统按照 L、R 或可支持的 E 分别执行和展示结果，并注入撤回与执行竞态、响应丢失、服务拒绝和进程重启。评价需要同时记录甲的停止、乙的可用性、已发生效果和未结责任。[L02,R27,R28]
[P371] 为什么完整系统值得作为毕业设计载体
[P372] 完整系统把方法的适用条件变成可观察的运行事实。凭据是否真正隔离、证据是否过期、撤回是否影响乙、恢复是否重复产生效果，都可以通过具体任务检查。工程贡献由功能闭环、可靠性和实验平台支撑，学术贡献由问题定义、方法性质及强基线差距支撑。两类贡献通过统一工作流关联起来。[L01,L02,L06]

[P401] 项目 pilot02 记录了288对、576次方法运行。六种方法各运行96次，每种方法均为20次合法完成、56次拒绝和20次 UNKNOWN。三个主要比较的成本均值比均为1.00，合法完成率差均为0。A 与 AB 的查询选择和配置反馈在该批已知契约输入上未激活。[L05]

[P410] 11 密码学在本课题中的基础作用和辅助研究空间
[P411] 基础安全首先依靠成熟密码学机制
[P412] 凭据保险库需要加密存储与密钥管理，服务通信需要安全通道，批准和证据需要完整性保护，令牌使用可以结合服务支持的发送方约束。它们分别保护秘密、通信、记录与调用者关系，属于系统可靠运行的基础。具体实现应沿用成熟库与协议，并由威胁模型确定密钥边界。[R02,R15,R17]
[P413] 这些基础机制与认证语义形成互补。签名可以确认某段记录来自持有相应密钥的一方，记录内容对服务行为的解释仍需契约和执行证据。加密可以保护凭据保存，用户要求的远端停止则依赖服务的失效与接受机制。把每种保证写清楚，有助于选择真正需要密码学支持的子问题。[R12,R26,R28]
[P414] 辅助研究可以围绕有限的私密证据问题展开
[P415] 本地密码学支线讨论稀疏残差、掩码、故障定位、来源绑定和 MPC 核验。一种相关应用设想是，在多方共同检查某项凭据记录关系时，只公开完成决定所需的结果，同时保护诊断过程中的额外信息。该设想需要先固定参与方、输入来源、被验证关系、允许泄漏和中止后的责任。[L07]
[P416] 现有材料包含限定模型下的秩与补证关系、两故障修复构造和有限验证。项目也记录了完整成本尚缺优势、成功域变化影响比较、来源与主线接口待接通等条件。后续应把这些结果作为具体理论候选继续核验，并单独评价它们是否改善主线系统的安全或成本。[L04,L07,L08]
[P417] 辅助方向的进入条件
[P418] 只有当主线出现明确的隐私需求，且现有签名、访问控制或直接可信检查难以按相同信任条件满足时，才有充分理由投入新的私密核验机制。届时需要提供具体输入族、泄漏指标、最强可用通用方法与预测差距，并保持输入成功域、预处理、通信和中止模型一致。[L04,L07]
[P419] 在论文结构中，密码学可以先承担安全基础，再以通过上述门槛的子问题形成辅助贡献。主线的认证语义、可撤销配置和系统实验可以独立评价，辅助结论通过明确接口与主线关联。[L02,L07]
[P420] 12 怎样把方向价值转化为可验证的研究贡献
[P421] 先固定比较条件
[P422] 候选方法和基线必须获得同一组可见信息、可调用接口、用户批准、初始状态、预算和安全目标。资源服务器的内部真值可以用于独立评分，算法应按其实际权限获得观察。真实服务原生能力与实验中新增的网关、取消接口或管理权限需要分别标记。[L02,L05]
[P423] 在精确求解相同优化问题时，参考方法已经给出的最优值是共同目标。候选可以争取更低计算开销或更好的可扩展性，也可以对新的问题域建立模型和性质。评价中应同时测量有效任务完成与安全，防止把大量拒绝造成的低风险误写成完整任务能力。[L05,L06,R34]
[P424] 实现前必须形成可证伪的分离声明
[P425] 按照项目规则，新候选机制进入实现前，需要同时给出具体输入族、度量指标、当前最强通用方法和预测差距，并先构造至少一个通用方法确实付出更高代价的实例。对本课题，“最强通用方法”应落实到可复现的比较集合，例如同语义精确联合参考、增量 SMT、共享相同剪枝信息的搜索，以及通用证书重放，并公开版本与适用条件。[L06及项目研究规则]
[P426] 以下检查记录可用于现有研究路线的后续筛选。它们说明应该验证什么，当前预测差距保持待建立状态。

[P474] 13 选题判断与后续研究顺序
[P475] 题目为什么能够形成连贯的研究主题
[P476] 现代密码管理器已经向代理代填和受控凭据使用扩展，身份平台与会话代理也提供了实际部署能力。完整任务还需要处理登录后的远端状态、共享授权和结果不明的操作。用户的停止与保留要求因此需要逐项对应到服务能力。证据足够时直接配置，决定所需事实缺失时评估安全补证，再选择满足目标的路径，构成了本题的研究链条。[R35–R42,R27–R29,L02]
[P477] 这一方向具有明确的实际问题、可以复用的技术基础和可构造的实验场景。现有任务级授权、长任务撤销和通用规划研究也给出了清楚的比较压力。适合作为硕士课题继续论证的依据，是能够把用户需求逐步收敛为有限且可验证的问题，同时通过完整系统说明方法的实际作用。[R25–R33,L02]
[P478] 建议保留的双层目标
[P479] 工程目标是自主设计并集成面向 AI 智能体的凭据管理系统，在明确的账户、服务、任务和威胁范围内完成批准、使用、撤回、保留、恢复与审计。其验收依据是可复现的完整业务闭环。[L01,L02]
