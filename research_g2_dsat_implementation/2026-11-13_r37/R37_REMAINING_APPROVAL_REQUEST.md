# 保留的9项合同修改

本轮按R37第一/七节已经批准符合条件的28组规则。以下9组在R36原合同中明确为FULL_MANDATORY_UNTIL_EXPLICIT_CHANGE，其有损替代仍需研究者单独确认。此表列出保真责任的具体差异；没有自动执行权限。

| 原字段组 | 需确认的责任变化 |
|---|---|
| `r35.exception_text` | 原完整异常文本 -> 最多4096B有界文本或UNRENDERED。原已知拒绝码/类型/errno等另行保留L0。 |
| `r35.exception_args` | 原完整参数 -> 最多2048B参数树。任何授权/消费/来源/预算/断言决定参数仍保留L0。 |
| `r35.exception_filename_strerror` | 原filename/filename2/strerror -> 各最多1024B显示。参与路径或来源判断的值须完整保留或精确可逆引用。 |
| `r35.traceback_file` | 原所需帧路径 -> 最多8帧、每路径1024B。原关键来源身份与其判定输入不在豁免内。 |
| `r35.traceback_module_function` | 原所需模块/函数上下文 -> 最多8帧、每字段256B。关键分类与安全上下文继续L0。 |
| `r35.traceback_source_excerpt` | 原全文责任中的摘录 -> 源摘录0B。R36生产来源none/候选0只描述新表示，尚无证据豁免原责任。 |
| `r35.exception_descriptor_total` | 原完整异常描述 -> 16384B有界描述。类型、已知errno、拒绝依据等L0保护头不得由整对象溢出丢弃。 |
| `r35.case_error_text` | 原case错误上下文 -> 8192B有界显示/可验证引用。原PASS/FAIL/ERROR及执行事实和必要理由继续L0。 |
| `r35.log_input_utf8` | 原必需stdout/stderr -> 在原64KiB份额内的有界非决策显示。原日志中的必需事实须完整保留，未证明冗余的内容不自动降级。 |

如后续研究者明确批准上述非决策子内容采用L2，应逐组绑定保留的L0成员/可逆引用、保存范围、原完整保留=false、未知长度/摘要规则及实际合同版本。只有完整原文实际处理过才能报告原摘要可用。未批准的条款继续保留原完整义务，缺失继续完整验收false。

研究者也可明确保留原完整义务并撤回相应有损提案。两种决定均不等于容量证明、Runner符合性、来源接纳或测试批准。source_excerpt候选0B与整体descriptor溢出尤其需要保留此边界。

禁止解释：将L0降为L3、将摘要当原文、将截断路径当身份、用期望元数据代替观察、凭版本相同接纳新运行时、用省略标志声明原完整义务已经满足。这些解释已被本轮拒绝。

上述条款保持待确认的政策状态；本轮没有发起第二个工程执行动作。唯一拟议工程下一项为申请仅使用已批准L0/无损规则的G2最小修复，见最终裁决及R37_G2_IMPLEMENTATION_OBLIGATIONS；本轮源码/测试授权均为false。
