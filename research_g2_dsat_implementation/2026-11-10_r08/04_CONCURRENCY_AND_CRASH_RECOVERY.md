# 并发、崩溃、重复提交与恢复

静态案例全部NOT_RUN。以(a,o)=(120,0)及O0为示例，不表示访问过真实数据库。

## 1. 并发场景

| 场景 | 允许次序/结果 | O、费用和证书 |
|---|---|---|
| C1 同基准P1/P2 | P1成功到(121,1)，P2旧base拒绝，仅记其拒绝簿 | O1完整保留；P2已付计算不退款，逻辑delta不重复；新ID重基准，数学输入不变可复用 |
| C2 撤回先commit后 | 撤回事务先令a/O变化，旧提案CAS失败 | gA不会被提案激活；新基准可归档历史且保留新隔离/关闭责任 |
| C2反序 | 归档先成功，随后撤回按当前状态更新O | 旧历史保留，任何旧当前许可重核；无S3新release权 |
| C3 迟到先到 | record与O原子变更使旧base不符 | 原origin隔离，重核U/E/c/D/O；不覆盖close:c新义务 |
| C4 第三批准 | 新入口改变a/O/manifest，旧全域结论过期 | 旧固定T历史保留；新scope重新计算/保持前沿 |
| C5 AS异步 | a/o不变，旧handler仍可AddToken | 本地CAS可成功归档，Native资格仍UNKNOWN；不以CAS代替fence |
| C6 O单独变化 | 任何规范O变更必须同时更新o与a；独立o钩子漏更为合同违约 | 两个base摘要/版本都检查；不得因a碰巧相同漏O |
| C7 权限/时效变化 | 写者当前权限再次检查；过时数学可仅历史归档 | current_use状态不从旧回执继承；原计算/读取成本保持 |
| C8 失败ID换body | 首次合法拒绝已绑定digest，同ID新body冲突 | a/o不变，旧拒绝/证据保留；新基准使用新ID |

## 2. 十四位置崩溃矩阵

| K | 持久/临时与恢复处理 |
|---|---|
| 1 读权威后 | 原W/O已持久，快照临时；重读当前再准备，不消费新Native预算 |
| 2 取证中 | 可能只有部分可信收件/读取历史；费用已发生，不能假定未生效；重获缺证并保O |
| 3 S1后 | projection临时，原O不动；可按已冻结数据重建，历史/费用引用保留 |
| 4 S2中 | 无完成证书，原O不动；重算或UNKNOWN，新的CPU工作单列 |
| 5 证明后 | durable artifact若有可按SHA复用，否则重建；不据“已生成”更新O |
| 6 检查后 | 验证receipt仅在可信且可解析对象存在时复用；检查器版本/当前scope重新验证 |
| 7 BEGIN前 | 没有本次数据库效果；重试会先查ID再CAS |
| 8 部分SQL写后 | 同库事务未提交则恢复旧W/O/簿，不能出现半份强状态；不同库/外部ref会破坏前提 |
| 9 COMMIT后ACK丢 | 全部W/O/簿已持久；同ID/body返回原receipt，当前权限另报，逻辑effects不重做 |
| 10 同ID/body重试 | 历史读取权限满足则回原结果，a/o不变；实际查库/验证/传输费用仍收费 |
| 11 同ID异体 | 比较摘要冲突，原O/费用/历史不动；拒绝记录与世界state分开 |
| 12 重启遇过时证书 | 历史数学事实保留；当前eligible/Native结论不继承，可仅归档或重准备 |
| 13 重启后迟到创建 | 以原attempt/origin登记/隔离并维护O；已过期旧proof不压制新风险 |
| 14 恢复期间再撤回 | 当前权威事务决定次序，旧cache/receipt不恢复批准；新O先保留再处理 |

每个位置的完整输入/retry/费用/证书/错误字段在CRASH_RECOVERY_MATRIX.json。当前无崩溃注入、恢复测试或数据库连接。

## 3. 幂等范围

exactly-once限同一可信实例中已持久的逻辑效果和回执，不保证HTTP仅发送一次或AS仅执行一次。数学归档不会新建凭据。未提交事务回滚后不存在持久首次ID，重试按新接纳处理；合法拒绝已提交的ID则始终绑定同body。

Replay先查持久簿再比较旧base；否则ACK丢失后，自己的成功a+1会使重试误报CAS冲突。权限先分读历史与新写，返回历史receipt不等于当前可用许可。

## 4. 成本与活性

逻辑cost_delta按work/effect ID只入一次，跨新proposal_id重用同work也去重；ID同内容不符冲突。真实SQL/解密/校验/锁等待/重试和重算每次都有成本。旧spent/actual_sends不退款，不能承诺“幂等重放零成本”。

频繁并发可使严格CAS持续冲突；安全性不蕴含有界成功/公平或SLA。数据库/密钥不可用返回UNKNOWN/UNAVAILABLE并保原责任，不退回旧缓存写入。备份还原/恶意回滚/多主分叉需要另有可靠fence，超当前崩溃模型。
