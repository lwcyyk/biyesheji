# 负证据、完整性与关闭的条件

## 1. 四种不同结论

`不存在可取回Inbox项`、`某标识行在一次读中缺失`、`完整Find内当前无目标材料`、`以后也无声明目标可用材料`是不同性质。前面三项均不能独立替代最后一项。

## 2. 条件表 N01—N12

| 条件 | 必需证据 | 当前边界 |
|---|---|---|
| N01 合法读与使用范围 | 原生组织/对象授权、Collector/当前用途权限 | 事后过滤不缩读取权；AI不直取管理secret |
| N02 精确对象/代次 | 账户/app/issuer、原生PK与birth、查询参数/绑定 | hash/JWT签名不自动证明attempt来源 |
| N03 响应完整 | HTTP/解析成功、未截断、预期字段 | 超时、1MiB截断或JSON损坏保留UNKNOWN |
| N04 集合边界 | 全组织/相关账户/app及初始记录、所有写入者 | 不只看i1/i2；第三grant/历史写入必须覆盖 |
| N05 分页一致 | 单Find足够界或合法一致分页/受控稳定集合 | 当前分页只支持固定p=1；普通多页无共同快照承诺 |
| N06 日志性质 | 正向条目来源可靠；若用缺失推无创建，另需事务级完备写入 | 现有journal/inbox位于响应后，不满足后一强条件 |
| N07 容量/来源全集 | I/T/c、真实来源包含E、互异历史U、F非空 | 外部创建/无界后代不能截成三槽 |
| N08 创建前沿 | 饱和证明，或独立可靠无效果/终态/不可再创建证据 | 现有Q成功、撤回ACK、空快照均不提供Fence |
| N09 后续入口 | 相关批准/重试/外部RT持有者受控、全部已放行派生纳入 | gV active余量/旧V位置handler均需保留 |
| N10 失活持续 | 声明路径P的inactive及无恢复/重激活frame | 单次内省/UserInfo拒绝只有点时范围 |
| N11 接受路径 | Token表路径、RT、相关下游及必要后代覆盖 | cookie、离线RP、已接纳业务效果另列 |
| N12 当前依赖 | source/profile/权限/时间/权威与原生frame仍满足 | 单一authority版本相等不能证明原生无并发 |

条件按所声明结论选用；正向创建见证无需假设日志覆盖所有失败，全集负证据则需要更强范围。没有把全部条件揉成一个来自上游的complete布尔。

## 3. 可用的三条关闭路径

**A. 容量饱和。** 在N07—N11及真实执行包含关系下，非空F、H_T=0，证明声明范围无剩余目标可用/迟到单位。U可以包含已经删除的可靠历史见证，不要求当前列表仍保存它。此路径不依赖“未找到”断言，不要求先知道每个u的唯一来源。

证明：固定真实f，已见可用数≤`|f⁻¹(T)\D|`，未见创建≤`C_T−|f⁻¹(T)|`。相加≤H_T=0。所有目标原材料、重试/派生和必要路径都在容量/其他scope中覆盖，所以无遗漏。若只覆盖直接i1/i2，结论只限该切片。

**B. 可靠无效果/终态。** 全生命周期无创建的可靠收据可把直接总容量取0。仅证明handler以后不再创建，则只排除未来增量，历史上已经创建但尚未被观察的材料仍可能存在；还需创建全集/来源及相应失活证据。不能把这种终态直接当R_T=0，R_T同时包含未见的既往创建。当前接口未提供通用这种收据，列SOURCE_OR_REFINEMENT_GAP，不由超时或AS缺行替代。

**C. 封口后完整存在性快照。** 若独立证据已经封闭所有相关未来创建/派生、当前快照覆盖全部目标存活表示，且“缺行”对全部声明接受路径持续意味着不可用、无删除后仍有效副本，则当前无相关行可证明该范围关闭。该路径对离线JWT/cookie通常缺前提；现有空Find自身不证明封口。

## 4. 手工反例

**空Inbox。** i1通过父检查后插入c，返回丢失。inbox/journal为空而c有效。直接c_i改0导致错误关闭。

**完整空快照。** i1已经通过检查但暂停于AddToken前；完整Find只有已知p/b或无新行。观察后i1插入c。快照完整仍未封未来。

**分页漂移。** 按name读第一页后，一行在已读位置之前插入，第二页按offset继续，或行删除使尚未读项前移；同一行可重复、另一行可漏。每页都成功不保证并集是完整同刻集合。单语句上界方案与一致快照必须另证。

**历史删行。** 可靠创建u已失活并删行，当前U_live为空。若丢掉历史U，容量被错误恢复；若同创建被多条日志重复计，容量可能错误饱和。两方向都需要birth去重/tombstone。

## 5. 结论边界

`INSUFFICIENT_COVERAGE`用于缺完整页/宇宙/路径；`UNKNOWN_PENDING`用于仍有可能创建；`SOURCE_OR_REFINEMENT_GAP`用于当前服务缺终态、受控导出或源契约。只有条件齐全且有可核对证明的scope才允许C_native。

所有未知输入都可以通过保留相应匿名风险得到保守投影；若请求强原生关闭，缺关键原生事实时只能给受限/未决结果。该保守规格不承诺所有实例最终完成。
