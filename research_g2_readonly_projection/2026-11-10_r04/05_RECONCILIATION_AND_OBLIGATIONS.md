# 证据融合、对账与责任覆盖

## 1. 融合原则

没有跨来源的“最后记录胜出”总序。先核权限/身份，再按证据所证明的谓词、创建代次和发生范围融合：

- 权威历史负责批准、请求、release、来源与隔离；原生列表不能修改这些事实。
- Inbox/可信journal与源映射负责正向结果/创建及原attempt连接；不是失败完备日志。
- 命名查询负责时点/路径状态；不能删除创建历史。
- 完整快照负责其Find范围内的集合；来源和未来前沿分别检查。
- 源容量、持续失活和frame合同负责把这些事实推成受限风险结论。

“优先级”仅表示某个字段的权威来源及验证依赖，不允许忽略另一份可信冲突证据。

## 2. 十类融合问题

| 问题 | 规则 |
|---|---|
| 同一材料 | 以issuer/DB实例、PK、birth及受控绑定证明连接；JWT/原值摘要只作可信内部辅助 |
| 重复 | 同创建多次观察合并引用，不增U；同attempt同体结果幂等登记，不退已付费用 |
| 来源不一致 | 未鉴别片段拒绝；可信硬约束不能共存时EVIDENCE_CONFLICT；保留双方及原O |
| 旧观察 | 留在历史时点；较晚结果可能解释生命周期变化，不自动判矛盾 |
| 权限不足 | 当前读取拒绝；不能根据未获得响应证明不存在；历史保留/使用遵守其批准 |
| 陈旧 | 过去创建/撤回事务仍可作历史；当前可用/持续失活/准入依赖重新验证 |
| 外部写入者 | 加入有可靠界的可能来源，或保留未覆盖frontier；不删有害候选 |
| 日志缺口 | 正向有效条目可保留；未覆盖范围继续未知；缺失无法补成无效果 |
| 删除/到期 | 历史U与spent、来源/关闭证据留tombstone；当前Token行另存 |
| 第三批准/后代 | 记录精确origin及允许的未来创建；重建全域manifest，不迁移旧A责任 |

## 3. O的字段和转换

每项义务保存id、kind、origin_scope、attempt/material/group refs、risk/审计性质、条件容量、接受路径、证据依赖、创建/更新版本、消解证明、剩余缺项与费用引用。

| 转换 | 前提 | 新责任/保留项 |
|---|---|---|
| A撤回 | 当前权威提交 | settle:i1/i2保持，close:p及已知A材料隔离；C_local可单独成立 |
| 新可信Issue结果 | 完整五元/原请求与单位绑定 | j_issue创建部分按容量饱和转close:u；归V；结果审计/派生仍按scope保留 |
| 未饱和见证 | 可靠创建但还有容量或来源歧义 | 原settle＋材料/分组关闭责任；不得任选来源删settle |
| 分组容量饱和 | F非空、R_T=0、全过程容量可靠 | 目标创建风险转换为全部可能目标材料处置；不要求唯一f |
| 材料持续失活 | D_P与必要后继覆盖/终态 | 关闭相应close风险，保留历史/未满足审计 |
| 迟到结果 | 原五元匹配，当前grant已撤回 | 原origin隔离；新增观察/匹配并重算容量/O；不恢复旧资格 |
| B放行/返回 | 最终当前守卫，可信结果绑定 | 增exec:rB，结果齐才结清该执行项；O_A/O_V保持 |
| 查询未知/失败 | 无新可靠排除证据 | 不退spent/机会，O保持；记录失败与缺证 |
| 日志冲突/失权 | 证据不够支撑原结论 | 保留/扩保守O，撤销相关当前证书使用，历史事实保留 |
| 管理窗口/恢复 | 当前真实权限/版本与无回滚 | window责任按真实接口另结；新纸面证书不擅自关闭旧单未知窗口 |

“settle转close”只转换已被证明覆盖的风险部分。若仍要求原handler终态或结果归档，保留await_terminal:i。一个材料范围C_native可在证明无再创建后成立，同时该审计义务仍在；全局COMPLETE继续取决于其实际目标。

## 4. ProjectEvidence的条件可靠性命题

前提H：可信当前权威/托管与原请求绑定；采纳证据真实且权限/时间范围正确；原生源码/部署合同包含真实执行；I及容量、见证互异、真实来源边、D和开放前沿保守；字段/规则按03执行；提交与恢复不丢旧历史、费用/O；使用证书时重核其依赖。H不由JSON中自填true得到证明。

结论：从可靠初态出发，对任意有限允许事件/观察序列，投影K包含全部真实相容状态，O覆盖全部声明风险；接受的局部证书只支持其scope。缺证可输出UNKNOWN或开放前沿，无法完整覆盖时不生成C_native；冲突不产生空集许可。

证明依赖链：

1. 基态：权威释放记录和旧风险先于外部效果持久，三未知及p/V未来入口都在O。
2. 合法观察：有效证据只排除与其**历史谓词**矛盾的轨迹；真实轨迹满足采纳证据，继续在K中。无权/缺项/陈旧现态不能缩当前可能集。
3. 创建：互异U提供可靠下界，真实来源保留在E，真实f满足容量，因此F含真实投影。F为空说明前提/证据冲突，停止强判断。
4. 容量/失活：02同f不等式给H_T可靠上界；04的路径/frame保证D不会抹掉可用风险。未覆盖后代由开放前沿保留。
5. O转换：每项风险要么仍由旧义务覆盖，要么被等价/更保守的新材料/分组义务覆盖，要么有逐scope排除证明。撤回/B完成不删除无关责任。
6. 当前性/恢复：依赖变化重基准、恢复累计历史，提交原子保留旧O；证书不能绕过真实release守卫。由事件归纳得结论。

性质是标准可靠抽象、来源图和持久工作流的条件实例化；本轮未证明源到二进制符合、实现执行精化或新的最优算法。

## 5. 冲突与局部进展

状态是分scope issues集合。一个伪造片段被拒绝不妨碍鉴别后的用户撤回；原生来源冲突也不能阻断已独立证明的C_local。B只有在自身非空可靠知识及充分frame下才能局部准入，不能从全局F空“任意命题为真”得到许可。

静态来源可由成熟整数最小费用流计算。即使F可计算，原生RT共享/持续失活/范围真实性仍是输入责任，流算法无法补出缺失的服务事实。
