## 0. 执行摘要和立项裁决

第四阶段提出的主假设 H1-S 是：在恶意同步、可信本地核心、独立新鲜度下界、同等功能和相同信任假设下，统一的“已见证账户状态—授权版本—功能执行依据”机制 `P` 能阻止正确实现的强组合基线 `B*` 仍允许的敏感功能效应。该假设尚无正面实验支持。竞争解释 H2 为 `B*` 已足够；H3 为发现的攻击只是既有事务/重检机制遗漏；H4 为观测与负载产生伪差异。

**阶段决策**：先开展状态机安全检查 E0；仅在识别具体待分辨机制的前提下进入 E1/E2（T3 动态策略发布泄漏、T5 隐私法定人数一致性），再决定是否投资完整协议原型。T1/T2 为必需的正确性回归实验，**不能据其弱基线失败论证创新性**。RSPK 核心派生协议暂缓扩张。若强基线在同等安全性质下全部通过，应按证据接受 H2，转向隐私/可用性权衡或系统化安全测量，不为保持研究规模强行制造机制创新。

本阶段最有信息增益的产物是：**可共同复现的参考状态机、强基线与候选新机制的差分实现、T1—T5 机器可读攻击轨迹、独立测试判定器以及预先约定的停止/转向门槛**。

## 1. 研究目标、输入和预期输出

### 1.1 研究目标

- **科学目标**：区分 H1-S（新增安全语义）与 H2（已有机制正确组合足够）、H3（普通实现漏洞）、H4（测试伪差异）；失败结果同样保留。
- **机制目标**：解释动态策略控制平面与私有状态之间的信息流关系、匿名多见证者如何同根确认、动态撤销中本地效应的精确线性化位置。
- **工程目标**：给出一个独立于 UI 的可复现安全核心模型，随后在真实同步、共享和恢复流程中复用测试轨迹。
- **范围控制**：当前只验证恶意云同步侧和受管理客户端的安全性质；终端完全失陷、已复制外部 Passkey 私钥撤销和第三方已处理的不可撤回请求单独列为范围外性质。

### 1.2 输入

3. `[PRIMARY]` Zanzibar 对因果授权顺序的既有保障、Macaroons 的可约束能力、VBP 的注入防御安全模型、C2SP 的检查点及见证法定人数策略、transparency-dev/witness 的现有实现。
4. `[DESIGN]` 可选额外机制：统一可信执行证明（`JointEffectProof`，目前仅为实验性的设计占位符）、隐私同根投票关系证明（`PrivateQuorumProof`，目前无安全证明和实现）；新增语义需先精确定义，再由独立判定器评价。

## 3. 安全模型、Oracle 与理论边界

### 3.1 参与者与攻击者

- 诚实已有设备 A/B、灾难恢复设备 C、共享内容攻击者 E、完全恶意 Sync、独立 Witness 集合 W，以及观察者 O。
- 默认配置 `n=4`、至多 `f=1` Byzantine Witness、确认阈值 `q=3`。满足 `2q-n=2>f` 和 `q<=n-f` 的静态交集与基础活性条件；**本算式不代替完整协议证明**。
- Sync 可删除、重排、重放、替换完整旧快照、选择性隔离设备、制造多分支和操控传输延迟；E 可连续注入共享更新、查看其本来有权看到的同步元数据和允许的网络输出。
- 信任本地安全核心、固定的恢复信任锚、正确密码学原语，以及模型内至少规定数量的诚实 Witness；**网络失联引起的活性失败单列**。
- 攻击者无法通过纯粹的重放获得新的合法设备签名，且不假设能够直接读取本地根私钥。

### 3.2 统一确认状态

定义 `S_e=(R_e,A_e,D_e,P_e,M_e)`，分别为凭据根、授权根、设备撤销根、功能策略根和可选 Passkey 元数据根；`C_e=(account_commitment,epoch,root,prev,registry_version,quorum_evidence)` 为见证状态证据。

`o` 是对象，`c` 是受约束功能能力，`f` 是受管理本地功能，`L` 是**经独立可信路径取得的新鲜度下界**。`Committed(C_e)` 表示 Witness 按本阶段固定的确认规则对它完成确认。 `KnownRevocation(device,t)` 与 `AdmitLocalEffect(t)` 分别记录客户端已知撤销证据进入状态机的时间/序点、以及副作用获得本地执行许可的时点。

核心 Oracle 的规范性前提：

```text
ApproveEffect(f,o,c,e,t) ->
    VerifyTrustAnchor()
 && VerifyAuthenticatedCheckpoint(C_e, S_e)
 && Committed(C_e)
 && e >= TrustedLowerBound L
 && VerifyObjectInclusion(o,R_e)
 && VerifyCapability(c,f,o,A_e,D_e,P_e,e)
 && VerifySameSnapshot(o,c,A_e,D_e,P_e)
 && VerifyAllowedInformationFlow(f, view_policy_e)
 && CheckLocalEffectAdmissionAt(t)
```

**独立判定器不能单纯复用 P 的代码**；应由安全不变量和历史事件真值生成，用已标记的恶意轨迹、变异种子进行自身正确性验证。对于被篡改的签名/承诺，在模型中以“不可伪造”语义检查，在实际原型中使用真实加密验签。

`e >= L` 的结论仅为“不早于受信下界”，无法单独推出“全球绝对最新”。需要在线挑战的实验，将查询可响应诚实见证者、最大等待、超时拒绝与外部确认延迟列为输入，不与离线恢复混为同一保证。

### 3.3 四类安全目标

- **P-Safe**：每个 `APPROVE` 效应都有一个可重建的合法状态/对象/授权/撤销/策略共同快照。
- **P-Fresh**：可信恢复下界为 `L` 时，所有 `e<L` 的恢复输入不得进入正常使用状态；未取得下界输出明确的 `DEGRADED/REJECT`。
- **P-Effect**：已知撤销发生在本地执行批准前的操作不得获批；请求发出后第三方实际完成不包含在此保证中。
- **P-Privacy**：存在两种只在无权私人秘密上不同、允许泄漏相同的世界 `V0,V1` 时，攻击者从观察转录中获取的区分优势受控。允许泄漏需先定义；有意公开的授权决定属于显式泄漏函数，不能一方面要求公开决策依赖秘密，另一方面要求零泄漏。

另外单列 **P-Available**：在指定网络与故障假设下给出恢复成功率、响应时延以及拒绝服务语义；优先安全时可以拒绝或降级。

### 3.4 必须保留的理论边界

`W0` 最新头为 `C5`，`W1` 已经确认 `C6`，恢复设备仅见相同 `C5` 时两个世界不可区分。这一实验用于检验**安全目标定义是否过强**，不得把缺少可信输入造成的不可能性包装成某一实现的普通漏洞。

## 4. Baselines：强组合对照与公平条件

| 实现 | 构成 | 实验目的 | 禁止误用 |
|---|---|---|---|
| `B0` | 字段认证、服务端同步、无可靠外部历史/统一授权绑定 | 确认攻击负载有效，建立薄弱系统反例 | **不得作为证明 novelty 的基线** |
| `B1` | 认证状态根 + 可信 Witness Head + 对象/ACL 同版本 + 客户端执行门禁 | 查明最低必要安全机制 | 不应故意省略其定义中应有的检查 |
| `B*` | `B1` + Zanzibar 式因果/版本约束（本地独立可验证）+ Macaroons 式 caveat + VBP 正确 view policy + 在途任务合理的二次检查 | **核心强组合基线**，是 H1-S 的主要反证方 | 不把依赖可信远端服务的 Zanzibar 原生 API 当成恶意服务器下的本地验证器 |
| `P` | `B*` 全部安全假设及全部合法功能 + 事先定义的可独立关闭新增机制 | 测试新增机制，及其隐私/成本作用 | 不以额外诚实节点、降低业务覆盖、禁止更新等获得不公平优势 |

**两条公平基线轨道**：

1. **功能安全轨道 `B*_F / P_F`**：完全相同账户状态、签名、Witness 证据、能力策略、VBP 功能集合和本地观察。P 新增语义与原机制隔离可开关。
2. **匿名见证轨道 `B*_Priv / P_Priv`**：二者均须满足同一隐私威胁模型；允许 `B*_Priv` 使用现有承诺、零知识证明、见证伪名技术实现等强匿名性。**不能拿公开账户 ID 的 B* 对比隐私化 P 后宣称 P 的安全优势。** 若 B* 可用成熟手段直接达到相同保证，则再比较证明复杂度、通信和恢复效率。

开工前冻结 `Baseline Parity Sheet`：输入消息、收到的可信下界、攻击者知识、正确功能操作列表、拒绝/降级策略、可观察网络面、Witness 数量/故障阈值、算法库版本、资源限制。每次修订使用独立实验版本，不覆盖原始实验结果。

## 5. 假设矩阵与差异判定

| 假设 | 如其成立，应观察到 | 削弱/否定它的观察 |
|---|---|---|
| H0 | B* 与 P 均通过同一安全轨迹；偶发差异无法复现 | 经独立 Oracle 复核的 B* 独有违反，P 同轨迹拒绝 |
| H1-S | `AttackSuccess(B*,τ)=1` 且 `AttackSuccess(P,τ)=0`，且两者可信输入/功能等价，差异映射到 P 独立新增语义 | B* 合理修补即通过；或者 P 因更强信任、少做业务才通过 |
| H1-E | 安全和隐私性质等价时 P 以一致方法降低证明、恢复或执行成本 | 优势来自少验证、不同缓存、不同语言/硬件、降低功能可用性 |
| H2 | 所有公平场景 B* 已满足目标性质 | 出现经复核的 B* 模型自身缺口，而非仅实现失误 |
| H3 | 增加既有事务/重检机制即可消除弱实现攻击 | 所有既有正确检查生效后仍存在安全违规 |
| H4 | 更换观测器/负载分布/缓存后泄漏消失或变号 | 多环境、多批次且同一权限/预算下泄漏持续可复现 |

请注意：**有界状态机未发现反例，只能排除所覆盖边界内的反例，不能证明系统在所有规模下安全。** 统计实验零次成功也不是密码学意义的安全证明。

**先验执行顺序**：E0 完成前不进入 E4。E1/E2 同时失败时停止 P 新机制扩张。所有攻击均在自建原型或仿真环境运行，不向真实用户网站注入或探测私人凭据。

## 7. Minimum Viable Experiment：可执行级别的最小实验

### 7.1 MVE-A：统一状态机与共同 Oracle

**目标**：用 6—8 个迁移组合，在无需完整浏览器扩展的环境中确定强基线能否排除 T1/T2，并为 T3/T5 提供一致测试设施。

**模块结构**：`StateStore`（认证快照）→ `WitnessOracle`（可信确认与外部下界）→ `AuthorizationChecker`（能力和因果版本）→ `ViewPolicy`（功能隔离）→ `EffectGate`（效应许可）→ `AdversarialSync`（事件调度）→ `ReferenceOracle`（独立判定）。状态机使用纯状态迁移接口，无真实用户秘密和在线生产依赖。

**T1 Golden Trace**：

```
1. register-witness-set(n=4,f=1,q=3)
2. commit(S4: shared-object active, cap4 valid)
3. issue-capability(cap4, object4, policy4)
4. revoke-in-S5(cap4); commit(S5)
5. trusted-channel-deliver-lower-bound(L=5)
6. malicious-sync-replay(S4, C4, cap4)
7. client-recover-and-attempt-effect()
EXPECTED: e=4 < L=5 ⇒ REJECT; B* 与 P 应一致。
```

**T2 Golden Trace**：

```
1. commit(S4, cap4 granted); commit(S5, cap4 revoked)
2. create-shared-object(object6); commit(S6)
3. malicious-sync-supply(object6, cap4, head6)
4. verify-account-root / capability / revoke / policy / object-evidence
5. attempt(admit-effect, object6, cap4)
EXPECTED: Reject due to mixed epoch and revoked capability.
```

**正向对照**：用 `object6+cap6`、有效功能 caveat、正确快照和满足可信下界的状态执行等价合法功能，必须成功。否则“全部拒绝”会被错误地判为安全。

**基本覆盖约束**：至少覆盖合法/非法对象、旧/新下界、已撤销/未撤销能力、同根/跨根凭证、可用/不可用 Witness。使用事件 trace ID 保证 B*/P 收到完全相同输入。若模型无法模拟“诚实与伪造证据的来源差别”，E0 判定不可信，先补模型。

### 7.2 MVE-B：T3 两世界自适应信息流实验

1. 生成等长、公开元数据相同的 `V0` 与 `V1`，仅在攻击者无权读取的一个私人字段上不同。
2. 固定公开的共享关系、账户状态、允许泄漏函数 `Leak(Vb)`，确保 `Leak(V0)=Leak(V1)`；合法发布政策在两个世界下应产生同等预先声明的可观察语义。
3. 攻击者提交自适应共享对象 `x_1, x_2,...,x_k`，每次依据上轮有权看到的输出选择下一输入。
4. 记录：`FIC issued/denied`、错误码/重试次数、图标网络触发、响应体长度、服务端密文尺寸、总调用次数、客户端耗时分布。明文秘密不写入日志。
5. 将两种世界随机交错运行于 B*_F/P_F；相同的输入种子和攻击者预算，训练与测试数据隔离。
6. 在独立测试集上估计攻击者成功区分能力，同时报告合法功能保留率。如果攻击来自“授予策略本来就读取并公开一个私人谓词”，应先修改泄漏定义或策略，明确其功能—隐私冲突；不能直接归功于新协议。

**区分优势**：`Adv = |Pr[D(Obs(V1))=1] - Pr[D(Obs(V0))=1]|`。实现采用多独立运行批次，按整批而非单条自适应查询估计置信区间。`Adv` 为经验值，不能用有限样本零优势代替理论安全证明。

**关键区分**：VBP 的正确视图策略本来能够排除一部分注入泄漏。若相同 `view policy` 即可让 B* 阻断，结果优先支持 H2；P 应改为评价更细的授权生命周期/性能权衡。

### 7.3 MVE-C：T5 同根投票、匿名性与错误接纳

**同根正确性场景**：账户 U 有 `commit(U,S5)`，四名 Witness 的三票具有不同对外投影但能对同一 `S5`、同一前序及同一 Registry 验证。B*_Priv 与 P_Priv 都应接受。

**混合攻击场景**：攻击者持有 `U` 的两票和另一账户 `V` 的一票，尝试拼成三票；也尝试重复一名 Witness 的不同伪名、混入旧 Registry 投票和旧前驱投票。正确验证器一律拒绝。

**隐私实验**：把单账户在不同 Witness 的内部记录映射为两个可交换实验世界，观察者取至多约定的腐化 Witness 转录和公开记录，估计其能否把不同伪名关联为同一账户。**单纯更改网络 IP 或共用相同上传时刻会泄漏关联，网络元数据单独建立实验轨道**。

**证明义务**：列出 `ProofStatement`，至少约束同一隐藏账户根、同一状态承诺、同一前驱关系、被认可的 Witness 集合、有效证书、不同 Witness 唯一计数、确认纪元及 Registry 版本。零知识相关性质需要正式游戏定义/证明或使用已证明系统的安全假设，性能实验只能评价实现成本。

**公平性**：若 `B*_Priv` 使用常规匿名承诺证明也能满足上述性质，则这一结果削弱 PACW 独立创新；此时比较操作复杂度、证明大小、升级和恢复成本。

### 7.4 MVE-D：T4 撤销与效应时序

四个基本序列：

A. 撤销状态进入本地 → 申请发出新效应：应拒绝。  
B. 申请获批 → 撤销进入本地 → 效应尚未发送：应按预定可取消任务策略重新验证并拒绝发出。  
C. 请求已发出 → 撤销进入本地 → 第三方随后完成：本地系统不能单方承诺已完成效应撤回，标记 `OUT_OF_SCOPE_EXTERNAL_COMMIT`。  
D. 撤销在其他设备已确认，本地尚未收到：依可信下界与在线确认策略判断，不能把全局最新假定为已知本地事件。

记录本地判定与第三方是否执行两个不同时间轴，不将“远端请求已完成”误判为“本地在撤销后批准”。

## 8. 独立变量、控制变量与混杂因素

| 类型 | 明确变量 | 设计要求 |
|---|---|---|
| 自变量 | Baseline=`B0/B1/B*/P`，T1—T5，W 数量与 f/q，网络分区，状态纪元，策略，攻击预算 k | 按实验矩阵受控改变 |
| 因变量 | 非法接纳率、合法拒绝率、旧状态恢复率、隐私 Adv、投票混合错误接纳、延迟、证明字节数、CPU/内存 | 由独立 Oracle、记录器和统计脚本计算 |
| 控制变量 | 同一初始数据、随机种子、可信锚、客户端收到的 Witness 消息、功能清单、密码学算法、观察权限、执行环境、时间预算 | B* 与 P 成对回放 |
| 混杂因素 | 网络缓存/重试、语言优化、时间同步、策略过度拒绝、日志记录成本、压力负载偏置、额外受信基础设施、隐私范围不同 | 通过随机交错、暖机、分层报告、双观察手段处理 |

**最重要的公平约束**：P 的好结果不能来自拒绝所有共享更新、删除图标/健康检查功能、仅额外查询新诚实 Witness、不给 B* 同样新鲜度下界或降低攻击查询预算。

## 9. Workload：合成、代表性和压力场景

- **Synthetic**：单账户、单共享对象、固定四 Witness，6—8 事件的最小可区分 trace；受控改变 `L`、ACL epoch、权限撤销和视图策略。
- **Representative**：多设备浏览器型密码管理器抽象负载，覆盖创建/修改密码、共享、权限撤销、跨设备拉取、密码健康统计、图标获取、设备失去后恢复；使用经明确标注的合成网站标识、随机凭据和实际可执行的请求回放，不采集真实密码或真实用户浏览记录。该负载是否代表真实分布是后续待验证事项。
- **Stress**：连续共享更新与自适应注入、同时多个设备竞争更新、恶意 Sync 针对单设备分叉、Witness 部分失联、恢复期间 Registry 轮换、历史膨胀、客户端崩溃重启与资源限制。

拟议扩展参数：账户凭据数 `{10,100,1000}`，设备数 `{2,3,5}`，Witness 配置 `{(4,1,3),(7,2,5),(10,3,7)}`（分别为 n,f,q），注入查询预算 `{1,10,100,1000}`，不同设备同步/恢复并发度按实际资源分层。参数仅为设计网格，不宣称真实典型用户值，也不要求做全笛卡尔积；应先根据 Pilot 缩减到能区分机制的最小场景。

## 11. 指标、统计和结果判定

### 11.1 安全指标

1. `UnauthorizedAcceptRate = unauthorized effects approved / adversarial attempts`；T1/T2/T5 正确实现预期应为 0，出现一次可重放反例就需要解释。
2. `FalseRejectRate = eligible legitimate operations rejected / eligible legitimate operations`；同时报告 `FunctionRetention`，防止“全部拒绝”骗取安全分数。
3. `RollbackRejectRate = correctly rejected e<L recovery attempts / e<L attempts`；记录无可信 L 时的独立安全/可用性结果。
4. `PrivacyAdv` 及可置信的训练/测试分离结果；按攻击预算 k、网络/密码学观察范围分层报告。
5. `QuorumMixAccept`、`DuplicateVoteAccept`、`CrossEpochVoteAccept`：应由独立验证器判定非法投票组合是否获批。
6. `KnownRevocationLocalEffectViolations`：只统计客户机**已知撤销后的新批准或规定需重检的待发请求**，外部请求已提交单独记账。
7. `CounterexampleSize`、`StateCoverage`：最小反例事件数、状态/转换覆盖及攻击变异种类。

安全测试中，模型检测对给定状态空间可做穷举；随机试验的 0 次违规仅提供经验上界。例如独立同分布试验 N 次未观察到违规时，95% 上界约为 `3/N`（大样本近似），**无法替代形式化正确性证明**。

### 11.2 系统与隐私成本

- 正常更新及效应许可时延（p50/p95/p99）；断网/恢复/超时单列；Witness 投票和验证耗时。
- 证明生成与验证耗时、证明字节、网络交互次数、检查点增量、Witness 存储增长和客户端峰值内存/CPU。
- 恢复设备首次可用时间、从确认状态到可见状态的延迟、网络分区后的拒绝/降级比例。
- 合法功能保留率、共享更新吞吐、用户可感知等待（需正式定义交互场景）及错误处理可解释性。
- 账户关联攻击成功率，区分密码学转录与包含网络元数据的转录。

### 11.3 统计预注册建议

- **E0/E1 有限状态机**：在定义的有界空间内全部枚举可达迁移；再随机验证高维事件交错。安全结论优先保留最小反例而非均值。
- **T3 隐私两世界**：Pilot 阶段建议每种世界至少 30 个独立批次，固定每批查询预算，并以成对或分层 bootstrap 给出 95% 置信区间；预先固定区分器训练/测试划分。正式样本量基于 Pilot 方差及期望检测的最小效应确定，不能凭空宣称统计功效。
- **性能实验**：拟议单配置至少 5 次暖机后开展不少于 30 次独立运行，记录原始端到端轨迹；比较成对差分和 bootstrap 置信区间，必要时考虑自相关或按运行批次聚类。
- **异常值**：记录而不直接删除；只有预注册的可追溯仪器故障才允许剔除，保留剔除前后结果。
- **禁止事后改变攻击预算、观察范围、正向功能集合来选择有利结果。**

## 12. Failure-oriented Tests：专门寻找失效和最差情况

1. **F-1 绝对最新性反例**：W0/W1 观察相同旧检查点，无独立下界时强制测试 `DEGRADED/REJECT`；若系统悄然接受“绝对最新”则目标设定失败。
2. **F-2 拒绝服务**：恶意服务器隐藏 Sync 数据，且至多 `f` 个 Witness 不响应；报告安全拒绝与活性失效的条件，不把 DoS 误计入秘密泄漏。
3. **F-3 交集与成员变更**：Witness 变化时出现旧成员签名、成员身份重复和前驱跳跃；要求 epoch/Registry 明确绑定，记录跨配置边界。
4. **F-4 完整合法旧状态**：包括旧 ACL 和旧恢复策略的整体重放，测试只验单对象签名时的盲区。
5. **F-5 控制平面秘密依赖**：故意设计隐私不合法的 FIC 发布策略，验证观测器能检出问题、且策略调整或允许泄漏声明能解释结果。
6. **F-6 匿名同根投票**：跨用户拼票、同一 Witness 重复、伪造 ZK 语句/旧证明重用及账户链接，分别测证明声音性和隐私。
7. **F-7 版本竞争**：撤销与功能发出交错、崩溃后任务重放、网络重试，测试本地 effect admission 的线性化。
8. **F-8 降级/版本迁移**：旧格式、安全参数、旧 Registry 与状态新版本混合；认证数据必须覆盖政策版本和能力类型。
9. **F-9 多维资源压力**：慢 Witness、高延迟、新设备大量凭据、批处理检查点拥塞，定位延迟尾部与安全降级策略。

## 13. 工程设施、记录规范与可复现性

### 13.1 最小软件工程架构

建议先使用单语言的纯内存状态机与事件回放引擎，不依赖真实数据库或外部网站。工程模块清单：

```
research/
  model/            # account state, transition relation, independent oracle
  policies/         # auth, epoch/causality, VBP-inspired views, capability caveats
  witness/          # checkpoint, quorum, recovery trust bootstrap, registry
  candidate/        # independently toggleable P-only semantics
  adversary/        # malicious sync scheduling, injection, fork, replay
  fixtures/         # human-reviewed T1–T5 traces and positive controls
  evaluation/       # paired replay, metrics, CI, ablation, minimization
  evidence/         # raw immutable traces, manifests, failure certificates
```

实施技术可以选择 Python 3.12 以上做首轮可审计原型；密码学验证使用成熟库的当前稳定版本，并在正式实验时固定具体版本与依赖锁文件。**当前未指定真实依赖版本、模型检查工具版本、宿主硬件和数据集版本，需在执行前以实验环境 manifest 锁定。** 后续若采用 TLA+/PlusCal、Apalache、Alloy 或其他模型工具，应说明所覆盖模型与安全属性，不能把抽象模拟器运行当作真实密码学证明。

## 14. 分阶段准入、停止和转向

| Gate | 必须满足的事实性证据 | 未满足时的行动 |
|---|---|---|
| G0 模型正确 | Oracle 自测通过，T1/T2 正反例区分且 B* 的必要成熟防线实际实现 | 停止创新比较，先修基本实现 |
| G1 对照公平 | B*/P 同一信任锚、L、见证能力、网络可达性、业务覆盖及观察范围 | 不发布比较结果，修订 Parity Sheet |
| G2 安全差异 | 提交可重放的 `B*` 独有违反轨迹与独立 Oracle 证据 | H1-S 保持未获支持；优先接受 H2/H3 并缩窄方向 |
| G3 隐私/法定人数 | T3 的允许泄漏一致；T5 同匿名威胁模型、同根证明有效且可验证 | 不声称隐私优势或同根安全创新 |
| G4 机制可行 | T3/T5 有合理可实现的方案、可承受成本和恢复可用性边界 | 暂缓 ZK-QC/复杂 PACW 工程投入 |
| G5 正式评价 | 正确性通过、实现冻结、实验与统计方案预注册完成 | 不进行大规模 E4，也不提出最终 novelty 结论 |

**核心 pivot 分支**：

- **结果 A：B* 失败，P 成功且公平**。进入机制证明、T3/T5 形式化建模与真实系统 E4；候选论文主线为“可信状态与功能效应联合验证”。
- **结果 B：B* 与 P 均满足安全且 P 有同等保证下显著且可解释的隐私/效率收益**。转向“隐私保护恢复/可验证见证效率”，需要证明成本改善有系统意义，并与成熟可直接组装的方案对比。
- **结果 C：B* 与 P 等价或均有相同失效**。终止新增机制首创性主张；优先考虑系统性攻击面测量、参考模型、复现实验套件作为贡献，或返回 Discovery 寻找更强问题。
- **结果 D：P 需要更强可信第三方、更少合法功能或特殊人工负载**。当前 H1-S 不成立，进一步收缩安全承诺或更换课题。

**重要限定**：有限测试中找不到 `B*` 反例，仅说明“在已检查范围内尚无差异”；不能断言所有可能状态中 B* 与 P 等价。当前论文创新判断采取保守立场，在正向证据不足前不将 H1-S 升级为成立。

## 15. 研究工作量、工程里程碑与论文结构建议

阶段优先顺序是 `E0 Sanity → E1 Mechanism → E2 Discrimination → E3 Generalization → E4 Full Evaluation`。可按下述有条件路线安排，时间仅为规划建议，需根据个人研究时间、导师要求和硬件条件细化：

| 阶段产物 | 最少可交付结果 | 与硕士工作量的关系 |
|---|---|---|
| M0 安全模型与 Oracle | 状态机、原子状态根/授权模型、4 基线约定、trace schema | 形式化问题定义与系统模型 |
| M1 攻击回放与基础反例 | T1/T2 正反例、恢复 W0/W1、性质变异回归 | 安全分析和可信正确性测试 |
| M2 分离性实验 | T3/T5 隐私与一致性对照、T4 竞态、攻击轨迹最小化 | 主要候选学术贡献位置 |
| M3 全功能安全原型 | 本地密码保险库、恶意 Sync、见证/恢复、共享与功能安全执行 | 平台系统与关键模块工作量 |
| M4 形式化证明与全面评价 | 机制证明/反例集、多负载、故障、隐私、效率、消融与复现 | 论文完整性与答辩可解释性 |

**风险控制**：硕士工作量可以来自验证设施、跨模块系统原型、恶意状态测试、性能评价与清晰的可复现数据。独立创新性最终由可证明的安全定义、有效的反例、准确的因果机制或有价值的系统测量支撑。RSPK 与 VDNS 历史轮换不并入 M0—M2，以避免将“工作量足够大”误当作“科学贡献足够新”。
