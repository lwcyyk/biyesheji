## 1. Current Observation：目前能够直接确认什么

### 已知观察（仅关于项目文档自身）

- **O1 [SOURCE]**：整合版设计的账户对象包含传统密码、TOTP、恢复码、共享对象和 Passkey；安全流程覆盖存储、同步、接纳、使用及恢复（整合版 §5.1–5.8）。
- **O2 [SOURCE]**：整合版将完全恶意同步服务器的合法旧状态回滚、分叉、拼接、撤销隐藏列为威胁，提出独立 Witness、PACW、VCC/Bootstrap（§5.2.1、§5.9.1–5.9.2）。
- **O3 [SOURCE]**：整合版将共享对象更新后的功能影响权限与内容更新权限分开，提出 FIC、Feature Projection 和 Effect Non-Interference（§5.2.2、§5.9.4）。
- **O4 [SOURCE]**：RSPK 提出高熵根秘密确定性导出 Passkey 私钥、只同步重建元数据、新设备自验证重建、兼容现有 WebAuthn RP 验证（RSPK §4–5）。
- **O5 [SOURCE]**：整合版已经列出五个原型模块、PACW/FICAP/RSPK 的攻击、性能及跨协议实验，并给出 26 周工作安排（§5.11–5.15）。这是已有设计，不是已完成实验。
- **O6 [SOURCE]**：既有文献笔记明确讨论主密码协议安全、恶意服务器、注入泄漏和 Passkey 生命周期等安全分析线索。论文内容和引用准确性须在下一阶段核实。

### 未知

1. 是否有已发表方案在同一威胁模型下解决“灾难恢复新鲜度 + 跨见证隐私 + 多对象原子连续性”。
2. 已有注入防御（尤其视图隔离）能否提供与版本绑定 Feature Influence Authority 等价的安全性质。
3. RSPK 是否相对独立恢复根加密的常规 E2EE 备份带来可证明、额外且可部署的安全收益。
4. 三个机制组合后，是否出现单一模块证明无法覆盖的跨层攻击与新安全性质。
5. 所谓新设备“恢复高熵根”怎样同时满足离线可恢复、根隔离以及供应商失陷模型。
6. 指定平台能否通过 WebAuthn 客户端和认证器边界实现可重建私钥，且正确满足用户验证、凭据标记及应用兼容性。

### 当前仅是推测

- **[INFERENCE]**：跨生命周期的安全性不足可能主要来自模块之间的信任传递缺口，而不仅来自各模块的密码学强度。
- **[HYPOTHESIS]**：类型化可信状态句柄及版本绑定能力能缩小“已认证数据被过度授权使用”的攻击面。
- **[HYPOTHESIS]**：外部见证提供的恢复新鲜度，结合本地功能准入控制，可以产生超越两项机制分别部署的可检验安全保证。

| 观察 | 候选解释（尚未确立） | 典型混淆 |
|---|---|---|
| 签名及 AEAD 验证通过的旧状态可被呈现 | 新鲜度需独立历史参照 | 将“密码学合法”误认为“当前最新” |

| 三项协议能通过统一账户状态相连 | 跨层安全接口可能有独立研究价值 | 将工程组合自动认定为创新 |

## 3. Competing Explanations：至少两个相互竞争的解释

### 对 PACW 的竞争性解释

- **H-P1 [HYPOTHESIS]：外部独立新鲜度必需。** 在全部旧设备丢失、服务器任意回滚、设备无可信历史的情况下，独立锚定的历史参照是发现合法旧状态的必要条件；不同见证投影及一致性证明可以在限定隐私模型下减少跨见证关联。
- **H-P2 [ALTERNATIVE]：轻量已有机制足够。** 可信旧设备备份、透明度日志及定期核验可在目标可用性条件下达到同等安全结果，无须复杂的 ZK-QC。
- **H-P0 [NULL]：目前缺少独立优势。** 文献中已有同等安全性质的恢复/见证协议，或者新增隐私属性在流量和时间关联下很弱。
- **可区分证据**：完整丢失恢复时的旧状态拒绝能力、恶意见证条件下的冲突接纳、网络可观测关联，以及协议证明复杂度。

### 对 FICAP 的竞争性解释

- **H-F1 [HYPOTHESIS]：权限与数据内容分离有效。** 版本绑定 FIC + 功能准入 + 外部效应非干扰，能够在保持有条件共享功能的前提下抑制自适应注入的信息增益。
- **H-F2 [ALTERNATIVE]：仅分区隔离已足够。** 视图隔离或本地沙箱，在同一功能目标下即可达到相同泄漏边界，FIC 只增加用户交互和状态管理复杂度。
- **H-F3 [ALTERNATIVE]：核心原因在外部效果。** 即使存在 FIC，响应大小、调度、URL 图标、网络缓存等旁路仍可形成泄漏，关键机制应是完整效应隔离。
- **可区分证据**：固定可用性要求下的信息泄漏优势、合法共享更新正常通过率、额外授权开销、未受控副作用。

### 对 RSPK 的竞争性解释

- **H-R1 [HYPOTHESIS]：同步元数据与根秘密隔离降低云集中风险。** 在攻击者掌握同步快照及其常规解密材料，但缺少独立的 Passkey 根秘密时，无法重建 WebAuthn 私钥。
- **H-R2 [ALTERNATIVE]：安全收益来自根密钥隔离本身。** 使用另一份高熵独立密钥加密私钥备份，可达到同等失陷边界，确定性派生不是关键改进。
- **H-R0 [NULL]：恢复链条抵消隔离收益。** 若全设备丢失恢复也需由同一云方备份根秘密，云方失陷可能重新构成单点威胁。
- **可区分证据**：逐项控制攻击者所获快照/密钥、恢复根物理位置、密钥泄露后的横向影响及现有 WebAuthn 兼容性。

## 4. Researchable Unknown：提出值得研究的“未知”

### 总体候选科学问题（RQ-0）

> 在多设备、完全恶意云同步服务器和本地可信凭据核心的条件下，如何定义并实现一个可组合的安全状态接纳流程，使账户状态的连续性证据、共享对象的功能影响资格和 Passkey 签名能力边界在跨设备同步与灾难恢复过程中保持一致？哪些外部新鲜度、功能隔离和恢复根独立性假设不可省略，其安全与可用性代价如何变化？

这个问题包含对象（多凭据状态和跨层接口）、自变量（见证模型、授权粒度、恢复根部署）、因变量（攻击成功、泄漏优势、恢复正确性、代价）以及明确安全假设。

### 三个子问题

- **RQ-1 状态连续性**：当设备全丢失且服务器返回一个历史上合法的完整账户状态时，哪些独立证据和法定人数条件足以区分当前已确认状态、历史状态与缺失最新密文的拒绝服务状态？
- **RQ-2 功能权限**：在共享者和同步服务器均可恶意更新对象时，相同服务功能与可用性目标下，版本绑定的功能影响能力相较视图隔离，是否降低了主动注入的额外泄漏，同时控制授权成本？
- **RQ-3 签名能力隔离**：在区分云快照、同步解密材料、恢复根和终端私钥等失陷层次后，根种子派生方案在安全收益、恢复能力及标准 WebAuthn 兼容性上处于何种 Pareto 边界？
- **RQ-4 组合安全性（决定是否构成统一硕士课题的核心）**：即使每个单独子机制接受了合法输入，过期的 FIC、跨纪元恢复元数据和旧句柄是否仍能经跨模块路径产生有害状态？将信任证据封装为不可伪造的类型化接口能否从架构层限制这种违规路径？

## 5. Research Type：研究类型

- **主类型**：`Security + Systems + Architecture + Mixed`。
- **辅助类型**：`Method`（可验证接口和授权模型）、`Measurement`（攻击与成本的可重复测量）、`Theoretical`（限定假设下的不可能性/组合性质）。
- **论文定位建议**：以“具体威胁模型 + 新安全定义/组合不变量 + 原型 + 反证导向实验”为主；密码学成熟工具的调用本身不构成创新点。

### 为什么不建议直接同时宣称 A 中全部创新

1. PACW 的 ZK-QC、拜占庭一致性和隐私证明属于独立困难问题。
2. FICAP 的自适应泄漏论证及用户接纳策略也属于独立困难问题。
3. RSPK 的根密钥恢复和 WebAuthn 认证器适配存在另一组密码学与工程边界。
4. 三者同时完成独立的严格形式化证明、完整原型和广泛复现实验，很可能压缩每项工作的验证深度。
5. 统一主线应建立在可反驳的跨层安全性质上，而不是把三套技术的功能集合直接作为科学贡献。

## 7. 第一阶段 Value Test（不打分）

### Scientific value（科学价值）
潜在价值在于：厘清“密码学验证有效”与“当前状态可接纳、更新有权影响功能、元数据有权导出认证能力”之间的层级关系；若可构造现有独立模块无法排除的跨层攻击，则有机会给出新的组合安全定义。**这是待验证机会，不是已证实的 gap。**

### Technical value（技术价值）
真实场景包括设备丢失恢复、共享凭据更新、密钥备份与 Passkey 跨设备使用。成功原型至少需要可重现实验用的恶意同步服务器、状态验证器、共享功能引擎与恢复客户端。

### Generalizability（一般性）
若安全模型只依赖“远端数据接纳 → 本地敏感执行”的边界，成果可能迁移至端到端加密笔记、密钥保管库或多端安全配置同步。需用至少一个替代工作负载或案例证实，避免仅适用于特定代码实现。

### Falsifiability（可证伪性）
若最强已有隔离与状态验证组合已满足全部安全目标、且额外设计没有提高可测安全性/可用性，则核心创新性减弱；若有未受控外部效应、跨设备重放或新设备恢复绕过，则具体机制假设可能失败。

### Feasibility（可行性）
原型原则上可在单机/虚拟机条件下搭建，但 ZK-QC 电路、恢复根独立保管、真实浏览器 WebAuthn 接口和多人用户研究需要单独资源评估。项目文件给出的 26 周计划仅是目标排期，未形成资源和完成度证据。

## 8. 强反对意见与关键技术风险（为下一阶段保留）

**最强审稿人反对意见：** 状态见证、视图隔离、版本能力以及确定性密钥派生都属于已有技术。将这些方法组合在一个密码管理器原型中，可能只是成熟机制的架构整合。若无法识别已有方法明确遗漏的安全性质、给出区分性攻击或强于最接近工作的验证证据，就不足以支撑独立的高创新硕士课题。

**针对 PACW**：区分“账户状态验证”“外部当前性参照”“最新密文可用性”。ZK-QC 的跨见证证明必须连接同一账户和相同底层状态，且保持法定人数交集安全；异步故障时检查 Safety/Liveness；秘密伪名的不可链接性只在明确定义的观测模型下成立，IP、时序与批处理频率可构成侧信道。外部锚点自身的最新性及全设备丢失后的根恢复形成关键依赖。

**针对 FICAP**：FIC 如果依据私有状态自动签发，签发事件本身可能成为新泄漏。隐藏密文长度不足以解决网络次数、定时、缓存和资源消耗。FIC 的价值需要相对基于视图的分区、隔离执行和显式审批等最强对照展示。跨功能共用的规范化 token 可能引入新的关联路径。

**针对 RSPK**：普通 E2EE 在解密材料未失陷时本来也使快照不能产生签名。额外收益只存在于清晰区分常规同步材料与独立高熵根秘密的失陷模型。全设备丢失后的根恢复必须独立于相同失陷路径。自定义认证器或密钥导入对平台支持存在约束；RP 不需修改验证端接口，仍需检验实际浏览器/平台实现与备份标志语义。已完整复制的 Passkey 私钥依旧需 RP 侧撤销或换绑。

**针对总体系统**：类型句柄防绕过的论证需要清楚区分静态类型约束、运行时验证、恶意客户端与本地可信代码。一个模块可能把安全状态降级为普通对象后重新使用；并发更新可能导致旧 FIC、新账户纪元和新 metadata 混搭。统一账户状态的全局原子性、增量更新粒度与正常可用性之间存在需量化的冲突。

### RP-2026-001 — 恶意同步服务下的状态连续性与跨层授权一致性

- Main Hypothesis: 版本绑定的可信句柄 + 独立状态连续性参照将减少跨模块旧状态混用和权限绕过。
- Competing Explanation: 强事务快照 + 原子授权校验已足够，额外密码学句柄没有独立收益。

- Candidate Gap: Combination / Architecture / Evaluation，`UNKNOWN`。

### RP-2026-002 — 无历史设备的隐私保护恢复新鲜度
- Revision: r1
- Status: `EXPLORE`
- Type: Security / Theoretical / Systems
- Source Observation: 恶意服务器可以提供签名和认证加密均有效的旧状态；PACW 提出见证者、两阶段确认、VCC 和 Secret Bootstrap Head。
- Core Question: 独立状态见证的最小信任阈值、证明结构与隐私开销为何，如何支持所有旧设备丢失后的当前恢复？
- Main Hypothesis: 外部可信检查点和阈值见证可在指定拜占庭条件下排除稳定状态的静默分叉及回滚。
- Competing Explanation: 传统透明日志、gossip 或可信备份足以满足应用目标。
- Failure Condition: 存在可被合法接受的两条相互冲突的稳定历史；最新 VCC 本身可被无声回滚；ZK 隐私保证被观测模型破坏。

- Relationship: 支撑 RP-2026-001 与 RP-2026-004。

### RP-2026-003 — 远端共享更新的功能影响权限
- Revision: r1
- Status: `EXPLORE`
- Type: Security / Method / Systems
- Source Observation: 共享者多次合法更新可与本地敏感计算交互并触发可观察外部效应；FICAP 设计版本绑定能力。
- Core Question: 把对象更新权限与功能影响权限分离后，能否在固定功能保留程度下，降低攻击者相对被动观察的额外泄漏？
- Main Hypothesis: FIC + 受控功能投影 + 效应隔离的组合可以阻止版本更新自动放大查询权。
- Competing Explanation: 分区隔离或独立沙箱在相同可用性下已经实现等价非干扰。
- Failure Condition: FIC 签发本身成为信息泄漏，或任一敏感功能可重复泄漏私人状态；同等功能条件下无额外防护价值。
- Candidate Gap: Mechanism / Architecture / Evaluation，`UNKNOWN`。
- Biggest Unknown: 与已有 view-based injection security 的真实差异。
- Relationship: 可作为 RP-2026-001 的子问题，依赖 RP-2026-002 或等价连续性接口。

### RP-2026-004 — 云快照与 Passkey 签名能力隔离
- Revision: r1
- Status: `EXPLORE`
- Type: Security / Method / Systems
- Source Observation: RSPK 只同步元数据，由独立高熵根决定性派生认证密钥，恢复后验证公钥承诺。
- Core Question: 在哪些精确定义的泄露能力及根恢复策略下，同步元数据表示能兼顾云快照不具有认证能力与完全设备丢失后的重新登录？
- Main Hypothesis: 元数据与本地根秘密隔离可降低特定云密钥失陷情形的批量 Passkey 暴露。
- Competing Explanation: 额外独立密钥加密传统 Passkey 备份即可实现相同目标；根恢复路径会重建集中风险。
- Failure Condition: 根恢复材料与同步材料同路径泄露；确定性签名密钥重建在目标 WebAuthn 平台不可部署；同等信任假设下安全收益不优于基线。
- Candidate Gap: Setting / Architecture / Evaluation，`UNKNOWN`。
- Biggest Unknown: 最接近的 deterministic passkey、seed recovery 及平台密钥管理工作。
- Relationship: 应用级扩展，依赖 RP-2026-002 或等价可信 metadata 新鲜度来源。
