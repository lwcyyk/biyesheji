P7 [Normal] 原范围是否已关闭；保留任务在本地选中了哪条获准路径；这条路径在实际使用时是否仍然被远端接受。历史交接完成不能充当永久可用性证明，也不能阻止用户后来撤回批准。

P12 [Normal] 本轮取得根范围授权静止论文的结构化正文，核对其原子重绑、独立支持保留和恢复论证。该文已经要求以精确操作和效果范围替换选定支持，并区分后续独立支持的变化。因此，不能将本轮“重新核对、原子切换、旧路径不重开”作为新一般思想。[R1]
P13 [Heading 2] 本轮候选增量的位置
P14 [Normal] 仍然限定为密码管理器领域：一个由静态求解器产生的保留见证，怎样与实际密文材料、用户批准、任务绑定及已有恢复机制保持一致；哪些条件仅在本地可维持，哪些依赖外部服务。可复用方法和独立比较尚待完成。
P15 [Normal] 查新是对研究主张的约束，不是自动完成了强基线。没有把自己编写的粗糙脚本称作 R1、Chubby 或 Zanzibar 的实现。公开预印本的作者证明也不等于本轮独立验证。
P17 [Normal] 03 / 继承依据、公开先例、研究提案与实际运行分别登记
P18 [Heading 1] 先定义保留语义，再讨论动态交接
P19 [Normal] v2.12 §03 与 §05 明确只保留获准的后续操作能力，不保证原会话或全部业务进度；其交接依赖冻结的可信映射和单线程驱动。本轮在此基础上增加可变本地登记及故障状态，并不把超出旧假设的行为登记为旧版本漏洞。[D212]
P20 [Heading 2] 一条应当诚实保留的反例
P21 [Normal] B 的替代授权 g1 在最后一次核验时有效；核验之后，外部控制者撤销 g1；随后本系统按原批准关闭共享范围 g0。即使本地数据库没有竞争、计划没有被篡改，B 仍然可能失去远端访问。
P22 [Normal] 这说明，本地冻结或比较并交换不能阻止一个不受其控制的远端撤销。要声明持续可用，必须另有适用的外部维持条件，或者改变保证范围。增加一次“最新”查询不能消除查询之后的变化。
P23 [Heading 2] 建议采用的条件性表述
P24 [Normal] 交接不因关闭源范围而破坏独立继续路径；如果该路径后来因用户撤回、服务撤销、到期或网络失效而不可用，系统拒绝错误继续，并分别报告源范围的历史关闭事实与当前继续条件。
P25 [Normal] 代码接受 NO_LOCAL_COLLATERAL，拒绝 REMOTE_UNINTERRUPTED。该差异必须进入用户认可的目标，而不是由 AI 或恢复程序事后重新解释。[E213]
P27 [Normal] 04 / 继承依据、公开先例、研究提案与实际运行分别登记
P28 [Heading 1] 研究一：把静态见证转换为有生效点的本地选择
P29 [Normal] 新增方法先调用原 v2.12 求解器与独立检查器；不更改其有限静态语义。在投影到本轮两任务交接 profile 时，显式绑定目标任务、保留任务、源范围、替代范围、密文引用、批准指纹、登记版本和任务代次。
P30 [Heading 2] 预留保护的是什么？
P31 [Normal] 保护的是已声明本地登记中的依赖关系。它不是租用网站授权，不阻止远端独立失效，也不保护绕过受控入口的原始令牌副本。当前预留不自动过期，避免崩溃后旧进程与新进程各自恢复一条不一致路径。
P32 [Heading 2] 撤回批准具有更高优先级
P33 [Normal] 冻结登记不能冻结用户的撤回权。切换前撤回会使计划失效；切换后撤回会阻止继续使用。不能以“为保证可用性”为理由暂时忽略撤回。已经交给外部服务的在途操作仍需按原有边界处理。
P34 [Normal] 常规版本校验、持久预留和原子切换是复用机制；本轮完成的是它们与有限保留见证及真实密文接口的连接，不是新的通用锁协议。[R1][R2][R5]
P36 [Normal] 05 / 继承依据、公开先例、研究提案与实际运行分别登记
P37 [Heading 1] 研究二：持久交接状态与向前恢复
P38 [Heading 2] 与旧后端的实际连接
P39 [Normal] 发送关闭之前持久记录意图，再调用未修改的 CloseExecutor、CompletionRecords 和 FamilyLedger。部分资源未完成时保留未决；重开后从缺失条件继续。原操作已生效但本地处理返回结果中断时，不将已经关闭的源范围重新开放。
P40 [Normal] 最终完成后释放临时登记预留，源范围停止标记保留。B 可以在以后经过适当批准建立新的绑定代次。旧交接状态不因此变成新的执行许可，也不让旧请求绕过当前检查。
P41 [Heading 2] 为什么不自动回滚？
P42 [Normal] 源范围可能已经被远端撤销，本地恢复旧标签不能恢复它的真实权限；回滚还可能违反用户已经作出的停止决定。成熟补偿方法也明确指出，补偿不一定是恢复到原状态，且可能需要人工处理。[R6]
P43 [Normal] 首版仅在 RESERVED 阶段支持显式取消。切换后如替代条件失效，可能停在等待重新规划的状态；这是一项仍待完善的活性边界，不能以“保守”掩盖正常任务始终无法结束的问题。
P44 [Heading 2] 使用结果与历史完成分开
P45 [Normal] status 同时输出源范围是否已关闭、当前绑定代次、替代批准是否仍有效，以及是否必须重新核验。实际读取才产生时点可用性结果，不将一次历史成功长期缓存成通行资格。
P47 [Normal] 06 / 继承依据、公开先例、研究提案与实际运行分别登记
P48 [Heading 1] 可论证的性质，以及明确不能保证的性质
P49 [Heading 2] P1：本地切换前后不会出现半份绑定
P50 [Normal] 在单一受信任 SQLite 数据库的事务假设下，切换前仍保存原绑定和未停止的本地入口；切换提交后同时保存新绑定、递增代次、目标停止及源停止。真实进程退出测试分别检查提交前与提交后。SQLite 的单写事务并不延伸到远端服务。[R5]
P51 [Heading 2] P2：旧实例不能借用新的保留见证
P52 [Normal] 当请求仍携带旧绑定代次，受控新使用入口必须拒绝。新引用必须匹配当前任务、执行者与批准。原生范围材料仍在受信任执行内存中，模型不可直接调用底层解密函数；本轮没有证明 Python 进程隔离或操作系统失陷安全。
P53 [Heading 2] P3：撤回与历史证据不会被误解释
P54 [Normal] 相关批准的撤回不被预留阻挡；恢复检查当前资格。源关闭记录是历史结果，不意味着 B 以后一直获准或可用；迟到源材料只能进入既有恢复域。改变批准不自动抹去已经发生的外部效果。
P55 [Heading 2] P4：局部约束成立不等于远端连续可用
P56 [Normal] 若外部可以在最后观察后独立撤销替代范围，存在两条本地观察完全相同但远端继续能力不同的轨迹。仅靠本地算法不能同时保证在两者中都成功继续。当前严格目标在发送前拒绝，有限目标则明确保留使用时检查。
P57 [Heading 2] 条件性精化目标
P58 [Normal] 实际轨迹投影到抽象交接时，应保留任务代次、源停止、秘密使用、批准撤回、远端关闭和结果未知等安全事件。不能在投影中删掉失败或在途效果。需要逐事务边界论证，并另查真实适配器是否满足原语契约。
P59 [Normal] 上述均为本轮的条件分析与测试目标，未完成完整机器证明。Chubby 已讨论接收端必须检查序列信息，根范围授权静止工作已证明特定原子重绑模型的性质；本轮不重复主张这些一般原理。[R1][R2]
P60 [Normal] 当前读取接口在本地写事务内调用进程内验证器，以序列化本地批准与使用。它不是建议对任意网络请求长期持有数据库事务；真实分布式接入仍需单独的执行点机制。

P71 [Normal] 初次开发时，一项部分关闭断言误用了从未进入缓存的子令牌；原撤销已经使它被在线拒绝。测试随后改为预先缓存的根材料，以实际检查剩余缓存路径。失败运行保留说明，不计为通过。
P72 [Heading 2] 没有完成的工作
P73 [Normal] 没有真实模型、浏览器、网络/TLS、独立完整认证平台、远端签名报告、生产账户或公开强框架复现。批准和执行者仍是可信夹具输入；元数据与日志没有全面加密。无全量身份发现、业务进度迁移、任意并发证明或恢复活性保证。

Zanzibar 官方摘要 [R7] | 授权决定与状态更新的一致性已有系统基础；本轮仅读摘要，不声称已复现其模型。

目标 | 本轮能够／不能承诺
本地不误伤 | 交接本身不删除独立批准；在本地切换点选定正确路径，旧任务版本不能通过受控新使用入口。
远端时点可用 | 允许的核验在一次实际调用中确认替代材料及账户；只支持该观察点，不产生远端租约。
持续远端可用 | 若用户要求任意外部变化下都不中断，本轮契约不支持，在生成计划之前拒绝，不默默降级。
完整业务连续 | 在途请求、业务数据、编辑会话和计划记忆无损迁移，仍不属于本轮实现。
TABLE 3
阶段 | 实际实施及必须保留的前提
1. 计划核对 | 核对静态方案、同账户语义、替代批准和材料引用。业务等价性来自可信登记，不从不透明令牌猜测。
2. 持久依赖预留 | 在 SQLite 写事务中重核登记版本，预留有关任务和范围。相关重绑与新路径扩展被拒；用户撤回批准始终可以进行。
3. 核验替代材料 | 通过原密文使用入口和未修改 OAuthlib 资源验证，确认一次获准读取及实际账户。结果是时点观察。
4. 原子本地切换 | 同一密码库事务内：B 选择替代路径、B 代次递增、A 新使用停止、源范围停止标记写入、交接阶段变为 SWITCHED。
5. 使用时核对 | 后续使用检查任务、执行者、当前批准和绑定代次。旧计划中的正确账户标识也不能跳过这些检查。
