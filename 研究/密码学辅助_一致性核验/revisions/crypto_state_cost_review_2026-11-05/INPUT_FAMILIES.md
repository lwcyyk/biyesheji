# 三个最小输入族及条件覆盖

证据等级：以下轨迹、计数和证明均为 H（手工论证）。它们没有在原生服务上执行，亦未作为机器证明提交。历史 ci01 数据只支持其已经观察的原生行为。全部成本沿用 PROBLEM_AND_MODEL 的向量。

## 1. F1：多次撤回后恢复

### 输入族与最小实例

`F1_t` 有 t 个独立批准 `A_1,…,A_t` 和一个保持有效的 B，`n=t+1`。每次更新在上一次撤回 ACK 后才提交，用户选择的撤回对象在其提交时才确定；从而提前预测未来操作无法取代更新记录。考察 t 个有不同授权结果的已承诺前缀以及在各前缀后的恢复，`u=t,c=t,m=0,b=t`。单次恢复轨迹可独立评价，实际重复恢复的额外写入照实计费。

最小非平凡实例取 `t=2`：

| 顺序 | 合法事件 | 承诺后应有状态 |
|---|---|---|
| 0 | A1、A2、B 均有效，快照 S0 | 三者可合法接纳 |
| 1 | Revoke(A1) 提交，ACK1 | A1 拒绝，A2/B 保留，快照 S1 |
| 2 | 攻击者崩溃 R，并给出 S0 | 已知旧锚点时拒绝 S0；取得匹配当前数据后恢复 A2/B |
| 3 | Revoke(A2) 提交，ACK2 | A1/A2 拒绝，B 保留，快照 S2 |
| 4 | 再次崩溃，提供 S1 | 拒绝旧 S1，恢复当前 S2；B 合法 |

攻击路径是在步骤 2 或 4 用签名仍有效的旧批准获得新接纳。普通签名/认证加密保证了旧快照真实来源；当前锚点决定该快照是否仍可充任当前状态。

### 受限离线模型的持久区别引理

考虑模型 O：任意 ACK 后可立即丢失全部易失状态；普通存储可回滚；密钥不泄露；唯一跨该故障保留、能够反映更新的可信信息是所计费的本地持久状态。没有在线权威、客户端新鲜回执、可信时钟、保留易失内存或保证完成的关机刷写。有效状态可恢复时要求合法接纳，整体永久拒绝不满足功能。

**命题 H-O。** 对上述顺序产生的 b 个恢复可区分承诺，每个成功承诺与其前缀之间，都必须在 ACK 前留下新的可信持久区别。因此该类协议的逻辑可信持久更新次数 `W_local ≥ b`。一次安全物理提交可能需要多个写操作，该式仅为逻辑更新的下界。

**证明。** 固定任一前缀 H0，其中资格 x 有效。在 H0 后立刻断电并诚实恢复其快照，合法恢复要求最终允许 x。另考虑 H1：相同前缀之后撤回 x 并成功 ACK，然后立刻断电。若此次承诺没有改变任何可信持久状态，攻击者在 H1 给出 H0 的完整旧快照。两次恢复的可信状态、密钥、所有可取输入及后续调度可以相同。恢复算法作出相同决策；H0 的合法接纳与 H1 的撤销保持发生冲突。随机算法可耦合相同恢复随机带，两个错误概率之和至少为 1，无法同时可忽略。故必须留下持久区别。后续更新在此前 ACK 后才到达，每个这样的承诺均需独立的更新区间，累计得到 b。

这个论证是状态连续性中标准不可区分性思路的实例化，SUNDR §3.2 与 Memoir 的模型说明提供近邻依据。本轮不主张其一般原创性、所有密码协议的下界或可信存储字节最优。

**必要限定。** 多个并发撤回可共享同一次承诺；b 随统一 ACK 合同确定。更新前已存在可区分承诺的外部信息时须计入相应资源，模型 O 的排除前提不再成立。可信擦除、受保护时钟、用户设备状态和远端权威均可能改变计费位置。`W_local + 新鲜读次数 ≥ b` 也不由此推出：在线权威可承接全部更新，并以缓存/租约减少读。

### 强基线与成本

G1 的可信事务或 G2-Basic 的受保护历史摘要提供 `O(b)` 逻辑持久更新，达此受限次数阶数。最小实例中两次严格分开的撤回 ACK 对应两次新的持久区别，另加初始化和具体恢复修复成本。认证字典可把每个提交组的可信摘要字节压到 `O(λ)`，普通状态与树路径成本另计。

G2-Opt 在保证掉电前 checkpoint 的模型 C 内可将 NVRAM 次数转到 boot/checkpoint，PCR 更新和 UPS 继续计费。G3 在模型 N 内将更新移到权威及网络。二者在各自合同下可用，比较时必须让双方拥有同样资源。

结论：`CONDITIONAL_EXISTING_METHOD_COVERAGE`。严格密码学差距实例为 0。若用户确认模型 O 且要求少于 b 次持久区别、又维持全部排除条件，该要求与引理冲突，优先修改功能/资源合同。

## 2. F2：批处理与明确承诺窗口

### 输入族与手工最小实例

`F2_{h,s}`：h 个时间簇，每簇 s 个独立撤回，加一个保留 B；不同簇之间间隔足够大，使前簇最早请求的 ACK 截止早于下一簇到达。簇内请求可在同一合法组提交中完成。`n=hs+1,u=hs,m=0`；成功稳定执行所需组数为 h。每次成功组提交耗时 `τ>0`，正常 ACK 时限 `Δ≥τ`，崩溃窗口的时限另按可用性合同处理。

具体输入为四个撤回目标加 B：到达时间 `[0,1,2,6]`，`Δ=3,τ=1`。合法组提交：

| 组 | 请求到达 | 提交开始 | 完成/应用 ACK | 各请求等待 |
|---|---|---|---|---|
| 1 | 0、1、2 | 2 | 3 | 3、2、1 |
| 2 | 6 | 8 | 9 | 3 |

两次持久提交满足所有截止。一次提交无法同时包含 t=6 才到达的更新并在最早请求截止 t=3 前 ACK，所以该实例在组提交模型中的最少组数恰为 2。通用 G1 组提交和 G5 的批处理＋Checker 同样达到 2。逐请求同步的 4 次写只是未优化实现，不能充任最强通用下界。

在一般到达序列中，单项请求可容许的开始区间为 `[a_i,a_i+Δ−τ]`。组提交还需真实 I/O 调度、容量、依赖和可重叠条件。本文没有把区间刺点数直接宣布为所有存储系统的最优批次数；上述两个实例/族只使用其明确可行的时序。

### 合法轨迹与攻击轨迹

合法轨迹：应用排队独立撤回，组事务写业务数据及当前性锚点，阻塞式 barrier 确认覆盖，才给用户撤回成功。B 的独立请求可否在提交期间执行依同一事务/快照隔离合同；等待计入 B 中断。

攻击轨迹：t=0 的撤回收到乐观“已 fsync”响应，攻击者在防回滚计数器更新前断电，再恢复旧状态。若该响应被上层误报为强撤回成功，就违反统一功能。CRISP §III.B 明示该窗口；其 §III.C Checker 是基线可用的补强，应用 ACK 应在 barrier 后。

崩溃发生在组提交中间时，对尚未发成功 ACK 的操作保持 UNKNOWN/按精确请求标识重试。对已 ACK 的操作按已承诺状态恢复。多次无限崩溃下的硬墙钟 ACK/B 上界不由该轨迹保证；需要稳定时段与完成时间假设。

### 成本与淘汰

最小实例：两次逻辑锚点更新、四项业务变化、两次组等待，恢复验证与数据读取另计；在普通存储中可以共享 WAL flush、索引路径和预处理。一个“新批量撤回机制”若同样只把四项合成两组，与强 G 的差距为 0。缩短提交窗口减少等待但可能增写，属于已知调度/提交权衡。

结论：`EXISTING_METHOD_COVERAGE_WITH_MATCHED_ACK`。未发现新的密码学权衡；新的工程调度仍需真实约束和证据才可判断系统价值。

## 3. F3：迟到结果、新批准与恢复

### 输入族与最小实例

`F3_t` 为 t 个独立旧批准的迟到请求与 t 个合法新批准，可保留独立 B。每个请求携带不可混淆的 rid、请求摘要及批准来源；每次撤回和重新批准的因果顺序固定。m 随同时未决数计，所有必须防回滚的记录更新纳入 u。

最小实例有 A.g0 与 B.g1 两个批准实例，恢复时有一个未决请求 `p`。以四项本地更新为例：Begin(p)、Revoke(A.g0)、Grant(B.g1)、Receive(p)。此例 `n=2,u=4,c=1,m=1`；B 的只读资格核验额外执行。若 B 执行会消费配额或产生新 pending，则相应增加 u 和最大 m。

| 步骤 | 合法执行与必要信息 |
|---|---|
| 1 | R 验证 A.g0，提交 `p=(rid,A,g0,account,audience,caller,request_digest)`，然后允许外发 |
| 2 | 外部请求结果迟到；运行者只知道 pending，评分器暂存真值保持不可见 |
| 3 | 提交 A.g0 撤回，给成功 ACK |
| 4 | 经真实用户认证提交 B.g1 新批准；如果 B 原有批准持续有效，则无需此更新 |
| 5 | R 崩溃；攻击者给出早于步骤 3 的快照，或给出删掉 p 的快照 |
| 6 | 合格当前性来源确定最新提交前缀；从认证状态重建 A 撤回、B 有效及 p 的原来源 |
| 7 | p 的结果到达，按原来源隔离/处置，B 依据自己的新批准接受资格核验 |

新鲜信息包括：撤回和新批准均已提交的状态、原 p 的来源与处理进度。身份相同、账户相同、上下文相近都不足以把旧 p 改归 B。新批准的存在也不等于 AS 已撤销旧材料。

### 攻击轨迹与强组合

攻击一：恢复 S0，使 A.g0 重新有效。G2/G3/G5 当前根检测旧状态。

攻击二：恢复时丢弃 pending，再把 p 的结果当作 B.g1 的新响应。G1 来源账本、持久 pending、精确请求摘要和接纳事务排除该重标。来源真实性依赖 R 观测/认证请求与结果的真实绑定；仅增加签名字段无法填补未观察的原生归属。

攻击三：未知原生结果触发重复 refresh，产生新后继。Memoir 的确定性本地重放不能推出原生幂等。组合应保留未知义务，调用获准的原生查询/截止，或者依赖真正的幂等接口。额外原生请求与新材料数计入主线预算。

攻击四：仅缓存一份在线“当前”答复，然后在撤回 ACK 后继续接纳。G3 必须把接纳序列、更新/CAS、租约或失效通知一起实例化。Nonce 绑定只支持本次答复的新鲜性，缓存的持续有效性单独负责。

### 完整成本与保留 B

G1+G2 或 G1+G3 给出对应合同的上界：安全更新/提交组为 u/b；普通业务状态为 `O((n+m)ℓ)` 加消费/历史窗口；当前根 `O(λ)`；认证索引按实际变更 `O(log N)` 路径或批量路径。恢复读相应 checkpoint 与 `d_h` 增量；若 m 个 pending 的状态都需要恢复，读取/重建其信息必须计费。

基线也可把不可变来源记录移到认证普通存储、使用已有回执或合法重建。移往客户端的持久状态、重新认证、新授权和外部查询继续计费。只保留一个摘要虽然节省可信字节，恢复仍需取得相关业务内容。

B 的可用性需要合格当前状态、可获得数据和同合同调度。旧 A 的未知外部义务可与 B 分离处理的前提是批准和原生支持独立，且主线目标允许这种局部继续；共享根关闭使 B 中断时，应如实计入。当前项目只完成有限原生保留实例，控制器恢复期间的 B 上界仍待证。

结论：`CONDITIONAL_EXISTING_METHOD_COVERAGE`。本地来源/恢复由成熟组合覆盖；原生截止、数据完整性和真实 B 可用性继续为能力或部署证据问题。

## 4. 自我反驳与贡献资格

| 检查 | 结果 |
|---|---|
| 普通签名加可信当前状态能否完成同一决定 | 对本文本地功能，在正确事务/来源组合下可以；单独签名旧状态缺当前性 |
| 认证树、缓存和批量是否已经达到所见改进 | 对 F1–F3 已给出同合同组合及计数；当前严格差距为 0 |
| 纯拒绝是否冒充恢复 | 模型单列合法恢复要求，Memoir-Opt 非预期断电及 Nimble 多数丢失均保留活性边界 |
| 一般通信下界是否得到证明 | 尚无；权威、客户端、租约和可信硬件可转移代价，禁止由单一实现推出一般结论 |
| 新鲜度是否被当作免费 oracle | 全部条件模型列出来源及写入/通信/存活成本，现实来源待确认 |
| AS/RP 是否消费本地状态证据 | 当前无完整接收端契约；L1 覆盖不延伸到旧 Bearer 远端拒绝 |
| 增量来源 | 已分析改进归于现有状态连续性、认证结构、组提交或资源转移 |
| 是否支持强独立密码学贡献 | 本轮证据未建立；受限引理为边界说明，组合映射可作为系统论证支撑 |

没有存活候选进入实现规格。模型 O 的下界是受限类手工论证；F2 的两次最小组提交是纸面实例最优；G 的成本为具体成熟组合上界。三种证据分别登记。
