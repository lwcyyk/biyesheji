# 中介合同与三个分支

本轮只选择P-MED作为拟议主profile，P-EXPORT作为必要反方。架构选择问题已发给研究者，答复前P-MED保持PROPOSED_PENDING_RESEARCHER。跨信任域分支仅登记其需求成立条件。

## 1. R保管的准确含义

R保管表示客户端/代理侧的独占托管。AT仍需向获准RP发送，RT和客户端认证材料仍需向获准AS发送。矩阵明确登记这些离开R的协议传输。关键限制是代理、未获准适配器和其他接收方无法取得或重新获取相应原生认证能力。

R的可信边界拟包含凭据存储、当前批准检查、请求调度、原生适配器和交付过滤。AS/RP具有独立的最后接受权，按声明的原生合同使用材料。评分器及管理夹具的额外知识不属于R的运行输入。从适配器日志补收材料的任何恢复路径，都需要明确为R可用的获准观察并计费。

## 2. 主profile P-MED

固定同一Casdoor试验子域、两个任务A/B及已测独立原生支持。A.g0为停止对象，B的保持目标、资源范围和时间区间明确登记。正常的新B批准创建新来源，旧A迟到结果保持旧来源。

| 条款 | 要求 | 当前证据状态 |
|---|---|---|
| M1 初始与持续托管 | A/B不取得相关AT、RT、ID token、应用管理凭据、用户密码、会话使用权或可代签证明等旁路能力 | PROPOSED，实际代理交付边界未知 |
| M2 全路径登记 | 覆盖签发、刷新、资源访问、管理枚举、SSO/恢复和重试。未建模路径保留UNKNOWN | 原生子集已审计，生产闭包未知 |
| M3 调用主体与用途 | 句柄绑定caller、task、account、audience、scope、operation和批准代次，精确请求不可在核验后替换 | 生产接纳器未验收 |
| M4 原子本地接纳 | 当前批准核验、预算与一次接纳记录在明确本地线性化点协调，撤回后待发队列重新判定 | 现有Gate只提供部分实验检查 |
| M5 在途与来源 | 派发前登记pending，所有返回和未知效果归入同一来源，旧代次结果隔离并处置 | W01单条数据流成立，持久恢复待证 |
| M6 保留B | A处置与B原生支持不重叠。若目标为端到端连续可用，还需R及B调度在声明区间可用，崩溃/切换成本单列 | 独立grant的原生有限实例成立，R故障期间的端到端保证未验证 |
| M7 恢复当前性 | 批准、已消费引用、pending和材料归属从可信当前状态恢复；证据不足时保留UNKNOWN | 实际恢复未运行 |
| M8 交付过滤 | 业务输出、错误、日志、重定向、管理列表和浏览器状态不会把认证能力交给A/B | 生产实现未知 |
| M9 原生效果合同 | 撤销、读取和最终接受的作用域、延迟、持久性及再激活条件明确 | 当前UserInfo/refresh有限证据，其他RP未知 |

本地句柄可复制，但每次使用须重新经过M3/M4。句柄若本身可被任意持有者直接调用R完成认证操作，就应作为本地能力凭据计入交付矩阵，不能只凭命名赋予“无能力”属性。

## 3. 三个不同的停止谓词

- L表示R在本地关闭点后停止新增A.g0的接纳；关闭前已接纳、可能已发出的请求明确保留在pending范围。
- U表示在声明的全部相关路径中，旧A无法继续获得新的认证接受。
- N表示指定原生材料/授权范围在目标AS/RP上已失效。

M3/M4可以支撑L。M1/M2加上完整在途闭合及原生前提才可能支撑U。N还需要对对应原生单位执行有效处置及作用域核验。R本地锁门不能自动把仍在AS中有效的材料判为N。

B的原生授权存活与经R的端到端可用性分别登记。现有B检查由独立观察者直接调用UserInfo，不能证明R停机或队列阻塞期间B仍可工作。若要求此类连续可用，需要真实的冗余/故障转移合同并给双方相同资源；当前尚未建立。

本轮保留ci01的原生终点要求，检查登记的A材料在UserInfo和refresh上拒绝，并保留B。全托管不用于把这个目标悄悄降级为只检查本地界面。

本地接纳线性化点与AS的提交点分别登记。关闭前已接纳的意图即使尚未送达AS，也应明确撤销或作为登记在途处理。若合同额外要求关闭后绝无网络发送，需要单独的发送围栏证据。

R在本地关闭后仍可有已发出的请求。只有其终态或合格的无效果/围栏事实足以闭合时，才宣布所声明的U/N。派发前停止、HTTP响应返回和最终关闭点分别记录。

## 4. 反方P-EXPORT

A持有自己来源的Bearer AT/RT及client_id，可以直接访问同一AS/RP，R保留client_secret、批准和B材料。其他接口、原生配置及B保持目标相同。C01与UserInfo轨迹实例化了这些能力，实际生产交付仍未知。

两个profile用于检验材料交付这一前提，攻击者持有能力有所不同。这种差异不能作为同合同算法优势的分离见证。G0/G9与任何候选都须在各自相同的合同内比较。

在该分支下，仅由R停止本地派发可以实现L，但A原生路径继续存在。撤销已消耗父RT的200无法单独实现N，已知最新子代逐材料撤销有实例正例。允许A继续刷新或存在未知在途时，需要真正的发行/资源截止条件或持续保守UNKNOWN。

可核查的成熟方案包括原生撤销、在线检查、发送者约束及可信完整中介。双方获得相同接口和批准，配置更改、可信存储、密钥保管、时限与中断B的成本单列。旧Bearer材料的处理属于迁移义务，新增绑定不自动处理既有副本。

## 5. 三分支裁决

| 分支 | 已经确定的事实 | 需要的条件 | 裁决 |
|---|---|---|---|
| 全部相关调用经过可信R | R可信及持有所收输入由研究者确认，全面中介仍为拟议 | M1—M9及有限处置前提 | G0加现有原生能力在声明合同类内条件充分，新增密码功能需求未建立 |
| A持有旁路材料 | 所测AT/RT具有对应原生能力 | 真实交付事实、接收端控制、完整来源与截止点 | 当前属于能力和组合边界，局部签名证明无法替代接收端约束 |
| 跨信任域私密输入或独立验证职责 | 未找到实际业务决定、独立V责任或研究者确认 | 明确谁不能看什么、谁不信任谁、谁必须核验什么 | 需求门未过，暂不重开私密证明/分布式计算 |

“所有路径受R约束”需要针对材料、会话、签名服务和恢复入口的完整证据。信任R与已经证明中介闭包是两项独立前提。

## 6. 最少待确认问题

本轮唯一架构问题是原生材料是否仅由R保管，或向代理交付AT/RT。待确认合同文本已供审阅。研究者选择后，状态改为DESIGN_CONFIRMED，已有执行证据保持原等级，仍需实现与部署符合性核验。

下一项可审查工件是某个真实代理边界的入站/出站接口与权限清单，列出原生材料从R到AS/RP及到代理的全部通道。它应覆盖正常、错误、管理查询、重定向和恢复，保持当前一个服务与两个profile的范围。
