## 方案一　在线可信当前状态

已确认合同标识为 ONLINE_TRUSTED_STATE_V1。采用单活的可信 R、R 控制的适配器和一个独立恢复域的可信持久事务服务。该服务属于 R 的逻辑可信边界，保管当前安全状态及材料恢复所需信息。具体 SQL 产品和部署位置在后续工程选型时确定。下表为研究者接受的原始建议条款，条款中的部署验收和产品选型事项仍按各自状态登记。

| 必选字段 | 已确认条款 |
|---|---|
| 1 材料交付边界 | 原生 AT、RT、ID token、会话能力、应用凭据和后继材料仅在 R 的可信边界与获准 AS/RP 之间传输。代理 A/B 获得绑定调用者、任务、账户、受众和批准代次的句柄。业务结果和管理列表经过交付过滤。未来采用 PoP/mTLS 时，其密钥及可用预签材料一并纳入托管 |
| 2 故障与攻击 | 允许 R 进程崩溃、本地缓存或旧快照恢复、消息延迟/重放、结果未知和旧代理恶意调用。恢复前停止原活动 R，按单活顺序重启。权威服务的已承诺状态与密钥处于独立保护域，保持当前性。并发克隆、多活以及权威域自身恶意回滚需另行冻结合同 |
| 3 必须存活的可信状态 | 权威服务保存批准版本、撤回、预算/消费、pending、请求来源和已收材料的可恢复记录。权威身份信任根、R 的恢复认证途径及材料解密能力须可获得。权威域恢复须保留全部已 ACK 提交 |
| 4 撤回 ACK | `LOCAL_REVOKE_COMMITTED` 在权威事务持久提交后发出。该事务与新接纳串行化，承诺其后新接纳拒绝旧批准。提交前已放行的调用继续列入在途。原生失效、全部后代关闭和外部效果终结各自等待对应证据 |
| 5 在途与迟到结果 | 外发前持久记录原 rid、规范化请求摘要、任务、账户、调用者及批准代次。确定未放行的队列项在撤回时取消。可能已放行或已发送的项保留未知义务。迟到材料始终归原请求，并进入隔离/获准处置。新批准使用独立来源 |
| 6 B 可用性 | 允许 R 重启及权威中断期间暂停 B。权威、B 所需数据/密钥和原生支持可达且调度公平后，恢复合法 B。独立 B 可先于 A 的未知义务全部收尾而恢复，前提为来源和支持独立。当前采用最终恢复目标，硬性秒数上限待后续业务要求。共享账户处置造成的 B 中断单独判定 |
| 7 在线恢复 | 明确允许。R 恢复时从可信当前服务读状态，每次新接纳通过当前事务检查。权威不可达时返回 UNKNOWN，保留未决义务。离线缓存用途限于展示和辅助计算 |
| 8 资源 | 增加一个可信持久事务服务及恢复认证路径。计入每组 durable commit、应用记录/WAL/备份字节、在线交互、认证通信、恢复读取、失败重试、撤回延迟与 B 中断。已选“暂无硬性上限，先采用正确的成熟方案”，具体数值保持 null |
| 9 实际与拟议 | R 的可信性为研究者确认。实验 Gate、内存 pending、适配器及有限原生行为已有证据。材料全托管、生产任务句柄、权威数据库、单活恢复和持久接纳的设计已确认，部署符合性待验收 |

收益来自一个清晰的当前状态来源、成熟事务和可恢复来源记录。代价集中在可信服务及在线依赖。若权威与本地快照同时回滚，或代理已取得可绕过 R 的原生材料，需重新审查对应合同条件。合法 B 的最终恢复依赖明确的服务和数据可用性。

本方案适用于从托管入口签发并完整登记的材料。既有已导出的 AT/RT、浏览器会话或签名能力需要单独的迁移清单和接收端处置证据。研究者若选择向代理交付原生材料，下一动作转为 P-EXPORT 接受路径审查。

## 方案二　离线恢复与受保护本地锚点

建议标识为 OFFLINE_PROTECTED_ANCHOR_V1。使用单活可信 R、受保护且独立于普通快照的持久锚点，以及可取得最新承诺数据的本地业务存储。当前硬件型号、接口和可信重置政策均待确认。

| 必选字段 | 可直接审议的建议条款 |
|---|---|
| 1 材料交付边界 | 采用方案一同样的全托管与任务句柄规则 |
| 2 故障与攻击 | 允许任意断电、普通盘旧快照替换、重放、消息延迟及旧代理恶意调用。可信执行和锚点更新权限受保护。锚点、根密钥和普通盘同时回滚超出本合同可接受故障范围 |
| 3 必须存活的可信状态 | 当前授权状态的受保护承诺及必要密钥。最新提交的业务记录、材料及 pending 数据须由可取得的本地持久副本提供。锚点支持检测旧数据，恢复数据的可取得性由存储合同负责 |
| 4 撤回 ACK | 完成业务数据与锚点之间经审查的崩溃安全提交后发 `LOCAL_REVOKE_COMMITTED`。恢复和半提交处理采用成熟状态连续性方法，具体硬件写序列待选定组件后实例化 |
| 5 在途与迟到结果 | 与方案一采用同样的请求来源和 pending 规则。纯本地重放仅重建本地状态，原生结果未知的请求进入对账/处置义务 |
| 6 B 可用性 | 锚点、最新业务数据、密钥、调度及 B 的原生支持均可用后恢复 B。最新数据缺失时返回 UNKNOWN。建议最终恢复目标，硬性恢复上限待确认 |
| 7 在线恢复 | 恢复本地授权状态可离线。执行实际认证操作仍按原生 AS/RP 的网络条件进行 |
| 8 资源 | 新增受保护持久硬件或等效可信存储、密钥恢复和本地备份。计入每组锚点写、字节、普通 WAL/快照、故障修复写、恢复验证和 B 中断。若改用可靠关机刷写，UPS 与关机处理成为另一显式故障前提 |
| 9 实际与拟议 | 当前核读范围只有普通日志/内存状态和取证存储。受保护锚点、原子恢复和最新数据备份尚待硬件与配置证据 |

收益是本地状态恢复对在线权威的依赖降低。代价为额外可信硬件、崩溃安全提交与备份管理。任意断电后若所有可信当前信息均丢失，同时要求恢复合法状态并保持已 ACK 撤回，前轮不可区分性边界适用。可调整项为保留独立锚点、允许在线当前权威或改变明确的故障合同。

## 资源约束的三种可选状态

每个资源字段独立记录，零值表示实际零预算，null 表示尚无数值。两个含 null 的状态通过枚举值区分。

| 状态 | 研究者选择的含义 | 后续动作 |
|---|---|---|
| HARD_LIMIT_DEFINED | 已有明确上限，需要数值、单位、统计口径、适用故障/负载与依据 | 用解析成本及同条件测量判断成熟组合能否达到 |
| NO_HARD_LIMIT_YET | 暂无硬性上限，先采用正确的成熟方案 | 可进入成熟方案的集成准备，逐项记录成本 |
| UNDECIDED | 资源要求尚未决定 | 保留条件方案与冻结状态，等待本卡选择 |

资源字段包含可信持久写次数/字节、在线交互/字节、普通存储、硬件条件、ACK 时限、恢复时间和 B 中断时间。方案一已统一选择 NO_HARD_LIMIT_YET，作为当前研究原型的明确设计决策。该建议由当前资源需求状态及成熟覆盖证据支持，数值门槛留待实际需求。
