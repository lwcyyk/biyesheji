# 已确认合同的成熟组合选择

2026-11-05。研究者已接受 ONLINE_TRUSTED_STATE_V1 和 NO_HARD_LIMIT_YET。选择的组合为可信持久事务库、单活 R 的原子接纳、请求来源账本、持久 pending，以及在线恢复检查。该组合对应前轮 G1 与 G3 的最简单实例。

纸面分析支持它在已声明前提下满足本地功能。当前状态为 READY_FOR_MAINLINE_INTEGRATION_PREPARATION，部署验收为 PENDING。下一阶段首先集成成熟组件，再取得恢复轨迹及原生能力的分层证据。

## 1. 最小组合及责任

权威事务服务提供已提交状态的持久性和当前性，R 通过受认证的信道访问。R 的代理入口、可信适配器、材料存储和恢复路径属于同一可信域。代理只使用任务句柄，原生材料按注册端点向 AS/RP 发送。事务产品、部署位置、权限、备份与恢复认证是实施前的工程选型字段。

| 步骤 | 成熟组合承担的操作 | 崩溃与未知处理 |
|---|---|---|
| 用户批准 | 认证用户操作，记录唯一批准实例、task/account/caller/audience、scope、代次及预算 | 相同批准请求通过唯一键查已提交结果，冲突正文拒绝 |
| 接纳和待发 | 在事务内读取并锁定相应当前批准，检查调用者、任务、账户、受众、操作摘要和预算，写 pending/来源并预留消费 | 已提交待发项可查询重建。未提交项保持未放行状态 |
| 派发放行 | 持久记录一次派发尝试和精确 rid，放行与撤回在批准的同一事务顺序中决定 | 从放行到收到确定结果之间均按可能已有外部效果处理。崩溃后保留未知义务 |
| 撤回 | 同一序列化规则下标记旧批准撤回，取消确定未放行的项，提交后给本地 ACK | ACK 丢失时查询原操作的提交结果。权威不可达返回 UNKNOWN |
| 返回接纳 | 先核验原 rid/请求摘要与材料来源，持久记录结果及责任。当前批准决定其后续使用权限 | 旧代次迟到结果进入原来源隔离/处置。新 B 批准与旧 A 结果分别处理 |
| 恢复 | 停止旧活动 R，认证权威服务，读取当前批准、消费、pending 与材料恢复信息，再开放句柄使用 | 本地缓存或旧快照只作待核验输入。缺少权威、密钥或必要数据时保留 UNKNOWN |
| B 继续 | 在 B 批准、预算、来源及原生支持有效的前提下独立恢复调度 | 独立 A 的未知义务保留在自己的记录中。共享根处置对 B 的影响须单独评估 |

实现可用序列化事务，或正确覆盖同一批准、预算和唯一请求键的显式锁/版本检查。代码须验证冲突和重试路径。外部 I/O 使用已持久登记的尝试，恢复时对可能已发送的请求先对账。该结构的本地去重保证需与提供方幂等能力分别验收。

批准核验与网络发送存在边界。若派发放行先于撤回提交，该尝试属于在途，可能在 ACK 后到达 AS。合同已将此情形纳入 pending。要求 ACK 后所有外部承诺停止时，需要另外确认接收端截止与在途终结能力。

将权威数据服务纳入可信域后，普通事务、认证通信、访问控制和正确恢复承担主要功能。只有存储信任或披露需求改变时，才重新选择相应密码组件。前轮已核读的 Memoir、CRISP、Nimble、SUNDR 用于确定边界和备选能力，本选型只采用上述实际需要的组件。[既有近邻映射](D:/毕业设计/研究/密码学辅助_一致性核验/revisions/crypto_state_cost_review_2026-11-05/GENERIC_BASELINES.md)

## 2. 本地正确性的条件论证

假定权威保留已 ACK 提交，R 和适配器可信，身份和材料绑定正确，恢复遵守单活条件，所有新接纳与撤回共用权威序列化规则。

对同一批准的任一新放行和撤回，事务顺序给出两种情况。放行在先时，已提交 pending 保留其原来源和处置责任。撤回在先时，放行检查读到撤回状态并拒绝。恢复从同一当前提交序列重建预算、消费和 pending，因此旧本地快照无法使旧批准再次获得新的本地放行。迟到结果按不可变 rid 和来源归档，新批准的存在只授权自己的请求。该论证的假设与实现入口在下表对应。

B 的活性单独依赖权威、数据、密钥、原生支持及公平调度。研究者接受恢复期中断与最终恢复，具体时间上限处于 NO_HARD_LIMIT_YET。永久 UNKNOWN 仍需保留失败状态及原因，不能计作一次合法恢复完成。

| 结论 | 所需证据与当前状态 |
|---|---|
| 本地旧批准拒绝 | 上述事务/恢复组合可条件满足，集成验收待完成 |
| 已知旧材料原生失效 | 所测 Casdoor 已知 AT/RT 的逐项处置有有限证据，按每个原生单元和端点核验 |
| 全部后代关闭 | 需完整来源、材料托管闭包、全部在途的终态或截止，当前证据仍有缺口 |
| 外部效果终结 | 需业务 RP 的接受、提交与终态语义，现有 UserInfo 证据只覆盖其接受范围 |
| B 持续可用 | 已选合同允许恢复期中断。正常及恢复后的 B 目标按批准/预算/支持有效和公平调度核验 |

## 4. 成本与可行性

沿用 n 个批准实例、u 次安全相关更新、c 次恢复和 m 个同时未决请求。令 h 为仍需保留的历史请求记录数，N 为当前索引规模，ℓ 为记录平均字节，b 为符合 ACK 合同的提交组数，r 为失败重试次数。批准、派发、返回接纳、消费及必要处置分别计入 u。

| 成本 | 可核对的解析范围 | 当前证据强度 |
|---|---|---|
| 可信持久写 | b 次成功逻辑提交。物理写次数/字节由事务产品、WAL、索引、复制和重试决定，可表达为各提交实测成本之和 | 解析计费边界明确，物理常数待测 |
| 在线交互 | 简单逐事务版本的更新交互为 O(u+r)。每次恢复至少执行该实现规定的权威认证/状态读取流程，额外重试计费 | 具体实现上界，通用最优性保持开放 |
| 状态与存储 | 业务记录为 O((n+m+h)ℓ)，再加索引、WAL、备份及秘密材料大小。批量、保留窗口和增量恢复可优化 | 解析范围，实际大小待测 |
| 查询/恢复 | 普通平衡索引按 O(log N) 查定位项。恢复需读取必要批准、pending、材料及增量历史，按实际字节计 | 允许按需加载，首次合法 B 放行时间待测 |
| 密码与信任 | 认证信道、R 身份凭据、静态秘密保护及密钥恢复。权威本身可信且维护已提交当前状态 | 成熟组件的条件能力，配置验收待完成 |
| 时间与中断 | 撤回 ACK 等待持久提交，B 恢复等待权威、数据、密钥和原生支持。故障与重试时段单列 | NO_HARD_LIMIT_YET，数值为 null |

现有资源合同允许选择成熟正确组合进入集成准备。具体性能可行性等待实际常数，当前各项硬上限均为空，基线超预算结论尚无判断依据。前轮论文的毫秒数字、ci01 的 199 次采集 HTTP 和旧批准预算分别保持其原始用途。

## 5. 唯一优先的最小测量规格

该规格为后续成熟基线的验收准备，状态为 PROPOSED_NOT_EXECUTED。对象是 R 权威事务提交到恢复后合法 B 首次接纳的路径。它同时观察本地安全不变量与恢复工作量，优先解决实际集成是否兑现已确认合同。

输入固定为两个批准实例 A.g0/B.g1，一个 A 在途请求，隔离的本地假 provider 按脚本产生迟到结果。原生服务请求预算为 0，使用合成材料。七种场景为正常运行、pending 提交前中断、pending/派发放行提交后外发前中断、外发后结果登记前中断、撤回提交前中断、撤回成功 ACK 后旧快照恢复、恢复时权威不可达后重新可达。

每种场景拟重复 3 次，共 21 条轨迹。每条至多 100 次数据库操作，观测窗口至多 60 秒，总墙钟预算至多 30 分钟。这些数值只是待确认的测量执行预算，依据为覆盖提交边界并限制下一轮工作量。当前设计合同的时间与资源上限仍为 null。超出观测窗口登记 INCONCLUSIVE，不据此宣告违反 B 的硬时限。

记录所有成功、失败、中止及未完成轨迹，至少包括持久提交次数/字节、数据库往返/字节、重试、恢复读取、源绑定完整性、A 的 ACK 后新放行、旧结果重标、未知请求自动重发、B 恢复时间和待决义务。撤回 ACK 后已放行在途的迟到效果按原责任观察。性能结果报告全部样本和范围，正式统计判定另行设计。

拟区分两个下一步裁决。若本地不变量与合格恢复轨迹成立，进入原生证据和部署符合性审查。若出现错误接纳、重标、义务丢失或可确定的合法恢复故障，先修复成熟组合的集成。出现安全失败即停止后续场景并保留反例。预算耗尽或状态来源无法确定时停止并登记未完成。

启动该测量需在后续明确授权成熟基线集成/运行，并固定具体事务配置。旧原生采样批准与本次设计确认均按自己的授权范围登记。
