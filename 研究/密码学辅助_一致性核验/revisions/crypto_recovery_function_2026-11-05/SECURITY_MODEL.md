**参考功能与五项证明责任**

需求门未通过，新增私密功能F_private尚未激活。本文定义已有本地决定的参考功能F0，固定可检查的安全义务，并用条件反例审查恢复前提。新增角色、隐藏字段及恢复方案没有据此成为实际部署事实。

F0的参数为明确策略P、规范编码规则、受信来源集合、当前状态来源、资源范围Ω及预算。计算安全参数κ由所选签名/MAC/AEAD实例确定。历史PSCD的数据域GF(2^128)与底座40位统计参数各自保留，不作为本轮新功能的统一安全级别。

F0维护批准表A、来源记录L、pending集合Pnd、已消费调用集合U，以及当前已核实的状态版本v。来源记录形式为

L[rid] = (task, approval_id, issuer, account, caller, query_client, audience, scope, operation_digest, material_digest, outcome)。

这些字段需要可信生成与绑定。把它们放进一个JSON对象本身不提供来源真实性。当前AS响应没有原生携带本地task/approval_id，请求关联由受信调用记录承担。

| 参考接口 | 输入和作用 | 前提/失败处理 |
|---|---|---|
| RegisterIntent | 固定rid、task、批准与精确操作，记录pending | 当前批准、调用者身份和预算由可信入口核验 |
| BindResult | 将实际返回材料绑定到原rid及原批准 | 来源不匹配则REJECT，缺少可信关联则UNKNOWN |
| RetireLocal | 把A.g0退役并停止新增本地接纳 | 与当前批准表及接纳记录在声明线性化点协调 |
| CheckCurrent | 根据可信当前状态来源核对版本与批准 | 只读到有效旧签名时不能自动得到CURRENT |
| AdmitLocal | 核对来源、当前批准、账户、调用者、受众、scope和调用唯一性 | 全部所需谓词成立才ALLOW，已证冲突REJECT，事实不足UNKNOWN |
| RecordNativeEvidence | 接收有作用域的原生关闭/接受证据 | 本地决定与AS/RP效果分别登记，缺截止或完整性时原生状态UNKNOWN |
| Resume | 从可证明当前的状态恢复来源与pending | 可信重启与旧快照恢复分支分开；实际恢复未实施 |

这些是参考规格接口，现有代码并没有逐一实现同名生产API。UNKNOWN表示事实或模型前提不足，INCONCLUSIVE用于有界验证尚未完成。二者均不能直接充当成功。中止保留原pending和计费，重试需明确是否会产生新的原生效果。

原始来源与当前授权支持也分别处理。A1的原始来源保持A.g0；当前B新批准不会重写这项事实。若某功能明确允许重新授权使用旧材料，则须新增显式支持迁移语义并保留来源。本轮原生参照为新发行B1，不把迁移能力默认为已有。

**安全游戏只采用有依据的能力。**

现有模型信任用户批准来源、R和固定原生服务合同。A可使用自己的原生材料并调度调用，结果延迟/丢失有取证依据。R、AS数据库或B秘密被恶意控制不属于已确认场景。旧快照由对手选择的能力仅作为条件恢复模型，仍需后续架构确认。它不会取消研究者已经赋予R的当前输入；只用于审查该输入在一种尚未实现的恢复方式中如何取得。新增独立V的腐化游戏和隐私泄漏函数保持未冻结。

1. 来源完整性游戏。挑战者建立权威A/L/Pnd状态，攻击者可提交自己的旧材料、重放已见包并调用AdmitLocal。获胜事件为A来源的材料被接受且归属被改成B新批准。已认证的caller由入口提供。若只有有效AS签名与有效B批准两个独立事实，而缺少同一材料/rid关系，组合仍可能错绑。G0用同一来源记录和当前批准关联消除此类拼接，前提是记录真实且完整。字段缺失返回UNKNOWN。

2. 当前性游戏。干净重启恢复同一已提交权威状态时，F0继续按该状态工作。旧快照模型另给攻击者Snapshot/RestoreOld查询，限制其不能修改独立受信锚点。若系统尚无该锚点，恢复后“当前”查询的必要输入缺失。安全事件为恢复者把已退役g0当作当前有效批准；当前实现没有给出这个模型的通用保证。

3. 撤销保持游戏。挑战者区分本地接纳关闭点c_L和原生范围关闭点c_N。攻击者可在其获准能力内调用NativeRefresh/NativeUse。c_L之后新增本地A.g0接纳违反L；只有承诺c_N之后仍在Ω中得到A的原生接受，才违反对应N。R签过一份本地拒绝回执不能让c_N自动成立。游戏评分可读取挑战者真值，运行者继续仅使用获准观察。

4. 隐私审查。R已经合法掌握的输入不能再被用来制造对R隐藏这些输入的需求。现有秘密token/密钥对未经授权主体的保护由访问控制、认证信道和适当存储机密性承担。对独立验证者的λ、成功/失败、中止、重试和跨轮关联约束尚未确定，故没有新增隐私游戏通过结论。若未来角色成立，必须要求挑战两历史的允许泄漏相同，并纳入所有公开执行事件。

5. 活性与B保留游戏。在受信状态可达、原生前提满足、pending可最终解析、预算足够且调度满足约定公平性时，合法B请求应得到合同要求的处理。始终REJECT或UNKNOWN会违反该活性目标。无限停机、无限网络中断或无限资源耗尽没有免费完成保证。原生B凭据存活与R故障期间端到端可用性分别计量，当前生产目标尚未确认。

**五项证明对象具有独立前提。**

| 对象 | 密码学关系检查可以提供的内容 | 额外事实 |
|---|---|---|
| 提交状态上的关系 | 见证满足固定电路/规则，或承诺中包含指定记录 | 关系本身必须对应所需安全决定 |
| 来源真实性 | 验证授权签名/MAC、会话来源或代码绑定 | 签名者权限、真实输入与调用关联 |
| 状态完整性 | 相对于已认证根的成员/一致性 | 所有相关写入均进入该根、接口覆盖和枚举范围 |
| 状态新鲜度 | 验证某版本声明的认证性 | 谁知道并保证当前版本，恢复时哪个状态不会同时回滚 |
| AS/RP效果 | 验证提交证据或接收方声明 | 原生语义、提交/截止边界、覆盖范围和持久效果 |

R需要的一个安全决定可能依赖多项内容，任何一项未知都不能被另一项的证明通过填平。

**两条前提边界的手工论证。**

令H0中g0仍有效，H1中g0已撤回。若恢复者得到相同旧快照、密钥、公开输入及随机性分布，且缺少其他新鲜输入，则其决定分布相同。若H0接受概率至少1−α而H1错误接受至多β，必有α+β≥1。给旧状态附加新nonce或新签名仍不提供未进入视图的撤回事实。该论证属于已知不可区分性边界，SUNDR §3.2和Memoir的状态连续性问题提供直接近邻。[PA4][PA5]

第二条边界涉及原生效果。若一份提交记录只包含旧RT的撤销200和本地状态，两种相容世界可以分别没有后继、或者存在尚未交付的后继。对相同提交见证生成的正确关系证明无法区分这两种原生状态。正确组合保留pending/UNKNOWN，或取得额外完整性与截止事实。W01支持后继存活这一具体可能性。这是证明作用域边界，尚未形成覆盖全部接口的不可实现性定理。

**组合保证的使用方式。**

在可信来源记录、真实当前状态、正确策略和原子本地接纳这些系统前提下，MAC/签名伪造及承诺碰撞的失败概率可以按相应原语安全优势并界。系统前提本身未验证时，不给它们编造数值ε。普通ZK或MPC可证明同一已定义关系，仍需同样的来源、完整性、当前性及原生效果连接。

本轮对新的受限披露功能保留恢复模式、A材料交付、B故障期可用性、λ及独立验证职责为UNSPECIFIED。因第一道门未过，优先问题的完整候选构造、隐私证明和实施规格保持未激活。
