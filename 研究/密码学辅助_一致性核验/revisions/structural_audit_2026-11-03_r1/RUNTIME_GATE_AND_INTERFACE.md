# 真实支持前提、gate及主线接口边界

## 1. 两条路径中当前能成立的范围

路径A必须有可核验的来源关系，证明实际残差的支持一定属于𝓕；配置声明、失败数≤k、攻击者承诺都不够。当前AES/GCM前端可以把残差与实验记录的计算关系关联，却**不能**推出“同记录最多一个检查失败”。

原 `source_binding/generated01/bind_gcm.mpc:184` 计算tag差，185行计算明文声明差，236行送入诊断。四坐标为 (tag0,claim0,tag1,claim1)。原 `results/source_binding_mpc01/verification.json` 的batch3和5实际得到支持[0,1]；同一记录两项同时失败。该历史证据保留，未重命名成本轮实验。

拟议压缩 V=[e1,e1,e2,e2] 的全部独立集是“每记录至多一个失败”。原契约则定位所有 |S|≤2。GF(4)^4 共256输入，原契约接受67，限制契约接受49；18个原来必须定位的输入被拒绝，例如(1,1,0,0)。所以不存在当前已验证的路径A保证。原生撤销单元G在这两个记录中没有得到确认，不能写G=2。

本轮选择路径B，先构造简单正确的通用gate。但它只保证**提交并固定的残差**符合结构。若攻击者能够替换来源或残差生成电路，仍不能保证这些残差代表真实认证状态。来源绑定是另一前置义务。

## 2. 理想功能

公开参数 ctx 包含版本、域、坐标意义、完整𝓕、来源与策略摘要、世界/epoch、批准/预算/输出接收者。参与方先固定 ctx；输入份额进入认证共享，完成本轮输入固定和一致性检查后，计算 d。若d来自服务数据，需先验证其来源关系；本轮MPC测试是合成d，不声称完成该步骤。

gate计算 S(d)={i:d_i≠0}，g=[S(d)∈𝓕]。gate-only理想功能只公开g。诊断profile在g=1时另外向指定输出方公开S(d)，g=0则只给REJECTED，不公开各零标志。本轮参考的允许接收者是两个计算方；仅party0打印日志不表示party1无法读取reveal结果。真实实现存在检测到欺骗或断连后ABORTED的可能，不保证公平交付。

输入必须在任何g或诊断输出之前固定。禁止收到拒绝后在同一批准下自适应更换输入重试；每次重试都是新查询，需要新预算和泄漏记录。多次不同策略的成员资格位本身可泄漏结构；不能因单次只公开一位而声称多次安全。

## 3. 通用私密合规电路

令 b_i=d_i^(q−1)，则 b_i∈{0,1}。对每个唯一支持T定义

δ_T=∏_{i∈T}b_i ∏_{i∉T}(1−b_i)，g=Σ_{T∈𝓕}δ_T。

恰有一个δ_T可能为1，故和是成员资格位。支持不能重复，否则在特征2中会抵消。空族输出0，只有空支持的族仅接受全零向量。

`gate_reference.py` 是GF3/GF4的公开L0电路解释器，不能承担秘密输入安全；它与直接集合查找的oracle在538个输入上核对。真实参考 `gate_mpc/support_gate.mpc` 在GF(2^128)执行同一逻辑，固定非零判定指数链、公开支持列表遍历和数组访问；中间b_i不打开，gate只开g。多项式表示按现有底座约定，统计安全参数40，不能称128位统计安全。

源程序固定算术流程不证明CPU/缓存/网络的恒定时间。gate后支持公开的分支只依赖已公开g，所增加时间/输出长度至多跟允许泄漏相关；底座侧信道和恶意终止行为未审计。固定测试种子仅产生合成输入；在线MASCOT使用正常随机预处理。

复杂度：直接电路 O(n log q+n|𝓕|) 秘密乘法的保守上界，存储可流式O(n)秘密值加公开族；本版生成电路大小为上述量级，实际解释器保存全部wire。显式族至多2^n，因此这只是正确参考。二进制域的平方优化、匹配/拟阵秩gate均未实施，不能用低效参考断言所有结构gate昂贵。

## 4. 不可遗漏的强负控制

gate已经计算b_i。接受后直接公开它们就完成定位；n≤128时可打包为GF(2^128)元素 Σ_i b_i·x^i 进行一次支持开值。`gate_mpc/gate_release.mpc` 使用原gate完全相同的算术，只增加公开接受分支及打包开值。没有额外秘密乘法，但仍有开值/MAC检查、轮次和通信开销。

这不否定未来无需逐项零判断的结构gate；它否定了“使用这个通用gate后，仅凭结构掩码减少行数就已产生端到端优势”的说法。所有比较必须包含这个基线。

## 5. 五类方法的公平契约

| 方法 | 在限制profile下 | 在原最多两失败profile下 | 本轮状态 |
|---|---|---|---|
| 全维均匀可逆掩码 | 可作为参考，完整gate相同 | 对重复列字典允许依赖支持时C1不可能；可换满火花字典，但须固定公开选择规则与完整成本 | 解析比较，未新跑候选MPC |
| 简单独立分块 | 与C3匹配构造完全等效 | 重复列压缩不支持[0,1] | 保留等效负控制 |
| 逐项私密零判断/独立掩码 | 同gate接受后直接发布支持 | 同样合法，接受范围更广 | 两profile均有MPC参考实跑 |
| moments/rowspace/seed-repair | 需套相同gate、批准、底座及失败策略 | 原有版本留存；不能直接挪旧数据称本轮公平结果 | 本轮未作重新适配计时 |
| 结构编译+完整gate+掩码 | 数学有条件成立；多出编译检查采样掩码工作 | 不能靠拒绝部分原输入算作优势 | 决策门未过，优化实现NOT_RUN |

字典若作为方法可选的公开算法参数，必须预先登记选择成本和可行性范围，不允许不同方法暗用不同输入接口。原profile和限制profile分开报告，拒绝率不得跨功能比较。没有执行未经决策门批准的结构MPC扩展或正式统计判定。

## 6. 不具放行权限的主线接口提案

提案名 `PublicDiagnosticEvidence`，仅供A/B/AB审阅，不安装进auth-lifecycle。链条为：已认证检查项ID及scope → 有证明/可信执行依据的残差函数及坐标 → 固定字典列 → 公开完整支持策略及其来源保证或gate结果 → 代数证书。当前仅中间代数部分和合成gate参考已有实现，服务端链条不是既成事实。

请求字段：request/session/epoch、任务与账户/服务作用域、检查项与残差版本、字典/域/profile摘要、允许泄漏与接收者、来源关系证据、批准及剩余请求/计算预算、取消/超时和清理策略。支持前提路径A或B必须显式标记，不能二者皆无。

响应分离登记：`source_status`、`algebra_verification_status`、`gate_status`、`diagnostic_status`、证书及scope、已消费外部请求/计算/开值次数、未决清理义务。固定 `authorizes_execution=false`；无“configuration_safe=true”、真实撤销指令或自动放行入口。

| 状态 | 使用条件 | 后续动作 |
|---|---|---|
| UNKNOWN | 来源真实性、账户scope、服务语义或epoch无法确认 | A可登记待补证；不解读为无失败 |
| INCONCLUSIVE | 支持族未知/检查预算耗尽/超出可核验范围 | 保留未完成工作与预算原因 |
| REJECTED | gate确认输入不在声明诊断成功范围，或批准不允许该查询 | 不把域外输入称无解；按新批准评估其他诊断 |
| ABORTED | 协议中断、MAC失败、超时、批准执行中撤回 | 记录未知交付状态、已消耗预算及清理义务；不得自动重试 |
| COMPLETED_DIAGNOSTIC | 来源前提满足，gate合规并完成被批准的输出 | 只提供诊断证据，仍需主线独立决策 |

失效条件：服务/账户/批准/预算/策略/epoch变化、来源关系撤回、残差或字典更换、输入未固定、掩码复用、允许泄漏变更。摘要变化使原证书不能直接复用；摘要相同也不代表来源状态仍新鲜。

分别保存 G（原生语义确认的独立撤销单元数）、拟阵分量数h、秩向量(d_j)、环境/有效维度m/d、掩码行数r。这些量没有默认相等关系。密码学遗漏修复只处理代数定位信息；AB补证处理服务语义分歧与配置冲突，不能互相冒充。
