# 协议对象与明确边界

## 1. 输入、输出与允许泄漏

输入为已固定的认证秘密份额 `[d_0],…,[d_(n−1)]`，取值于 F=GF(2^b)。`d_i=0` 表示某项一致性条件满足。它可以是认证标签差、份额链接残差或其他已正确生成的代数残差；本内核不保证这些残差的来源正确。

原型支持 k=1 或 2，本轮核心是 k=2。令 S={i:d_i≠0}。

- 若 |S|≤k，目标是返回 S；空集对应 ALL_VALID。
- 若 |S|>k，可返回 MANY，不负责定位所有错误。
- 掩码重试耗尽、解码失败或执行中止返回 INCONCLUSIVE/中止，不写成全部通过或配置不可行。

允许的诊断泄漏 Λ_k(d) 定义为：|S|≤k 时为 S；否则为 MANY。保护的是除此之外的残差数值。**即使最后返回 INCONCLUSIVE，前面的公开掩码矩也可能已经揭示部分失败位置。不能声称整个转录仅泄漏最后的 INCONCLUSIVE 字符串。** 对不同残差、相同 Λ_k 的输入，研究公开转录的不可区分性。

秘密份额、随机性与乘法采用理想算术底座。要求：主动安全且允许中止、输入在挑战前不可变、秘密非零掩码新鲜、状态与上下文不被替换。代码只检查这些理想 API 条件，没有实现它们的密码学保障；恶意参与方可任意修改 Python 内存的威胁不在实现保证中。

上下文标识、n、k、域参数和批次标识均属于公开输入。不能将真实秘密或其可枚举摘要放入上下文后，仍声称它们被掩码隐藏。实验驱动者显式传入随机币以便穷尽与重放；实际协议必须联合安全地产生这些随机量，而不是允许恶意方选择全部随机币。

## 2. 两处失败定位

选公开 g，使 a_i=g^i（0≤i<n）两两不同，定义 P(X)=Σ_i d_i X^i。所有 n 个输入、记录标识、方向、密钥代次与上下文先固定，再产生本批次公开随机挑战。

**步骤 A：保密的稀疏性检查。**

对独立均匀 x_0,x_1,x_2∈F*，计算秘密矩阵

`M[r,j]=P(g^r x_j),  r,j∈{0,1,2}`。

计算 D=det(M)，但不公开 D。对两套独立挑战得到 D_0,D_1。选公开 c∈F，满足绝对迹 Tr(c)=1，计算

`N(D_0,D_1)=D_0²+D_0D_1+cD_1²`。

用新鲜秘密 ρ∈F* 乘上 N，**只公开 ρN**。非零则返回 MANY。两个 D 及各自的零/非零状态均不公开。

**步骤 B：隐藏非零数值的矩。**

采样独立均匀秘密 r_0,r_1∈F，允许其为零。令 R(X)=r_0+r_1X，隐式定义 w_i=d_iR(a_i)。只公开四个矩：

`U_j=Σ_i w_i a_i^j, j=0,1,2,3`。

实现不逐项计算所有 w_i。先在线性共享上得到 s_l=P(g^l)，l=0,…,4，随后计算 `U_j=r_0s_j+r_1s_(j+1)`。五点循环中间积将这一层从 8 次秘密乘法降至 5 次，详见 PROOFS.md。该优化来自经典多项式算术结构，不单列“首次”主张。

**步骤 C：公开解码与秘密遗漏检查。**

由四个公开矩解码一个至多两处非零的向量，得到候选位置集合 S'。使用 Berlekamp–Massey 定位，并重新检查全部四个矩；独立参考用显式 Prony 解码和小域枚举。

掩码可能使某个 R(a_i)=0，因此 **S' 可能少于 S**。不能直接发布 S' 为完整结果。

固定 S' 后，选新的独立均匀 ξ_0,ξ_1∈F*，在秘密共享上计算

`E_b=Σ_(i∉S') d_i ξ_b^i, b∈{0,1}`。

再用域范数 `N(E_0,E_1)` 合并，乘新鲜秘密非零掩码 σ，**只公开 σN(E_0,E_1)**。零则返回 S'；非零则使用新 R 重试。原型最多 A≤4 次尝试，超限为 INCONCLUSIVE。

## 3. 为什么不能简化

- 不检查稀疏性就公开低维矩：多错误输入可能泄漏残差关系。
- 分别公开两个重复检查的零状态：即使最终采用 AND 接纳，也可能泄漏哪一次命中了输入相关根。
- 禁止 R 在所有公开位置取零：会使联合掩码分布不再隐藏残差值。
- 不做遗漏检查：被随机掩码乘成零的错误会被漏报。
- 挑战在输入固定之前产生，或对新输入复用旧挑战：攻击者可以构造通过检查的错误向量。
- 用本协议直接替代 AES 正确性验证：错误。合法 GCM 标签不保证执行器给出的明文/份额与该密文一致。

## 4. 成本和不作出的承诺

在原型的 k=2、一次掩码尝试中，按一般认证算术底座保守计价，平方也计为秘密乘法：

- 两个 3×3 行列式：18 次；
- 范数组合与隐藏输出：4 次；
- 四个掩码矩的中间积：5 次；
- 遗漏检查的范数组合与隐藏输出：4 次；
- 合计 31 次在线秘密乘法。每次重试增加 9 次。

未放大版本为 16 次，但其错误/隐私界较弱。非零随机掩码生成、认证份额初始化、MPC 底座、输入绑定、TLS 握手、AES 和响应解析全部另计。每方仍需 O(n) 或 O(nk²) 的本地线性工作；不能宣称总计算与 n 无关。

这不是原有“单故障 5 次乘法”版本的无成本增强。对很小批次或全部有效的场景，本协议未必优于简单聚合检查。没有运行真实 MPC 性能比较。

## 5. 与 A/B/AB 的连接条件

本内核将来只能接收由可信/密码学认证执行链正确生成的残差句柄。B 的原生撤销单元 G 不改变；MANY 也不等于 B 的配置不可行。

任何返回的失败位置只用于定位相关认证检查。实际如何关闭连接、保留其他任务、处理未知句柄，仍由原生语义和 A/B 控制。特别是 TLS 认证失败通常影响整条连接，不能因其他记录校验为零就越过 TLS 本身的关闭规则。

秘密随机掩码可能导致重试，底座也可能被恶意中止。不能由本构造推导出任意攻击者行为下的严格有限完成；若接入 W_r，必须显式登记失败、未决义务及适用的完成前提。

此外，随机恒等测试本身具有非零误接纳概率。需要在端到端定理中携带该误差界，不能删掉误接纳随机带后，把密码学上的高概率保证写成原 L0 的无条件、逐轨迹保证。
