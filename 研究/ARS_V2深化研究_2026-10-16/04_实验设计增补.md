# V2 实验设计增补

本文件增补V2第五阶段，原E0至E4、TL1至TL6不变。DR2-T01至DR2-T13是符号化设计，不是运行轨迹或密码学证明；期望结果不是观察值。实施、原始资料与统计结果均为NOT_RUN。

## 最小实施顺序

先执行原E0-01/TL5与E0-02/TL1，确保应用合法性和下界判定正确，再做T12的诚实见证持久化。接著以T01、T02验证读取信息与法定人数边界。前序能正确重放后，加入T03、T06故障域与引导政策。

W_STAR补齐可信状态取得后做T04、T05，再接CAEP和提交竞态T07至T09。隐私T10、T11最后实施。T13为选做边界，不扩张主线。

## Oracle的必要修订

规范Oracle同时记录真实世界状态、客户端可见证据及政策。隐藏更新只用于测量绝对状态年龄，不能无条件要求客户端知道该更新。

known_lower_bound政策测试是否延伸已知可信锚点；bounded_freshness政策另外要求可验证的时效。后者证据不足时HOLD，前者在旧下界上ACCEPT不自动算协议错误。若Oracle直接把hidden_latest_epoch交给被测客户端，就破坏信息隔离。

签名、包含、一致性与最终性应有真正的验证元件。JSON中的“真实证明”是待建立的符号前提，不能用true布林值或指定expected字段冒充完成证明验证。

## DR2-T01 零串谋时重放旧最终化证据

研究点 RP-2026-005；主张 C11, C12。

1. 恢复设备无本地历史
2. 提供两世界相同的旧转录
3. 在所有后端使用相同政策

政策预期：同转录判定分布应相同；新鲜度政策无时效证明时HOLD，不把下界政策ACCEPT自动算错。

关键指标：transcript_equal、policy_decision、true_state_age、successful_recovery。

反证和公平性：若转录不同，先定位额外可信新信息。

## DR2-T02 法定人数的2/4最小故障交界

研究点 RP-2026-005；主张 C13。

1. 固定同一成员集合和纪元
2. 恶意a,b双签
3. 诚实c和d各只看到一分支
4. 比较外部锚点是否已取得

前提是两个待见证分支均有可验证的应用授权，例如合法并发设备更新。若受信设备协议根本不可能产生这类冲突承诺，该见证反例只说明抽象法定人数边界，不能假装已构成完整密码库攻击。恶意Witness不能凭空伪造设备签名。

政策预期：f=1不应有两份冲突QC；f=2构造a,b,c与a,b,d；可见冲突时隔离，单份不可见时不得要求Oracle魔法识别。

关键指标：conflicting_certificates、client_visible_evidence、conflict_detection。

反证和公平性：检查诚实方是否其实双签或跨纪元，避免错用定理。

## DR2-T03 见证成员及引导政策回滚

研究点 RP-2026-005；主张 C13, C14。

1. e10使用registry_v1
2. e11经授权转到registry_v2
3. 恢复方取得v1旧签名与旧政策
4. 分别提供或扣留可信v2下界

政策预期：有v2可信下界时不得用旧集合绕过；无近期信息时按T01区分下界与新鲜度保证。

关键指标：registry_version、authority_chain_valid、accept_policy。

反证和公平性：若只有一方额外获v2，结果属R2信息差异。

## DR2-T04 合约外部依赖未被证明

研究点 RP-2026-006；主张 C16。

1. 测试1271合约同时依赖owner和外部module.enabled
2. 固定同一可信区块根
3. 只提供owner存储证明
4. module已停用但RPC回传magic value

政策预期：受限模板须证明全部依赖，或由可信节点执行；不完整证据HOLD/不授权。

关键指标：covered_state_dependencies、execution_source、unauthorized_commit。

反证和公平性：不能以模拟owner字段代替真实执行依赖。

## DR2-T05 相同高度的不同区块与虚假canonical

研究点 RP-2026-006；主张 C17。

1. 建立同高度不同hash的测试分支
2. 部分查询用分支A，部分用B
3. 恶意RPC对requireCanonical回true
4. 再提供固定可信hash的完整对照

政策预期：混合快照拒绝或HOLD；单靠RPC宣告不可升级为可信证据。

关键指标：block_hash_set、root_match、execution_context。

反证和公平性：相同可信快照和同验签政策下不应有方案独有差异。

## DR2-T06 同一读取CDN使多来源同时陈旧

研究点 RP-2026-005；主张 C11, C14。

1. 多个组织来源共用一读取代理
2. 隔离代理只返回旧但有效信息
3. 对照真正独立的近期读取来源

政策预期：新鲜度不足须HOLD；不能把服务商名称数当故障域数。

关键指标：administrative_domains、read_path_domains、freshness_coverage、recovery_availability。

反证和公平性：独立读取收益须计入额外网路和信任预算。

## DR2-T07 CAEP事件丢失重复及乱序

研究点 RP-2026-006；主张 C15, C18。

1. 合作发送者建立受认证session-revoked/credential-change映射
2. 先交付新撤销再交付旧状态事件
3. 重放事件，丢失推送，延迟补取
4. 加入不匹配issuer/audience/subject的对照

政策预期：有效撤销不被旧事件重新启用；无效事件不影响合法session；丢失时依刷新期限处理。

关键指标：event_acceptance、subject_mapping、local_control_epoch、stale_accept_window。

反证和公平性：通知政策须等价，不能只给W_P可靠推送。

## DR2-T08 已批准操作的提交竞态

研究点 RP-2026-006；主张 C18。

1. 旧版本通过初步授权并进入队列
2. RP接纳control_epoch提升
3. 暂停的工作者恢复提交
4. 正向对照在撤销前已完成提交

政策预期：接纳撤销之后的新最后批准不能用旧版本；撤销前完成提交不追溯标错。

关键指标：t_admit、t_seen、t_commit、linearization_order、committed_control_epoch。

反证和公平性：两基线都完整重检后若等效，不能称新机制收益。

## DR2-T09 短TTL被陈旧重新登录绕过

研究点 RP-2026-006；主张 C11, C18。

1. 旧控制人会话到期
2. RPC持续提供旧有效状态
3. 每次到期再次SIWE验证或refresh
4. 对照新鲜度租约到期时必须阻断

政策预期：不得以刷新session时计时取代状态年龄；有界政策无新证据时不续期。

关键指标：session_age、evidence_age、reauth_count、last_stale_commit。

反证和公平性：若允许陈旧续期，TTL本身不构成撤销上界。

## DR2-T10 证明查询选择器与IP关联

研究点 RP-2026-008；主张 C19, C20。

1. 固定相同批次、时延和合法操作
2. P4隐藏证明内账户关系
3. 观测HTTP/RPC长期选择器和来源
4. 比较无中继、非串谋中继和中继串谋

政策预期：若选择器公开关联，ZK内容隐藏不应被误报为完整匿名；结果需实测。

关键指标：balanced_accuracy、normalized_advantage、recovery_rate、observer_access。

反证和公平性：不能让P4使用较少辅助信息或更多中继预算。

## DR2-T11 低负载和离线账户的批次代价

研究点 RP-2026-008；主张 C20, C25。

1. 合成不同活跃度但相同公开活动分布
2. 固定发布容量，不足以dummy填充
3. 记录离线恢复的证明取得与等待
4. 不能通过逾期丢弃请求改善数字

政策预期：测量隐私、延迟、流量、填充成本和恢复率的联合权衡，不默认P4胜出。

关键指标：normalized_advantage、p95_wait、p99_wait、padding_ratio、true_recovery_rate、bytes_per_recovery。

反证和公平性：若差异仅来自更长等待或更大批次，归为服务能力差异。

## DR2-T12 诚实见证的持久化竞态与重启

研究点 RP-2026-005；主张 C13。

1. 并发提交两份检查点
2. 在签名返回与持久化之间注入crash
3. 重启后重放旧检查点
4. 对照原子检查并持久化后才返回签名

政策预期：诚实见证不得因回滚持久化而双签；此为基线正确性前提。

关键指标：persist_before_reply、monotonic_checkpoint、double_sign。

反证和公平性：实现竞态失败不能归因缺少区块链。

## DR2-T13 EOA委托与验签政策

研究点 RP-2026-006；主张 C24。本案例选做。

1. 测试EOA无代码、委托代码和撤回委托
2. 对每种状态明列支持的验签方法
3. 单独验证原EOA ECDSA签名能力是否仍在

政策预期：不得把委托撤回误报为EOA私钥撤销；不支持类型依政策拒绝。

关键指标：account_code_mode、verification_method、policy_result。

反证和公平性：必须区分RP应用政策和链上签名数学能力。

## 配对与统计计划

安全性案例先做有限小状态的系统性枚举，再做种子化调度。记录完整事件顺序与可见信息；有限枚举通过只支持该有限模型，不推出无界正确。对有因果顺序的事件只枚举合法调度，不任意重排成不可能的世界。

独立Oracle不能直接重用被测核心判定函数。先对签名缺失、根不相容、错误成员、旧政策与资料缺失做有意义的正负变异，并保留成功合法操作。R1测同信息与政策，R2则列出每个新增信任来源。二者的结果分开统计。

隐私试验以隐藏位均匀的配对世界产生资料。先用独立pilot决定事件率与样本量，再冻结测试集；不以看见效果后的样本量或阈值作事前注册。若进行确认性检验，事前列主要终点、最小实用差异及停止规则。重复次数不是统计效力的替代品。

同一账户或完整session属同一群集，bootstrap或其他不确定性估计按群集计算，不把一条轨迹中的大量请求当独立样本。配对差异保留配对；比较多种分类器和设定时，区分探索与确认性结果。

费用先报gas或后端实际资源单位，若换算法币需记录链、交易类型、实际日期、费率和汇率。L2需分开排序器接收、L2状态与L1结算，不与L1 finalized混用。模拟器的等待参数只能作敏感性分析，不能当真实链性能。

## 强基线配置

B2保留完整见证、应用签名、前驱与可信下界。B3的非分叉、发布与可读性需具体机制；B4明列共识及引导根；B5明列治理与成员独立性。所有后端同样检查应用授权，不能把错误锚定后的状态当业务合法。

W_STAR包含SIWE/ERC-1271、可信且有时效的状态取得、同blockHash执行上下文、合作方CAEP/SSF或等价通知、硬TTL、禁止陈旧续期、高风险操作最后版本检查。W_P只能在相同输入和功能下比较额外作用。

P3/P4匹配批次、周期、中继、攻击者观察、合法功能与最大等待；控制证明取得流量、长期查询键与公开地址。共同中继失陷和低负载都纳入。

## 每次执行的必要记录

run_id、来源版本及代码commit、dirty状态、模型范围、环境、seed、基线、政策、可见与隐藏事件、可信根、各项时间点、判定和理由、成功恢复或真实提交、原始日志及哈希。事件时间使用可比较的单调时钟；跨节点误差独立报告。

“全拒绝”即使没有未授权接受，也可能没有实用价值。因此同报误接纳、合法成功、HOLD、超时和不可恢复，不把HOLD算成成功恢复。

## 停止与转向

E0或T12不通过先修正基线。T01证明新鲜度无法建立时，缩小承诺或增加具来源的可信信息；不得靠改Oracle掩盖。R1差异先查策略和实现，R2差异先归因信息与故障域。W_STAR与W_P等效可形成整合和测量结果，P3/P4等效则不优先投入ZK。

本设计未建立完整协议实现，实际执行仍是下一阶段。
