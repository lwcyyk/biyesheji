      Abstract. Updatable encryption (UE) allows a third-party server to
      update outsourced encrypted data without exposing keys and plain-
        texts. The server can update ciphertexts to ones under a new key using
      an update token provided by the client. UE can realize eﬃcient key
       rotation and is eﬀective against key compromise. The standard security
       notions of UE capture the property that even if keys or update tokens
       are compromised, the conﬁdentiality of messages is maintained by the
      key update and ciphertext update. In general, the randomnesses used in
       the encryption and ciphertext update algorithms must be kept secret in
       the same way as the keys. On the other hand, while key compromise is
       considered in existing security notions, randomness compromise is not.
       In this paper, we deﬁne a new security notion for UE, IND-UE-R secu-
         rity, that is resilient to the compromise of randomnesses used to generate
       or update ciphertexts. Furthermore, we prove that the UE construction
      RISE (EUROCRYPT’18) satisﬁes our proposed security notion.


     Keywords: Updatable Encryption · Public-Key Encryption · ElGamal
      Encryption · DDH Assumption · Randomness Compromise


1  Introduction

Encryption is an indispensable tool for securely managing sensitive information
within a cloud environment. By encrypting data locally and then uploading it
to a cloud server, users can protect important information even if it is compro-
mised due to misconﬁguration. However, key compromise is now recognized as
a serious threat to encrypted cloud servers. For instance, if a user’s computer
is infected with malware and the key is compromised, the encrypted data on
the server is vulnerable to decryption at any time. Recently, a vulnerability in
intel processors [27] that could cause a key compromise has highlighted the real
threat of key compromise. To counter the threat, many cloud service providers

recommend key rotation [1,21], where the key is periodically updated, and the
ciphertext is re-encrypted with the new key. The naive method for realizing it
would be to download all ciphertexts from the server, decrypt them, encrypt
them with a new key, and then upload them again. Although this method can
update ciphertexts, it requires downloading and uploading all ciphertexts for
each update, and thus communication costs would be prohibitively expensive.
   Boneh et al. [8] proposed a better solution, updatable encryption (UE), which
enables a third party to update the ciphertext without exposing keys and plain-
texts. Using UE, we can generate an update token with the new key when the
key is updated. A third party who holds the encrypted data can use the update
token to transform the ciphertext to correspond to the new key. The user only
needs to send the update token to the server, thus reducing the communication
cost.
   The compromise of the randomness used to generate ciphertexts poses as
much of a threat as a key compromise. If a key is compromised due to malware
infection, there is a concern that the randomness used for generating a ciphertext
may also be compromised. In general, the security of cryptographic primitives
relies on the assumption that the randomness used is kept secret. The existing
security notions of UE1 [9] capture the property that even if a key or update
token is compromised, the conﬁdentiality of messages is kept by updating the key
or ciphertexts. On the other hand, it has not been considered security against
the compromise of randomnesses used in the encryption and ciphertext update
processes. In this study, we revisit the security deﬁnition of UE to reduce the
impact of randomness compromises by updating ciphertexts.


1.1  Our Contribution

In this paper, we propose a new security notion that UE2 is resilient to the com-
promise of randomnesses used in encryption and ciphertext updates. This secu-
rity notion captures that even if an adversary obtains the randomness in addition
to keys and update tokens, the conﬁdentiality of the ciphertext is restored by
updating it. Technically, our new security notion secure against randomness com-
promise, which we name IND-UE-R security, is deﬁned by extending the existing
security notion for UE named IND-UE security [9]. To capture the compromise
of randomness used for encryption or update, we modify the encryption and
ciphertext-update oracles so that they return not only a ciphertext but also a
randomness used in the encryption/update algorithms. In our security notion,
the conﬁdentiality of encrypted messages can be restored by updating ciphertexts
with a new token and a new randomness even if keys, tokens and/or random-
nesses are compromised in the past, as existing security notions for UE in case

1.2  Related Works

Prior Works on UE. UE was ﬁrst introduced by Boneh et al. [8] and has been
the subject of various studies [7,9–12,14–17,19,20,22–26]. There are two types
of UEs: ciphertext-dependent and ciphertext-independent. In the former type, an
update token is generated depending on a ciphertext to be updated, and a token
for a particular ciphertext cannot be used to update a diﬀerent ciphertext. This
is not the case in the latter type of UE, and an update token is not tied to a
particular ciphertext and can be used to update multiple diﬀerent ciphertexts.
For ciphertext-dependent schemes, Everspaugh et al. [14] formulated security
deﬁnitions that capture the security against chosen-plaintext attack (CPA) and
indistinguishability of updated ciphertexts. For concrete ciphertext-dependent
UE schemes, see [7,8,11,12,14]. The concept of ciphertext-independent UE was
proposed by Boneh et al. [8]. Lehmann and Tackmann [19] gave the concrete for-
mulation of security notions of ciphertext-independent UE based on the security
deﬁnitions for ciphertext-dependent UE [14]. More speciﬁcally, they proposed
security against CPA and the indistinguishability of updated ciphertexts. Fur-
thermore, Boyd et al. [9] proposed a stronger security notion called IND-UE
security, which is satisﬁed by several schemes based on the DDH and LWE
assumptions [9,15,19,20] and schemes constructed using bilinear groups [24]. In
UE, it is sometimes possible to infer the key of the previous and next epochs from
the key and token of one epoch, and there has been a lot of discussions about the
directionality of key update and ciphertext update in recent years [10,15,16,22].
There has also been a work extending UE to the public key settings [18].

Security Notions Against Randomness Compromise. Selective opening attacks
[5] for an encryption scheme are attacks to break the conﬁdentiality of multiple
ciphertexts by disclosing a part of secret information to an adversary. Security
against selective opening attacks is informally described as follows: an adversary
cannot infer undisclosed secret information from the ciphertext even if some of
the secret information is disclosed to the adversary. Technically, in the secu-
rity game, there are multiple target (challenge) ciphertexts, and an adversary
can ask to “open” a part of them to obtain the plaintexts and randomnesses
used for generating the opened ciphertexts, and then the adversary is tasked to
guess/infer the information of the unopened ciphertexts.
   Leakage resilience [13] is a security notion that protects conﬁdential infor-
mation even if partial information of values used for encryption is leaked to an

attacker (say, by side-channel attacks). Dziembowski and Pietrzak [13], who ﬁrst
proposed leakage resilience, modeled the leakage of partial information about the
secret key or randomnesses as outputs from the leakage function. In the case of
a partial randomness leakage, its security experiment is deﬁned in the same way
as an ordinary security experiment (without leakage), except that an adversary
is given partial information of the randomness used for generating the challenge
ciphertext as input.
   Our security notion for UE introduced in this paper, IND-UE-R security, dif-
fers from the above security notions in the properties it captures. Our notion cap-
tures the restorability of the ciphertext conﬁdentiality by the ciphertext update
process in case of randomness compromises, which means that even if the internal
randomnesses used in the past encryption or ciphertext update processes have
been leaked to an adversary, the conﬁdentiality of the ciphertext is restored to
the same level as before the compromise. In contrast, security against selective
opening attacks and leakage resilience ensure that even if some secret informa-
tion is compromised (even from the challenge ciphertext(s)), the conﬁdentiality
of the unleaked secret information is maintained without any additional process.

Resisting Randomness Subversion Attacks. Randomness compromise is related
to randomness subversion attacks [4] that undermine randomness-generation
processes. Deterministic encryption and hedged encryption are well-known
notions of encryption against the attack. Deterministic encryption [2,6] is an
encryption scheme whose encryption algorithm is deterministic and thus has no
randomness to be compromised or subverted. It protects the conﬁdentiality of
messages which have high min-entropy. Hedged encryption [3] is an encryption
scheme that is secure as long as the pair of a message and a randomness used
for encryption has high entropy. Therefore, even if the randomness-generation
process has some failure, the scheme is secure as long as the entropy of a mes-
sage is high. Motivations of deterministic encryption and hedged encryption are
slightly diﬀerent from ours since we aim to consider security against randomness
compromise, not the failure of randomness generation. Furthermore, these two
types of encryption require high entropy for a message or a message-randomness
pair, but our notion does not.

2.1 DDH Assumption

Here, we recall the decisional Diﬃe-Hellman (DDH) assumption.

Deﬁnition 2.1 (DDH assumption). Let G be a cyclic group with prime order
q (where |q| = Ω(λ)), and let g ∈G be its generator. We say that the DDH

2.2  Updatable Encryption

Here, we review the syntax and correctness of UE and the deﬁnition of IND-UE
security.
  A UE scheme UE consists of the following ﬁve PPT algorithms (UE.KG,
UE.Enc, UE.Dec, UE.Next, UE.Upd).
UE.KG(1λ) $−→k1: The key generation algorithm UE.KG takes a security param-
   eter 1λ as input, and outputs a key k1 (at the initial epoch).
UE.Enc(ke, m) $−→ce: The encryption algorithm UE.Enc takes a key ke (at some
   epoch e) and a message m as input, and outputs a ciphertext ce.
UE.Dec(ke, ce) →m′/⊥: The decryption algorithm UE.Dec takes a key ke and
   a ciphertext ce (both at some epoch e) as input, and outputs a decrypted
   message m′ (which could be the special symbol ⊥indicating a decryption
   error).
UE.Next(ke) $−→(ke+1, Δe+1): This is the algorithm for updating a key and gener-
   ating a corresponding token. UE.Next takes a key ke at epoch e as input, and
   outputs a new key ke+1 and an update token (or just “token” for simplicity)
   Δe+1, both at the next epoch e + 1.
UE.Upd(Δe+1, ce) $−→ce+1: The ciphertext-update algorithm UE.Upd takes a
   token Δe+1 at some epoch e + 1 and a ciphertext ce at epoch e as input, and
   outputs a ciphertext ce+1 at epoch e + 1.

  We refer to a ciphertext generated by UE.Enc as an original ciphertext, and
one generated by UE.Upd as an updated ciphertext.

3  IND-UE Security Against Randomness Compromise

In this section, we provide a formal deﬁnition of the new security notion for
UE that we call IND-UE-R, which captures the security property stronger than
IND-UE security. Formally, IND-UE-R security for UE is deﬁned as follows:

Deﬁnition 3.1 (IND-UE-R Security). We say that a UE scheme UE =  (
UE.KG, UE.Enc, UE.Dec, UE.Next, UE.Upd) is IND-UE-R secure, if for any PPT
adversary A, we have | Pr[ExptIND-UE-RUE,A   (λ) = 1] −12| = negl(λ), where the exper-
iment ExptIND-UE-RUE,A   (λ) is deﬁned in the same way as ExptIND-UEUE,A  (λ) in Fig. 1,
except that the oracles O.Enc and O.Upd are deﬁned as in Fig. 2.

   For clarity, we also describe the behavior of the oracles in the following (where
we underline the diﬀerence from the IND-UE experiment):

 – O.Enc(m): It takes a message m as input, picks a randomness r uniformly
   at random from the randomness space REnc of UE.Enc, and computes ce ←
   UE.Enc(ke, m; r). Then, it returns the pair (ce, r). It also adds the pair (ce, e)
   into L.
 – O.Upd(ce−1): It takes a ciphertext ce−1 as input, where it is required that
   (ce−1, e−1) ∈L. Then, it picks a randomness r uniformly at random from the
   randomness space RUpd of UE.Upd, and computes ce ←UE.Upd(Δe, ce−1; r).
   Then, it returns the pair (ce, r). It also adds (ce, e) into L.

   The above deﬁnition of IND-UE-R security ensures that an (updated) cipher-
text c is kept conﬁdential even if the randomnesses, which were used to generate
the previous-epoch ciphertexts (i.e. ciphertexts generated in the past) leading to
c via the ciphertext update, are compromised. Technically, we deﬁne this secu-
rity notion by making a simple modiﬁcation to the interfaces of the encryption
oracle O.Enc and the ciphertext-update oracle O.Upd in the IND-UE experiment.
In the experiment for IND-UE-R security, these oracles return not only an origi-
nal or updated ciphertext but also a randomness used to run UE.Enc or UE.Upd,
respectively.
   Note that we do not consider the compromise of the randomnesses used
for generating challenge(-equal) ciphertexts, since we would like to capture the
security property that the ciphertext update restores the conﬁdentiality from

4 A UE Scheme Satisfying IND-UE-R Security

In this section, as our main technical result, we show a UE scheme satisfying our
new notion of IND-UE-R security.
    Speciﬁcally, the UE scheme for which we prove IND-UE-R security is the UE
scheme called RISE proposed by Lehmann and Tackmann [19], which is based
on the ElGamal encryption scheme. It was shown by Boyd et al. [9] that RISE
is IND-UE secure based on the DDH assumption. We will show that RISE as it
also satisﬁes IND-UE-R security under the DDH assumption.

4.2  Security Proof

The following theorem captures the main technical result of this paper.

Theorem 4.1. If the DDH assumption holds in G, then RISE is IND-UE-R
secure.

Intuitions Behind the Proof. Intuitively, we can rely on the security of the ElGa-
mal encryption scheme to conclude the security of RISE. However, the diﬃculty
of proving security for UE (even without considering the randomness compro-
mise) is that it is not known beforehand at which of the epochs an adversary
corrupts the key. The reduction cannot embed its DDH instance to the epoch at
which an adversary compromises the key. Note that naively guessing the epochs
at which an adversary corrupts keys does not work, since correctly guessing all
the epochs at which an adversary corrupts the key, can succeed only with an
exponentially small probability. To deal with the issue, we will employ a clever
technique used in [19] (and many other recent works on UE). Speciﬁcally, observe
that when the trivial win condition (K∗∩C∗̸ = ∅) is not triggered in the secu-
rity game, there exists a range of consecutive epochs where the key has not been
compromised (we call it an insulated region), and the epoch to be challenged
should be included in this range. The reduction guesses the insulated region to
which the epoch for embedding the reduction’s challenge (i.e. the DDH instance)
is included. To guess the region, the epochs at both ends (i.e. its beginning and

its end) of the region are guessed. The probability of succeeding in guessing,
which will be reﬂected as the loss of the reduction, can be only polynomial.
   Recall that IND-UE-R security  is an extension of IND-UE security. The
IND-UE-R security proof of RISE can be conducted similarly to the IND-UE
security proof of this scheme, except for the simulation of the O.Upd oracle.
In the IND-UE security proof by Galterand and Pan [15], the generation of an
updated ciphertext in O.Upd is simulated by not using the UE.Upd, but by just
returning an encrypted corresponding message (which is known to the reduction
since it must have been previously submitted to O.Enc). This simulation is pos-
sible since the distribution of ciphertexts output by UE.Enc and that of UE.Upd
are the same, as we checked above. However, if the randomnesses used to gen-
erate the ciphertexts are given, these distributions could be distinguishable. In
fact, if additionally the update token (which contains an ElGamal public key)
corresponding to the epoch is given, an adversary can by itself check whether
an updated ciphertext obtained from O.Upd is indeed computed using UE.Upd.
Therefore, in the security proof, we need to carefully simulate the behavior of
UE.Upd to an adversary. We can rely on the property of the ElGamal encryption
to simulate the randomness used for UE.Upd. In the UE.Upd process of RISE, the
(newly sampled) randomness for the ciphertext update is added to the random-
ness part of the ciphertext to be updated. The distribution of (newly sampled)
randomnesses to be added {r $←−Zq  : r} is the same as that of the diﬀerence
between the randomnesses used for UE.Enc and those used for generating the
input ciphertext {r $←−Zq : r −r′} for any r′ ∈Zq (where r′ corresponds to the
randomness part of the input ciphertext). Therefore, the randomness used for
UE.Upd can be simulated and this enables us to simulate O.Upd. Based on the
above explanation, the proof can be completed even if randomnesses are added
to the response of O.Enc and O.Upd. For the details, see the formal security
proof below.

5  Conclusion

In this paper, we deﬁned IND-UE-R security as a new security notion of UE
resistant to the compromise of randomnesses used in encryption and ciphertext
updates. IND-UE-R security captures the property that even if the randomness
used for encryption and/or ciphertext update in the past is leaked to an adver-
sary, the ciphertext conﬁdentiality is kept by updating the ciphertext. Then, we
showed the UE scheme RISE [19] as a concrete scheme that satisﬁes IND-UE-R
security and gave a security proof based on the DDH assumption.
  We leave the question of constructing IND-UE-R secure schemes in which
ciphertext and key updates have uni-directionalities as an interesting open
problem. In this paper, IND-UE-R security is deﬁned for UE schemes with bi-
directional ciphertext updates and bi-directional key updates, but IND-UE-R
security for uni-directional key/ciphertext updates can be deﬁned immediately
by changing the trivial win condition in the deﬁnition in this paper. It is natural
to extend IND-UE-R security to a chosen-ciphertext attack (CCA) setting, and
constructing a scheme satisfying it is also an interesting open problem.
   Recently, the expiration of ciphertexts has been introduced for UE [24]. The
encryption algorithm in this setting takes an expiry epoch as input in addition

=== PDF PAGE 21 ===
                    UE Secure Against Randomness Compromise     67


to a key and a message. If the ciphertext is updated several times and its epoch
exceeds its expiry epoch, the ciphertext cannot be decrypted correctly. This
setting limits the damage of the key compromise and it is also interesting to
consider the randomness compromise in the setting.
   Another open question is to clarify whether IND-UE-R-secure schemes exist
under other assumptions such as the learning-with-errors (LWE) assumption
which is one of the post-quantum assumptions.
