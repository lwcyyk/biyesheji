P19 SAGA
标题/载体：SAGA: A Security Architecture for Governing AI Agentic Systems，Syros 等（美国东北大学），NDSS 2026（正式发表，代码开源；另有 arXiv:2504.21034）。
SAGA 针对"agent 间授权停留在理论、用户无法控制自己 agent 生命周期"的缺口，提出以 Provider（集中式注册服务）为核心的治理架构：用户经 OpenID Connect 注册，为每个 agent 登记 TLS 证书、访问控制密钥对和一批一次性密钥（OTK），并定义基于模式匹配的联系人白名单（Agent Contact Policy，每条规则附 OTK 预算）。通信时发起方从 Provider 取接收方元数据和一个 OTK，双方用 Diffie-Hellman 派生共享密钥，接收方据此签发带过期时间与最大请求数的访问控制令牌，有效期内复用不必再过 Provider，在细粒度控制与性能间折中。
ProVerif 在 Dolev-Yao 模型下自动证明令牌保密性与双向认证；支持 RAFT 容错、分片、BFT 与联邦部署，并给出与 Google A2A 的集成方案。协议开销低于任务成本 0.6%，10 分片吞吐线性扩展，理论容量约 3 亿活跃 agent。
对于本课题，SAGA 将用户对 agent 的控制落实为身份登记、一次性密钥、过期时间与请求配额，可以作为系统能力层的直接对照。P01 的相关工作比较也纳入了该系统。
P21 Permission Assistant
标题/载体：实际标题为 Towards Automating Data Access Permissions in AI Agents，Wu 等（圣路易斯华盛顿大学 / UC Irvine / 华盛顿大学 / 乔治城），IEEE S&P 2026（正式发表，文末收录录用元审稿）。
Permission Assistant 研究"agent 代用户做数据访问决定"的两难：逐次弹窗造成权限疲劳、破坏自动化价值，不弹窗又过度授权，因此主张构建能代替用户做权限决定的自动化权限管理。研究分为两个阶段。首先开展 205 人情景模拟用户研究（8 个域、21 个工具、142 种数据类型），发现过度授权比授权不足更普遍（90% 参与者对至少 15% 的请求过度授权），agent 出错后用户明显收紧授权，偏好受上下文与数据敏感性影响（SSN 欠授权率 46.3%）但同一上下文内跨用户相似；据此提出 permission assistant，LLM 上下文学习（OpenAI o3-mini 推理模型，以人口属性/隐私意识/权限历史做角色提示）与协同过滤（LightGCN）混合，仅采纳高置信 CF 预测（FPR/FNR 均低于 5%），用置信阈值控制覆盖-精度权衡。
181 名用户 7,565 条决定、5 折交叉验证：准确率 85.1%、精确率 92.8%，高置信（阈值 0.91）下 94.4%（覆盖 25.9%），冷启动仍有 66.9%。
这一工作为动态授予与撤销提供了用户行为依据。其过度授权测量、偏好学习和置信度门控，可以用于设计授权交互与评价基线。
P22 Authenticated Delegation
标题/载体：Position: AI Agents Need Authenticated Delegation，South 等（MIT / 牛津 / UC Berkeley / 斯坦福），ICML 2025（PMLR 267，立场论文）。
Authenticated Delegation 论证：第三方（数字服务、其他 agent、人类）与 AI agent 交互时必须能同时验证"谁在授权"与"代理权限的精确范围"，否则提示注入、越权、冒充与问责断裂不可避免。技术路线是扩展 OpenID Connect 与 OAuth 2.0：人类用户先向 OpenID Provider 注册 agent 并签发委托令牌，令牌引用用户 ID-token 与 Agent-ID token、携带范围限制、可嵌入 W3C 可验证凭证；借鉴 UMA 实现策略向多个 agent 传播。
权限界定主张"结构化资源范围 + LLM 把自然语言约束翻译成 XACML 类策略 + 人类审核"的混合机制，并给出网页浏览、API 数据聚合、SSH 远程环境、agent 间协作四个用例与代理法/UETA 法律分析。论文以研究路线和协议框架论证为主，实验评估与形式化证明仍有待补充。
本课题可以借鉴其委托凭证框架，组织签发、验证、过期和跨 agent 传递过程，并明确 OIDC、OAuth 与可验证凭证之间的衔接关系。
P27 临床超图委托
标题/载体：实际标题为 Securing Autonomous Clinical Agents: Time-Scoped Hypergraph Delegation for Controlling Patient Data Access，Karimi 等（Zetafence / Texas A&M-Commerce / Howard 大学），IEEE ICDH 2026（pp. 352–358）。
临床超图委托 研究多 agent 临床系统中的"委托链失控"：嵌入化验报告的注入载荷可在任何人审之前贯通整个委托层级，RBAC 角色继承与 Macaroons 凭证链都不能从结构上保证子 agent 权限严格有界于父级。机制是 NGAC-超图委托：每条委托边是带时间窗的超边（委托方、能力、对象、资源、起止时间），子 agent 权限集是父集的真子集，衰减由图构造可证明，由授权结构独立强制执行；执行点在工具调用层，到期即拒绝越权操作。
SEPI 方法论实验（50 名合成患者、39 个临床扎根注入载荷 × 3 种失陷位置 × 4 种架构）：加权爆炸半径较 Flat RBAC 降 75%、较 Macaroon 链降 65%；消融证明去掉时间过期使爆炸半径增 75%，时间域是独立贡献。Claude Sonnet 4.6 行为层主动检测全部 39 个载荷而小模型不稳定，支持"授权层承担隔离责任、不依赖模型行为"。
这项工作将多跳委托的权限衰减与时间窗结合，能够为委托凭证的颁发、收窄和到期处理提供实现参照。
P28 APEX
标题/载体：实际标题为 Protocols and Formal Models for Delegated Authorisation with Server-Side Secrecy，Snyman 等（Surrey / Castellan /墨尔本大学 / TII），ASIACCS 2025（pp. 1372–1393）。APEX 是文中协议套件名。
APEX 研究 OAuth 委托授权中"资源在服务器端明文存放，服务器与被授权第三方都能读"的问题：提出 APEX 协议套件，实现"受限委托授权 + 服务器端保密"，资源加密存放于服务器，只有运行在用户设备上的软件代理能触碰明文与密钥。机制包括一次性码（OTC）在不可信服务器中介下绑定双方 agent 身份、双中介授权授予协议、资源注册/检索、密钥重封装与承诺/删除协议（服务器只存密文与 wrapped key）。形式化提出 RAD（受限授权委托）模型，Bellare–Rogaway 风格的通用委托授权形式模型，定义授权授予安全与加密资源授权安全两类性质，并证明 APEX 全部满足而 OAuth 2.0 本身不满足。
原型实测注册约 9 倍、检索约 10.8 倍于普通 OAuth 的延迟。
APEX 的 RAD 模型为受限委托授权提供了形式化依据。其加密资源注册、检索、密钥重封装和删除流程，也可用于分析凭证保密与资源访问之间的关系。
P35 AGentVLM
标题/载体：AGentVLM: Access control policy generation and verification framework with language models，Jayasundara 等（奥克兰大学 / RMIT），Journal of Information Security and Applications（Elsevier） 第 98 卷，2026。
AGentVLM 研究"从自然语言高层需求手工生成访问控制策略费时易错、且缺少验证"的问题：四阶段框架，微调 BERT 识别自然语言策略文本；LoRA 微调 LLaMA 3 8B，借结构化信息抽取同时捕捉显式 token 与语义级隐含规则，生成含主体/动作/资源/目的/条件五要素的中间表示（可模板化为 XACML）；微调 BART 构建 12 类序列对分类验证器，判断策略正误并定位 11 类错误，用积分梯度归因给出可操作反馈。策略生成 F1 80.6%（较现有框架相对提升至少 34.4%，超 GPT-4o 的 59.9%），验证 F1 94.4%；经提示注入红队微调增强对抗鲁棒性，本地部署小模型保护需求机密性。
对于本课题，AGentVLM 可支持授权策略生成、部署前验证和修正反馈。其研究对象是组织级访问控制策略，具体应用时还需建立与 agent 委托凭证之间的映射。
P37 CapChain
标题/载体：CapChain: A Capability-Token Access Control Architecture with Verifiable Provenance for Multi-Agent LLM Systems，Choong 等（台湾科技大学 / 嘉义大学），Applied Sciences（MDPI）16 卷 7776，2026-08。
CapChain 针对 LangGraph 类多智能体系统共享同一个无加密、无字段级读控的状态存储（以 langgraph-checkpoint-sqlite 的 CVE-2025-6764 为现实动机），在状态合并（reducer）处部署三个原语：CapTok，HMAC 签名的七元组能力令牌，支持签发/收窄/验证，委托只能收窄不能扩权（EUF-CMA 不可伪造论证）；ProvChain，Ed25519 签名 + Merkle 链的溯源日志，O(log N) 审计；CAR，能力感知 reducer，合并前过三道门（令牌有效性、溯源完整性、属性-目的集合交集），拒绝即写审计日志。
150 条件的事后推导评估 + 18 条件运行时可行性检查：属性-目的门在 4.67% 的代理间消息上触发裁剪，单次写入门开销合计约 6.8 微秒。
CapChain 在编排器状态转移层实现了能力令牌与可验证溯源，可作为代理间授权、委托收窄、防重放和审计的直接比较对象。
运行时强制与工具最小权限
授权关系建立后，还需要在工具使用时持续执行。相关研究分别约束任务对齐、工具可见性、服务器操作能力、数据流和运行轨迹，使批准范围能够落实到具体动作。
P23 Task Shield
标题/载体：实际标题为 The Task Shield: Enforcing Task Alignment to Defend Against Indirect Prompt Injection in LLM Agents，Jia 等（宾州州立 / 普林斯顿），ACL 2025（pp. 29680–29697）。
Task Shield 提出"任务对齐"新视角防间接提示注入：通过校验每条指令对用户目标的贡献判断任务对齐情况。形式化定义任务指令、ContributesTo 贡献关系、对齐条件与任务对齐，沿用系统>用户>助手>工具的指令特权层级。运行时防御系统三组件：保守提取嵌套/隐式指令构建用户任务集；对齐检查用 LLM 对每条指令相对每个用户任务打贡献分并聚合（总分归零即判失配）；失配时生成反馈（告警+风险说明+重申用户任务）让 agent 自我修正。
AgentDojo 上对 GPT-4o：最强攻击的成功率从 47.69% 降至 2.07%，受攻击效用（69.79%）高于无防御基线（50.08%）；轻量版 Input Shield 以约 19 秒中位延迟（完整版 62.56 秒）将攻击成功率降至 4.76%；防御器换 GPT-3.5-turbo 仍能把成功率降约一个数量级。
Task Shield 为动作与用户任务之间的关系提供了形式化描述及拦截反馈机制。本系统可以据此将意图检查与凭证验证结合。
P25 Prompts Don't Protect
标题/载体：Prompts Don't Protect: Architectural Enforcement via MCP Proxy for LLM Tool Access Control，Uppala（独立研究者），EMNLP 2026 Industry Track（pp. 43–49），代码开源。CCF B
它实证"提示词层面的工具访问控制在对抗下不可靠"：未授权工具出现在上下文中时，即使系统提示明令禁止，前沿模型仍以 48%–68.5% 的比率选择它们（角色提升攻击最高 96%）；显式 per-tool 白名单也只降到 4%–37% 且跨模型不可预测。机制是"受治理的 MCP 代理"：工具发现（tools/list）时做 JWT 验证 + 基于属性的访问控制（ABAC）过滤，未授权工具根本不进入模型上下文；调用（tools/call）时再做第二次校验，检查幻觉或注入产生的工具名。
注册表含 507 个真实服务的 MCP 工具，200 个对抗任务（直接注入/间接指令/角色提升/多步欺骗）× 三模型：治理条件下未授权调用率均为 0%，代理 p50 延迟仅 1.52ms。
这项实证研究支持在 MCP 工具发现和调用环节设置独立授权执行点，为凭证使用过程中的工具访问控制提供基础设施层的实现依据。
P26 Verifiably Safe Tool Use
标题/载体：Towards Verifiably Safe Tool Use for LLM Agents，Doshi 等（Georgia Tech / CMU / HKUST / NC State），ICSE-NIER 2026（愿景短文，5 页）。其 PDF 页眉中的年份与 DOI 为模板占位信息，引用需依据 ACM Reference Format 块核对。  CCF A。
Verifiably Safe Tool Use 将独立安全策略与形式化验证引入 agent 工具使用过程。它主张从"概率性防护栏"转向"可验证保证"：模型封装类防护（GuardAgent、LLM-judge、模式过滤）只能提升可靠性不能保证安全，而传统信息流控制标签依赖昂贵且不可靠的人工标注。研究路线分为三个步骤。借航空/汽车安全工程的 STPA 方法识别直接/间接利益相关者并推导安全需求，形式化为时序逻辑流约束；提出带结构化标签的能力增强 MCP 框架，能力（read-only/write/execute）、数据保密级（public/private）、信任级（trusted/untrusted），配四级执行结构（自动阻断/强制必做/安全流免确认/高风险需用户确认）；用 Alloy 对增强版 MCP 形式建模，穷举有界执行轨迹验证"私密数据到达未授权工具"等危险谓词不可能发生。
愿景阶段，初步结果仅验证可行性，未来才做外部策略引擎与真实部署。
该研究把工具能力、数据保密性和信任级别纳入形式化约束，能够支持本课题建立可验证的工具使用模型。其未来工作还涉及过度委托，适合继续追踪。
P29 AgentBound
标题/载体：AgentBound: Securing Execution Boundaries of AI Agents，Bühler 等（圣加仑大学），FSE 2026（PACMSE Vol.3, FSE096）。 CCF A
AgentBound 针对 MCP 服务器在主机上"隐式完全信任"运行、继承 agent 的操作系统权限的问题，给出首个面向 MCP 服务器的访问控制框架：AgentManifest，借鉴 Android 权限模型，从 19 篇文献与 16 个用例提炼出 16 项平台无关的 MCP 服务器能力词汇（文件系统读写删、环境变量、进程执行、网络客户端/服务端、外设等五大类）；AgentBox，用 Docker 容器沙箱封装 MCP 服务器（零默认权限），mounts 限定文件系统、iptables 出站白名单限定网络，运行时把通用能力细化为具体权限（目录、URL）经用户同意授予；另有两阶段 LLM 流水线自动从代码生成 manifest。
评估中，296 个热门 MCP 服务器数据集，96 份自动生成 manifest 提交开发者评审 80.9% 判正确、能力词汇覆盖真实需求 100%；48 台服务器人工细粒度对比准确率 96.5%；运行时开销平均 0.6ms，仅容器启动多花约 150–400ms。
AgentBound 展示了 MCP 服务器从权限声明、用户同意到沙箱执行的完整过程。本系统可以据此明确 API Key、环境变量和本地文件等凭证资源的访问需求。
P30 Tracked Capabilities
标题/载体：Securing Agents With Tracked Capabilities，Odersky 等（EPFL LAMP 实验室，Scala 语言创始团队），CAIS 2026（ACM Conference on AI and Agentic Systems，pp. 812–838），实现开源（TACIT）。该会议主要关注 AI 智能体、复合 AI 系统、系统优化、安全性与工程化。
Tracked Capabilities 将 agent 置于基于编程语言的"安全挽具"中：agent 通过生成表达操作意图的 Scala 3 代码发起工具使用，由捕获检查（capture checking）在静态类型中追踪能力，local purity 保证机密数据（包在 Classified[T] 容器中）只能经纯函数变换、永不泄露；能力经作用域块授予并在块结束时自动失效，生命周期控制做进了类型系统；配合"不可信云端 LLM + 可信本地 LLM"双模型架构与双重输出通道。实现为开源 MCP 服务器 TACIT，兼容 OpenCode、Claude Code 等标准 MCP 客户端。
作者报告的实验结果为：AgentDojo 注入攻击下 classified 模式对 Claude Sonnet 4.6 与 MiniMax M2.5 均 100% 拦截、效用保持 99.2%/90.9%；τ²-bench 与 SWE-Bench Lite 上性能与标准工具调用持平甚至略优，编译重试率仅 0.32%–2.93%。附录与 CaMeL 逐点对比：静态追踪代码上的能力 与 运行时追踪数据上的污点。
这一方法把能力的授予、传递、捕获和作用域到期纳入静态类型检查，为凭证生命周期管理提供了语言层的实现路线。
P31 过度特权工具选择
标题/载体：When Lower Privileges Suffice: Investigating Over-Privileged Tool Selection in LLM Agents，Yang 等（中科院信工所 / BAAI / 港中文 / 北大），EMNLP 2026 Findings（pp. 43846–43867）。CCF B
过度特权工具选择 研究 agent 的"过度特权工具选择"：存在足够低特权替代工具时，仍直接选高特权工具（激进选择），或在短暂、与特权无关的失败后立即升级特权（过早升级）。构建 ToolPrivBench：8 个应用领域 × 5 类风险（权限提升、范围扩张、时间持久性、安全绕过、数据过度暴露），每场景 3 低特权 + 3 高特权工具且全部能独立完成任务；双 LLM 评审加人工专家审计。11 个主流模型评测：Qwen3-8B 过度特权使用率高达 64.9%，Claude 4.6 Sonnet 仅 2.6%；瞬时失败显著放大升级；安全对齐与三种编码脚手架都不能消除该行为。
缓解：特权感知后训练（SFT + GRPO，奖励"标准工具优先完成、升级仅作最后手段"），把三个 Qwen 变体的过度特权使用率从 39.7%–70.0% 降到 18.9%–38.4%，必要高特权场景保留 90%+，通用能力基本无损。
该基准可用于评价 agent 的最小权限工具选择。其训练方法也说明，授权层的强制控制可以与 agent 侧的行为改进共同开展。
P32 AgentSpec
标题/载体：AgentSpec: Customizable Runtime Enforcement for Safe and Reliable LLM Agents，Wang 等（新加坡管理大学），ICSE 2026，代码开源。 CCF A
AgentSpec 提出运行时强制的领域特定语言（DSL）：规则由触发（state_change/before_action/agent_finish 及领域事件）—检查（谓词条件）—强制（stop/user_inspection/invoke_action/llm_self_examine）三段组成，论文给出规则-轨迹的形式化语义。实现基于 LangChain（拦截行动决策点，行动前评估约束），规则用 ANTLR 解析，可扩展至 AutoGen 与自动驾驶栈。作者报告，阻止 25 类风险中 24 类的 >90% 不安全代码执行，10 类具身危险动作全部归零，自动驾驶场景 100% 合规；开销毫秒级。
LLM 自动生成规则实验（OpenAI o1）精确率 95.6%、召回 71.0%，拦截 87.3% 风险代码。
AgentSpec 提供可执行的运行时规则及轨迹语义，可以作为权限边界和凭证使用策略的落地组件。P06 的比较基线也包含该工作。
P39 ProbGuard
标题/载体：ProbGuard: Proactive Runtime Monitoring for LLM Agent Safety via Probabilistic Prediction，Wang 等（新加坡管理大学 / 西安交大），ASE 2026。CCF A
ProbGuard 将运行时监控从"违规已发生才被动响应"推进到主动预测：离线对执行轨迹做谓词抽象并学习离散时间马尔可夫链（DTMC）刻画行为动态，用 PAC 分析刻画学习模型与真实系统的偏差；运行时用 PRISM 做 PCTL 模型检测，计算"从当前状态出发安全性质保持"的概率，低于阈值即向 agent 提示风险上下文（advisory 式干预，不覆盖控制流）。自动驾驶域最早可提前 15.8–38.7 秒预警，阈值 0.3 时 4 条法规 0% 误报、100% 检出，开销约 100ms；具身任务中 re-prompt 干预使不安全行为降 65.4%、保留 80.4% 完成率。
与 AgentSpec、REDriver 对比：概率分数可解释且预警更早。
ProbGuard 为危险或越权操作发生前的风险预警提供了概率模型与 PAC 分析依据。它与 P32 出自同一团队，可结合比较主动预测和运行时强制的适用条件。
MCP 生态威胁与实证测量
运行时机制的必要性还需要真实攻击证据支持。以下两项工作把 MCP 服务和工具元数据纳入实验，说明有效凭证与合法工具仍可能被组合为超出用户授权的行为。
P36 GrantBox
标题/载体：实际标题为 Evaluating Privilege Usage of Agents with Real-World Tools，Zhang 等（华东师大 / 新疆大学 / 清华），FSE 2026 Companion（5 页）。GrantBox 是文中系统名。 CCF A
GrantBox 针对现有 agent 安全基准只用预编码工具/模拟环境、无法评估真实特权使用的问题，构建基于真实 MCP 服务的特权使用评估沙箱：10 个真实 MCP server、122 个特权敏感服务（云运维、数据库、邮件、文件系统），容器隔离 + 请求记录 + 监控；LLM 驱动生成 100 条良性请求与 90 个特权劫持用例（基础设施破坏、数据外泄、数据销毁、工作区篡改、资源耗尽五类）。
对 GPT-5、Gemini-3 Flash、Qwen3-Max、DeepSeek-v3 在 ReAct 与 Plan-and-Execute 模式各测 500 次：ReAct 平均攻击成功率 90.6%、Plan-and-Execute 79.1%，八种设置总平均 84.8%，LLM 只有基础安全意识，能够阻断部分直接攻击，面对精心构造的特权劫持仍存在明显风险。
GrantBox 直接测量 agent 持有真实凭证时的特权滥用后果。其真实服务、容器隔离和攻击用例设计，可以作为本课题端到端实验的方法参照。
P38 MCPTox
标题/载体：MCPTox: A Benchmark for Tool Poisoning Attack on Real-World MCP Servers，Wang 等（中科大 / 北航），AAAI 2026（pp. 35811–35819）。 CCF A
MCPTox 考察 MCP 工具描述中的恶意指令对后续调用的影响。攻击者可以借助被投毒的描述信息，诱导 agent 调用其他合法工具执行超出用户授权的操作；投毒工具自身可以始终处于未调用状态。该工作提出首个真实世界 MCP 工具投毒攻击基准：覆盖 45 个真实在线 MCP 服务器的 353 个真实认证工具，按三种攻击范式（显式触发-函数劫持、隐式触发-函数劫持、隐式触发-参数篡改）半自动生成并人工校验出 1348 个恶意用例；关键设计约束是恶意动作必须由服务器上已有的合法工具完成、被投毒工具本身从不执行，恶意指令藏在工具描述/元数据里，不执行即生效。
对 20 个主流模型配置评测：平均攻击成功率 36.6%，最高 72.8%，存在"反向缩放"（模型越强越易受攻击，开推理使 Qwen3-32b 上升 27.8 个百分点）；拒绝率最高的 Claude-3.7-Sonnet 也低于 3%，现有内容安全对齐基本失效。另证把 InjecAgent 的载荷改成工具描述投毒后成功率近 0%，说明该攻击面需要专门基准。
MCPTox 将工具元数据纳入威胁模型，并提供工具调用前授权校验的可复用攻击基准。评价时需要同时检查工具发现过程与实际调用过程。
OAuth 账号绑定与动态生态建模
进一步沿凭据取得过程向前检查，平台需要持续维护用户、应用与授权会话之间的绑定。跨应用攻击测量与动态账号生态模型分别提供协议层和状态演化层的分析依据。
P20 Universal Cross-app Attacks
标题/载体：Universal Cross-app Attacks: Exploiting and Securing OAuth 2.0 in Integration Platforms，Luo 等（香港中文大学 / Samsung Research America），USENIX Security 2025（pp. 3221–3238，Artifact Evaluated）。与 P07 OASIS 出自同一研究组，是其在集成平台上的前作。  CCF A
在平台同时管理多个第三方应用的 OAuth 授权时，授权发起、重定向、授权码兑换和令牌保存需要持续绑定到同一应用及用户授权会话。该工作研究集成平台（工作流自动化如 Zapier/IFTTT、虚拟助手如 Alexa/Google Assistant、智能家居）中 OAuth 的角色反转：平台自身充当统一 OAuth client，而授权服务器反而由开放市场里不受信的第三方应用运营；平台在多应用架构下无法可靠追踪"活跃应用"，由此产生两类平台级跨应用攻击：COAT（跨应用 OAuth 账号接管，恶意应用让受害者的授权重定向到良性应用的授权服务器，却在自己的令牌端点收到对方的授权码，进而接管受害者账号）与 CORF（跨应用 OAuth 请求伪造），且都有"单击"变体（一条 crafted 链接即可，可借 prompt=none 绕过授权确认）。
自研黑盒扫描器 COVScan 实测 18 个平台：16 个存在跨应用漏洞，含 Microsoft Power Automate（CVE-2023-36019，CVSS 9.6，单击可接管任意 Microsoft 365 账户）、Google Assistant（5 亿月活）等。修复方案是应用级绑定（全局唯一 per-app ID 嵌入 state + 专用 redirect_uri 双重确认），并指出 PKCE 并非有效防御。负责任披露 9 家修复、赏金 3.5 万美元，推动 OAuth 2.1 规范讨论。
该工作揭示了 agent 类平台代用户完成 OAuth 委托时的跨应用绑定风险。它与 P07 构成同一研究团队在集成平台和连接器生态中的两组测量依据。
P08 RAG
标题/载体：Verifying Account Ecosystems With Graph Transformations，Murphy & Radomirović（Surrey / Heriot-Watt），IEEE EuroS&P 2026。RAG（Resource Access Graph）是文中形式模型名。 CCF C
RAG 研究静态账号生态分析无法建模"生态随时间演化"的问题：将账号、设备、凭据以及它们之间的访问关系构建成一张能够随时间变化的图，再通过形式化模型检测，自动找到可能导致账号接管、权限失控或用户失去访问能力的操作序列。生态演化是图重写转移系统，用户行为与攻击者规则统一为图变换规则，安全性质用 CTL 表达（资源完整性、可用性），用图重写模型检测器 GROOVE 自动验证。运行实例是 Apple 账号生态与 iOS 的失窃设备保护（SDP）：无 SDP 时自动重发现已知账号接管攻击（完整性与可用性均被违反）；开 SDP 后可用性恢复但完整性仍违反；进而提出"从受信设备访问 Apple 账号强制二因素"的改进并在模型中验证通过。
RAG 将账号、凭据及访问依赖的动态变化纳入自动模型检测，可为本课题验证凭证生命周期策略提供完整的方法参照。
撤销与凭证基础设施
在访问与状态变化得到描述后，撤销还面临规模和隐私约束。PRC 从匿名凭证基础设施出发，给出了大规模状态查询与非撤销证明的实现方法。
P24 PRC
标题/载体：实际标题为 Do You Need a Receipt? Anonymous Credential Revocation at Continental Scale via Private Record Certification，EdalatNejad 等（达姆施塔特工业大学），USENIX Security 2026（正式发表，Artifact Evaluated）。文件简称取自其核心原语 PRC。  CCF A
PRC 关注匿名凭证系统的"撤销"难题：现有累加器、黑名单、epoch 型方案普遍开销大、撤销生效延迟、需向全体用户推送更新。论文提出新密码学原语 Private Record Certification（PRC）：客户端从 n 个撤销机构秘密共享维护的状态数据库中，不泄露所查索引地取得记录的签名证书（非撤销令牌），再以零知识证明向验证者出示。技术上把多服务器 PIR 与 GMW 安全多方计算结合，关键贡献是布尔秘密分享到 One-Hot 编码的转换 Bin2OHE（乘法深度 O(lg N)），配合 Pedersen 同态承诺与门限签名，使客户端通信只取决于索引位数。
Rust 原型在 10 亿凭证规模下实现亚秒级（<400ms）实时撤销，单服务器处理百万请求运维成本约 2.5 美元；较 ALLOSAUR 快逾 20,000 倍，较 PIR 基线节省 900–2700 倍服务器计算。
PRC 将凭证撤销扩展到大规模、隐私保护的状态校验基础设施，可用于分析 agent 持有匿名凭证或可验证凭证时的撤销与出示成本。
凭证数据的来源证明与隐私保护
除访问是否有效之外，系统还可能需要证明凭证取得的数据来源，并限制证明过程中披露的信息。DECO 提供了这一方向的基础，相关后续工作及多方策略求值材料同时列入总览。
P14 DECO
标题/载体：DECO: Liberating Web Data Using Decentralized Oracles for TLS，Zhang 等（Cornell Tech），arXiv 2020 扩展版（DECO 原文发表于 CCS 2020）。 CCF A
DECO 研究"用户无法向第三方证明经 TLS 取回的网页数据确实来自某网站"的问题，且不依赖可信硬件（TEE）或服务器端改造。协议三方为证明者、验证者与 TLS 服务器：三方握手中对 MAC 密钥做加性秘密共享（证明者提交会话密文后才取得验证者份额，会话承诺不可伪造）；查询用定制 2PC-HMAC；证明阶段支持选择性打开/隐去子串；形式化为理想功能并给出 UC 安全证明。应用包括保密金融合约、把遗留凭证转匿名凭证（年龄证明）等，端到端约十几秒。
DECO 支持把 Web 账号中已有的数据转化为可验证声明，为凭证来源证明和隐私化出示提供基础。其后续实用化路线可结合总览中的 P15 继续比较。
预印本及其他相关研究
在上述研究基础上，预印本和其他探索性工作进一步把任务意图、动态权限、在途效果与撤销后状态纳入分析。这部分材料与本课题的研究对象更为接近，比较时需要保留版本、实现成熟度及验证条件。
任务意图与动态权限管理
这一组工作围绕任务要求与具体权限之间的关系展开。SUDP 约束秘密使用边界，PAuth、ASTRA、CASA 和意图凭证逐步细化任务匹配粒度，弹性最小特权与 Progent 则进一步处理权限的动态调整。
P01 SUDP
标题/载体：SUDP: Secret-Use Delegation Protocol for Agentic Systems，Yu 等（帝国理工/牛津/斯坦福），arXiv 预印本（2026-10，v4）。
SUDP 针对"授权即暴露"：现有部分 agent 运行时在执行动作前需要把可复用密钥（API key、OAuth token）放进运行时，一次瞬时提示注入就升级为持久账号失陷。论文把这件事形式化为 Agent Secret Use（ASU）问题，定义了 7 条安全性质（授权完整性 + 秘密保密性），并提出 SUDP 协议：请求方提议一个规范化操作，用户在一次认证器仪式里对这一具体操作签发一次性 grant，托管方（本地代理、HSM/TEE 等）验证 grant 后代为执行，可复用权限从不进入请求方边界。主定理证明 7 条性质中 6 条在标准密码假设下原生成立，参考实现每次受代理调用仅增加约 0.76ms 开销。
SUDP 是凭证交付与执行边界的直接对照。它把授权具体化为一次性、操作绑定的许可，可用于分析长期秘密保管与单次授权执行之间的关系。
P02 PAuth
标题/载体：Beyond OAuth: Task-Scoped Authorization for AI Agents via Natural Language Slices，Sharma 等（UW/俄亥俄州立/微软研究院），arXiv 预印本（2026-08）。文件简称 PAuth 取自其机制名（Precise Task-Scoped Implicit Authorization）。
PAuth 指出 OAuth 的结构性错配：scope 只管"操作符"（如转账权限）不管"操作"（操作符+操作数），而"转账 Citi 余额的四分之一"这类操作数依赖运行时计算，任何静态 scope 都表达不了，agent 因此被结构性过度授权。PAuth 让用户签名的自然语言任务本身成为授权依据：每个 MCP 服务器用 LLM 按受限语法生成代码，再经确定性切片编译得到逐工具授权规则；运行时用服务器签名的 envelope 把具体操作数绑定到任务蕴含的计算，不一致就升级为用户弹窗。在自建基准 AuthBench 上，100 个良性任务全部放行、634 个对抗调用全部阻断。
PAuth 为任务要求与具体操作参数之间的绑定提供直接参照，其 AuthBench 也可用于评价任务级授权与最小充分委托。
P40 ASTRA
标题/载体：实际标题为 Delegated Authorization for Agents Constrained to Semantic Task-to-Scope Matching，El Helou 等（Cisco Systems 瑞士），arXiv 预印本（2025-10）。ASTRA 是文中基准数据集名。
ASTRA 研究 OAuth 委托授权流"只认显式 scope 请求、不感知自然语言任务意图"的失配：agent 可在令牌中夹带超出任务范围的写权限。其实现机制为：授权服务器侧加入可信代理转发全部委托授权流并附加原始 prompt 元数据，AS 内置可信 LLM 语义匹配模块，把任务描述与所请求工具/资源做语义比对，只发放与任务最小 scope 对应、任务完成即自动回收的即时最小权限令牌，并将授权基础设施分割为轻量虚拟化实例以收敛爆炸半径。
评估中，自建 ASTRA 数据集管线（12 个企业级 MCP Server）+ Toucan 公开数据集；单工具任务 LLM 判断准确率 0.84–0.96 优于嵌入相似度（0.77–0.86），3 工具任务召回降至 0.57，过度放行与误拒绝的权衡说明语义匹配必要但有局限。数据集开源。
ASTRA 将任务语义匹配放在 OAuth 授权服务器侧，通过最小 scope 签发和任务结束回收约束凭证生命周期，可与 P02 的逐工具规则路线比较。
P41 CASA
标题/载体：实际标题为 Hybrid Inspection and Task-Based Access Control in Zero-Trust Agentic AI，El Helou 等（Cisco，与 P40 同组），arXiv 预印本（2026-05）。CASA 是文中框架名（Continuous Agent Semantic Authorization）。
它面向多轮、多 agent 协作场景（工具定义篡改、调用伪造、参数与返回数据篡改、诱导越范围调用），在零信任拦截层部署两类互补控制：五项确定性检查（工具定义完整性、请求授权验证、动作对齐、参数完整性、数据保真度）用二元逻辑捕获结构性违规；语义控制层把 P40 的单任务匹配分解为"会话任务抽取 + 任务-工具匹配"两阶段，逐工具做二元判定支撑 TBAC（基于任务的访问控制）。
数据：扩展 ASTRA 数据集生成 3,524 条会话-工具测试样本与含恶意 agent 的多智能体测试集 3,242 条；GPT-5.4/5.2、Claude Sonnet/Opus 4.6 四模型评测单轮 F1 0.93–0.98、多轮 0.90–0.98，多智能体场景最难（FPR 升至 0.15–0.20）。附录案例表明恶意系统提示注入可绕过全部五项确定性检查、必须依赖语义层。
CASA 把确定性结构检查与语义任务匹配结合，并扩展到多轮及多 agent 场景。它与 P02、P45 共同构成本课题任务级授权的重要比较集合。
P42 弹性最小特权
标题/载体：Towards Elastic Least Privilege for Agent Planning，Parkinson 等（曼彻斯特城市大学 / 曼彻斯特大学），arXiv 预印本（2026-10-29，BlueSky 立场/议程论文，无实现）。
弹性最小特权 针对"agent 所需权限随任务与执行动态变化、静态宽授权造成过度赋权"（447,000 个 GitHub CI 工作流 99.8% 过度赋权；GitHub MCP 编码代理拿 repo-scope 令牌即获得约 40 个工具且 16 个可全仓写入），提出弹性最小特权概念模型：agent 静止时只持基线 B(a)，可在所有者定义的包络 V(a) 内申请提升；每次扩展产生随功率与重复请求超可加增长的成本率，受组织级天花板约束（含"不可信输入、敏感数据、外传通道不可同时持有"类不变量，会话属性有粘性）；提升一律以租约授予，到期/主动释放/预算耗尽即回弹到基线；跨任务经 grant 日志审计"可塑性"重定基线。
形式化给出四条由签发方强制、与 planner 行为无关的保证：天花板、有界提升暴露、回收、独立性。
弹性最小特权模型为基线、权限包络、租约、预算和回收提供统一描述，可用于组织本课题的动态权限管理。其机制价值仍需结合后续实现与实证检验。
P43 Progent
标题/载体：Progent: Securing AI Agents with Privilege Control，Shi 等（UC Berkeley / UCSB / 新加坡国立大学），arXiv 预印本（2025-04 首版，2026-05 v3）。
Progent 提出工具调用级权限控制框架：权限策略由针对工具名与参数的符号化规则（allow/forbid + fallback 动作）组成，由 LLM 从用户任务自动生成初始策略并随执行动态更新；每次更新经确定性 SMT 求解器（Z3）判定为"收窄"（自动应用）或"扩张"（需显式批准），从而保证单调约束性质，无显式批准时 agent 的有效动作空间只能缩小，对抗性输入也无法静默提权。
AgentDojo 与 ASB 基准上攻击成功率从 39.9%→约 1.0%、70.3%→3.9%，效用基本不变；仅约 6% 的策略更新需人工批准；已集成 LangChain、OpenAI Agents SDK、OpenHands 与 AutoGen；三类自适应攻击下成功率仅升至 0.5–1.4%。
Progent 通过策略生成、SMT 判定与显式批准管理权限更新，是动态授予与最小权限收敛的直接比较对象，也是 P06 的基线之一。
P45 意图凭证
标题/载体：实际标题为 Intent-Governed Tool Authorization for AI Agents，Zhu & Wang（Accentrust / Georgia Tech / UIUC，与 P03 同一作者对），arXiv 预印本（2026-09）。
意图凭证 指出凭证中心授权只回答"应用被允许调用什么"，而 agent 工具使用还须回答"该调用是否被用户当前请求正当化"，意图-工具失配。其实现机制为：意图凭证（intent certificate）授权层，服务器端从可信用户请求派生短生命周期策略断言（请求哈希、主体/租户/会话绑定、意图类别、资源与效果边界、置信度、过期与撤销状态），据此单调收窄静态工具清单，经一致性门检查调用-载荷-效果一致，按置信度路由到拒绝/澄清/草拟/预检/确认/执行六种结果（fail-closed：低置信度、冲突意图、高风险均不得直接执行）。形式化给出清单单调性、静态策略不扩张、高风险 fail-closed、请求封闭合同四个命题。
评估中，复合暴露指标从 1.0000 降至 0、零起不安全执行完成；但严格良性完成率仅 0/108，凭证的精确资源/效果边界归一化是主要剩余瓶颈。
意图凭证与本课题的请求级最小权限管理紧密相关。它与 P03 出自同一作者团队，两项工作分别覆盖请求级签发和授权生命周期终止，适合结合分析。
运行时状态与效果闭环
任务级批准需要延续到实际效果落地。以下研究分别处理重试恢复、授权修订、数据传播和累积风险，说明逐次准入还需与持续状态及执行结果关联。
P05 AID-Guard
标题/载体：AID-Guard: Stateful Authorization for Delegated Agent Effects，佟英哲等（信息工程大学），arXiv 预印本（2026-08）。
AID-Guard 针对"授权-效果鸿沟"：授权检查止步于准入，而之后请求可被篡改、响应可能丢失、重试与恢复可能让一次批准产生第二个效果。AID-Guard 是从批准到效果落地的有状态闭环：provider 提交处重验证与批准完全一致的请求和当前状态；结果歧义时保留原 reservation、持续保留原批准的唯一性；只有终态结果或"经认证的无效果证书"才能释放配额或转移给唯一后继。实验里 13 次活体变异全部拦截、AgentDojo 保护臂 0 个不安全效果，代价是保护路径中位延迟约 2.35 倍。作者将重试与恢复视为授权权威转移的一部分，要求恢复过程持续遵守原有批准与效果约束。
AID-Guard 关注准入之后至效果落地之前的授权状态，能够支持本系统处理重试、丢响应、配额预留和唯一后继等执行问题。
P06 ACG
标题/载体：Authorization Closure Graph: Minimal Repair for LLM Agents with Evolving User Instructions，Wang 等（同济大学），arXiv 预印本（2026-09）。
用户修改任务要求后，已有授权需要随之选择性更新。ACG 针对逐调用检查和整单重新授权之间的更新粒度问题开展研究。ACG 把授权状态做成版本化有向无环图：节点分 Authority（用户授权）/ Evidence（权威环境证据）/ Derived（派生后果）三类，用 COMMIT、REVOKE、REVISE 等六种认证操作更新；检查候选动作时输出 AUTHORIZE / BLOCK / MINIMAL REPAIR 三种决策，最后一种会返回"依赖最小修复集"，只重授权真正受影响的部分；执行前对记录的节点版本做重验证，防止用过期授权。在 τ²-bench 两个域、三个模型上动作安全性全部最高，不安全写任务从 75 降到 8。
ACG 为授权修订提供了版本化、选择性失效和最小修复机制，可作为本课题处理用户指令变化及旧授权重验证的运行时对照。
P13 CaMeL
标题/载体：Defeating Prompt Injections by Design，Debenedetti 等（Google DeepMind & ETH Zurich），arXiv 2025（2025-06 v2）；系统名 CaMeL，代码开源。
CaMeL 针对提示注入里最棘手的一类：攻击者可以通过污染数据流、篡改工具调用参数造成数据外泄，控制流在此过程中仍可能保持原有结构。CaMeL 在模型外建立保护层：特权 LLM 只看用户查询、生成计划代码；隔离 LLM 无工具权限、只负责把非结构化数据解析成结构化输出；每个值带能力标签（来源 provenance + 允许读者）；自定义解释器维护数据流依赖并在每次工具调用前强制执行策略。论文把威胁形式化为 PI-SEC 安全博弈，CaMeL 按构造满足。AgentDojo 上以可证明安全性解决 77% 任务（未防御 84%），949 个攻击下多数模型成功攻击数降为 0，代价约 2.7–2.8 倍 token。
作者坦承钓鱼展示、侧信道等仍不可防。
CaMeL 的能力标签与信息流强制为凭证和敏感数据的受控流动提供系统参照。比较时需要记录其任务完成率、攻击覆盖及额外 token 成本。
P44 Irreversibility Budget
标题/载体：实际标题为 The Irreversibility Budget: Fleet-Level Risk Accounting and Admission Control for Agent Operating Systems，Mohammadi & Bindschaedler（MPI-SWS），Agentic OS Workshop 2026（2026-09-29，布拉格）+ arXiv 预印本。
Irreversibility Budget 指出 agent 舰队的不可逆效应（转账、部署代码、删数据、泄露信息）只有逐笔检查、没有跨 agent/工作流/租户的累积核算：个体均被授权的动作在共享触发（供应商涨价警报、提示注入）下会集体突破主体风险限额（模拟中最多超支租户限额 48 倍）。其实现机制为：把不可逆性视为一等资源，可信运行时在每个主体的提交边界维护"剩余风险价值"累积账户，按各效应的剩余损失定价收费，边际收费会超出授权预算即拒绝该效应；配套风险类型化效应声明（工具规范声明效应类别、暴露上界、可逆/补偿路径）、层级账本与预留-确认-取消（防双花）、基于风险压力的准入控制。
控制模拟与真实 trace（τ-bench 38,452 条轨迹）表明预算每次运行都守住限额、单笔局部闸门超支 2.4–48 倍；账本开销约 2.6 微秒/预留。
不可逆性预算将逐次授权扩展到跨 agent、工作流和租户的累积核算。其预算、预留和冻结机制可与 P05 的效果闭环及 P11 的代价有界验证结合分析。
撤销后状态与凭证托管
当用户撤回授权时，系统还要处理后代能力和已经传播的状态。根域静止、残余授权状态、签名心跳与凭证托管分别从完成条件、信息需求、离线校验和秘密保管提供分析依据。
P03 Root-Scoped Quiescence
标题/载体：Authorization Revocation for Long-Running AI Agents: Root-Scoped Quiescence under Delegation and Asynchronous Execution，Zhu & Wang（Accentrust / Georgia Tech / UIUC），arXiv 预印本（2026-09）。
Root-Scoped Quiescence 研究长期运行 agent 的"停不下来"问题：单点取消（MCP 取消、OAuth 令牌吊销、进程退出）各自只关掉一个本地对象，已入队消息、衍生凭证、cron/webhook 触发器、provider 侧预留操作仍能在已被退役的授权根下产生效果；而盲目级联吊销又会误杀独立授权的共享工作。论文定义"根域授权静止"，给出协议：持久 root-epoch 原子冻结签发；各 provider 装本地 fence，栅栏后的旧提交一律拒绝；跨根存续必须经 rebind 到独立见证（防"根洗白"）；用 channel-token 收支核对跨 provider 传递，最终输出 Quiescent / Not-Quiescent / Indeterminate 三值判定（超时或缺证据绝不升级为成功）。
全文 3 引理 6 定理共 9 条结果，17 个晚效应用例全部通过。
根域授权静止为撤回授权后的残余能力提供可验证的收尾协议，可直接支持本课题区分令牌处置、后代终止和在途效果处理。
P04 ResidualAuth
标题/载体：ResidualAuth: What Authorization State Must Agent Systems Preserve Under Revocable Delegation?，Choi 等（首尔国立大学），arXiv 预印本（2026-09）。
它回答"可撤销委托下系统必须保存什么授权状态"。核心观察：两条授权历史可以有完全相同的当前权限，但同一次撤销之后，一个该拦、一个该放，差别在授权来源。论文用 Myhill–Nerode 等价定义"残余授权状态"，证明精确在线监控器所需的状态数与比特数（冗余-记忆律：无撤销 Θ(rN) 比特、级联撤销 Θ(rN²)），以及信息预算下的决策错误率下界。作者的实验进一步比较了授权信息的可获得性。LLM 仅凭 256-token 摘要几乎做不对配对判断（0–2/16），但给它一个可信的"当前授权查询"就升到 15–16/16。这一结果表明，可信授权信息的可获得性会直接影响判断结果。
ResidualAuth 从信息论角度刻画撤销后必须持续保留的可信授权信息，为本课题确定状态记录、授权来源和补证需求提供理论依据。
P17 HBHC
标题/载体：Heartbeat-Bound Hierarchical Credentials: Cryptographic Revocation for AI Agent Swarms，Deochake（SentinelOne），arXiv 预印本（2026-05）。
HBHC 研究"僵尸 agent"问题：父 agent 被关停后，子 agent 凭现有令牌还能继续执行特权操作几分钟到几小时，因为 OAuth 内省、OCSP、W3C Status List 这些撤销机制都要在线连接中心权威。HBHC 把凭证有效性绑定到父 agent 的周期性签名心跳：子 agent 在每次认证中纳入新鲜心跳，验证方只用缓存公钥和本地时钟就能离线校验新鲜度，撤销窗口有确定上界；结合 BIP-32 分层密钥派生，给出形式化证明与 OAuth 2.0 / W3C VC 集成方案。作者报告的实验结果为：僵尸窗口较 OAuth 缩短 90 倍（约 40 秒），认证 0.26ms，工具调用端到端开销仅 0.71%。
HBHC 提供基于签名心跳的离线新鲜度验证，可用于比较在线撤销与离线校验的传播条件、认证成本和确定性终止窗口。
P18 Vault 中介执行边界
标题/载体：API Secrets Should Never Become Tokens in the LLM's Vocabulary: A Threat Analysis of API Credential Handling in LLM Agent Systems and an Empirical Evaluation of a Vault-Mediated Execution Boundary，Kenney 等（Corvic AI），arXiv 预印本（2026-09，7 页）。文件简称取自副标题概念。
Vault 中介执行边界 指出工具型 agent 把"凭证卫生"从存储问题变成了执行安全问题：API 密钥会进入对话历史、日志、记忆/向量库、生成代码和错误载荷这些"复制点"，提示注入可把被动泄露转化为未授权操作。论文四项贡献：形式化五阶段暴露链（引入→传播→触发→执行→持久化）；综合 2024 年 Hugging Face 密钥事件、GitGuardian 2377 万硬编码密钥测量与 OWASP/NIST 指南三类证据；描述 vault 中介执行边界，agent 只拿连接器标识符，可信边界按配置注入认证头，凭证保存在可信执行边界内；16 个黑盒探针验证不可观测性、源绑定、集中生命周期等性质，并报告阴性作者报告，集中托管不等于配置正确。
Vault 中介执行边界从保管、注入与轮换环节补充凭证生命周期分析。其阴性结果也要求本系统分别检查集中托管能力与配置正确性。
OAuth 与 MCP 的协议及生态威胁
最后回到接入协议与 MCP 生态，以下工作补充账号错链、客户端认证和工具生命周期中的攻击面，使本课题的威胁模型覆盖凭据取得、使用及维护过程。
P07 OASIS
标题/载体：Demystifying the (In)Security of OAuth-based Account Linking in Connector Ecosystems，Luo 等（香港中文大学 / Samsung Research America），2026（文内未标注正式出处，USENIX 风格稿）。OASIS 是文中扫描工具名；与 P20 出自同一研究组，是其在 connector/Agentic AI 生态上的后作。
OASIS 首次系统研究 connector 生态（连接器应用、集成平台、Agentic AI 基础设施）中基于 OAuth 的账号链接，作者称之为"二阶 OAuth"，是 RFC 6749 未建模的维度。核心发现：当应用业务逻辑与 OAuth client 解耦（跨 origin 回调、或外包给 OAuth-as-a-Service 的中央令牌保管）时，回调落在"未认证空间"，会话可被固定，由此提出新攻击类 COSF（跨用户 OAuth 会话固定）：受害者点一下攻击者的链接、静默授权后，自己的 connector 账号被绑到攻击者应用账号上，形成一键账号接管；OaaS 多租户下还有跨租户 client_id 混淆等 confused-deputy 攻击。
实测 46 家厂商中 42 家有错链风险（含 Slack、Alexa、n8n、IFTTT、Perplexity、Manus 等）；负责任披露获 20 家确认、15+ 家修复、赏金 35,850 美元，作者撰写的 IETF 草案已被 OAuth 工作组采纳。
OASIS 为 agent 和连接器获取凭证时的账号错链风险提供实测依据，其用户、租户与连接器绑定要求可进入本系统的接入检查。
P33 Audience Injection
标题/载体：Audience Injection Attacks: A New Class of Attacks on Web-Based Authorization and Authentication Standards，Hosseyni 等（斯图加特大学信息安全研究所），文内未标注出处（披露时间线 2024-09 至 2025，与 OIDF/IETF 协同披露中）。
Audience Injection 提出受众注入攻击，针对签名式客户端认证的一类新漏洞，波及作者所称 OMAA 协议族：OAuth 2.0、OIDC、FAPI 1.0/2.0 高安全 profile、CIBA、设备授权，以及 PAR、令牌吊销/内省、OpenID Federation 等十余项标准与扩展。核心弱点是 Private Key JWT 等 client assertion 的 aud 声明：标准允许（且常推荐）取 token endpoint URL 作受众值，而客户端无法外部校验其真伪。
两阶段攻击：恶意授权服务器伪造配置文档把自己的端点列为 token endpoint，诱使诚实客户端发出 aud 指向诚实 AS 的有效 client assertion；攻击者重放该断言冒充客户端向诚实 AS 换取受害者资源令牌，同时影响授权与认证安全目标，FAPI 2.0 的 PKCE 也无法阻止。负责任披露推动十多项标准及 Microsoft、Okta、Authlete 等大量实现协调修复：将 aud 强制限定为 AS issuer identifier。
受众注入攻击补充了客户端认证和签发阶段的协议威胁模型。其受众绑定规则可用于检查 agent 使用的 OAuth 与 OIDC 凭证流程。
P34 MCP Landscape
标题/载体：实际标题为 Model Context Protocol (MCP): Landscape, Security Threats, and Future Research Directions，Hou 等（华中科技大学），ACM 格式排版预印本（2025-10，DOI 占位，自标 vision paper，在投状态）。
它是 MCP 生态的首个系统性安全分析：定义 MCP server 四阶段生命周期（创建、部署、运营、维护）细分 16 项关键活动；以攻击者类型为轴构建威胁分类法，恶意开发者、外部攻击者、恶意用户、安全缺陷四大类 16 个威胁场景（命名空间抢注、工具投毒、rug pull、跨服务器 shadowing、安装器欺骗、间接提示注入、凭证窃取、沙箱逃逸、越权访问、漏洞版本重部署、升级后权限残留、配置漂移等）；用官方 SDK 自建 host 与 16 个 PoC server 在隔离环境真实验证。

D3 draft-mcguinness-oauth-mission-02
标题/状态：Mission-Bound Authorization for OAuth 2.0，Karl McGuinness（独立提交），-02 版，2026-11-02，2027-05-06 过期；个人草案（非工作组采纳），自建"Mission 家族"配套草案群覆盖运行时强制、跨域投影、安全模型等。
它为 OAuth 2.0 补上此前缺失的标准化对象，Mission（任务）：一个持久授权对象，把披露的任务意图（目标、目标资源、边界、用途、过期时间）与授权服务器机械派生的 Authority Set（RFC 9396 条目集合）绑定；批准者对派生权限集本身（而非任务文字）作出同意，内容用 JCS+SHA-256 完整性锚固定。此后每次发令牌（码兑换、刷新、Token Exchange、委派）都门控于：Mission 必须为 active、结果必须是已批准集合的子集、令牌携带 mission 声明且 exp 不超过 Mission 过期；按 mission_id 撤销阻断后续签发（但不召回已发令牌）；可选支持代理间委派策略与降权自交换。
显式处理的威胁包括：批准后注入的文本无法扩权、委派链破解、降权遗漏。
Mission 将一次批准组织为持久、可审计且可撤销的授权对象，并区分签发治理与逐动作执行。它在八份草案中具有较完整的配套协议描述。

5 现有产品与技术路线的能力及适用边界
凭据保险库与代填已经解决了重要的接入问题
现代凭据保险库可以集中保管秘密，并通过受控组件完成交付或使用。1Password 的不同代理集成提供了具体例子。其 Claude 集成文档描述本地批准、按代理会话保护的凭据交付，以及填充时暂停代理读取页面等措施。面向托管代理的集成则使用机密计算与浏览器扩展交付链。两种部署需要分别按其安全模型评价。[R37,R36]
与本课题直接相关的是官方对保证范围的说明。1Password for Agents 的安全文档把保护范围定位于凭据的存储、批准、交付和填充，登录后的操作由代理自身的防护控制。其使用文档进一步说明，登录成功后的会话按目标网站的规则运行。由此可以把代填成功视为取得访问能力的一个节点，再继续检查任务约束和访问结束条件。[R35,R36]
这一边界足以支持系统研究中的一项需求，密码管理器与任务执行组件应交换账户、会话和批准信息，使用户能够知道一次登录为哪个任务产生了什么访问状态。该需求的可实现程度还取决于浏览器和目标网站提供的接口。
身份与凭据平台已经支持代理归属和按身份授权
Microsoft Entra Agent ID 在既有服务主体基础上提供代理身份、蓝图关系、权限分配与日志。AWS AgentCore 的工作负载访问令牌关联代理身份及其代表的用户。阿里云 Agent Identity 通过策略约束工作负载可以访问的凭据提供方，并把身份管理和凭据取得操作写入审计日志。这些功能能够支持“由哪个代理代表哪个用户取得什么凭据”的管理。[R38–R40]
因此，为代理增加唯一标识、集中保存凭据、建立审计台账，都应作为系统基础能力。研究若进一步要求“撤回甲时乙继续完成工作”，还要把代理身份映射到目标服务实际承认的授权和会话关系。多个清晰可区分的代理身份可以共享同一项下游访问能力，这种共享关系应进入配置记录。
凭据交付位置也需具体分析。阿里云的 API Key 文档明确说明，代理通过出站授权后可以取得明文 API Key。对于这种接口，平台保护了存储和交付资格，应用运行时还要决定是否把密钥留在可信执行组件。把“存储加密”“授权后可取出”“模型接触不到秘密”分别验证，才能准确评价系统边界。[R41]
会话代理已经能够限制工具和结束本地访问
Nango 的官方 Agent Sessions 教程提供了一个范围很明确的邮件摘要示例。它把会话绑定到指定邮箱连接和只读工具，设置有效期，由后端使用提供方凭据，并在任务完成后结束会话。教程还关闭通用代理等间接执行入口，再检查工具限制、会话终止和过期。[R42]
这类设计是本课题必须认真对待的强基线。若所有访问都经过受控代理，用户要求是停止甲继续通过该入口调用，同时保留乙的入口，按任务区分会话并检查当前状态就可能满足要求。在这样的场景中，研究评价应确认直接方案的效果与成本，再决定额外补证和更复杂配置是否有价值。
任务和信息流约束已有独立执行机制
CaMeL 从可信任务提取控制与数据流，并通过能力和策略约束工具使用。Microsoft Agent Framework 的 FIDES 给内容附加完整性与保密性标签，在敏感工具执行前检查策略。PAuth 则研究从任务要求得到具体操作约束。这些方案已经把部分安全责任放到可检查的执行层，为本系统提供可复用机制和强对照。[R25,R44,R45]
执行覆盖范围会影响保证。例如，FIDES 的官方文档明确列出部分 CodeAct 提供方中的嵌套工具调用绕过其逐工具中间件路径，需要宿主工具自行落实授权和目的地控制。这是特定集成的覆盖条件，说明评价一个策略层时，要列出所有实际调用路径并逐一核对。[R45]
表5  现有技术路线的能力与核对边界
表中能力来自官方文档或论文中的明确描述。最右列列出组合部署应检查的条件，对具体产品的额外功能需要依据相应版本继续核对。[R25,R35–R45]
密码 通行密钥 API Key 和令牌作为接入基础
本系统可以通过密码或通行密钥形成网站会话，通过 API Key 调用接口，也可以使用 OAuth 等标准化授权机制取得和更新令牌。OAuth、OIDC 及相关撤销、内省、交换、发送方约束和细粒度授权标准，提供可复用的凭据与身份基础。研究模型从具体接入方式中提取主体、权限、有效期、依赖关系和处置操作，再据此作出配置决定。[R03,R10–R17]
MCP 与 A2A 承担工具和代理交互，AuthZEN 为策略判定与执行提供通信接口，GNAP 等协议提供其他授权委托方式。它们按照系统需要接入适配层。选题论证的中心是任务访问能力如何建立、约束与结束，相关协议为这些环节提供实施能力。[R20–R23]
现有方案共同指向的组合问题
上述方案已经分别推进了安全接入、代理身份、任务会话和执行约束。把它们用于同一个长期任务时，系统仍需核对这些层之间的状态是否一致。任务批准、保险库交付资格、工具会话、远端会话和服务端效果分别由不同组件维护。用户的一次撤回需要说明应改变其中哪些对象，以及用什么证据确认结果。
由此产生的研究需求可以表述为，依据具体服务和执行路径的能力，把用户目标转换为可检查的凭据配置与状态处置计划。第6章通过可复现的情形说明这项转换在哪些地方会出错。
6 认证语义缺失如何导致配置与撤销错误
把控制目标写成能够验证的结果
用户说“停止代理甲”，可能要求受控入口停止接受甲的新请求，也可能要求甲关联的远端会话和令牌失效，或者要求已经排队的操作停止产生后续效果。本地方案用 L、R、E 分别记录这些目标。目标不同，系统需要操作和检查的对象也不同。[L02,R27,R28]
表6  停止目标及其执行和观察位置
同一用户可以只要求其中一项，也可以要求其组合。系统应记录作用范围和时间边界，再选择实现方式。已经发生的读取或写入属于历史效果，后续补偿需要单独的业务决定。[L02,R27,R28]
情形一 关闭凭据入口之后 已有访问状态如何处理
考虑代理甲通过代填登录网站，网站已建立会话 s甲。用户随后断开代理与密码管理器的连接。密码管理器处理了自己的连接和批准，网站仍按自身规则管理已经建立的会话。1Password 的官方使用与安全文档明确区分了这两个职责。[R35,R36]
这个场景应分目标验收。如果用户只要求阻止后续代填，断开连接可以完成相应控制。如果用户还要求 s甲 在网站端失效，就要调用和核验网站支持的会话处置操作。在受控浏览器始终隔离、甲已经停止、且用户只要求 L 的配置中，系统可以采用较低成本的本地停止方案。R 的额外步骤由明确需求触发。
秘密管理服务也存在类似的生命周期分层。Bitwarden Secrets Manager 文档说明，访问令牌撤销后会阻止新的认证，已经认证的机器仍可能在原会话到期前取得并解密秘密，最长可达一小时。这个例子提供了可查证的实际行为，凭据入口失效与已有会话结束需要分别记录。[R09]
由此推导的模型要求是，系统至少要区分访问的来源、已经形成的会话、续期能力和接受方。只记录“连接已删除”或“密钥已移除”，还缺少与用户 R 目标相对应的状态证据。
情形二 独立代理身份可能共享下游撤销范围
设甲乙在代理平台中有独立身份与任务记录，分别使用 t甲、t乙 访问同一账户。后端可能允许分别处置这两份材料，也可能把它们关联到同一授权范围。Google 的官方撤销说明给出了较大范围关联的实例，其程序化撤销会影响此前授予相应项目的权限及相关客户端令牌。Microsoft Graph 的 revokeSignInSessions 又提供了用户刷新令牌与浏览器会话 Cookie 的处置接口。[R18,R19]
因此，“每个代理一个身份”和“每份材料可独立撤销”需要各自的证据。前者可以改善归因，后者取决于下游服务的实际关系。若甲乙共享同一原生撤销范围，直接撤销甲所依赖的根可能同时影响乙。此时系统应在配置阶段选择受支持的独立路径，或者明确采用本地停止目标，并向用户说明相应保证。
已有会话代理可以在共同下游连接上分别控制甲乙的本地入口。对于所有请求均被中介且目标仅为 L 的场景，这正是合理的直接方案。需要研究配置的情形，应额外说明用户为何要求 R、哪些接受路径被纳入目标，以及服务是否允许在既定批准下取得更合适的原生授权。[R42,L02]
情形三 请求结果不明时 重新操作会改变风险与成本
假设系统发送一次创建会话、刷新或业务提交请求，服务端执行了操作，但返回消息丢失。此时本地记录只知道请求发出，远端可能已经产生新材料或业务效果。若把超时直接当作未执行，后续重试和清理就可能遗漏已有状态。AID-Guard 将这种不确定性纳入保留预约、效果确认和恢复规则，说明它已有直接研究基础。[R27]
凭据配置还会受这些状态影响。例如，首次登录可能已经形成会话，再次登录则可能生成第二个会话。两个会话是否独立、能否查询、退出一个是否影响另一个，都由具体服务决定。安全补证因此需要描述允许结果和处置责任，避免把所有查询都当作免费、无副作用的信息读取。[L02]
在完整任务中，甲的停止、乙的保留和新会话的清理可能竞争同一操作预算。某个核验步骤单独看能够增加信息，放到全流程却可能消耗结束任务所需的资源。研究必须把取得证据和证据取得后的状态变化一起计算。
认证语义是这些行为关系的可检查描述
本报告所说的认证语义，具体指服务对账户、凭据、会话、授权依赖和处置操作的行为约定。它需要回答一次动作作用于哪个对象，可能产生什么结果，哪些其他对象会随之变化，以及系统能观察到什么。语义描述可以来自标准、版本化文档、可信配置和获准的运行观察。[L02]
表7  认证语义与配置决定的对应关系
表中是本课题用于组织决定的证据结构。服务已经提供的可信事实可以直接登记，运行观察只在其对应范围内支持结论。[L02,R12,R13,R27]
异构性与不确定性分别带来什么工作
若网站甲和乙的规则不同，但每项规则都已可靠掌握，版本化适配表和普通规划就可以处理。值得引入主动感知的条件，是某个尚未确定的事实会改变安全动作、可行配置或完整成本，而且存在合法、可承担后果的补证方式。[L02,R30]
这类不确定性可能来自当前连接的实际账户绑定、历史材料与现行配置的对应关系、响应丢失后的远端状态，或文档与当前部署的适用性。它应作为具体事实登记。对于缺少有效观察路径的事实，系统保持受限结论，并通过已有安全配置、补充批准或人工核验处理。
因此，认证语义感知需要以决定为目标。它要说明当前缺少哪项事实，这项事实会改变什么选择，以及补证本身是否保持合法完成和清理的可能性。这个要求将第5章的产品能力与后续 A/B/AB 的输入连接起来。
7 从真实缺口到本课题的研究问题
先把需求落到一个可以验收的问题
给定用户的任务批准、代理身份、已有凭据和目标服务，系统需要产出一项可执行决定。它应说明采用哪个账户和访问路径，允许哪些操作，用户撤回时怎样处置目标范围，其他任务依靠什么继续工作，以及每项判断由什么证据支持。[L02]
以双代理场景为例，可验收要求可以写为甲和乙均能完成各自获准的读取，用户撤回甲后，甲满足事先声明的 L 或 R，乙继续保持已批准的访问。若任务包含异步写入，再按服务能力单独加入 E。这样得到的成功条件同时包含合法工作、选择性停止和证据范围。
为什么只增加一个保险库还不足以完成该目标
保险库可以正确保护并交付凭据。在第6章的情形一中，后续需要处置的对象却已经变成网站会话。系统要把这项状态与任务、执行环境和停止目标关联起来，才能继续判断。因而，凭据保管是必要模块，完整管理还需要一份面向使用过程的状态与依赖记录。[R35,R36,L02]
类似地，给甲乙分配不同代理身份可以明确归因，在情形二中仍需要检查它们下游是否共享同一撤销范围。上述分析把研究对象收敛为任务、凭据和服务行为之间的关系，也为系统应保存什么状态给出了具体理由。[R39,R29]
用已知关系与未知关系构造两个对照场景
场景甲中，可信适配配置已经说明甲乙均通过同一网关访问，秘密留在网关，用户只要求 L。系统创建两个任务入口，撤回时仅关闭甲的入口。该场景验证直接共享方案的可用性，也作为额外探测应当为零的负控制。Nango 的会话与工具范围控制提供了相应技术基线。[R42,L02]
场景乙中，用户要求覆盖明确远端材料的 R，并持续保留乙。现有证据只表明 t甲、t乙 当前可用，尚未确认它们的原生撤销关系。系统可以直接处置甲、先安全补证，或在获准且原生支持的情况下建立新的独立路径。选择哪条路线取决于真实关系、补证成本和新配置的成立条件。
这两个场景同时存在，才能检验所谓感知是否有用。若两者都执行相同的大量探测，方法增加了原本可以避免的开销。若两者都依据令牌表面差异执行撤销，方法可能遗漏场景乙中的关联影响。评价应观察证据是否改变了最终决定。
一个更具体的可区分性例子
构造具有相同初始观察的两个服务状态。状态一中，t甲、t乙 分别依赖 g甲、g乙，处置 g甲 可以保留乙。状态二中，t甲、t乙 均依赖 g共同，处置该根会影响二者。暂且假设账户查询与当前访问测试的返回相同，并且这两个状态都符合现有证据。此例是用于问题分析的构造，服务是否允许这样的关系和查询，需要在实际后端中验证。
只依据这些共同观察，系统会对两个状态作出同样的决定。直接处置原生根在状态二中损害乙。总是取得额外独立路径可以作为保守方案，但其成立仍需要服务支持和用户批准，并可能在状态一增加授权、交互和清理成本。如果存在能够区分两种关系的获准查询，系统就有机会根据结果选择更合适的路径。
这个构造建立的是信息与决定的依赖。如果最强通用规划器获得同样的可能状态、查询和代价，它也能够作出相应策略。新的学术贡献需要进一步说明，所提出的表示、证据处理或求解机制相对该通用方法的具体增量。[R30–R33,L06]
由此依次得到 A B 和 AB 的职责
第一，配置之前需要掌握足以支撑当前决定的服务事实。A 因而承担认证语义的证据组织与安全补证，包括区分已知、待决和观察冲突，并记录核验带来的新状态与义务。[L02]
第二，获得语义后仍需选择访问路径。B 根据用户的停止与保留目标，在服务支持和批准允许的配置中比较成本。共享连接、隔离执行和独立原生授权都属于候选选择，其可行性由适用条件决定。[L02,L04]
第三，应该补什么证据又取决于配置缺少什么事实。AB 把配置可行性和成本的差异反馈给 A，让核验围绕当前决定展开。核验产生的新状态随后重新进入配置与停止规划，形成联合问题。[L02,R30]
表8  从实际问题到可验证研究职责
这些问题分别说明了感知、配置、反馈和完整系统的必要职责。它们的算法原创性需要继续经过直接相关工作的模型映射和同条件比较。
为什么选择这一范围开展硕士研究
这项范围具有三个可具体检验的条件。需求能够落到用户可理解的停甲留乙和任务结束目标。失败情形能够用会话、授权关系和响应丢失构造，并在受控后端中复现。项目已经具有有限模型、独立参考和后端校准，可以用来检查机制是否真正带来增量。[L02,L05,L06]
在此范围内，完整凭据管理系统负责把账户连接、批准、执行、撤回和审计组织成可用闭环。学术研究优先处理不完整证据如何影响安全配置以及补证策略。其他任务语义和信息流控制能力可以采用现有方法，再检查它们与凭据生命周期的组合条件。[R25–R29,R44,R45]
研究成立的条件和收敛标准
如果固定适配表加会话网关已经以可接受成本满足全部目标，相关场景应作为基线成功记录。若实际服务提供完整语义，也应直接使用。主动感知的价值，需要由真实缺证场景中的配置改变、合法任务保留、错误保证减少或完整成本改善体现。
同样，支持 R 的目标需要原生处置能力，支持 E 的目标需要覆盖对应业务效果路径。模型应反映能力边界。新候选机制进入实现前，继续遵循具体输入族、度量指标、最强通用方法和预测差距组成的分离声明，并先形成至少一个通用方法付出更高代价的可复查实例。[L02,L06及项目研究规则]
因此，选择该方向的依据可以落到一条完整论证上，代理已经实际使用账户，既有安全组件各有明确保证范围，跨组件的访问状态影响用户的停止与保留要求，证据不足又会影响配置决定，而这些关系可以通过有限模型和真实后端共同验证。
8 把研究问题具体化为 A B 和 AB
核心研究问题
在多个 AI 智能体共享用户账户、服务原生认证与撤销关系存在不确定性、核验受到批准与预算限制的条件下，系统如何获取足以支持决定的证据，并选择满足指定停止和其他任务保留目标的凭据配置，同时控制端到端成本。
这个问题至少包含输入、约束、输出和代价。输入是账户与任务、用户批准、已有凭据、候选服务契约和可用操作。约束是当前访问合法性、停止目标、保留目标、预算和后续清理责任。输出是可执行策略或具有明确原因的其他结论。代价同时包括原生授权单元、请求、用户交互和计算开销。[L02]
A 认证语义感知
A 维护与现有证据相容的可能状态集合 K。每次核验之后，根据允许的状态变化和观察结果更新 K，并保存新形成的义务。一个动作只有在模型覆盖的可能状态中都符合批准和安全条件，并且保留合法结束路径时，才进入可执行集合。已有项目把这类有限有界判定作为 A 的安全内核。[L02,L05]
例如，系统需要确认当前连接实际属于哪个账户。若有获准的详情查询，可以先检查身份与范围。若需要新的登录尝试才能确认，就必须考虑新会话创建与清理成本。查询到的账户信息可用于更新对应事实，原生撤销独立性仍由其自己的证据支持。这种按事实类型和作用域更新的方式有助于防止结论扩张。[L02]
B 可撤销凭据配置
B 根据任务需求和认证契约，选择哪些凭据、授权单元和支持路径供各代理使用。它需要检查任务开始时能够完成获准工作，未来执行指定停止时能够满足目标，并在要求保留的路径上维持乙的合法访问。[L02,L04]
本地 B 的历史目标以原生效果单元数量 G 为主，配置字典序用于同值选择。新增批准、隔离资源、请求和计算时间应分别记录。G 的含义需要依据服务的效果关系定义，不能直接用令牌字符串数替代。对于已经按同目标精确求解的基线，候选方法的价值可以体现为更低求解成本、更清晰的证据或更广的可处理结构。[L02,L06]
AB 配置反馈驱动的安全补证
AB 把配置器遇到的具体缺口反馈给 A。例如，B 发现停甲留乙是否可行取决于两个凭据是否共享撤销范围，就可以把这一事实标记为补证目标。A 再判断可用查询能否获得相关信息，以及查询之后是否仍能完成整个任务和清理责任。[L02]
在贯穿场景中，如果现有证据已支持共享连接满足 L，AB 可以直接进入配置。如果 R 需要独立性证据，AB 才考虑相应补证。当证据表明原生授权不可分、且现有批准中没有其他可行路径时，系统应给出明确的受限结论，并说明需要何种新的能力或用户决定才能继续。[L02]

9 完整凭据管理系统应如何承载研究
工程交付范围
完整系统可以围绕一个用户、两个代理、两个服务和少量明确任务形成可演示闭环。用户能够建立账户连接、保管凭据、确认任务、查看使用记录、撤回单项任务，并观察其他任务是否保留。研究方法通过这个闭环接受真实后端与故障情形的检验。该范围与本地需求规格和三个贯穿场景相衔接。[L01,L02]
系统的逻辑顺序可以描述为用户批准任务，代理提交操作，A 与 AB 根据必要性取得证据，B 提出配置，独立检查器核验适用条件，可信执行者落实真实调用，持久协调器记录结果、撤回和清理责任。已有证据足够时，流程直接使用现有契约。各模块承担逻辑职责，部署时可以组合成少量进程。[L02]

谁可以决定 谁可以执行
AI 智能体负责提出任务步骤和操作请求。可信批准界面记录用户意图，执行边界检查操作参数与当前授权。保险库仅向获准执行组件开放必要材料。规划器和证书生成器提供建议，检查器核对建议所依赖的范围、状态和证据。外部服务则决定原生令牌、会话和业务提交行为。[L02,R22,R26]

用三个场景展示系统的研究作用
场景一是已知契约下完成正常任务。代理甲读取并生成摘要，代理乙继续监测，系统测量合法完成与凭据暴露边界。该场景也用于检查 A 和 AB 是否产生了多余核验。[L02]
场景二是配置所需证据不足。系统显示具体缺口，执行获准补证，更新证据后重新决定配置。评价重点是证据是否真正改变配置，以及全流程增加了多少请求、授权和清理成本。[L02]
场景三是用户停止代理甲并保留代理乙。系统按照 L、R 或可支持的 E 分别执行和展示结果，并注入撤回与执行竞态、响应丢失、服务拒绝和进程重启。评价需要同时记录甲的停止、乙的可用性、已发生效果和未结责任。[L02,R27,R28]
为什么完整系统值得作为毕业设计载体
完整系统把方法的适用条件变成可观察的运行事实。凭据是否真正隔离、证据是否过期、撤回是否影响乙、恢复是否重复产生效果，都可以通过具体任务检查。工程贡献由功能闭环、可靠性和实验平台支撑，学术贡献由问题定义、方法性质及强基线差距支撑。两类贡献通过统一工作流关联起来。[L01,L02,L06]

11 密码学在本课题中的基础作用和辅助研究空间
基础安全首先依靠成熟密码学机制
凭据保险库需要加密存储与密钥管理，服务通信需要安全通道，批准和证据需要完整性保护，令牌使用可以结合服务支持的发送方约束。它们分别保护秘密、通信、记录与调用者关系，属于系统可靠运行的基础。具体实现应沿用成熟库与协议，并由威胁模型确定密钥边界。[R02,R15,R17]
这些基础机制与认证语义形成互补。签名可以确认某段记录来自持有相应密钥的一方，记录内容对服务行为的解释仍需契约和执行证据。加密可以保护凭据保存，用户要求的远端停止则依赖服务的失效与接受机制。把每种保证写清楚，有助于选择真正需要密码学支持的子问题。[R12,R26,R28]
辅助研究可以围绕有限的私密证据问题展开
本地密码学支线讨论稀疏残差、掩码、故障定位、来源绑定和 MPC 核验。一种相关应用设想是，在多方共同检查某项凭据记录关系时，只公开完成决定所需的结果，同时保护诊断过程中的额外信息。该设想需要先固定参与方、输入来源、被验证关系、允许泄漏和中止后的责任。[L07]
现有材料包含限定模型下的秩与补证关系、两故障修复构造和有限验证。项目也记录了完整成本尚缺优势、成功域变化影响比较、来源与主线接口待接通等条件。后续应把这些结果作为具体理论候选继续核验，并单独评价它们是否改善主线系统的安全或成本。[L04,L07,L08]
辅助方向的进入条件
只有当主线出现明确的隐私需求，且现有签名、访问控制或直接可信检查难以按相同信任条件满足时，才有充分理由投入新的私密核验机制。届时需要提供具体输入族、泄漏指标、最强可用通用方法与预测差距，并保持输入成功域、预处理、通信和中止模型一致。[L04,L07]
在论文结构中，密码学可以先承担安全基础，再以通过上述门槛的子问题形成辅助贡献。主线的认证语义、可撤销配置和系统实验可以独立评价，辅助结论通过明确接口与主线关联。[L02,L07]
12 怎样把方向价值转化为可验证的研究贡献
先固定比较条件
候选方法和基线必须获得同一组可见信息、可调用接口、用户批准、初始状态、预算和安全目标。资源服务器的内部真值可以用于独立评分，算法应按其实际权限获得观察。真实服务原生能力与实验中新增的网关、取消接口或管理权限需要分别标记。[L02,L05]
在精确求解相同优化问题时，参考方法已经给出的最优值是共同目标。候选可以争取更低计算开销或更好的可扩展性，也可以对新的问题域建立模型和性质。评价中应同时测量有效任务完成与安全，防止把大量拒绝造成的低风险误写成完整任务能力。[L05,L06,R34]
实现前必须形成可证伪的分离声明
按照项目规则，新候选机制进入实现前，需要同时给出具体输入族、度量指标、当前最强通用方法和预测差距，并先构造至少一个通用方法确实付出更高代价的实例。对本课题，“最强通用方法”应落实到可复现的比较集合，例如同语义精确联合参考、增量 SMT、共享相同剪枝信息的搜索，以及通用证书重放，并公开版本与适用条件。[L06及项目研究规则]
以下检查记录可用于现有研究路线的后续筛选。它们说明应该验证什么，当前预测差距保持待建立状态。

一个合格分离声明应当写到什么程度
以决定保持抽象为例，首先要给出 F_n 的完整状态、动作和观察规则，说明哪些维度随 n 增长。其次明确候选与基线在相同保证下比较的指标，例如从输入构建到最终证书核验的总时间。然后列出比较中实际最强的通用实现和它可使用的缓存、抽象及下界。最后说明差距的数值或渐近形式，以及一个能够复查的实例和推导。

13 选题判断与后续研究顺序
题目为什么能够形成连贯的研究主题
现代密码管理器已经向代理代填和受控凭据使用扩展，身份平台与会话代理也提供了实际部署能力。完整任务还需要处理登录后的远端状态、共享授权和结果不明的操作。用户的停止与保留要求因此需要逐项对应到服务能力。证据足够时直接配置，决定所需事实缺失时评估安全补证，再选择满足目标的路径，构成了本题的研究链条。[R35–R42,R27–R29,L02]
这一方向具有明确的实际问题、可以复用的技术基础和可构造的实验场景。现有任务级授权、长任务撤销和通用规划研究也给出了清楚的比较压力。适合作为硕士课题继续论证的依据，是能够把用户需求逐步收敛为有限且可验证的问题，同时通过完整系统说明方法的实际作用。[R25–R33,L02]
建议保留的双层目标
工程目标是自主设计并集成面向 AI 智能体的凭据管理系统，在明确的账户、服务、任务和威胁范围内完成批准、使用、撤回、保留、恢复与审计。其验收依据是可复现的完整业务闭环。[L01,L02]
学术目标是优先验证认证语义不确定条件下的安全补证与可撤销凭据配置。贡献可以围绕可靠的服务语义模型、可检查的决定条件、满足分离门槛的方法，以及同条件端到端实验形成。密码学辅助依据独立需求与分离证据推进。[L02,L04,L07]
后续工作按证据依赖推进
首先固定双代理场景、用户批准、L/R/E 目标和各服务的可用接口，建立可追踪的认证契约与证据表。随后补齐强近邻研究的模型映射，对现有原型的作用域与状态处理问题形成明确修复记录。在此基础上，完成候选机制的具体分离声明，再安排对应实现和消融实验。[L02,L06,L08]
完整系统的研究规格和验收用例可以随这一过程逐步细化。新机制实现应以分离门槛为前提，系统整合则以已经获得支持的方法与能力为依据。最终论文需要让读者沿着同一条证据链理解需求、方法、真实运行和实验结论。[L02,L08]
