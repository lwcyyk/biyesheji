## 1. 审计范围与方法

本次复核覆盖根胶囊、恢复胶囊、HKDF 域分离、字段 AEAD、事件 AEAD、HPKE、Ed25519 签名、确定性 CBOR、随机标识、RouteMap、OriginBinding、透明 Merkle 证明、L1～L5 解析、Epoch 审计见证和秘密销毁。

方法包括：

1. 标准已知答案测试（KAT）；
2. 冻结向量和确定性编码回归；
3. 错误 key purpose、context、对象类型、版本和签名域的交叉使用；
4. 密文、AAD、签名、证明和编码变异；
5. JSON、格式化和错误对象的秘密泄漏检查；
6. 销毁、并发销毁、重放和资源上限检查；
7. 公开日志叶、状态描述和分析结果的字段最小化检查。

自动门禁实际通过 385 个具名测试，失败包为 0。该计数来自 Go `-json` 事件，不把构建成功或无测试包计为具名测试。

## 2. 原语与 KAT

| 原语/协议 | 用途 | 验证 |
|---|---|---|
| Argon2id | 主密码本地 KDF | PHC 参考向量、策略上下界、P95 校准 |
| HKDF-SHA-256 | 根下用途密钥派生 | RFC 5869 向量、完整域分离矩阵 |
| AES-256-GCM | 胶囊、字段和事件 AEAD | NIST 向量、AAD/密文/nonce 变异 |
| Ed25519 | 根、设备、状态和日志签名 | RFC 8032 向量、签名域隔离 |
| HPKE X25519/HKDF/AES-GCM | 新设备根包传输 | RFC 9180 向量、低阶点和错误接收方 |
| CBOR deterministic encoding | 所有签名/摘要载荷 | RFC 8949 向量、非规范编码拒绝 |
| HMAC-SHA-256 | OriginBinding、RouteMap、审计见证 | 固定向量、输入精确编码和用途隔离 |
| Merkle tree | 透明包含和一致性 | KAT、穷举一致性、1m 叶形状上限 |

项目没有自创基础密码算法。所有随机生成器生产入口拒绝测试熵源和短读；固定 seed 只用于实验数据，不能进入生产生成路径。

## 3. 域分离与确定性编码

协议把用途、协议版本、密码套件、NamespaceID、对象类型和必要上下文放入 HKDF info、签名输入或 AEAD AAD。测试矩阵证明以下用途之间不能互换：

```text
CREDENTIAL-WRAP
CREDENTIAL-NAME
AUDIT
RELATION
ROTATION
ROOT-UNLOCK
ROUTE
FIELD
EVENT
SIGNATURE
```

签名前只接受具体结构体的确定性 CBOR；拒绝 map、未知字段绕行、自定义 binary unmarshaler、副作用 unmarshaler、过深嵌套、过大载荷和非最短整数。ID 在线上统一编码为定长 CBOR byte string，在 JSON 中使用无填充 base64url。

审计结论：域分离和编码约束通过。未来新增对象必须先在协议注册表中分配域，并新增交叉用途拒绝测试。

## 4. 密钥生命周期

### 4.1 创建与持有

- 名称空间根、根签名 key、设备秘密和恢复秘密由 OS CSPRNG 独立生成；
- 主密码只用于本地 RootCapsule 解锁，不发送到 HTTP、同步云或 VDNS；
- 每个凭据字段使用独立随机 DEK；
- 设备认证 key 与 HPKE 接收 key 分离；
- 一次性 secret handle 绑定 session、Origin、操作和过期时间。

### 4.2 使用与销毁

- `Secret`/`Key` 类型禁止 JSON 和普通格式化输出；
- 锁定、超时和主动销毁会使共享副本失效；
- 并发 open/destroy 由测试覆盖；
- 失败路径不返回部分明文；
- 审计见证在生成加密事件后尽力清零；
- 拒绝门禁不会错误消费句柄，通过后不能重放。

Go 运行时不能提供形式化的“编译器绝不复制”保证，因此文档统一使用“尽力清零”，不声称达到硬件隔离级秘密擦除。

### 4.3 撤销边界

撤销以最终序号和秘密代际阻止未来操作和新对象分发。它不能让设备忘记撤销前已经获取的密码或根材料；这是明确的系统边界，不是测试遗漏。

## 5. 公开字段复核

公开透明叶只允许：

```text
namespace_commitment
subject_pseudonym
object_type
object_digest
operation_type
final_sequence
epoch
```

公开投影不允许密码、Origin、用户名、CredentialID、DeviceID、TOTP、恢复码、稳定复用见证或 secret handle。CredentialID 虽为随机值，仍按敏感伪名处理。

Epoch 设备伪名和审计 key 随已验证 beacon/epoch 改变。该设计只消除协议公开字段中的稳定标签，不防御流量时间、源 IP、同 Epoch 聚类、padding 前长度或已解锁端点失陷。

## 6. 协议不变量复核

L1～L5 共同实施：

```text
Accept(E)
  = SigValid(E)
  ∧ CapabilityAllows(E)
  ∧ DeviceNotRevoked(E.final_sequence)
  ∧ CausalFresh(E)
  ∧ LogIncluded(E)
  ∧ LocalPolicyAccepted(E)
```

已验证的关键反例包括：

- 合法旧对象，但版本低于 VDNS 当前版本；
- 同版本、不同对象摘要；
- 签名正确但设备无相应 capability；
- 使用攻击者提供时间绕过撤销；
- 日志包含证明或检查点变异；
- 页面 Origin、账号绑定或 iframe 策略不匹配；
- 网站响应丢失时直接激活新密码；
- Pending/Failed/Unknown 被计入 ChangedSet。

全部反例失败关闭或进入人工复核，不进入 `ACCEPT`。

## 7. 发现项

### F-CRYPTO-001：基础工具链历史可达漏洞

- 初始状态：Go 1.22.2 与旧依赖扫描得到 30 个可达漏洞；
- 处置：升级至 Go 1.25.12 和当前兼容依赖，重跑全部测试；
- 当前结果：`govulncheck` 符号级扫描为 0 个可达漏洞；
- 证据：`test-results/g7/security/govulncheck.json` 与 `govulncheck-after.json`；
- 状态：已解决。

保留升级前结果是为了展示真实失败与修复过程，不删除负面证据。

### F-PROTO-002：10k SyncManifest 与公共签名载荷上限

协议类型允许 10,000 个对象引用，但冻结的公共签名载荷上限为 64 KiB，单份 10k manifest 不能编码。E3 使用 100 批、每批 100 个对象完成同一 10k 同步工作量。

- 风险：调用者若把类型上限误认为单消息上限，会遇到协议拒绝；
- 当前缓解：批处理、每批签名验证、集合根绑定和明确实验注释；
- 后续：在下一协议版本把批次/集合语义写入 OpenAPI 和注册表；
- 状态：中等设计债务，不阻断当前按批实现。

### F-DOC-003：密码学参数运维说明

Argon2id 参数在研究环境固定并有校准器，但生产硬件、移动端能耗和降级策略尚无现场数据。不得把本机 P95 直接当作所有设备 SLA。

## 8. 结论

密码套件、编码、域分离、秘密生命周期、公开字段和协议负面矩阵达到 G7 发布门禁。结论只适用于仓库当前实现、固定依赖和测试环境，不替代第三方密码学审计、移动安全芯片验证或生产渗透测试。
