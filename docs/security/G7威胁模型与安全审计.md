## 1. 信任边界

```text
不可信网页
   │ Origin + 用户动作
   ▼
浏览器扩展 ── Native Messaging ── 本地 Agent / 已解锁内存
                                      │
                    ┌─────────────────┼─────────────────┐
                    ▼                 ▼                 ▼
               本地 SQLite      不可信同步云       VDNS/日志/检查点
                    │                                   │
                    └──────── 本地独立验证 ─────────────┘
```

最高信任区是已解锁的本地 Agent。扩展不持有长期根；网页永不可信；同步云可任意回滚、替换、删除和重排；VDNS、日志和检查点响应必须通过签名、证明、最终序号与本地策略验证。

## 2. 资产

高敏感资产：

- 主密码、设备秘密和高熵恢复秘密；
- 名称空间根、根签名私钥、设备签名/HPKE 私钥；
- 字段明文、DEK、RouteMap、Origin/账号关系；
- 未公开审计见证和一次性 secret handle。

完整性资产：

- 当前 CredentialStateDescriptor、版本和 envelope hash；
- 设备 capability、撤销最终序号和秘密代际；
- 透明日志树头、一致性证明和周期检查点；
- 网站强确认回执、ChangedSet 和 RotationRoot。

可用性资产：

- 本地缓存的已验证当前凭据；
- 耐久候选/outbox；
- 恢复胶囊、内容寻址对象和可验证 VDNS 状态。

## 3. STRIDE 复核

| 类别 | 代表攻击 | 主要控制 | 残余风险 |
|---|---|---|---|
| Spoofing | 伪设备、伪网站 Origin、伪 VDNS | Ed25519、根签 capability、OriginBinding、L1～L5 | 已解锁端点被完全控制 |
| Tampering | 云替换/回滚、密文/AAD/证明变异 | AEAD、对象摘要、版本、Merkle 证明、已见检查点 | 云可拒绝服务 |
| Repudiation | 否认更新或撤销 | 签名事件、最终序号、透明包含和周期根 | 站点外部确认能力不一致 |
| Information Disclosure | 云库泄漏、日志稳定标签、错误回显 | 字段加密、RootCapsule、最小公开叶、统一错误、CSP | 流量元数据和端点内存 |
| Denial of Service | 删除对象、日志不可用、过大输入 | 离线缓存、资源上限、批处理、退化 verdict | 首次同步和新更新依赖外部可用性 |
| Elevation of Privilege | READ 变 UPDATE、撤销后继续写、PUBLISH 变 ANALYZE | capability 精确权限、scope、final sequence、generation | 根控制者失陷影响整个名称空间 |

## 4. 高优先级滥用场景

### 4.1 云端回滚

攻击者返回合法签名的旧 envelope。设备以 VDNS 当前 descriptor 的版本和摘要为裁判；版本低、同版本异摘要或对象缺失均拒绝。故障注入和 H1 消融均保留机器证据。

### 4.2 撤销后重放

攻击者使用仍可签名的丢失设备并伪造早期时间。验证使用接收方认可的最终序号和 secret generation，不使用攻击者提供的 wall clock 决定撤销。旧 counter、旧 capability、旧代际和 backdated event 均拒绝。

### 4.3 恶意网页索取其他站点密码

扩展传递规范化顶层 Origin；本地 RouteMap 重新解析 CredentialID，并验证 OriginBinding、账号和 iframe 策略。HTTP 调用方不能直接提供任意 CredentialID 获得明文。

### 4.4 网站改密状态错配

新密码先作为耐久候选保存，只有强网站确认或用户明确确认后才激活。响应丢失进入 `UNKNOWN/REVIEW_REQUIRED`，保留旧 active 与候选，不做乐观覆盖。

### 4.5 主密码数据库泄漏

云端 RootCapsule 还需设备高熵秘密才能形成解锁 key。若攻击者同时取得本机胶囊和设备秘密，低熵主密码仍可能被离线猜测；Argon2id、设备安全存储和用户密码质量是必要缓解，系统不声称消除该风险。

## 6. 秘密、CSP 与错误

项目级扫描覆盖：

- 私钥、云凭证、token 和高熵秘密模式；
- 测试 fixture 与真实秘密的路径/上下文区分；
- 扩展 `content_security_policy`；
- 禁止远程脚本和 `unsafe-eval`；
- HTTP/OpenAPI 统一错误；
- Secret/Key 类型的 JSON、格式化和错误输出。

通用扫描器对测试密码和摘要产生假阳性，原始结果与人工裁决均保留。项目专用扫描通过，不能通过删除测试 fixture 来“修复”扫描结果。

## 7. 风险登记

| 风险 | 等级 | 状态/缓解 |
|---|---:|---|
| 完全控制已解锁端点 | 高 | 非目标；最小解锁窗口、锁定和 OS 隔离 |
| 根控制私钥失陷 | 高 | 恢复/轮换流程；生产需硬件密钥保护 |
| 10k 单 manifest 超 64 KiB | 中 | 当前 100×100 分批；下版协议明确 |
| 流量和时间元数据链接 | 中 | Epoch 伪名不解决网络匿名；可增加代理/定长批次 |
| 外部服务拒绝可用性 | 中 | 已验证缓存、耐久 outbox、退化策略 |
| 站点确认启发式差异 | 中 | 强确认/人工确认；不把填充或跳转当成功 |
| SCOPE-ZK 未配置 | 低 | 功能显式 unavailable；不影响日常路径 |
| 研究适配器不等于生产部署 | 中 | 答辩和文档明确 provider 分类 |

## 8. 安全发布条件

以下任一项出现即阻断：

- 可达高危漏洞；
- 规范 baseline 或迁移 checksum 漂移；
- 主密码、字段明文或长期秘密进入日志/API；
- 旧版本、撤销后操作或错误 Origin 被接受；
- Pending/Failed/Unknown 改变有效凭据；
- 扩展允许远程代码或 `unsafe-eval`；
- 许可证出现未知或拒绝项。

当前机器门禁全部通过，但结论限定于研究原型和已记录环境，不替代外部第三方审计。
