## 1. 阶段判定

当前统一阶段为：

```text
文档版本：2.1.0
阶段：G6
状态：研究原型集成；G7研究原型冻结未达成
协议文档：Stage 1设计冻结
代码状态：需要第二阶段按冻结协议迁移
```

不采用 v3.0.0/G7 的原因是：

- 没有独立的最终序权威、多节点日志共识或生产检查点终局实现；
- 本地 CAS 不能保证两台设备只产生一个全局 v2；
- 网站确认证据代码仍是旧枚举，当前实现依赖 Mock Site；
- 同步性能不包含真实网络与对象传输；
- G7 E5 的微秒值只测 Merkle 包含证明，不是完整 L1～L5；
- E1～E8 缺少逐次原始性能样本；
- SCOPE-ZK 未实现；
- 当前漏洞状态没有基于审计日数据库重新扫描。

## 2. 版本语义

`VDNS-PM/2` 和 `VDNS-PM-CP-2` 的线协议大版本保持不变。文档版本从2.0.0提升到2.1.0，用于冻结信任、排序、冲突、确认、撤销、Origin和证据规则。第二阶段不得把2.1.0文档直接解释为代码已经迁移完成。

证据等级的 E0～E5 是规范性变更。现有数据库和代码使用数值1～5的旧枚举，不能就地重解释。第二阶段必须使用显式迁移或新编码版本，旧对象保持 legacy 语义并禁止混用。

## 3. G7重新进入条件

只有同时满足下列条件，才能重新声明 G7：

1. P0协议任务全部完成并通过负向测试；
2. 最终序生产者、签名排序回执、可信初始检查点和分叉处置在代码中闭合；
3. 两设备并发 `v2-A/v2-B` 能可靠进入 `CONFLICTED`，且最终选择可验证；
4. E0～E5在代码、SQLite、OpenAPI、扩展和论文中一致；
5. 设备撤销三层边界在实现和UI中无夸大；
6. E1～E8输出逐样本原始数据、环境和失败样本；
7. E3补充网络传输口径，E5分别报告完整L1～L5与Merkle微基准；
8. 8项故障和7项恢复按准确名称重新运行；
9. 当前漏洞、依赖、许可证和秘密扫描重新运行；
10. 论文声明核对表中所有阻断项不再为 `UNVERIFIED` 或 `NOT_IMPLEMENTED`。

## 4. 历史证据处理

`test-results/g7/` 保留为2026-07-23左右生成的历史证据快照，不删除、不覆盖、不改写为新的G6结果。它可以支持限定后的本地研究结论，不能单独支持“当前G7已经冻结”。后续实验必须写入新目录并带数据集版本、工具链、开始/结束时间、原始样本和工作树标识。
