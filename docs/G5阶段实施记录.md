# G5 阶段实施记录：本地 API、浏览器扩展与日常体验

日期：2026-07-23  
阶段状态：完成  
任务范围：T-G5-001～T-G5-012

## 1. 阶段结论

G5 已把前四阶段的密码学、凭据生命周期、同步和 VDNS 控制能力接入一个可操作的日常密码管理原型：

```text
安全输入 / Native Messaging
  → 受认证的 /api/v2 回环 API
  → vault session 与一次性 secret handle
  → 生成、保存、解析、填充和候选改密
  → 同步、设备、恢复与异步操作状态
  → Manifest V3 弹窗和安全控制台
```

主密码、网站密码和 RecoverySecret 不作为普通 HTTP JSON 字段。扩展通过持久 Native Messaging 通道提交安全输入；HTTP 层只接收句柄。自动填充必须依次取得本地路由、可信 current version/对象投影和精确 Origin 许可，任一门禁失败时不会向页面发送字段。

## 2. 主要实现

### 2.1 本地 API 与安全边界

新增：

- `internal/localapi/application`：vault session、句柄代理、凭据/版本状态、同步和设备操作；
- `internal/localapi/ports`：幂等响应与异步操作持久化端口；
- `internal/adapters/inbound/httpapi`：OpenAPI v2 回环适配器；
- `internal/adapters/inbound/nativemessaging`：Chrome 长连接帧协议和安全输入桥；
- `cmd/vdns-local-agent`：RootCapsule/RecoveryCapsule 校验、随机回环端口、HTTP 与 Native Messaging 组合入口。

HTTP 安全规则：

- Bearer InstallToken 使用 SHA-256 后常量时间比较；
- 只接受回环 peer 和 IP 形式回环 Host，拦截 DNS rebinding Host；
- CORS 仅允许配置的精确 `chrome-extension://<id>`，拒绝 `*` 和 `null`；
- nonce 为 22～128 字符的一次性值，五分钟内拒绝重放；
- 写请求使用 16～128 字符 Idempotency-Key；
- JSON 使用 `DisallowUnknownFields`，请求体默认上限 64 KiB；
- unlock、recovery 和普通请求分别限速；
- 错误统一为 `code/message/requestId/details?`，不返回栈、SQL、路径或秘密；
- vault session 具有空闲和绝对超时，锁定时销毁会话句柄；
- cursor 使用 HMAC 绑定设备和查询范围。

### 2.2 幂等、版本与操作状态

同一幂等键和同一 canonical JSON 请求返回原响应；同键异请求返回 `409 IDEMPOTENCY_CONFLICT`。凭据版本写同时检查：

```text
expectedVersion
previousDescriptorHash
```

网站结果为 `UNKNOWN` 时：

```text
candidate.state = UNKNOWN
credential.activeVersion 保持旧版本
credential.lifecycleStatus = SITE_CONFIRM_PENDING
```

只有 `SITE_CONFIRMED` 或用户明确确认的成功结果才能激活候选。同步、加入、撤销、恢复和安全分析返回的 `PENDING` 不会映射为 `COMPLETED`。

### 2.3 SQLite v6

新增 append-only 迁移 `0006_g5_local_api.sql`，checksum：

```text
8d0f548d0dc65ab00f4b9e4a13b4cc80b64b09c4ffe0e7fb8527200c1d45e056
```

新增三张表：

- `local_api_installations_v2`：只保存安装令牌哈希和扩展 Origin 哈希；
- `local_api_idempotency_v2`：只保存幂等键哈希、请求哈希和安全响应；
- `local_api_operations_v2`：耐久保存 `QUEUED/RUNNING/COMPLETED/PENDING/FAILED/UNKNOWN`。

会话、nonce 和 secret handle 不写入 SQLite。含一次性句柄的响应也不跨进程持久化。

### 2.4 Manifest V3 扩展

扩展位于 `apps/browser-extension`，权限为：

```text
activeTab
nativeMessaging
scripting
host_permissions = http://127.0.0.1/*
```

没有常驻 `<all_urls>` content script，没有远程脚本，没有 `unsafe-eval`，没有扩展 storage、localStorage、console secret log 或 `innerHTML` 注入。

实现的交互包括：

- 主密码解锁与显式锁定；
- top-frame 字段发现；
- IDN、大小写和默认端口 Origin 规范化；
- 同域多账号选择；
- 密码策略展示、生成句柄、加密保存和失败重试提示；
- VDNS/对象/Origin 三重门禁后填充；
- 候选改密、新密码框填充与成功/失败/MFA/UNKNOWN/人工确认；
- 密码库、current version 来源、Verdict、版本历史、冲突说明和恢复动作。

### 2.5 Mock Site 日常闭环

新增 `internal/adapters/inbound/mocksiteweb` 和 E2E 用例：

```text
解锁
→ 生成并保存凭据
→ Mock Site 注册
→ 自动填充登录
→ 创建候选版本
→ 网站改密与回执
→ 激活 v2
→ 同步 publish/pull
→ 新设备加入与撤销
→ 网站离线时读取已验证本地 active v2
```

该场景不修改数据库，不依赖公网，不把 Pending 误报为 Completed。

## 3. 合同与测试

`api-test-suite-builder` 技能用于制定以下合同覆盖：

- 全局安装令牌、Host、Origin、nonce 和 session；
- 必填字段、未知字段、错误结构、尺寸和限速；
- 幂等重放、同键异 body 冲突和 handler 重启恢复；
- secret handle 一次消费、跨 Origin/会话拒绝；
- expectedVersion/descriptor CAS；
- UNKNOWN 不激活；
- 分页 cursor 和响应 shape；
- Native Messaging 长连接、帧上限与无秘密错误；
- OpenAPI 22 个 operationId 与实现清单一致。

完整门禁：

```sh
./scripts/check-g5.sh
G5_FUZZ_TIME=3s ./scripts/fuzz-g5.sh
```

结果：

- `g5-check-ok`；
- `g5-fuzz-ok`；
- 全量 `go test ./...` 通过；
- 全量非性能阈值 `go test -race ./...` 通过；
- OpenAPI/安全合同定向通过 20 项；
- 扩展 Node 测试 9/9 通过；
- SQLite `constraint_smoke_g5_ok`；
- HTTP strict JSON fuzz 30,071 次执行；
- Native Messaging fuzz 78,695 次执行；
- 一键日常演示通过。

race 插桩会显著改变密码学性能，因此竞态门禁跳过纯性能阈值用例；相同阈值仍在普通构建和独立证据测试中执行。

## 6. 研究边界

G5 的 Mock Site/E2E 使用本地 accepted projection 隔离验证传输、状态机和浏览器交互；G4 已独立验证真实 L1～L5、ProofBundle、日志一致性和检查点。生产组合必须继续通过既有 `DailyVaultService.StateDescriptorVerifier` 边界注入 G4 解析结果，不能把云端版本或扩展提示当作 current version。

`/exposure-analyses` 和 `/remediation-campaigns` 仍按合同返回 `501 OPTIONAL_FEATURE_UNAVAILABLE`，将在 G6 作为可选泄露响应增强实现，不进入日常密码管理主路径。
