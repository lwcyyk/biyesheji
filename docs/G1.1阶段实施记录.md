# G1.1 阶段实施记录

> 本文为历史阶段记录，其中VDNS-PM为VPass的旧名称。

日期：2026-07-23  
规范基线：`spec-001-v2.0.0-g0.2`  
目标：完成 VDNS-PM/2 的协议、密码学、本地解锁和持久化硬迁移底座。

阶段结论：**G1.1 的 13 项任务已全部满足完成定义，下一阶段进入 G2 日常密码库核心。**

## 1. 已实现范围

- 协议固定为 `VDNS-PM/2` 和 `VDNS-PM-CP-2`；
- CredentialID、EventID、CampaignID 固定为 32 字节，CP-1 协议、套件、旧枚举和错误宽度输入硬拒绝；
- 操作、能力、证据等级和对象类型切换到 v2 注册表；
- 主密码使用 Argon2id v1.3；RootCapsule 由主密码派生密钥和设备秘密共同解锁；
- Argon2id 参数策略支持受上下限约束的本机 P95 校准，校准使用独立随机材料，不接触用户真实主密码；
- RecoveryCapsule 只接受 32 字节高熵恢复秘密；
- `Kwrap`、`Kname`、`Kaudit`、`Krelation`、`Krotation` 及其子域完成严格分离；
- HPKE 切换到 X25519/HKDF-SHA256/AES-256-GCM，Info/AAD 绑定接收公钥指纹、发行序、秘密代际和外层对象类型，并加入 RFC 9180 向量；
- OriginBinding 接入规范化 Origin 与账号关系；
- 顶层 HTTPS Origin、opaque Origin、iframe、跨账号、扩展提示 ID 和 loopback 开发例外形成显式自动填充授权边界；
- Origin、用户名、密码、TOTP、恢复码和备注六字段接入 CP-2 AAD；
- 内存 VaultSession 持有解锁根、派生密钥和一次性 secret handle；显式锁定、空闲超时和绝对超时会销毁全部活动秘密；
- DeviceOperationCredential v2 根签名绑定设备认证/HPKE 公钥、Capability、四类 CredentialScope、有效序、发行计数器、状态引用和秘密代际；
- 新建库使用 `0002_v2_initial.sql`；CP-1 数据库只能进入显式导出、重加密和导入流程。

## 2. 关键失败安全结论

- 错误主密码、设备秘密、DeviceID、恢复秘密、KDF 参数、AAD 或密文均不能返回 RootSecretBundle；
- RootSecretBundle、Secret 和私钥默认拒绝通用序列化与日志输出；
- 字段密文不能跨 Credential、版本、字段、CryptoPolicyHash 或 OriginBinding 重放；
- 云端或数据库中的 16 字节 CP-1 CredentialID 不会被 v2 repository 静默接受；
- v1 SQLite 文件由运行时返回 `ErrExplicitCP2Migration`，不执行原位扩列或双格式读取。
- DeviceOperationCredential 的 Namespace、设备、Capability、Scope、最终序、撤销序、counter、statusRef 和 generation 任一不匹配均失败关闭；
- secret handle 绑定扩展安装、OriginBinding、CredentialID 和字段类型，且消费后不能重放。

## 4. G2 入口与未完成边界

G1.1 已完成，但以下工作属于 G2 及后续阶段，不得据此宣称 v2 产品整体完成：

- VaultProfile 和加密 RouteMap repository；
- 无偏密码生成器与版本化站点策略引擎；
- CredentialEnvelope/StateDescriptor v2、聚合 CAS 和耐久 outbox；
- `/api/v2` 会话、凭据创建/读取和自动填充资源的端到端集成；
- 10k/100k 查询基准、崩溃恢复和主路径故障注入；
- G3 之后的生命周期、多设备、VDNS L1～L5、审计和客户端。

G2 实现必须复用本阶段的 VaultSession、Origin 授权、字段加密和设备凭证边界，不得绕过这些验证直接从云对象返回密码明文。
