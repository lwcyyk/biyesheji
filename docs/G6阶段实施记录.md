# G6 阶段实施记录：隐私审计与可选事故响应

日期：2026-07-23  
阶段状态：完成  
任务范围：T-G6-001～T-G6-014

## 1. 阶段结论

G6 已在完整密码管理主线之上增加隐私安全检查和可选事故响应能力：

```text
Epoch 审计 key
  → ExactEncode + HMAC 隐藏见证
  → AEAD 加密使用事件
  → 本地耐久 outbox / 最小公开叶
  → AUDIT_ANALYZE 独立能力门禁
  → 重复、历史、陈旧、异常、回滚和冲突分析
  → 分页风险结果与证明查看

显式事故分析
  → 固定 IncidentSnapshot
  → AffectedRoot 绑定
  → 成本/恢复风险规划
  → Completed/Pending/Failed/Unknown
  → RotationRoot 与 attempt 防重放
```

日常解锁、查询、填充、同步和普通改密没有新增 SCOPE-ZK、通用 zkVM、链或 VRF 在线依赖。SCOPE-ZK 插件默认关闭，稳定返回 `OPTIONAL_FEATURE_UNAVAILABLE`；本阶段没有把模拟器输出冒充为零知识证明。

## 2. 隐私审计实现

### 2.1 Epoch key 与隐藏见证

G1 已实现的 `DeriveAuditKey` 继续作为唯一 Epoch key 原语，输入绑定 chain ID、NamespaceID、secret generation、Epoch 和 verified beacon hash。

隐藏见证复用：

```text
ReuseWitness = HMAC-SHA-256(Kaudit,e, ExactEncode(password))
```

`ReuseTag` 拒绝普通 JSON、文本和格式化输出。G6 新增 `ComputeAuditReuseTag`，只允许在活动 `VaultSession` 内派生；调用方得到的临时值在生成私有事件后立即清零。

### 2.2 加密使用事件与公开面

`PrivateUseEvent` 包含 CredentialID/版本、DeviceID、evidence level、粗粒度时间桶、descriptor digest 和 Epoch 隐藏见证。它使用确定性 CBOR 编码后立即交给既有 per-event AEAD。

公开透明叶仅包含：

```text
namespace_commitment
subject_pseudonym
object_type
object_digest
operation_type
final_sequence
epoch
```

公开叶不含密码、ReuseWitness、CredentialID、DeviceID、Origin、账号或 secret handle。只有加密对象和 outbox 在本地耐久后，使用事件才算已接收；日志包含和检查点锚定由后台完成，离线重试复用相同密文，不重新封装 nonce。

### 2.3 独立分析授权

`AuthorizeAnalysis` 同时验证：

1. L1～L5 全部通过且最终 Verdict 为 `ACCEPT`；
2. operation 为 `AUDIT_ANALYZE`；
3. 设备凭证含独立 `CapabilityAuditAnalyze`；
4. 根签设备凭证 digest、Namespace、Device 和 secret generation 与 Resolution 一致；
5. 每个目标 CredentialID 在私有 CredentialScope 内；
6. ProofBundle digest 和 subject context 与已验证 Resolution 一致；
7. 一次性 secret handle 存在且只在所有门禁通过后消费。

测试明确证明 `PUBLISH_AUDIT` 不隐含 `AUDIT_ANALYZE`。拒绝请求不会提前消费句柄，已消费句柄不能重放。

### 2.4 分析结果

分析器输出：

- `PASSWORD_REUSE`；
- `HISTORICAL_USE`；
- `STALE_CREDENTIAL`；
- `ANOMALOUS_DEVICE`；
- `ROLLBACK`；
- `CONFLICT`。

每项结果只保存本次分析的 Credential pseudonym、风险类型、证据置信度、证明对象摘要、时间桶和版本。结构中不存在密码、稳定 ReuseTag、DeviceID、CredentialID 或 secret handle。

预置真值测试得到强证据 precision/recall 均为 1。异常设备、陈旧、回滚和冲突结果都必须携带证明引用；两个及以上独立摘要标记为强证据。

## 3. API 与控制台

冻结 OpenAPI 的 `POST /security-analyses` 继续作为安全检查入口。密码候选不进入 HTTP JSON：

```text
dashboard password input
  → Native Messaging stageAuditAnalysisSecret
  → session-bound one-use handle
  → POST /security-analyses（无密码字段）
  → native-security-analysis result reference
  → readSecurityAnalysisResult 分页读取
```

控制台新增“隐私安全检查”，支持六类风险联合检查、20 项分页、HMAC scope-bound cursor、置信度显示和逐项展开 proof digest。输入框在提交后立即清空。

本地 Agent 是研究参考组合，使用本地 accepted projection；真实 L1～L5 和 ProofBundle 已在 G4 独立验证。G7 生产组合仍须在调用 G6 分析器前注入 G4 Resolution，不能把本地 UI 状态当成新的信任根。

## 4. 可选事故响应

### 4.1 插件边界

`internal/exposure/ports.Provider` 是可选证明系统端口。默认 `DisabledProvider` 返回：

```text
OPTIONAL_FEATURE_UNAVAILABLE
```

失败不会创建伪 Completed 分析，不影响 E1～E7 或日常密码路径。调用方和 provider 使用的事故见证副本均尽力清零。

### 4.2 IncidentSnapshot 与 AffectedRoot

IncidentSnapshot 固定 Namespace、起止时间桶、source checkpoint、incident commitment，以及按 CredentialID、时间桶、版本和事件摘要排序的证据项。

AffectedSet 只允许引用快照内 CredentialID，并按 CredentialID 去重排序。`AffectedRoot` 绑定 snapshot root、incident commitment、集合 Merkle root 和数量。

证明边界保持为：

> AffectedRoot 证明特定快照和集合的提交后绑定性，不单独证明分析语义正确或证据全局完整。

### 4.3 修复规划与真实结果

规划器支持：

```text
ROTATE_PASSWORD
REVOKE_SESSION
CHANGE_RECOVERY_CHANNEL
REMOVE_SSO_BINDING
RESET_MFA
REVOKE_DEVICE
REVOKE_API_TOKEN
```

每个候选动作携带成本、前置条件和恢复风险。规划器只从用户允许、前置条件已满足、恢复风险不超过阈值的动作中选择最低成本方案。

结果严格区分 `COMPLETED/PENDING/FAILED/UNKNOWN`。只有 Completed 进入 ChangedSet。Pending/Failed/Unknown 必须保持 old version 和所有字段摘要不变。改密 Completed 只允许 password 字段变化且新版本等于旧版本加一；任何越界 CredentialID 或无关字段变化均拒绝。

RotationRoot 以确定性顺序绑定 CampaignID、AffectedRoot、item/action、old/new version、attempt、outcome、evidence digest、Before/After 字段摘要、四态计数和 ChangedSet。每个 `(campaign, item, attempt)` 单调消费，旧 attempt 重放被拒绝。

## 9. 安全审查影响

本阶段按 STRIDE 和密码学边界审查重点落实：

1. Spoofing/Elevation：发布能力不等于分析能力，分析必须通过 G4 主体、scope 和撤销语义；
2. Tampering：快照、AffectedRoot、RotationRoot 和 attempt 单调性阻止换集、越界和重放；
3. Repudiation：finding 和修复结果携带证明/回执摘要；
4. Information Disclosure：见证只在 AEAD 内，结果和公开叶排除稳定秘密标识；
5. Denial of Service：请求、分页、事件、快照和集合均有尺寸上限；
6. Recovery safety：高锁定风险动作不能被低成本偏好绕过。
