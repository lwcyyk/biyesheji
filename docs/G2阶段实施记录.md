# G2 日常密码库核心阶段实施记录

日期：2026-07-23  
规范基线：`spec-001-v2.0.0-g0.2`  
阶段目标：完成 VDNS-PM 的本地密码库、可信控制对象、原子创建/读取和可恢复事件发布主路径。

阶段结论：**G2 的 12 项任务已形成可执行闭环，日常创建与读取不依赖区块链或零知识泄露分析；下一阶段进入 G3 生命周期、多设备与恢复。**

## 1. 本阶段交付

### 1.1 VaultProfile 与本地路由

- 追加迁移 `0003_g2_core.sql`，保留冻结的 `0002_v2_initial.sql`；
- VaultProfile repository 原子保存公开 profile、RootCapsule 和 RecoveryCapsule，重启后可恢复；
- 落库边界只接受加密胶囊和公开摘要，测试会直接扫描数据库文件，拒绝裸 `namespace_root`、签名 seed 和 mapping seed；
- RouteMap 以 `K_name` 派生的 `RouteID` 和 `OriginIndex` 建立私有索引；
- Origin 与 AccountID 使用不同 AAD、随机 nonce 分别加密；
- 支持同域多账号、精确查询、Origin 账号枚举、软删除、CAS 和重启恢复。

### 1.2 密码生成与策略

- 站点密码策略具有独立版本、确定性 CBOR 和 SHA-256 policy hash；
- 支持长度上下限、默认长度、字符类最小数量、允许符号和禁止字符；
- 密码生成使用操作系统 CSPRNG；
- 字符选择和 Fisher–Yates 洗牌均使用拒绝采样，不使用有偏的直接取模；
- 默认策略和自定义站点约束经过 1,000 组生成性质测试及精确桶分布测试。

### 1.3 CredentialEnvelope 与 StateDescriptor

- `CredentialEnvelope v2` 绑定 NamespaceID、CredentialID、版本、1～6 个升序字段引用、OriginBinding、VersionDraft binding hash 和 CryptoPolicyHash；
- CP-2 不公开低熵密码的无 key plaintext hash，字段 plaintext commitment 保持省略语义；
- `CredentialStateDescriptor v2` 绑定当前 Envelope、前序 descriptor、生命周期状态、最后操作事件、设备集合根、审计检查点、final sequence 和 updater device；
- StateDescriptor 通过统一 `SigInput` 域签名，使协议、套件、链、Namespace、KeyID 和 key generation 同时进入 Ed25519 签名；
- Envelope 和 StateDescriptor 均具有固定 KAT、规范编码往返、篡改和 fuzz 测试。

### 1.4 CAS、事件与 Outbox

- `credential_acceptance_v2` 同时保存 accepted version、descriptor hash、envelope hash 和 updated sequence；
- 初始接受要求 `v1 + previous=nil`，后续接受同时比较 expected version 和 expected descriptor hash；
- 同版本生命周期更新必须复用当前 Envelope，跨版本更新最多前进一版；
- 并发写入最多一个成功，失败事务不留下 Envelope、StateDescriptor 或 accepted pointer；
- OperationEvent、设备 counter、前序事件 hash、密文对象和 outbox 在同一事务提交；
- Outbox 支持持久租约、过期回收、退避时间、retry counter、错误码、幂等日志包含和冲突包含拒绝；
- 进程重启后，未过期租约不会被抢占，过期租约可由新 worker 取得。

### 1.5 创建与读取闭环

创建路径：

```text
trusted Origin + account
  → session 授权 OriginBinding
  → 无偏生成密码
  → Origin/Username/Password 字段级加密
  → 内容寻址对象 fsync
  → VersionDraft + CredentialEnvelope
  → 加密 CREATE 审计对象 + 设备签名事件
  → 签名 StateDescriptor
  → 单事务提交 Credential + RouteMap + Event + Outbox + AcceptedState
  → 返回单次 password handle
```

读取路径：

```text
trusted Origin + account
  → K_name 精确 RouteLookup
  → accepted control state
  → StateDescriptor verifier
  → Envelope/version/OriginBinding/policy/field reference
  → 内容寻址对象完整性
  → 字段 AEAD
  → session/origin/credential/field/expiry 绑定的一次性 handle
```

应用层只返回 handle，不返回密码字符串。`VaultSession` 继续独占 `K_wrap`、`K_name` 和审计派生密钥。

## 2. 关键失败安全性质

- RouteMap 指向错误 Credential 时，Envelope 的 OriginBinding 不匹配，读取失败；
- 云端或本地对象返回旧版、错误 digest 或篡改 CBOR 时，读取在解密前失败；
- StateDescriptor 签名、签名输入或 descriptor hash 任一变化均不能通过 verifier；
- 字段对象即使能被定位，也必须同时匹配 Envelope 引用、数据库 mapping、内容地址和 AEAD AAD；
- CREATE 事务在 Route 冲突、事件 counter 冲突、accepted CAS 冲突或注入式数据库失败时全部回滚；
- Outbox 重试只发布首次持久化的 CBOR、签名和对象地址，不重新封装随机 AEAD；
- secret handle 绑定 Session、InstallationID、OriginBinding、CredentialID、FieldType、过期时间和单次消费语义。

## 3. 实验结果

实验环境：

```text
OS/Arch: linux/amd64
CPU: AMD Ryzen 9 8945HX with Radeon Graphics
SQLite: 单连接、WAL、synchronous=FULL
```

基准命令和结果：

```text
BenchmarkRouteRepositoryResolveLookup/10000entries-16
20 iterations, 130746 ns/op

BenchmarkRouteRepositoryResolveLookup/100000entries-16
20 iterations, 114017 ns/op

BenchmarkDailyVaultRead-16
100 iterations, 1116278 ns/op

BenchmarkDailyVaultCreate-16
20 iterations, 37008092 ns/op
```

解释：

- 10k 与 100k RouteMap 精确查询均约为 `0.11～0.13 ms/op`，符合索引精确命中预期；
- 完整本地读取包含 Route、控制对象、签名验证、三层对象匹配、AEAD 和 handle 签发，约 `1.12 ms/op`；
- 创建包含三字段随机 AEAD、多个文件 fsync、事件加密和 SQLite FULL 同步事务，约 `37.0 ms/op`；
- 这些数值是本机原型证据，不代表跨设备同步或 VDNS 网络延迟。

故障注入已覆盖：

- Capsule、Route ciphertext/binding、Envelope、StateDescriptor、字段对象篡改；
- 并发 Credential/accepted CAS；
- accepted pointer 更新前注入数据库 abort；
- 重复 Origin/account 导致的创建事务回滚；
- Outbox 错误 lease、重试退避、worker 崩溃和数据库重启；
- 对象读取时的字节翻转；
- 错误 Origin/account、过期 handle 和 handle 重放。
