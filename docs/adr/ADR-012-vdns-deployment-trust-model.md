# ADR-012：VDNS 部署与信任模型

> 历史命名提示：当前组件展示名为可验证状态控制层、State Resolver和Local State Verifier；本ADR中旧术语用于保留决策历史。

- 状态：Accepted
- 日期：2026-07-31
- 追踪：FR-028～035；AC-009～010、AC-016、AC-021

## 背景

既有文档把 VDNS、透明日志、检查点和区块链放在同一控制平面中，没有完整说明各自的发布者、返回者和最终序生产者。当前仓库只有本地验证器、单进程日志、内存适配器和 Anvil 研究适配器，不存在多节点拜占庭共识。

## 决策

VDNS 在本项目中定义为：

> 以名称空间根授权、签名状态对象、透明历史、周期检查点和本地策略为基础的可验证凭据状态解析控制平面。

VDNS 不是传统 DNS，不解析公网域名到 IP，也不替代 DNSSEC。`CanonicalOrigin` 只在本地 RouteMap 中映射到随机 CredentialID。VDNS 解析的是该私有凭据标识对应的状态、版本、主体、授权和证明。

角色固定如下：

| 角色 | 责任 |
|---|---|
| 名称空间根控制者 | 签发/撤销设备能力凭证和根链对象；属于单用户名称空间的中心治理点 |
| 授权设备 | 签署候选生命周期事件和状态描述，不自行产生全局最终性 |
| VDNS Publisher | 校验候选格式并提交给排序/日志层；不能越权代表设备签名 |
| Final Order Authority | 为相互竞争事件产生唯一、可验证的最终序与排序回执 |
| Transparency Log | 追加已排序对象，返回包含/一致性证明和签名树头 |
| Checkpoint Publisher/Anchor | 周期聚合状态根并发布公告，不存储密码或逐次填充 |
| VDNS Resolver | 收集状态对象、能力、日志和检查点，返回候选解析包 |
| 本地 VDNS Verifier | 执行 L1～L5并作最终采信，是设备安全决策点 |
| Monitor/见证者 | 比较树头和公告，发现回滚、双视图与同版本双描述 |

中心治理部分是单个用户名称空间的根授权、恢复策略和冲突裁决。分布式验证部分是各设备、Monitor和见证者独立验证签名、证明、一致性和检查点。分布式验证不等于已经实现分布式共识。

区块链只是一种检查点公告 Provider。透明日志保存可证明的追加历史。VDNS把身份/状态对象与日志/检查点证明组织为解析结果。本地设备验证结果后才接受。链既不保存密码，也不参与普通自动填充。

当前原型的部署标签固定为：

```text
SINGLE_PROCESS_RESEARCH_LOG
SIMULATED_CHECKPOINT
ANVIL_RESEARCH_ADAPTER
NO_MULTI_NODE_CONSENSUS
```

## 后果

- 论文和UI不得把当前原型写成生产共识、生产链最终性或多节点VDNS网络。
- 第二阶段需实现 Final Order Authority 端口和签名回执；生产共识仍可保持后续工作。
- Resolver返回结果不自动可信，本地Verifier始终执行L1～L5。
