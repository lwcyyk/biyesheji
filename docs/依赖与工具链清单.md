## 兼容性与安全限制

1. CIRCL v1.6.4 要求 Go 1.24，因此答辩环境保持 Go 1.22 时锁定 v1.6.3。升级 Go 或 CIRCL 必须新建 ADR，并重新运行 RFC 9180 Appendix A.2 与项目上下文隔离向量。
2. CIRCL 的包注释仍保留早期 HPKE draft 表述；本项目不据此放宽套件。v2 只允许 `protocol-registry.md` 登记的 RFC 9180 代码点，并须以标准向量和项目上下文向量逐字节验证 `enc` 与 ciphertext。现有 ChaCha20-Poly1305 适配器属于 v1 迁移资产，在 AES-256-GCM 适配和 v2 KAT 完成前不得标记 CP-2 合规。
3. CBOR 库的通用 API 不等于协议策略。项目 wrapper 额外禁止 float、tag、不定长、重复 key、未知字段、非规范编码、非法 UTF-8、尾随数据和超限嵌套。
4. 所有依赖升级都必须由 `go get module@exact-version` 显式执行；禁止 `@latest`、浮动分支和伪装为格式化的静默升级。
5. 发布门禁必须运行单元/KAT、负向篡改、fuzz smoke、`go vet`、漏洞扫描、许可证扫描、秘密扫描和 SBOM 生成。高危发现未处置时不得形成发布基线。
6. Go 1.22 可编译的 modernc v1.36.1 内置 SQLite 3.49.0，落在 SQLite 官方披露的 WAL-reset 多连接竞争受影响范围。生产 adapter 因此强制 `MaxOpenConns=1` 和 `MaxIdleConns=1`；Monitor/CLI 只能走 API/IPC，不得同时直连数据库文件。只有升级到已包含 SQLite 3.51.3 或更新修复的驱动、重跑并发/崩溃实验并写 ADR 后，才可放开多连接。风险依据见 [SQLite 官方 WAL-reset 说明](https://www.sqlite.org/wal.html#the_wal_reset_bug)。

## v2 新增使用边界

- Argon2id 仅用于主密码本地解锁，参数进入 RootCapsule 并设置实现上限；不得在持有 SQLite writer lock 时运行。
- 浏览器扩展和本地 API 尚未引入 Node 依赖；选型时必须锁定版本并补充许可证、SBOM、CSP 和供应链审查。
- SCOPE-ZK/通用 zkVM 依赖尚未列为首版必需依赖；在 G6 选型前，系统应稳定返回可选功能不可用而不影响日常路径。
- v2 目标协议的 32 字节 CredentialID、RootCapsule、OriginBinding 和新枚举属于代码迁移工作，当前 `go.mod` 锁定不代表这些功能已经实现。
