# VPass 答辩讲稿

建议总时长 12～15 分钟，演示另留 3 分钟。

## 1. 开场

本课题首先是一个完整密码管理器：用户只记一个主密码，系统生成、保存、查询、填充、同步、更新和撤销各站点复杂密码。研究重点不是把密码写到区块链，也不是把泄露响应作为主线，而是验证每一次密码控制操作。

核心命题是：AEAD保护密码内容，可验证状态控制层保证凭据版本和生命周期状态可信。

## 2. 问题

即使同步存储层无法解密，合法旧密文仍可能通过 AEAD。若存储层返回旧密码，设备仍需要独立验证版本、主体、授权、撤销和历史。

## 3. 架构与密码学

用六个逻辑平面介绍前五层日常路径和第六层增强能力。强调随机名称空间根不是由主密码直接生成，主密码和设备高熵秘密共同解锁设备专属胶囊。字段独立 DEK 使只改密码时其他字段不变。

## 4. 自动填充与生命周期

自动填充先从本地 RouteMap 找到随机 CredentialID，再执行可信状态解析、验证 L1～L5、下载匹配 hash 的密文、核对 OriginBinding，最后通过一次性句柄填充。

网站改密使用耐久候选。页面跳转、表单提交都不是强确认；响应丢失进入 UNKNOWN/REVIEW，不猜测。

## 5. 可信状态与同步

设备签名只回答“谁持有私钥”，能力凭证回答“当时是否有权操作”。同步存储层只是密文对象分发者，当前版本由设备验证。返回版本低于可信当前版本或 hash 不一致时直接拒绝。

## 6. 隐私审计

Epoch 见证只进入加密事件，公开叶不含密码、域名、账号或稳定复用标签。SCOPE-ZK 是可选事故模块，当前未配置，证据中的 proof 指标是 null，不宣称已经实现。

## 7. 实验

突出四个结果：

- 解锁 P95 392.85 ms；
- 10k 对象分批同步 P95 614.70 ms；
- 百万叶证明验证 P95 16.79 μs、20 个哈希；
- 100k 审计扫描 563.62 ms。

再说明 8/8 故障和 7/7 恢复演练通过。消融不是隐藏弱模式，而是 test-only 决策模型，用于展示移除机制后的风险。

## 8. 负面结果

主动说明：

- 单份 10k manifest 超过 64 KiB，当前按 100×100 分批；
- 升级前发现 30 个可达漏洞，升级后为 0，前后证据均保留；
- 浏览器、移动端和生产链没有实测；
- SCOPE-ZK 未配置。

## 9. 演示

```bash
demo_dir="$(mktemp -d)"
./scripts/demo-vpass.sh --data-dir "${demo_dir}"
```

展示初始化、创建/填充、同步、更新确认、撤销、离线、可信状态、审计和 optional unavailable。不要展示任何真实密码库。

## 10. 收束

本文的主要贡献是把当前密码的裁判权从不可信同步存储层交回每台验证设备。隐私审计和泄露响应建立在可信生命周期之上，不改变系统的密码管理器定位。
