# 成熟转换与随机带保持审查

日期 2026-11-06。仅在同功能、同暴露和同量词下判断覆盖。普通算法的随机化性质与完整带返回分别登记。

## 1. RC26 的覆盖范围

RC26 Definition 3/Fig.2 明确普通 Enc/Upd 返回随机带，挑战等价链的带隐藏。RISE 的输入关系 x_{e+1}=δ_{e+1}x_e 允许从旧钥匙和 token 正向取得新钥匙，也允许反向取得旧钥匙；其双向钥匙闭包会将“旧 K1＋全部 token＋第2代挑战”判为平凡胜利。

所以 RC26 的 RISE 定理直接覆盖双向模型中的普通随机带目标，不覆盖本轮允许的单向恢复 profile。只改方向名称或元数据无法改变可计算关系。它可提供底层 modified ElGamal 的域和诚实普通带模拟方法。

## 2. GP23 的泛型变换：本轮成熟覆盖

GP23 Fig.5 只依赖 key-homomorphic、message-homomorphic PKE。其公开迁移倍率处理旧坐标，新的独立最后坐标承载下一代保护。图中 ciphertext/keys 的代次增长是能力和成本的一部分，不能省略后再与常数长度方案比较。

本轮 profile 在该变换上具体采用 modified ElGamal，公开目标键上下文显式化。完整映射如下：

| 新游戏接口 | 原构造及模拟 | 暴露条件 |
|---|---|---|
| EncLeak | Fig.5 Enc；当前公钥向量可计算，诚实采 pad/指数并返回所有位 | 不需要未知钥匙标量；包含 pad 的采样带 |
| UpdLeak | 实际 KHC、消息同态乘法、新坐标加密 | token 倍率及目标公钥均已知；重复输入独立采样 |
| Challenge fresh/update | 更新分支的隐藏带通过统一平移/乘法双射新鲜化 | 父对象及普通带可全部固定，仍精确同分布 |
| Next/公开 token | Fig.5 新增独立秘密坐标；已知倍率维护未知锚公钥 | Next 带隐藏；不能把新钥匙采样值算作普通带 |
| 合法历史 Corrupt | K1 完整已知；未来完整钥匙因公开 token 闭包禁止 | 同一轨迹的所有检查一致 |
| 后续挑战版本 | 对同一编码挑战执行实际公共 Upd | 不打开挑战初始未知指数 |

定理 UNI-1 给 DDH* 下的完整证明，固定切点损失 1。它无需 GP23 的 IND$ 中间定义，因为对受限 profile 可以直接用 DDH 随机掩码；这不构成对原文 `2l²` 更广游戏归约的紧致性改进。

因此当前增强目标在登记的受限模型中得到**成熟组合覆盖**。若目标扩展到动态合法腐化区域，仍需按相应切点建立联合模拟，不能由一行公开后处理推全量词结论。

## 3. MPW23：KPHE 转换的接口障碍

正式章取得并核对 §2 的 KPHE 与 Fig.3 blinding、§3 泛型 UE。KPHE 的 PKGen 是 `PKGen(pp,sk;ρ_pk)`，普通 UE.Enc 会重新生成公钥。已有 blinding 游戏提供变换后的公钥/密文，不提供与其相符的 PKGen/Eval 全随机带；原证明还会把普通更新换成新鲜输出。

因此，已知某个编码公钥并不自动足以诚实运行**读取秘密 sk 的**随机 PKGen。要搬用 R2-LOCAL，需证明相应具体实例的公开可执行接口，或给带打开的增强 blinding/联合未来钥匙模拟。普通输出边缘相同不能替代此条件。

正式章将具体 DDH KPHE 和多条详细归约委托 ePrint 2022/311；扩展 PDF 本轮仍为挑战 HTML。本文保留“随机带保持未核实”，没有把这个接口障碍转成对 MPW23 实方案的攻击；也没有深入第三个具体构造。

## 4. 其它方向/公钥转换

GP23 的 no-directional/backward-leak 游戏等价涉及原闭包和原 oracle；带暴露加入后仍须逐接口证明带的一致联合视图，原等价声明本身未完成该步骤。

GP23 §6 bootstrappable PKE 的 Recrypt 只给输出与新鲜加密的关系。若普通 Recrypt/Upd 带需返回，应保持其真实执行带；若模拟器把结果替为 fresh Enc，还须给相容打开。单独 bootstrappability 不蕴含一般 randomness-compromise 安全。

原 TIPE/DSG 资料等待线保持独立，不影响本轮已经固定的 GP23 证明；分叉和 CCA 仍在本 profile 范围之外。

## 5. 同条件最强基线和判废

当前最强直接适用的成熟 G 允许使用相同的群、预处理、公钥缓存、批处理和 GP23 逐代坐标结构。它实现相同的 UNI-R-CPA-1 功能及暴露合同。本轮主对象就是这个成熟组合的具体化，故没有输入族能在已登记度量上证明 G 必须付更高成本。

资源包括每代密钥、密文、token、通信、群运算、可信缓存、旧状态擦除、恢复/重试和参数损失。当前没有提出资源优势或候选协议实现。Frodo 的安全反例只支持淘汰该具体路线，不能充当相对安全强基线的资源分离。

后续若重开算法优化或新机制，仍须先给具体输入族、固定目标、最强同条件方法、完整度量、严格代价实例和判废条件。当前实现门未通过。
