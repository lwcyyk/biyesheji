# 后续验证计划

版本G1-r01；PLAN_ONLY。以下全部为待运行计划，本轮实际新增实验、测试重跑和原生请求均为0。历史证据只按原版本复用；本计划不授予执行、建户、真实共享、轮换、撤回或外发资格。

## 1. 共用验证协议 V0

每项同时指定实现/source/profile摘要、当前权威版本、用户或实验批准、允许账户/接口、预算、故障屏障、运行可见信息和独立评分真值。真值仅事后用于判断，运行者只消费其本来获准取得的信息。

固定安全合同后，双方使用相同原生能力、可信组件、缓存/结构/预处理、失败条件、预算和清理权限。强基线G*按06定义，具体实现与最强适用性在未来实验前固定；无法保持同条件的比较单列。

成熟工程的验收需另定范围/源码/授权；候选算法或求解器还需通过严格分离门。涉及真实服务的操作另需明确授权。产品组件缺失的场景先做合同/能力验证。本轮各项统一记`NOT_RUN`，历史已有运行另列。

## 4. 指标和分母

| 指标 | 定义与分母 | 解释要求 |
|---|---|---|
| 错误准入 | 当前合同禁止却被新放行的次数/可评价准入尝试 | 已合法放行后撤回的在途调用按原合同单列 |
| 错误关闭 | 声明scope内仍有可能/实际未关闭却宣告关闭的次数/可评价关闭声明 | 源真值不足时记INCONCLUSIVE，不填0 |
| 遗漏义务 | 已确认应登记但缺失的创建/派生/在途责任数/可评价责任总数 | 源完整性本身未证时加缺证标志 |
| 合法任务完成 | 完整合法业务完成数/预先确认属于目标可行分布的任务 | 拒绝、诊断任务、未触发故障另表 |
| 合同维护 | 源/profile变更后读源、重抽象、重检查、缓存失效工作 | 包含人工成本和维护范围；不只计求解器 |
| 分析费用 | 模型/图建立、求解、检查、拒绝/超限、恢复总成本 | 算法基本操作、CPU/内存按同定义 |
| 原生总费用 | 环境+方法+测量+清理+后续修复请求，分项保留 | 机会预记账/实际发送/AS效果数分别计；失败也收费 |
| 其他用户代价 | 批准次数、读取曝光、额外可信组件、暂停/完成时间 | 安全合同保持相同才比较 |

UNKNOWN为运行结论，TIMEOUT为时限事件，REJECTED为准入结果，模型内IMPOSSIBLE为固定scope结论，ABORTED为执行中止，NOT_TRIGGERED为预定故障未到达，NOT_RUN为未执行。它们各自保留。初始化槽、原生轨迹、方法运行、配对、历史离线修订及回归测试使用各自分母。

## 5. 从计划进入执行的条件

先完成固定profile的源后继/容量证明与版本绑定，再审查映射适用范围；工程接线或既有缺陷维护另列范围与验收。新候选的实现/求解器/穷尽测试需先有具体输入族、度量、最强同条件G、必要更高代价和严格实例，完整费用不能遗漏。原生操作在此基础上还需账户/接口/预算/清理的明确授权。

本轮只提交计划，没有生成故障注入器、模型求解器、参考实现或实验运行结果。
