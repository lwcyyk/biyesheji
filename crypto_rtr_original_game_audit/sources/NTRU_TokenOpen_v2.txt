                                           Abstract
Updatable encryption (UE) allows a client to outsource ciphertexts to a untrusted server and
periodically rotate the encryption key. The server can update ciphertexts from an old key to a
new key via an update token generated by the client without revealing anything about
plaintexts. In this paper, we presented a new security model of UE, which allowed the
adversary to corrupt all update tokens and keys of the past epochs. We showed that this model
reflected the updating characteristics of UE. Then we constructed a UE scheme based on
NTRU, named NTRU-UE. In our new scheme, the key-switching technique was used to
achieve backward-leak uni-directional key update and uni-directional ciphertext update and
the ciphertext-masking technique was used to achieve rand-update. We proved the security of
the scheme under our security model. In addition, we estimated the security levels in
classical/quantum model, gave the implementation efficiency of the scheme, and the number
of times the key can be updated under our recommended parameters.

Keywords: updatable encryption, post-quantum schemes, Token Open secure, NTRU

1. Introduction
1.1 Updatable Encryption
As an emerging network storage technology in the cloud era, cloud storage can make full use
of the storage capacity of existing hardware and provide nearly unlimited storage space for
users. According to SP800-57 [9] issued by NIST, keys have strict lifetimes and rotating keys
regularly is a common requirement in practice. When a user stores encrypted data on a cloud
server, the traditional way to rotate the key is to download the old ciphertext, decrypt it with
the old key, re-encrypt it with the new key and re-upload the new ciphertext. This way is
expensive because it requires lots of computing cost and communication cost for the user.
Updatable encryption (UE), first proposed by Boneh et al. [1], provides a better solution for
key rotation, in which the period the key is valid is called an epoch. (Denote the index of an
epoch with e .) The user uploads the ciphertext encrypted by the UE scheme to the cloud
server. If the user needs to update the key, he computes an update token (  e1 ) via the old key
( ke ) and the new key ( ke 1 ), and sends it to the server. The server uses the update token to
update the old ciphertext to the ciphertext encrypted by the new key. Using the UE scheme
can greatly reduce the computing cost and communication cost for the user.
1.2 Related work
In the research of updatable encryption, Boneh et al. [1] first constructed a UE scheme based
on key homomorphic pseudorandom function and symmetric cryptographic algorithm in 2013,
named BLMR. Although it is a ciphertext-dependent scheme, its idea guides the design of UE
scheme. Boneh et al. presented a simple security model with weak security strength. In 2018,
Lehmann and Tackmann [3] constructed a ciphertext-independent scheme based on the
EIGamal scheme, named RISE. And they presented two indistinguishable security models,
named IND-ENC and IND-UPD. In 2019, Boyd et al. [5] constructed a ciphertext- independent
UE scheme based on the DDH hard assumption and pseudorandom permutation, named
SHINE, and presented a new indistinguishable security model, named IND-UE.
     In 2020, Yao Jiang [6] presented the first post-quantum UE scheme based on the LWE
assumption, named LWEUE. She believed that the ideal UE scheme should have
no-directional key update, uni-directional ciphertext update settings, and proposed an open
problem: finding a no-directional key update scheme. In 2021, Nishimaki [7] firstly solved the
open problem proposed by Jiang and constructed a no-directional key update UE scheme based
on indistinguishable obfuscation, named UEio. Nishimaki presented a new key update type
named backward-leak uni-directional key update setting and constructed the first
b-uni-directional key update UE scheme, named RtR. In 2022, Song and Gao [26] presented a
new security model, named Token Open security model, which allows the adversary to corrupt
all update tokens.
     In the research of NTRU-like encryption system, Hoffstein et al. [22] proposed the NTRU
public-key cryptosystem in 1996, which is based on the NTRU assumption on the NTRU
lattice. Although it lacks formal security proofs, no effective attack has emerged in more than
two decades since it was proposed. In 2002, Banks and Shparlinski [23] modified the original
NTRU scheme and proved that in some cases the public keys of the scheme are almost
uniformly distributed. In 2011, Stehlé and Steinfeld [24] reduced the NTRU assumption using
the Gaussian distribution to the worst-case hard problem on the ideal lattice. They gave a new
NTRU-like scheme with IND-CPA proof under the RLWE assumption, but the parameter
requirements are not practical. In 2017, NIST solicited post-quantum cryptographic
algorithms, and NTRU was shortlisted for the third round of key encapsulation algorithms,
but the public key encryption algorithm within it can only achieve OW-CPA security. In 2017,
NIST solicited post-quantum cryptographic algorithms, of which NTRU was selected third
round of key encapsulation algorithms, but the public key encryption algorithm within it can
only achieve OW-CPA security. In 2019, Seck et al. [25] proposed a new provably secure
NTRU-like scheme with double-keys and double-ciphertexts.
     We believe the newly presented security model in [26] is closer to the real attack scenario,
because in the practical application of UE, the user and the server should use an open channel
to transmit the update token. We follow the study in [26] and improve it. In addition, there is
no updatable encryption scheme based on NTRU, which has the advantages of simple structure,
smaller size, and fast computation speed. Therefore, from the current research status and
practical application scenarios, we hope to design a ciphertext-independent UE scheme based
on the NTRU-like encryption scheme with backward-leak uni-directional key update and
uni-directional ciphertext update. More importantly, the user and the server can use an open
channel to transmit update tokens with post-quantum secure property.
1.3 Our contribution
    Our first work is presenting a new security model for UE on the basis of the security
model in [26], which is the TKOpen security model. In the TKOpen experiment, we design
intuitive and efficient oracles for the challenger and give the adversary as much attack power
as possible. Intuitively, the adversary is allowed to corrupt tokens of all epochs and keys of
the past epochs. Then the adversary submits a plaintext and an old ciphertext at the challenge
epoch to the challenger and obtains a new challenge ciphertext and distinguishes whether the
ciphertext is the encryption of the plaintext or the update ciphertext of the old ciphertext. The
new model conforms to the practical application of UE scheme that the user and the server
use an open channel to transmit the update token and reflects the updating characteristics of
UE.
    Our second work is proving the relationship between the TKOpen security model and the
scheme update setting. According to the randomness of the ciphertext update, the direction of
key update and the direction of ciphertext update, we categorize UE schemes into 16 types.
They are in xx-(kk,cc) settings, where xx∈{det,rand}, kk∈{no,f-uni,b-uni,bb}, cc∈{uni,bi}.
Through Lemma 1-4, we show that most of the 16 UE scheme types are not secure in the
TKOpen security model, but only the schemes in rand-(b-uni/no, uni) setting are secure in the
TKOpen security model. That is, (1) If a UE scheme is TKOpen secure, it is a rand-update
scheme with b-uni-directional or no-directional key update and uni-directional ciphertext
update. Then, we further discuss the relationship between b-uni-directional key update and
no-directional key update. That is, (2) In the TKOpen security model, b-uni-directional key
update and no-directional key update are equivalent.
   Our third work is constructing the first UE scheme based on NTRU, named NTRU-UE.
First, we successfully generalize the key-switching technique to the ring Rq =

2. Preliminaries
2.1 Classification of UE schemes
According to the independence of ciphertext, we categorize UE schemes into two types. One
is the ciphertext-dependent scheme. The user needs to pre-store or download the ciphertext or
part of the ciphertext from the cloud server when generating tokens. The other is the
ciphertext- independent scheme. The user does not need ciphertext when generating tokens.
This paper focuses on the ciphertext-independent scheme.
     According to the randomness of the ciphertext update, we categorize UE schemes into
two types. One is the det-update scheme. The ciphertext update algorithm is deterministic so
that the same ciphertexts are updated to the same ciphertexts via the token. The other is the
rand-update scheme. The ciphertext update algorithm is randomized so that the same
ciphertexts are updated to different ciphertexts via the token.
     According to the direction of the ciphertext update, we categorize UE schemes into two
types. One is the bi-directional ciphertext update scheme. The user can update the ciphertext
or downgrade the ciphertext via the token. The other is the uni-directional ciphertext update
scheme. The user can update the ciphertext but cannot downgrade the ciphertext via the
token.
     According to the direction of key update, we categorize UE schemes into four types. The
first is the bi- directional key update scheme. The user can derive ke 1 (the new key) from ke

(the old key) and  e1 (the token), or derive ke from ke 1 and  e1 . The second is the

forward-leak uni-directional key update scheme (abbreviated as f-uni-directional). The user
can only derive ke 1 from ke and  e1 . The third is the backward-leak uni-directional key

update scheme (abbreviated as b-uni-directional key). The user can only derive ke from ke 1

and  e1 . The fourth is the no-directional key update scheme. The user cannot derive keys

from the token.

3. TKOpen Security Model
In the pratical application of UE, the user and the server should use an open channel to
transmit the update token. Otherwise, the user and the server need to use a secure channel to
transmit the update token (that is sharing another encryption scheme), which will bring great
inconvenience. Aiming at the above problems, the Token Open security model was presented
recently in [26]. However, in the Token Open security model, the adversary submits two
plaintexts then obtains an encrypted ciphertext and distinguishes the original plaintext. We
improved it to TKOpen security model. In TKOpen, the adversary can corrupt tokens of all
epochs and keys of the past epochs. The adversary submits a plaintext and an old ciphertext
then obtains a new ciphertext and distinguishes whether the challenge ciphertext is the
encryption of the plaintext or the update ciphertext of the old ciphertext. Thus, the TKOpen
security model reflects the updating characteristics of UE.

4. Description of Schemes
In this section, we first present a NTRU-like PKE scheme and then construct our NTRU-UE
based on the PKE scheme. Our scheme is a rand-update UE scheme in backward-leak
uni-directional key update and uni-directional ciphertext update settings. We will prove in the
next section that this UE scheme satisfies the TKOpen security model.
4.1 IND-CPA secure NTRU-like PKE
Most of the existing practicable NTRU schemes (e.g., NTRUEncrypt,NTRU-Prime) do not
satisfy the IND-CPA security proof, and the schemes secure under IND-CPA [24,26] are too
loose in error rate estimation and have poor practicability. We design the new NTRU-like
PKE, the scheme is secure under IND-CPA, and the scheme satisfies the practicality
requirement under the tight estimation of decryption error rate condition.

Theorem 5. NTRU-UE is rand-TKOpen-CPA secure under the RLWE assumption.
Proof. Under the Token Open security model, the attack advantage of adversary against
NTRU-UE is the attack advantage against Game0b .
     According to Lemma 7 – 10, we have that Game0b and Game4b are distinguishable for

    In summary, NTRU-UE is rand-TKOpen-CPA secure under the RLWE assumption.
