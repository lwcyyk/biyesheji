## 2. CiC Appendix B到当前残差的具体代入

CiC附录的结构是

\[
e_{\rm out}=\langle x,\mathrm{BD}(c_1)\rangle
+e_{\rm fresh}+e_{\rm ct}.
\]

在T22的RtR转录算法上逐项代入：

| CiC结构项 | RtR对应项 |
|---|---|
| 已知接收方解密秘密 | 未来完整Key中的S₃ |
| 已知二进制父特征 | H=BD(u) |
| 固定重加密钥匙误差作用 | HR_gE₃ |
| 固定父噪声 | η_C=aE₂+e′ |
| 每次fresh噪声 | r̃_iR_tE₃ |
| 观测来源 | 本地从输出密文计算c′−u′S₃ |

故其平均思路可直接用于估计μ_C=η_C+HR_gE₃。当前下一步利用

\[
\eta_C=c-uS_2-\mathrm{Encode}(M_0),\quad
uS_2=HP_2(S_2)\pmod q
\]

把估计结果转换成HAΔ。这个变换避免先恢复附录中的x或完整源秘密；之后使用已有诚实父生成模工具，转为fresh/update标签分类。±1条件方差／cosh尾界也是标准Rademacher浓缩工具。

因此，**“隐藏有效随机性后仍可平均攻击”方法已被直接覆盖**。RtR的具体代入、共同提升、诚实分布覆盖和原闭包合法性是本轮必须独立完成的映射责任，不能从“二者都是格PRE/UE”直接跳过。

## 3. HRA接口的精确区别

CiC2025 Definition7在phase2预先计算每对钥匙的重加密钥匙，普通ReEnc使用对应固定对象。这与候选RtR同边界隐藏token复用的局部实验相匹配。

本轮取得的DDLM修订稿Fig.5则允许输入可选Δ；没有提供Δ时，oracle会现场调用ReKeyGen。普通父在诚实登记中保留，诚实到腐化目标的普通重加密允许。由此可见，固定未知token复用和每次重新生成token的联合分布各有定义，不能仅凭HRA名称宣布二者字节级等价。

更完整的迁移还需处理：

- PRE预先选腐化目标与UE在Next后才揭示未来Key：对独立epoch钥匙和当前固定轨迹，可先采全部钥匙、按时揭示，这是分布表示；正式RtR的全部条件仍需原文确认。
- PRE挑战是fresh加密M_b，UE挑战是Enc(M₀)或Upd(已登记M₁父)。HRA安全性、source hiding和fresh/update安全的蕴含需要实际定理，挑战形式差异不能略过。
- UE的K*/T*/C*终局与PRE的挑战派生图分别评分。当前原图缺口直接影响合法性，已有PRE攻击不替代这项认证。
- RtR初始χns及每次r̃R_tE₃的幅度分配，决定当前平均预算；DDLM的ring乘法和重采样误差公式不能直接作为RtR数值界。

DDLM正文还给HRA、PCS、source-hiding间的蕴含与分离，故这里没有采用“HRA安全自动等于所有UE fresh/update安全”的扩大命题。

## 4. 源定理参数账本：已知与缺项

T22 L1157–1164将以下条件关联到Theorems4.1／4.2：

| 量／约束 | 转录证据 | 当前认证 |
|---|---|---|
| λ | Setup(1^λ)，PPT实验 | 明确；n等与λ的完整约束缺预备段 |
| n,m,ℓ,q | pp显式含1^n、1^m、1^ℓ及q；A为m×n | 算法类型明确，q允许域与选择顺序缺完整源 |
| χ，B | Reg.Gen公钥误差，B-bounded | 具体分布族、bounded定义及尾部量词缺原文 |
| χns，B′ | 仅Reg.Enc抽样，B′-bounded；B/B′=negl(λ) | 大初始smudging可确认其位置；完整分布／平移性质缺项 |
| η | ceil(log₂q) | 明确 |
| m正确性条件 | 转录m=2n log₂q＋ω项，及F≤q/(4T) | 复杂式原图待核，本文计算包络留充分余量 |
| m安全性条件 | m≥(n+ℓ)log₂q+ω(logλ) | 转录明确，全部隐含前提待核 |
| 最大epoch T | 0≤e≤T，正确性定理使用 | 轨迹需至少2；示例T=3 |
| 查询上限 | 已读游戏无父限次／具体Q上限 | 仍需全文；PPT总时间始终约束调用 |
| 安全假设 | LWE(n,q,χ)，均匀秘密，公开共享A | 具体参数限制、采样量和困难性来源缺预备段 |
| 优势 | Def.2.3两实验输出1概率差绝对值 | 是gap口径，非CiC的平方优势 |

如果χ的真实数值宽度随q一起超多项式，均值充分预算可能超多项式；若源定理允许多项式宽度而将大χns放在固定父中，则该大初始项本身不构成平均复杂度障碍。本轮不把其中任一选择擅自赋给完整源参数。

RTR文件的P★验证了可见不等式有共同正确、多项式计算包络。它尚未获得“全部源安全定理量词范围”证书；对应精确LWE假设H★的困难性来源也缺项。故P★仅承担参数相容性检查，没有被登记为原定理反例实例。

## 5. 若出现定理冲突，应核对的顺序

1. **版本：** S22完整算法／游戏是否与T22一致；E24是否改变RtR或仅调整另一构造。
2. **合法性：** Fig.1的C语句列归属、完整T*/C*闭包及未来完整Key限制。
3. **行为：** 同一隐藏token、同父重复、独立±1新币及完整坐标；是否有遗漏的新鲜噪声／舍入。
4. **正确性：** B′、固定Key误差和一次／两次更新须同一参数；±1支撑的mean-update用凸区间或严格界证明。
5. **量词／假设：** n、q、χ的允许域及选择顺序、预算相关噪声条件、对应LWE样本与时间预算。
6. **完整模拟：** T22 Eq.(1)／Lemma4.2的边缘smudging是否覆盖父、多个响应和未来完整S的联合视图；右firewall处的普通Upd是否可模拟。

若以上全部通过且σ_k²为多项式，则RTR条件定理给常数gap，具体冲突对象是**Theorem4.2的(b-uni,uni)-r-IND-UE-CPA结论**。当前仅能指出这个潜在冲突位置和优先模拟责任，正式引理错误尚未得到完整原文反例认证。
