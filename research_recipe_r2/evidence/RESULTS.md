未决条件合计 156：132 项停止目标因批准撤回未满足，24 项未知创建材料在所登记离线资源策略下仍可验证。账户根处置使授权方判定失效，不会自动取消离线 JWT 的签名/期限有效性。这些值未删除、未写成“全部清理完成”。

故障运行中 240 次到达并触发所定事件，144 次因为方法未到达相应点而未触发。未触发不计抵抗成功。零 E/FA 仅表示这批已记录运行没有观察到相应事件，不证明 H-S，也不能消除 156 项未结条件。

## 3. 成本与比较

| 比较 | 主要成本的候选均值 | 基线均值 | 均值比 | 合法完成率差 |

较高均值包含失败惩罚：不完成时 C_Q=65、C_G=9；不能只用成功者平均替换。实际方法请求共 744 次，其中认证服务请求 588 次、资源/代理 HTTP 控制请求 156 次。包含实验建户、复位和独立测量的原生 HTTP 总量另记为 5,652 次，不隐藏这些基础设施开销。

运行主体耗时约 208.89 秒；每次方法及其测量段的最大记录时间约 0.661 秒。安装、服务首次构建/启动是单独基础设施成本，不混入每次认证请求。求解时间、缓存命中和逐请求时间均在原始日志中；单机单批测量不用于尾部延迟或速度优越性推断。

本轮 A/AB 的 query 选择和具体 B 反馈均未激活，因为输入为共同已知契约。它们是必要的无收益负控制，**不能据此估计查询需求分布上的 H-A/H-AB 效应**。B 的本子域也与强组合等效，没有通过调整 G 或额外接口保留优势。

## 4. R-J 补充对照

[reference02](../../results/experiments/reference02/runs.json) 对两个原生实现各运行 A1/R-J 一次，使用相同目标、G、接口、批准和预算，另行保存而不混入三项主比较。

两种实现上均合法完成，G=2。A1 总 Q=5，R-J 总 Q=3；两者认证服务请求同为 3，差异是 A1 重复关闭代理门控的两次 HTTP 调用。W_r 保证有限进度，不保证最少请求；R-J 直接选择能完成目标的原生撤销动作。

这暴露了当前控制选择的工程冗余。没有为追平参考改成本函数或候选源码，也不据此声称新的信息获取与控制原理。该对照同样只是已知契约子域，不代表原生 probe/configure/stop/cleanup 全联合故障策略已经验证。

## 5. 家族数量、方差与 ICC

每个实现有四个操作性家族，但仅一个构造谱系，独立性获确认的家族为 0。账户、重复和种子不增加这个数量。正式推断的前提不满足。

| 成本 / 实现 | 基线运行成本方差 | 原始成本 ICC 描述估计 |
|---|---:|---:|
| C_Q / Keycloak | 549.9415 | 0.0466 |
| C_Q / Casdoor | 736.5957 | −0.0411 |
| C_G / Keycloak | 8.5514 | 0.0410 |
| C_G / Casdoor | 11.3121 | −0.0467 |

这些是四簇下的不稳定描述值，不能据负值宣称没有家族依赖。候选−基线的配对成本差分方差为 0，其 ICC 因退化而**不可估**，没有填成 0 作为功效依据。单方法原始成本 ICC 也不能冒充配对影响量的 ICC。

按实现分层、家族整簇配对 bootstrap 的计算程序已运行，10,000 次、种子 20261102。名义单侧参数为 98.333%，但结果只保留为描述分位数：R 区间退化为 1，ΔU 为 0。家族过少且未证独立，**不能将其当成统计等效证明或正式反驳/支持**。

## 6. 功效与样本量

结论是 `NO_DEFENSIBLE_EMPIRICAL_SAMPLE_SIZE_YET`。当前负控制既没有表现出优势，也不能估计目标 D_A/D_AB 的效应方差；零差分不能推出极小样本量。若未来真实成本比在阈值上或更差，增大 N 不能创造所要求的优势功效。

另保存 216 组条件敏感性计算，明确不是经验样本量建议。成本参数的 SD 是 `C/μ_C − B/μ_B` 这一配对影响量对**均值比取对数**的标准差，不是个体 log(C/B) 的标准差。

例如假设真实比值为 0.70（H-A/H-B）或 0.75（H-AB）、影响量 SD=0.4、基线完成率 0.95、配对相关 0.5、配对贡献 ICC=0.2、每家族 12 对、两个实现等权，保守正态/设计效应近似给出每实现约 30 个家族。成本分量约需 14/14/16，非劣分量约需 30。

这里为了联合交并判定目标功效 0.80，使用各分量功效 0.90 的保守失效概率分配；**没有改变 α=0.05/3**。这一近似仍需联合 bootstrap 功效模拟与分布校验，不能把“30”写成已经足够或已经获研究者认可。

## 7. 修正与证据保留

- `survey01` 为初始调查，未在启动时记录完整源码哈希，保留为开发记录；后续调查补齐哈希/源码归档。各次调查不是新增独立实现。
- `smoke01` 为 16 次连通运行，不并入最终预实验。
- `pilot01` 原样保留。复核发现初始资源评分曾参与提前中止判断；最终 `pilot02` 删除该控制依赖，恢复决定也不使用评分器私有结果。主要计数未改变，但最终分析以修正后数据为准。
- `analysis01` 原样保留。功效说明从分量目标澄清为联合 IUT 功效，并明确影响量 SD；最终使用 `analysis02/03`。原始运行数据和成本函数未改。
- [信息隔离检查](../../results/experiments/information_isolation.json) 故意给评分器不利私有结果，验证方法仍按自己的观察执行，随后由独立评分判为不合法；这是合成单元检查，不是原生安全事件。
- [补充验证](../../results/experiments/validation_checks.json) 还验证了缺失配对臂保留为明确标记的分析惩罚占位，未伪造新的执行记录。
- 预实验后仅补充了发行版下载的幂等校验和新环境锁路径选项；默认算法、执行和评分逻辑未改。数据附带当时源码归档，交付清单另外标识当前工具源码，不将两者混作同一提交。

## 8. 测试与复现边界

当前全项目 96 个自动测试通过（原 77+新增 19），原 27 回归和 5,184 次 L0 有限查询无差异，见 [regression03](../../results/experiments/regression03/summary.json)。旧验收脚本的 `not_run` 只描述该 L0 命令本身；本轮原生 HTTP 运行由上述 L1 日志另行记录。

给定同一原始数据，`analysis02` 与 `analysis03` 的分析、功效及统计源码哈希文件逐字节相同。真实原生 token/UUID 和墙钟时间不可要求字节一致；并发调查也只保证触发边界可重现，不假称线程交错完全相同。

完整本轮结论：工具链与受控原生校准已落地；没有主方法收益证据，正式效应分布与 H-S 原生保持条件尚不充分。待确认和未完成项见 FREEZE_CHECKLIST.md，不能仅凭这批数据启动确认性实验。
