# 无标识结果的组织范围读取授权

2026-11-05。本轮采用成熟 G0/G9，对既有 Casdoor 4.25.0 的一项新部署范围进行条件验证，密码学辅助线保持 FROZEN。

原共享组织的精确账户级问题继续未解决。get-tokens 的 user 条件是 LIKE %value%，本轮不会用客户端后置筛选修补该读取授权。

本轮新增一个专用组织、一个专用应用、最多三个账户。整个专用组织的令牌读取明确授权给可信运行者。实际查询固定 owner=admin、organization=专用组织、pageSize=100、p=1、空 field/value、name 升序。原生组织字段由对象查询等值过滤，返回后先核对每行 organization，再进行精确账户与应用选择。

对已有 l1-study 组织及 app-l1-0 的操作仅为环境和依赖参照读取。新应用复用参照应用已经存在的签名证书，不创建证书、provider、policy 或其他原生对象。源码 AddOrganization 只插入组织，AddApplication 初始化字段后插入应用；不需要额外原生对象。若实际环境有额外配额或依赖要求，停止并记录缺项。

运行方法使用新应用的已有 Basic 认证机制，应用组织级读能力与本轮整个组织的授权对应。该额外组织、应用、凭据、读取更多账户材料、配置和传输成本全部计入本轮。它没有改变原共享组织接口的过滤语义。

## 真正无标识的输入

完整 operational inbox 和 identifier journal 均关闭。控制器在持久登记 A1 前崩溃，恢复状态仅保留 A0/B0、请求来源、批准/窗口、摘要、发送槽和效果上界。R 的恢复 API、缓存和普通日志不包含 A1 的 jti、原生 ID 或 AT/RT。

本轮新增单向封存的评分 HTTP 证据通道。运行客户端仅加载审计公钥，响应以随机 AES-GCM 密钥加密，再以成熟 RSA-OAEP 封装该密钥。审计私钥保存在独立评分路径，运行方法不加载。该通道用于证据隔离，不提供新密码原语或恶意 OS 用户隔离保证。单机同一可信 OS 用户仍是实验边界，按固定代码/API 信息流分别核对。

查询返回的所有账户材料均在授权范围内，进入可信适配器内存和加密证据。代理输出仅含安全投影。评分者可使用自己的响应、原生数据库和清理知识，均不回流运行态来源判断。

## 实际核验

专用应用使用新 client_id/secret，复用 cert-built-in 引用。没有新增原生证书、provider 或 policy。应用 Basic 认证完成三次组织范围 get-tokens 查询，实际返回分别为 3、5、5 条，全部 organization 等于专用组织。没有查询原共享组织的令牌集合。

原共享组织的账户级问题依旧为 UNRESOLVED_SUBSTRING_FILTER。专用组织的完整获准读取范围为本轮新部署与授权所建立，携带新增对象、组织级数据暴露和相应费用。跨组织拒绝攻击未对其他组织原生发起，源代码授权规则、客户端固定范围和实际返回核验分别登记。

运行者恢复前 A1 只有本地请求/attempt/摘要/批准等状态；lookup 返回 UNKNOWN，完整 inbox 和标识日志文件均不存在。预查询投影与 A1 实际 AT/RT/jti 的比对通过。运行审计对象未加载解密私钥，私钥仅在评分路径使用。可信 OS 用户可以访问测试工作区的权限边界继续保留，未宣称恶意同 OS 用户内存或文件取证隔离。
