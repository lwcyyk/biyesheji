日期为 2026-11-05。本轮实现成熟 G0/G9 的受限对账，密码学辅助线为 FROZEN。原 M2-03 的结果与源码锁保持原位，新增元数据日志不追补历史丢失事实。

普通 get-tokens 的 user 模糊匹配无法直接提供仅限本批账户的读取范围保证。事后过滤不能收回已读取的其他账户秘密。本轮保留该权限缺口，实际对账优先使用已知、本账户原生记录标识的精确 get-token。不会静默扩大到组织级列表读取。

## 受限模型与新增日志

模型含一个新账户、两个独立批准和初始材料 A0/B0、一个 A1 未知刷新。全部创建经登记可信入口，A 被撤回，窗口内 B 的发行/刷新暂停而资源使用继续。其他批准、在途创建、管理写入和原生凭据持有者分别登记。可信测试夹具排除其他原生创建者是显式模型前提，真实恶意 OS 用户或其他管理主体的强制隔离另待验证。

本轮在请求开始前启用 identifier-only journal。它仅在收到并核验原生响应之后，持久记录原生 jti、attempt、原来源和响应引用，完整结果收件箱保持关闭。由此可以在控制器结果未登记时，按已知标识精确点读。该普通日志属于成熟接收记录，完整结果收件箱同样可直接补收，二者不构成独立算法优势。

历史 M2-03 没有该标识日志，因此本轮成功路径只覆盖新 profile 中已收到响应并持久保存标识的尝试。完全没有标识或完整响应时，当前模糊枚举的授权范围缺口继续阻止本轮运行者安全发现未知单位。

## 关闭的充分条件

设一次实际发送最多产生 U=1 个单位，实际发送次数 S=1。可信来源已将一个独立单位绑定到该 attempt，精确读取证实其存在，故已发生的效果数下界 L=1。因为总效果数至多 S×U=1，未来创建能力上界为 S×U−L=0。该结论不需要断言整个 HTTP 处理已经终止。

关闭还要求新发送不会重启该能力、其他未决创建者不存在或已独立结清、材料来源明确、全部属于 A 的已知单位在指定接受路径失效、B 的保留检查通过。已放行但尚未发送时 L=0，剩余上界仍为 1。空集合、重复相同列表、连接关闭及超时均不能把该上界降至 0。

来源可来自可信签名验证后的标识日志，或具有完整写入者/已知集合和唯一未知尝试的排除推理。账户相同、时间接近和字符串数量不足以独立完成归属。多个未知创建、潜在重试或一请求多效果时，需要重新计算上界并保留相应未知。

精确点读的集合完整性只针对该尝试的效果集合，通过效果上界饱和建立。它不声称枚举了账户全部记录。一般分页需要一致快照或静止且完整的读取合同，当前 API 未提供相应证据。

## 两条原生轨迹的真实观察范围

M3-01 在控制器收到响应但结果登记前终止，标识日志已在此前启用并持久化。恢复者仅通过本轮获准精确接口和自身日志对账。

M3-02 的首个屏障在可信适配器发送原生请求之前。本地标识日志此时为空，原生列表不会因范围不明而发送。这个空观察只属于本地日志查询。释放请求后记录新单位，再通过精确点读与效果上界核对后续关闭条件。

两条轨迹均单次采样，预算在首次原生请求前冻结为环境 30、方法 45、测量 35、清理 50，总量 160，两个新账户。B 保留评分先于账户级收尾。所有关闭结果附带模型、来源、查询、创建上界、处置与 B 证据引用。

|---|---|---|
| 当前材料 | 普通精确 get-token 响应，验证原生 owner/name、账户、组织、应用及 AT/RT 签名 | 只覆盖已知标识对应单位 |

## 最强既有对账方式

| 方法 | 信息、前提与费用 | 截止及 B 影响 |
|---|---|---|
| 完整 operational inbox 补收 | 事先启用、响应已收到并持久保存、请求来源绑定。每响应保存完整密文；可免去本轮的原生点读 | 未收到的响应仍未知。B 可独立继续 |
| 应用凭据 get-tokens | 组织级应用读能力，返回 AT/RT/ID token、name、user、application、organization、scope、expiry、grantType 等。每页一次查询，源代码还执行 count 和 Find | user 为模糊过滤，当前新账户授权下缺少严格匹配范围证明，因此本轮未调用。改用精确已知标识点读 |
| 原生请求终态/审计 | 核读的 Token API 没有本地 rid/attempt 字段。更广审计接口的授权、关联和完备性未在本轮核实 | 当前不据此宣布原请求终态或无效果 |
| 已知后继逐材料处置 | 材料有可靠来源，按 RT 定位原生记录并验证接受。费用随单位数量和检查次数增长 | 只处理已知单位，开放创建前沿继续产生义务；B 需独立支持 |
| 等待失效 | 需要最新创建时间上界、最大寿命、时钟条件和禁止再派生。仅有“一小时寿命”配置不足以给未提交请求建立统一结束时点 | 可能中断 B 或遇到自身到期，等待费用与可用性须计入 |

本轮选定的元数据日志＋精确点读增加日志持久性和每尝试一次原生读，并不提供相对完整收件箱的一般成本优势。完整收件箱为可直接适用的成熟强对照，本轮按同样信任和接口条件登记。

## 分页与空观察的反例

若未来已有获准的精确账户过滤，受限模型的记录总上界为两个初始单位加一个刷新单位，即至多 3。页面容量大于该上界且使用第一页时，单个 Find 查询可覆盖其读时点的匹配记录；独立 count 返回值仍不能替代该模型上界或快照依据。这个反事实说明不改变当前 LIKE 授权缺口。

多页 OFFSET 读取时，前页之后插入或删除会改变后页位置。两次相同列表也可以发生在迟到创建之前。空集合只能说明指定观察时点没有可见记录，不能证明未知尝试已失去未来创建能力。客户端超时、断开或外层 RPC 返回同样不能证明服务器无效果。

若一次尝试可生成两个单位，已看到一个只使剩余上界降为 1。若实际发送两次，同样不能沿用单发送证明。若 A/B 各有未归属创建，账户相同与时间接近不足以决定剩余候选归属。上述情形均在开发负例中强制构造错误 CLOSED 收据并验证拒绝。

关闭收据依赖源代码模型忠实、受信任日志和受控写入者。文件哈希与检查器验证引用、条件及内部一致性，源码引理的完整语义证明、源到二进制可复现构建和部署中的外部写入者排除保持各自前提。

发送账本在 NativeHTTP.open 之前分配槽位，因而一般提供可信客户端调用上界，不能在该间隙崩溃时单独证明物理发送已经完成。本轮正例再由已绑定的响应标识和原生记录存在观察提供下界 1，使单槽位的实际效果上界达到饱和。原生网络抓包没有执行。

元数据日志及收据的真实性由已声明可信 R/适配器和受控存储承担。普通收据检查器核对给定事实与证据包的一致性，独立轨迹评分再核对实际权威、日志和发送记录。它们不自动建立敌对管理员环境下的全局写入者排除。
