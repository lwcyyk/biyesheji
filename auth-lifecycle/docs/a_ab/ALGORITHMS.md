# 选择器、B 反馈、联合参考和计算开销

## A1 与 B-A

两者先检查 W_r，再只在所有观察后继均属于 W_(r−1) 的菜单中选择动作。不要求识别完整服务。若已经存在合法配置与停止/收尾策略，可以立即使用。

共用控制选择顺序为：能减少最坏未决会话数的 cleanup、合法 stop、合法 configure，再选择 probe。configure 按固定 B 的原生 G 目标在安全菜单中选择，随后按排序路径列表打破平局；不改变 B 的成本函数。W 的联合约束可能排除确定性 B 单独看起来可行、但在故障或清理预算下不安全的配置。

令 Γ(K) 为可能状态的任务相关语义性质签名集合，n=|Γ(K)|，n_o=|Γ(Post(K,a,o))|，c(a)=max(1,请求费)。

- **B-A**：最大化 `(n−max_o n_o)/c(a)`。这是任务性质版本空间上的、按最坏剩余类别平衡的广义二分测试选择，加相同批准/预算/副作用/W 约束；无随机查询或强制全量识别。
- **A1（反馈关闭）**：最大化 `[C(n,2)−max_o C(n_o,2)]/c(a)`，按最坏剩余语义对衡量消歧。它是一个有限启发式，不是新信息论原理；许多等价价格的二分查询上会与 B-A 等效。

评分相同时，按最坏新增义务数、请求费和动作标识固定排序。零费动作使用分母 1 仅用于启发式排序，真实请求费仍按 0 记录。评分没有声称概率、期望最优或任意模型下最优。

任务性质投影只保留任务实际所需的权限、账户、相关原生撤销作用和控制属性。首轮开发曾保留未用 scope；反方检查认为这会削弱基线，已对所有方法统一纠正，详见 REVIEW.md。没有通过改变请求成本保留表面收益。

B-A 的原理来源及本实现与论文的边界见 SOURCES.md。本实现不是某成熟工具完整二进制复现，也不引用原论文的查询复杂度保证来证明本故障/多结果/带预算扩展。

## AB1 / B-AB 配对

`candidate.solve(method="A1", feedback=True/False)` 是唯一配对开关。两版共享任务、接口、原生授权、源模型、控制优先级、W、安全筛选、缓存、请求价格和执行评分器。关闭版仍有上述任务性质查询，不会被迫探索完整网站。

开启反馈时 `bridge.Feedback` 返回：

1. 配置前：对 K 的各可能具体状态，用当前批准和剩余共享预算调用固定 B 搜索及逐配置冲突生产/检查接口；给出配置、可行性、失败证书和 constraint_refs。证书保留完整原生契约/接口/批准/预算快照。
2. 配置后：对已安装配置，用固定 B 的具体停止语义给出各下一动作的合法/阻塞结果和约束引用；它是立即动作冲突，不是假装已经证明所有剩余策略无解。
3. 具体配置或停止动作结论不同的可能状态对、语义性质引用及上下文范围。派生权限性质的引用名为 `scope_for_task_permissions`，原数据来自 B 的 `scope`。

AB1 用这些配置分歧对替代普通语义对来排序安全 probe：最大化最坏情况下被排除的分歧对数/请求费。没有 B 分歧或反馈计算不完整时，回退同一 A1 性质排序；不将反馈超限转成不可行结论。B 诊断不授权动作，W 仍检查完整副作用、故障和 cleanup。

重要限制：逐契约 B 证书针对确定性 B 子问题，预算投影未预扣未来 probe cleanup；故其可行性不代表联合任务可行。配置后引用也只有立即动作含义。任意世界数的联合可行性由整个 K 上的 W/R-I/R-J 判定，不能因为没找到某一对冲突就宣告成功。

反馈缓存按 source digest、完整 K、r；不能复用其他 epoch、批准或预算下的报告。所有世界都是已公开候选，接口不读取评分器真实分支。

## R-I 与 R-J

原 v2.16 R-I 直接验证编译表的有界可行性，保持未改。R-J 新增完整可达观察信念图和自底向上动态规划。它不调用候选启发式、反馈或候选 W 实现，而使用原独立 `_reference_kernel`。

所有 probe/configure/stop/cleanup 都来自同一编译表。R-J 不被强制先学完再配置；测试包含 configure → probe → stop，也包含选择先核验以避免昂贵通用配置的例子。

终态值为 K 中最坏总请求 `Q_cap−剩余请求预算`。内部值为 `min_a max_o V(Post(K,a,o),r−1)`。已用费用在具体状态中，所以不会把不同隐藏分支的过去/未来费用错误拼接。只有完整图求解结束才宣告该有限表内的最坏请求最优；耗尽节点限额返回 INCONCLUSIVE。

R-J 优化同一合法完成目标下的 Q，允许使用同一 B 合法配置目录中的全部配置；它不承诺最小 G。A/B 组合的 configure 优先级仍用固定 G。输出同时记录实际 G，因此不能把 R-J 通过额外原生资源取得的差异隐去。当前“提前配置更贵”反例中 G 相同，差异来自查询与配置的时序/选择。

R-J 的准确范围：有限注册假设、原子可靠 setup、登记的 stop/cleanup/probe 故障、H≤8、有限会话槽和预算。不是无限时域 POMDP、一般真实网站规划器或任意故障下参考真值。若它在开发域内以可接受成本等效或更好，本工作不据此宣称新的信息获取与控制原理。

## 独立性边界

候选具体 plant 使用固定 B 的 engine；源检查器/评分器另行实现 probe/预算/故障转换，使用 B 的独立 kernel 判断生命周期。候选 W 使用 v2.16 `semantics`；R-I、R-J 与策略检查共用既有独立 `_reference_kernel`。schema、源输入和已验证 B 数据契约为共同信任基础。

这不是所有组件彼此独立的三重实现。测试通过让候选 plant 和候选求解报错，验证源审计、R-J 和重放仍能工作；同时用删结果、删义务、伪造观察分支等负例验证检查边界。

## 复杂度

设源动作数 A、每动作最多 F 个结果、整体深度 H。朴素可达具体展开上界约为 O((AF)^H)，同一具体快照/层合并后记 N 个节点；实现默认最多 20,000 节点，超限不暴露部分表。

可能信念空间最坏为非空具体状态子集，粗上界 O(H·2^N)。W 与 R-J 的运行开销取决于实际可达信念节点数 M，转移检查还需遍历 K、动作和结果；二者不是多项式通用算法。候选缓存布尔可完成性并按需选择；R-J 存储完整图及最坏费用值。默认求解节点限额 100,000；预评估统一 50,000。

B 反馈增加逐可能状态×配置的固定 B 搜索、失败证书与检查成本。B 本身的配置数最多 `∏(2^p_t−1)`，仍可能指数增长。报告 `shield_nodes`、`reference_nodes`、`B_work`、`B_guard_checks`、缓存命中和实际求解秒数。工作单元不同，不当作等价 CPU 指令；schema/复制/序列化开销由时间覆盖而非逐项计数。

最终策略树和所有具体轨迹的输出可能重复缓存节点；本版有轨迹访问限额，但没有独立序列化字节限额。超限评分返回 INCONCLUSIVE，不能把部分轨迹无错误当作全部验证通过。
