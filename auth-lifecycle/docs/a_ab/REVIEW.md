# 反方审查、已知限制和进入条件

## Material Passport

对象：A1/AB1 开发实现、固定 B、v2.15 H-A/H-AB 规约和本地原始结果。审查由同一工程代理执行，不是独立同行、跨模型复核或正式查新。有限独立性来自源转换、求解和评分代码的分离。正式假设状态：NOT_TESTED / 本轮 NOT_RUN。

## 主要结论

当前开发证据不支持 A1 相对 B-A 的请求数优势，也不支持 AB1 相对 B-AB 的反馈收益。R-J 在已测可行模型上请求数相同，或在一个具名例中更少；因此不声称提出新信息获取与控制原理。

反馈接口确实产生具体配置、受检查的 B 冲突证书、字段差异及配置后的停止阻塞信息，但“实现了反馈”不等于“反馈有实用收益”。成本中必须保留其 B 调用与证书检查开销。

## 首轮发现的基线弱化风险

`dev01` 的初始性质投影把任务不需要的额外原生 scope 也保留为查询目标。构造中的 scope 查询因而可能优先于真正影响配置的查询，造成反馈的表面收益。它不属于安全测试失败，却是对照设计问题。

处理：对 A1、B-A、AB1/B-AB **统一**改为任务所需权限的投影；保留派生性质名，避免误把投影写成完整 scope 证据。没有改 Q、G 或费用。对应场景现为 `irrelevant_scope_negative_control`，所有主要方法只查询必要原生语义，Q=4。旧 `dev01/unittest.log`、当时源码哈希和 `review_finding.json` 原样保留，未重标为正式成功证据。

这次修正很重要：研究不能通过让关闭反馈版本追问无关属性来保留创新主张。

最终接口检查还发现：正常选择器已经拒绝空 K，但直接调用反馈接口时，空 K 的空诊断会标成 COMPLETE。实际反例保留在 `results/a_ab/dev04_boundary_failure.json`；现已让空 K、外围栏状态及非法 r 直接返回 UNKNOWN，并新增测试。它没有造成接纳运行的安全反例，但属于应修正的接口状态分类问题；最终验证使用修正后的源码，旧运行记录保留。

## 逐项质疑

| 质疑 | 实施与剩余边界 |
|---|---|
| 是否把 K 简化为模型标签？ | 每个可能节点包含语义、实际配置/停止效果、会话、批准、预算、次数与 epoch；LOST 同观察下合并所有后继。 |
| 是否默认 UNKNOWN/active:false 已成功？ | 两类无区分结果保留多个语义可能，不能完成选择性远端停止；相应用例正确拒绝。 |
| 是否把已完成具体分支提前删除？ | 没有；编译保留其幂等动作，使停止/清理丢响应后的混合信念可合法重试。 |
| 是否重置预算给 B？ | 当前残余批准/预算投影给固定 B；执行状态中的总账涵盖 probe、setup、stop、cleanup。 |
| B 的确定性计划是否被当作故障安全证明？ | 没有；反馈只用于排序；所有实际分支由共同 W 检查，独立源评分器记录故障是否生效。 |
| 是否改写 B 或用隐藏真值？ | B 源码逐文件哈希保持；世界集合是公开假设类，实际分支只在评分器中。 |
| B-A 是否只是随机或全量学习？ | 否；使用成本敏感 GBS 性质选择；有共同完成策略即停止查询；同样过滤危险探测并缓存。 |
| 关闭反馈是否丢失其他能力？ | 同一函数只有 feedback 布尔差异，仍保留任务性质、W、控制选择、预算、义务和缓存。A1 与 B-AB 输出逐字节一致。 |
| pair 反馈是否再犯两世界无解错误？ | pair 只用于启发式权重；不可行结论由整个 K 的有界求解产生，单个 B 证书仅断言其声明子问题。 |
| 独立参考是否只是换名字？ | R-J 用独立 raw interpreter 构造全信念图/值；源效果另有独立解释器；但 schema、固定 B 与 reference kernel 有共享，明确不称完全独立。 |
| 只测安全过滤，没执行效果？ | 每个接纳策略均在独立 L0 源转换上穷尽实际结果分支，记录费用、会话创建、终态义务和错误保证。仍未执行真实认证端点。 |
| 被避免的故障是否算抵抗成功？ | 原始记录列 attempted probe、已触发与未触发的故障日程；从未使用危险 probe 只表示安全选择，不称故障恢复成功。 |
| G 不同是否污染 R-J 比较？ | 原始轨迹记录配置和 G。R-J 更低 Q 的例子两者 G=2；一般 R-J 只最小化 Q，不默认与固定 B 的 G 优先级相同。 |

## 消融解释

1. **A 选择方法**：A1 与 B-A 在当前输入族的请求和完成结果相同。这些模型没有支持 A1 优势。
2. **B 具体反馈**：AB1/B-AB 只切换反馈；当前输入族 Q 相同，反馈增加诊断计算，不能称为收益。
3. **移除 A 获取、保留 B 与处置**：限制选择器不使用 probe，仍提供同一接口表。普通未知契约场景不能交付；本地门控和昂贵通用配置负控制仍可完成。这说明获取有时必要，不证明本 A1 优于成熟获取方法。该消融的 IMPOSSIBLE 只针对不查询策略，不替代联合参考的可行性。
4. **义务账本×反馈开关 2×2**：在有 probe 会话副作用的两个合成场景，完整方法能收尾或正确拒绝；故意删除会话/义务抽象后，控制器可能误报完成，但独立源审计拒绝，原具体评分器发现未结清义务。此不安全诊断不是 B-A、B-AB，也不是生产可选运行方式；不能把它当作成熟学习器缺陷。

当前共享 W 本身在可行模型上提供完成屏障，因此正常方法同样安全并不意外。不能把共同安全核的效果归为 AB 独有贡献。

## R-J 反例与成本

`joint_planning_cheaper_than_early_configure` 提供一个昂贵但通用的合法配置。A/B 组合采用已固定的安全控制优先级直接配置，总 Q=5；R-J 先查询再选择较便宜的原生授权，总 Q=4，G 均为 2。两者取得的接口/批准相同。

这暴露的是候选控制排序的局限。未为了追平 R-J 修改成本函数或事后改写候选排序。本阶段可以将联合参考视为实际可运行的对照，不主张新的联合控制原理。工程“可接受成本”的通用阈值尚未预注册，只报告有限模型上的实际秒数与节点数。

## 未完成项

- 任意未知服务的状态机学习、未知假设空间发现、真实契约 evidence 的自动真实性核验。
- 非原子配置的中途故障、部分授权创建、setup 丢响应以及跨配置重绑；当前 configure 为可靠宏。
- 配置后的原生语义迁移、并发、迟到旧请求和任意长恢复序列。
- 原生撤销分区以外的重叠/层级撤销能力；沿用固定 B 边界。
- 最小字段级证据失效、跨会话持久缓存、可扩展冲突核心与序列化内存上限。
- 真实 OAuth/浏览器/AI 适配、独立服务效果日志、墙钟终止约束。
- 机器证明一般正确性、正式 H-A/H-AB、外部独立评审与新颖性确认。

## 下一阶段进入条件

先选择自有认证测试实现，验证原生操作、调用方/资源作用域、所有持久材料及未知句柄清理覆盖；为 configure 选定可验证的真实宏前提，或者展开中间状态和失败结果。完成源模型到真实执行的保持检查与独立效果日志后，再扩展 L1。

在确认性实验之前重新审查更强性质选择/联合规划基线，冻结同价格和批准、配置族与故障族、失败惩罚、统计方案和正式留出集。若仍等效，应保留负结果并把贡献收缩为建模、核验和测量工程，而不是调整成本或只保留反馈活跃样本。
