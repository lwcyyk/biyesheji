# 具体到抽象的保持条件

## 1 本阶段的映射

具体表 `C` 与抽象表 `A` 均采用同一有限状态 schema。提供关系 `R ⊆ S_C × S_A`、固定动作映射 `β: Act_A→Act_C` 和观察映射 `γ: Obs_C→Obs_A`。R 可以合并多个具体状态；γ 可以合并可见观察，但必须是同一确定函数，不能根据隐藏世界选择结果。

本阶段能力和严格义务采用同名标签。允许忽略与前置/目标无关的事实；不允许省略访问能力或严格义务。预算采用抽象值不高于具体值、抽象动作成本不低于具体成本的保守约束。

`check_relation` 检查完整给定有限状态空间，而不只检查当前最有利的路径；这种检查比只检查可达子集更严格，可能拒绝一些安全但不满足当前简化规则的抽象。

## 2 七组条件与反例

| 条件 | 形式化要求 | 本轮故意违反的反例 |
|---|---|---|
| 覆盖 | 每个具体节点至少关联一个存在的抽象节点；初始具体可能状态被抽象初始 K 覆盖 | 删掉具体 done 节点的关系项 |
| 前置保持 | 对任意 c R a，抽象动作在 a 启用时，β 动作在 c 也须启用；任务/账户/批准引用一致 | 具体批准已撤回但抽象仍持有 |
| 观察相容 | 每个具体后继边都能匹配观察 γ(o) 的抽象边，并保持后继关系；γ 不使用隐藏状态 | 将 finished 映射到抽象不存在的 invented |
| 副作用覆盖 | 匹配边须保留具体效果引用；具体能力状态不被遗漏，具体严格义务映射到抽象义务 | 删除 goal-effect 或丢掉 verify-outcome 义务 |
| 预算与批准 | 抽象余额≤具体余额、成本≥具体成本；抽象批准集合⊆具体集合 | 将抽象 calls 余额从 0 改为 1 |
| 终态反映 | Safe_A(a)⇒Safe_C(c)；Goal_A(a)⇒Goal_C(c)，含账户、目标事实及全部严格义务结清 | 抽象 done 无义务而具体仍有待验证结果 |
| 可执行回译 | 每个抽象动作映射到存在的具体动作，并有对应可调用的本地绑定 | β 动作有名字但没有 binding |

每一条具体转移都要被覆盖，而不是每个动作只找到一个“看起来正确”的结果。抽象可以多出保守后继，但这会降低可行性；不能为了得到好结果而省略丢响应、撤回或外部变化边。

## 3 条件性命题

若上述有限关系条件成立，抽象策略通过独立有界检查，且真实具体执行精化 C 的动作与观察，则通过 β、γ 回译的具体策略在同一剩余决策步数内保持安全，并达到所声明目标且结清严格义务。

证明思路：初始覆盖给出每个具体可能状态的抽象代表。假设当前信念之间满足该覆盖；抽象策略选择的动作对全部抽象可能状态获准，由前置保持可知其 β 回译对全部具体可能状态获准。每个具体结果由观察映射和转移模拟落入相应抽象策略分支，新的具体 K 仍被覆盖。预算/批准关系和副作用条件保持安全义务；r 同步递减。归纳到 r=0，终态反映给出具体目标及空严格义务。

这是条件性纸面论证，不是新的抽象理论。Python 检查器对上述规约的完整正确性、真实服务与 C 的符合关系，以及任意 adapter callable 的行为都**尚未机器证明**。

## 4 已实现与尚未验证的回译

`lift_policy` 在关系检查通过后，先独立检查抽象策略，再按可见具体观察生成具体策略，最后再次独立检查具体策略。它不调用候选搜索以“补救”错误映射。非平凡正例将 `s0/s1` 合并为 `s`，把 `ok:0/ok:1` 合并为 `ok`，并实际在 `TableAdapter` 上执行 finish。

`TableAdapter` 真正修改本地模拟器的隐藏节点并记录效果/预算 delta；它是可执行 L0 工件，**不是真实 OAuth 或浏览器实现**。`check_relation` 的 `valid` 仅表示给定有限表关系满足条件，其输出明确标记 `scope=finite_table_relation_only` 及 `external_adapter_proof=NOT_PROVED`。

检查 Python 对象可调用，不等于证明这个调用真的执行了所声明的网站动作。未来真实 adapter 必须有操作标识绑定、请求规范化、当前批准检查、独立效果记录、异常/超时结果枚举及原生语义实证；在此之前不得把当前回译通过当作网站安全结论。
