# 算法、基线和计算代价

## 固定规则

`OBJECTIVE_LOCK.json` 在实现和比较前写入。未因观察到收益或等效修改 G、排序或方法规则；后续开发修正只有检查器严格性、CLI 空值处理、测试和记录完善。正式 H-B 的分布与判定阈值仍未冻结，本文件不是外部预注册。

## B 候选

`search.solve` 按任务枚举非空路径子集，构成配置。部分配置只按单调约束剪枝：账户/范围/批准不合法、setup 预算超限，以及已用 G 严格大于当前合法 incumbent。不能仅因为当前还未覆盖所有任务而剪掉部分配置。

完整配置交给 `engine.deliver`：对每个停止场景用有界 DFS 搜索任务门控、环境关闭和原生撤销动作，缓存已执行动作集合。每个动作核对批准、剩余预算与保留任务；替代路径全部进入停止/保留谓词。每个可行 delivery 再经 `checker.check_delivery` 检查，G 从独立解释器重算后才参与选优。

这是标准有限枚举、单调剪枝和规划的工程组合；没有提出新的规划原理。`IMPOSSIBLE` 仅在该目录内穷尽；中断为 INCONCLUSIVE，可以附带已检查的 incumbent，但 `optimal=False`。

## B-B 强组合

四种规则接收**完全相同的输入 JSON**。不做删减接口的基线副本、不增加候选专用授权、不把独立批准或服务器真值交给某一个方法。每个非空路径集合只要符合至少一条规则就进入组合，保留全部规则标签并去重。所有结构规则候选和权限贪心候选都用与 B 相同的完整停止规划器寻找计划；合法交付都用相同独立检查器核验。

1. **共享代理**：所有选中路径位于同一受控 broker；不限制其使用多少种可获得原生授权，允许替代路径。共享 root 的本地门控可行时不强制拆授权。此定义比“只选一个共享 token”的基线更强。
2. **全部独立授权**：不同任务所使用的原生效果域两两不交；同一任务允许多条路径、AND 支持或多个域。按原生域判断独立性，多个 token 标签不算独立。
3. **静态终止签名分组**：按所有场景的 (local,remote,preserve) 三元成员签名分组；每个任务使用一个原生域，相同签名共域，不同签名异域。遍历全部与目录相容的实现。对受限静态实例保留其最优性，不把它包装成新算法。超出其假设的配置必须通过完整计划检查才被接纳。
4. **权限贪心**：遍历所有下一任务选择（等效所有任务顺序），每步选择新增原生权限原子数量最少的非空路径子集；保留全部并列最小选择。新增原子按每个新取得授权的 scope 大小计，非候选私有权重。部分配置违规则不可选择。最终无合法停止计划的分支被拒绝；此规则没有假称全局完备。

从所有已检查合法交付中按 `(G, sorted_paths)` 选优。不是只比较四个任意代表，也不根据结果临时决定使用哪条规则。`candidates` 保存各候选、规则来源、合法计划及指标；无法交付的候选保留 `NO_LEGAL_PLAN`。组合全部失败返回 `NO_BASELINE_SOLUTION`，**不等于原问题 IMPOSSIBLE**。`optimal=True` 对 B-B 只表示组合候选内最优。

当前实现使用完整位掩码扫描来收集结构规则候选，权限贪心用部分配置去重。它优先简单、可审计和不遗漏规则候选，尚未做组合生成性能优化。不能把这一参考式基线的枚举开销直接当作 B 有独立算法优势。

## 独立有限精确参考

`reference.solve` 不调用 `search`、`engine` 或 `baselines`。它枚举所有全局路径位掩码（包含空集并明确拒绝），在独立 `_kernel` 中重新计算 setup、G 和条件，再用具体有限状态 BFS 搜索每个场景；不使用候选的任务分解、剪枝或缓存。

该 profile 的服务语义完全已知且确定，没有隐藏世界供运行者偷看，也没有观察后再选真实世界的捷径。若需要 v2.16 的多世界/响应丢失分支，须提供保持映射和扩展参考，不能简单将此确定性 BFS 用作其真值。

候选和参考共享 schema/JSON 规范；参考与独立检查器共享 `_kernel.py`。独立性是“相对候选和生成器”，不是三套完全无共享的代码。自动测试通过 monkeypatch 使候选资源计算、检查和规划报错，参考与检查器仍能工作；这证明依赖隔离，不证明两套语义均无缺陷。

## 复杂度与预算

令任务数 T，路径总数 P，每任务路径数 p_t，原生域数 D，场景数 S，动作数 A，深度 H。完整覆盖任务的配置数为

`N=∏_t (2^{p_t}−1) ≤ 2^P`。

B 搜索在最坏情况下仍枚举 N 个配置，不宣称多项式。已执行动作集合最多涉及

`V ≤ Σ_{i=0}^{min(A,H)} C(A,i)`

种；每次状态检查需遍历动作及支持路径，粗上界为 `O(N·S·V·A·P)`，忽略集合表示等常数。参考枚举 `2^P` 个配置并执行 BFS；同样是指数过程。贪心的部分配置缓存数量受 `2^P` 限制，但每状态仍须计算许多下一任务/路径子集分数。完整失败证书按树序列化可能重复 DAG 子结构，最坏输出接近动作序列树而不是缓存状态数；不主张可扩展最小 UNSAT core。

`Work` 记录配置、规划状态、检查步等离散工作单元；不同算法的单元种类不完全一致，因此另报真实秒数。工作限额不等于硬 CPU 时间或内存上限，单次 schema 检查/路径扫描不逐操作计费。当前实现没有独立的证书序列化字节上限，近边界复杂目录可能占较多内存。

预评估用任务数 2/4/6/8、每任务两路径、相同批准/接口/预算、每方法 50,000 工作单元。保留所有超限记录。不从单次墙钟测量计算显著性或尾延迟，不将其视为真实认证外部开销。
