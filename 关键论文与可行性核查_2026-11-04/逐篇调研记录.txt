## 7 关键论文全文调研与现有主线的技术支撑

### 文献如何服务于现有研究
本课题采用认证语义感知 A、可撤销凭据配置 B、配置反馈与安全补证 AB 三项相互关联的职责，并由完整凭据管理系统承载执行、撤回和恢复。文献调研围绕这些职责，检查已有方法的输入、可信前提、实现和实验，再确定可以直接借鉴的部分及需要在本系统中验证的接口。[L02,L06]

本轮形成18篇核心论文全文和3份相关协议草案的本地文献包。18篇覆盖用户提供的查新清单及必要的方法、执行与密码学近邻。每篇均核读与本题相关的定义、方法、实验和限制，对关键公式与表格另做页面检查。下文 P01至P18 对应文献包中的固定文件，页码均为该 PDF 的物理页序，包含仓储封面。原文下载、结构完整性检查和关键章节核读分别登记，作者实验按论文所述条件引用。[L10,L11]

### P01 SUDP 支撑可信批准与秘密受控使用
SUDP v4 把请求者、批准者和秘密保管者分开，将操作、目标、范围、接收方、期限和使用次数绑定到授权对象。正文的 multiplicity 同时允许单次、多次和持续授权，这为重复读取类代理任务提供了可参考的批准形式。其安全结论依赖规范化字段完整、可信界面忠实显示、执行端按已批准对象确定调用，以及保管者状态与密钥的相应保护。[R26]

作者的参考实现包含 Rust 保管者与 TypeScript 客户端。回环 HTTP 微基准中，完整受控调用为1.21毫秒，直接调用为0.45毫秒，认证器采用软件模拟，真实人工交互和硬件认证时延另计。这支持核心密码学和批准绑定能够工程实现，整体任务成本仍需本系统测量。[R26]

本课题可借鉴其批准对象、次数约束、重放防护和秘密边界，落实 M02、M03 与 M09。A 继续提供服务事实，B 继续决定凭据与支持路径，AB 继续组织补证。秘密使用协议通过这些接口服务于现有主线。

核读位置　P01第2—5页、第12—13页，§III—V、§VII-C与§VIII。

### P02 PAuth 支撑任务到具体操作的执行约束
PAuth 使用自然语言切片和带签名来源的返回值，将任务中的条件及参数计算关联到实际工具调用。其可信基础包含任务界面、签名与通信、服务端规则生成正确性，以及服务对权威数据的诚实性。正文还讨论了由可信代理代行服务端检查的部署方式，适合与本系统的受控执行边界比较。[R25]

AuthBench 的100个任务经补全描述后均能无需额外用户干预地获准，保留原始间接指代时为71个。634次对抗调用均触发额外批准，正文将 block 和 reject 定义为转入用户批准流程。该结果说明任务表达的完备程度影响交互成本，也提示自然语言生成规则需要独立核验。[R25]

本课题可以先使用现有的结构化任务批准，再借鉴参数和来源绑定。凭据配置与撤销规划继续依赖 A/B/AB 的服务模型，任务执行层则确保实际调用符合批准。二者具有明确的组合位置。

核读位置　P02第4—5、7、9—10、12—13页，§III—VI及表II、表III。

### P03 Root Scoped Quiescence 支撑停止与保留的保证规格
该论文以授权根及其代次、实际选用的支持集合、在途载体和接收端围栏描述长任务撤销。独立支持保留通过明确重绑实现，重绑保持操作与效果范围，并重新核对当前支持。安全结论要求发行、支持来源、执行路径和证据完整，最终收敛还需要有限排空与证据最终可得等条件。[R28]

其17例测试使用本地持久账本、真实子进程和逻辑效果端，另以44条语义篡改轨迹检查证书。论文明确把这些结果限定为 provider-free 工件。它为有限执行控制和检查器提供了实现先例，真实服务仍需建立逐字段对应。[R28]

本课题可把这些前提转成 B 输出计划及 M08、M10 的验收条件。B 的事前配置仍负责选择未来能够满足停止与保留的关系，A 负责取得关系证据，AB 处理缺证。执行证书的条件为配置提供约束，也使 E 的覆盖范围更容易说明。

核读位置　P03第8—11、14—15、21—23页，表2、Definition 1—3、Theorem 1—6与§7。

### P04 ResidualAuth 支撑持久授权状态的充分性
ResidualAuth 将具有相同未来合法操作集合的历史归为同一残余授权状态。在其二元授权边、独立权限及规定更新规则下，相同当前权限乃至相同全对可达关系，仍可能对应不同的未来撤销结果。该结果为保存授权依赖和来源提供了理论理由。[R29]

正文分别评价信息取得、状态维护、答案使用和执行约束。可信查询能够改善所构造配对任务的判断，硬执行门能够阻止错误提议产生效果。论文同时限定了图与账本对应的输入族，有限探针通过只支持所测未来操作。[R29]

本课题可据此明确 M07 与 M10 应保存的父依赖、代次、期限及有效性信息，并用成对的同当前权限、异撤销后果用例检查 A/B 状态表示。具体序列化可以沿用现有数据结构，关键是保留决定所需的关系。

核读位置　P04第3—6、8—9页，§3—5、Proposition 1—2、Theorem 1—3与讨论。下载的 v2 PDF 题名采用 Agent Systems，文献表按该全文登记。

### P05 AID Guard 支撑提交与恢复过程的状态管理
AID-Guard 通过批准绑定、额度预约、执行边界认领和提交时再检查，把一项批准关联到实际效果。结果不明时保留同一预约。只有取得适用的无效果证据并落实前任投递围栏，才允许释放或产生一个后继。其保证依赖完整登记的效果路径、线性化存储和提供方契约。[R27]

原型使用 Python 与 SQLite，包含进程分离的 MCP 实验以及限定 Stripe、Resend 调度。正文把语义证明梗概、有限反例搜索和外部 API 观察分别说明。这支持本课题采用持久事务和分层适配器建立可信闭环。[R27]

可行的接入方式是沿用现有 M10 协调职责，依据服务能力开放不同恢复操作。具备原子提交或可靠终态查询的后端支持更完整的自动恢复，证据不足时保留待决状态与义务。A 提供契约证据，B/AB 在可用操作范围内规划。

核读位置　P05第2—6、8、12页，§II—IV、§VI与§VII。

### P06 ACG 支撑版本化依赖与补证接口
Authorization Closure Graph 以有向无环图记录批准、权威证据和派生事实。依赖版本变化后，受影响节点失效并按拓扑顺序重算。其最小修复集合是在当前缺口中去除无条件继承造成的重复需求，适用前提包括可信规格、权威观察和批准绑定。[R46]

正文评价两个业务领域中的50个航空任务和114个零售任务，并使用三个模型及模拟用户。命题1明确限定为当前依赖覆盖的最小集合，整段交互轮数和全局核验成本需要另外分析。[R46]

本课题可以借鉴证据版本、依赖失效和具体缺口接口，支撑 AB 向 A 传递补证需求。AB 的目标继续覆盖核验副作用、预算及完整策略成本，ACG 的依赖最小性可作为其中一个受限结构和对照。

核读位置　P06第4—7、9—10页，§3、式7、Proposition 1—2及§4—5。

### P07 OASIS 支撑 A 的实际账户绑定证据
OASIS 研究应用用户、租户和外部账户之间的连接绑定。正文把连接上下文表示为 user、tenant、connector，并说明跨来源或跨用户代理回调需要重新关联发起流程的应用会话。其防御原则可以细化本方案 F2 的证据条件。[R47]

研究样本包含46家供应商，作者报告其中40家受 COSF 影响。Android 检测评估包含27项，结果为20个真阳性、4个真阴性和3个假阴性。八家 OaaS 提供商的各类风险分别统计，具体供应商状态以论文测量和修复时点为准。[R47]

在本系统中，可以把批准主体、连接标识、回调发起会话和实际资源账户关联为可检查证据，并使用受控正负用例验收。OASIS 的静态分析有明确平台与检测边界，适合提供绑定检查原则和测试设计基础。

核读位置　P07第4—6、8、12—14页，§3、§4.3、§6.4与§7。已获取作者发布的20页全文。

### P08 RAG 支撑动态凭据关系的形式化分析
RAG 把账户、凭据、设备、主体和访问方式建模为带偏序标签的图，用图重写表达状态变化，再以 CTL 检查资源完整性和可用性。其属性和操作具有明确形式化定义，并通过 GROOVE 分析具体账户模型。[R48]

作者的基本示例具有21个初始顶点和5种转换，生成692或522个状态，报告可在2秒内探索。扩展示例的16422个状态约需10分钟，说明有限范围分析具备实现基础，也需要控制规模。可用性结果依赖攻击者能力和用户模型。[R48]

本课题可借鉴图状态、操作前提和属性检查，把 B 的停止、保留与配置约束写成可验证条件。B 继续优化现有定义的原生效果单元 G，RAG 提供关系语义及验证参照。不同的可用性或最优性目标应逐项映射。

核读位置　P08第4—6、9、11—13、15页，Definition 8、15、17—20与§8.2。全文为大学仓储作者稿，含封面共22页。

### P09 DRD 支撑配置驱动的信息获取
DRD 允许多个假设共享可接受决策区域，目标是取得足够信息，使剩余假设都落入某个共同区域。HEC 通过超边权重刻画决定分歧，并在规定先验与确定性测试模型下给出期望查询成本的近似保证。[R30]

原文假设一个固定假设把测试映射到固定观察，主要计量期望测试数，并讨论非均匀成本。算法的计算量仍受超边阶数影响。它为“只获取决定所需证据”提供了成熟基础。[R30]

AB 可以借鉴决策区域与冲突表达，用 B 的共同可行配置定义补证目标。对会创建会话、改变预算或产生义务的核验，应进入现有有状态联合模型，并继续使用同信息精确参考。这样能够在同一主线中分别处理静态适用子域和动态情形。

核读位置　P09第2—5、7—8页，§2—5、Theorem 1—3与结论。

### P10 部分可观测 Shielding 支撑安全动作筛选
该研究以 belief support 维护仍可能处于的状态，并通过 shield 限制动作，使后继继续位于获胜区域。其正文区分仅避免危险与最终到达目标，后者涉及公平策略及图结构保持等前提。原文也明确提到有限时域和成本受限的 shield 可以提供相应有限步保证。[R31]

这为 A 在有限可能状态上筛选安全动作提供了理论和实现基础。项目已有有界语义与检查器，可把核验副作用、预算和清理义务纳入状态，再对照通用屏障。模型覆盖真实转换、批准与执行正确映射，是连接有限结论和实际系统的关键条件。[L02,L05]

论文中的训练收益属于其 RL 场景。本课题主要复用安全判定结构，并测量自身的完整请求与计算成本。领域建模和特定结构优化的贡献可分别验证。

核读位置　P10第2—4、6—7页，§2—4、Theorem 1—5、脚注2及实验限制。

### P11 多成本 POMDP 支撑有限预算的联合模型
Multi-Cost-Bounded Reachability Analysis of POMDPs 把多个成本上限或下限加入部分可观测可达性问题，通过成本状态展开和分阶段分析处理。正文明确指出有限时域子类可以精确求解，并在 STORM 中实现相应构造与近似分析。[R32]

它为本课题把请求、批准和清理资源共同纳入模型提供了参照。论文目标是成本约束下的可达概率，现有 A/AB 则采用声明允许结果下的有界安全完成，比较时需对齐目标和观察。额外可见的成本信息也会改变策略能力，应按同信息条件控制。

因此，本课题的有限模型和资源边界有成熟技术支撑。可扩展性可以用既有精确参考及结构化方法逐步评价，通用求解结果也可作为检查候选正确性的依据。

核读位置　P11第4—7、9页，Problem 1、Definition 1—9、Theorem 1—4与实验。

### P12 Account Access Graph Tactics 支撑配置动作语义
该论文在账户访问图上加入主体当前访问状态，定义取得访问、丢失访问、创建、删除和修改访问关系等操作，再以顺序与选择组成 tactic。它用明确前提和后置状态描述账户体系如何变化，案例涉及账户接管及访问恢复。[R33]

其 tactic 在终止时具有确定结果，部分操作前提不足会导致推演停滞，真实服务的失败、回滚和副作用仍需具体映射。本课题可借鉴这类操作规约，完善 B 配置步骤和检查器，并由 A 提供相应服务事实。

本地 B 已有有限搜索与配置证书，因此可以在现有入口上继续核对操作前提、停止与保留属性及原生效果范围。图和状态转换的先例为可实现性提供基础，特定优化收益再通过同条件求解比较建立。[L02,L06]

核读位置　P12第3—6、9—11、17页，Definition 1—5、Proposition 1与结论。

### P13 CaMeL 支撑工具执行与数据流保护

原文在 AgentDojo 中分别评价任务效用和安全，同时讨论数据驱动计划、用户确认、模式选择与侧信道。受攻击条件下的中位任务输入与输出 token 开销分别约为直接调用的2.82倍和2.73倍。该测量说明执行保护可以工程实现，其完整资源代价仍需计入。[R44]

本课题可以在 M04、M09 中借鉴独立执行检查，保护资料读取、模型输入和结果接收方。凭据生命周期由 A/B/AB 及持久协调器继续管理，测试中同时记录合法任务完成与被阻止的效果。

核读位置　P13第4—6、9、11、18—20页，§3—6及§7。全文含长篇附录，共125页，本轮核读上列正文部分。

### P14 DECO 支撑私密的响应来源核验
DECO 使证明者与验证者共同参与 TLS 客户端过程，在保护私有输入和响应内容的条件下，证明数据来自指定服务器并满足约定陈述。其机制包含分散密钥控制、会话提交以及选择性披露，还特别处理被披露字段的上下文完整性。[R49]

安全模型包含诚实 TLS 服务器、规定的查询模板和带中止的恶意对手。文章实现以 TLS 1.2 为重点，并讨论协议适配和离线预处理。其应用实验说明来源证明与私密谓词核验存在可实现路径，成本与电路、数据量和网络条件相关。[R49]

本课题可把它作为来源证据接口的基础与对照，保护账户或响应中的敏感部分。证明对象应明确到服务器响应、字段和查询上下文，A 对撤销关系的推断继续依据服务契约与可观察行为，密码学辅助沿既定证据职责接入。

核读位置　P14第3—5、8—10、12页，§3—5、Theorem 4.1与§7。

### P15 Garble Then Prove 支撑来源核验的效率分析
Garble-Then-Prove 通过先计算再证明正确性的方式，降低认证 TLS 查询与响应的密码学开销，并给出向便于零知识证明的承诺转换的方法。其安全定义保护查询与响应一致性及隐私，依赖规定密码学假设和诚实服务器，允许协议中止。[R50]

论文实现并评价 TLS 1.2 的数据认证，TLS 1.3 在正文中作为扩展设计与后续实现说明。比较包括预处理与设置成本，报告约14倍通信改进，参照项是作者重建的 DECO 核心恶意2PC成本。该数值应按其对照范围理解。[R50]

对现有密码学辅助模块，它提供可核对的来源认证、承诺接口和完整成本边界。主线可先采用可信适配器证据，再在符合来源与隐私前提的子场景中评价辅助协议，分别记录前端认证与后续诊断开销。

核读位置　P15第5—7、11、13—14页，§2.2、§3—5与Theorem 1。归档为完整会议版本，详细归约还可参阅作者扩展版。

### P16 私密多方策略求值支撑同输出的密码学基线
该文把多方访问策略编码为可保护的数据，分别使用同态加密和安全函数求值计算策略组合。数据持有者可以预先提交受保护策略，由数据服务器与辅助方完成求值。其前提包括半诚实对手、两个计算方不串通及规定数量的诚实数据持有者。[R51]

作者提供 C++ 实现，比较原子目标、组合操作和不同规模策略的计算与通信。实验通过本地套接字模拟通信。组合结构和最终决定具有各自的披露范围，原文也讨论由最终结果带来的信息。[R51]

本课题可据此建立通用 MPC 同输入、同输出、同信任条件的比较方法。已有私密一致性诊断继续围绕自己的关系与来源条件验收，安全模型与泄漏口径保持一致后，再评价专用结构是否有收益。

### P17 心跳绑定凭据提供有限时间失效的比较对象
HBHC 把子代理认证关联到父代理的近期心跳，验证者通过签名、绑定关系和本地时钟检查新鲜度。其到期窗口依赖心跳间隔、最大年龄和时钟偏差，可信根、父签名密钥保护及验证者执行检查属于前提。[R52]

该工作为特定可改造执行路径提供有界失效的参考。正文的90倍比较采用一小时令牌作为对照，适用范围由该配置限定。选择性停止分发心跳，还需核对同父心跳的共享与转发条件，才能用于独立停止目标。[R52]

本课题可以把这类机制作为可选的已知能力类型登记到 A 的契约表，并由 B 判断它是否符合任务需求和部署条件。对于外部网站，仍应使用其实际接受规则。该对照有助于区分短期失效、原生撤销与效果停止。

核读位置　P17第5—11、13—14、20页，§3—4、Algorithm 1—3、Theorem 1—2及实验限制。

### P18 保险库中介执行提供直接的工程检查样例
该研究由代理使用连接器标识，可信请求边界补入对应凭据。作者用两个连接器进行了16项黑盒探针，并同时设置正常认证成功和非目标来源不携带凭据的对照。它提供了一组可以借鉴的执行边界检查方式。[R53]

论文还报告了一个功能失败，保存的认证头映射与服务要求的查询参数不一致。此例说明凭据保护和服务契约配置需要分别验证。实验属于小规模定向检查，覆盖范围按所测进程、文件、请求及目标记录。[R53]

本课题可将正常调用、秘密可见面、目的地绑定和配置错误纳入 M02/M09 的验收。A 取得服务适用事实，B 选择正确调用路径，系统记录可解释的失败原因，从而形成与用户任务相连的检查闭环。

核读位置　P18第1—6页，§2—6、§9与结论。

### 三份协议草案作为可选适配能力的演进线索
Agent Authorization Explicit Revocation 第01版提出按 agent_id、级联深度和保留范围发出撤销请求，并返回执行与审计信息。Verifiable Attenuated Delegation 第03版规定委托链、权限递减及有效期约束，也明确离线状态缓存与撤销传播窗口。Mission 第02版区分停止后续签发与已经签发令牌的接受状态。[R24,R54,R55]

这些文档均按个人 Internet-Draft 登记。委托链草案自身说明，所列参考库尚未执行持有者绑定与状态列表检查等完整步骤。因此，草案字段可以辅助整理适配接口，具体能力进入 A 的契约必须由所用实现和配置支持。主线继续采用现有凭据基础、批准条件与 L/R/E 目标。

核读位置　草案原文已归档。重点核对 revocation-01 §3，delegation-chain-03 §8、§9.5、§11，以及 mission-02 §10.2。
