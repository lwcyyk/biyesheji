# 第一部分 · 正式发表（顶会/期刊，27 篇）

## 1. 授权与委托机制：签发、治理、委托链

### P19 · SAGA

**标题/载体**：*SAGA: A Security Architecture for Governing AI Agentic Systems*，Syros 等（美国东北大学），**NDSS 2026**（正式发表，代码开源；另有 arXiv:2504.21034）。

它针对"agent 间授权停留在理论、用户无法控制自己 agent 生命周期"的缺口，提出以 Provider（集中式注册服务）为核心的治理架构：用户经 OpenID Connect 注册，为每个 agent 登记 TLS 证书、访问控制密钥对和一批一次性密钥（OTK），并定义基于模式匹配的联系人白名单（Agent Contact Policy，每条规则附 OTK 预算）。通信时发起方从 Provider 取接收方元数据和一个 OTK，双方用 Diffie-Hellman 派生共享密钥，接收方据此签发**带过期时间与最大请求数的访问控制令牌**——有效期内复用不必再过 Provider，在细粒度控制与性能间折中。ProVerif 在 Dolev-Yao 模型下自动证明令牌保密性与双向认证；支持 RAFT 容错、分片、BFT 与联邦部署，并给出与 Google A2A 的集成方案。协议开销低于任务成本 0.6%，10 分片吞吐线性扩展，理论容量约 3 亿活跃 agent。

**与课题关联**：把"用户对 agent 的授权控制"落成可形式化验证、已发表的系统（OTK→DH→过期+配额令牌）——P01 的工作对比表里它就是被对比的 11 个系统之一，是本课题系统能力层的直接参照。

### P21 · Permission Assistant

**标题/载体**：实际标题为 *Towards Automating Data Access Permissions in AI Agents*，Wu 等（圣路易斯华盛顿大学 / UC Irvine / 华盛顿大学 / 乔治城），**IEEE S&P 2026**（正式发表，文末收录录用元审稿）。

它解决"agent 代用户做数据访问决定"的两难：逐次弹窗造成权限疲劳、破坏自动化价值，不弹窗又过度授权，因此主张构建能**代替用户做权限决定**的自动化权限管理。两步走：先做 205 人情景模拟用户研究（8 个域、21 个工具、142 种数据类型），发现过度授权比授权不足更普遍（90% 参与者对至少 15% 的请求过度授权），agent 出错后用户明显收紧授权，偏好受上下文与数据敏感性影响（SSN 欠授权率 46.3%）但同一上下文内跨用户相似；据此提出 permission assistant——LLM 上下文学习（OpenAI o3-mini 推理模型，以人口属性/隐私意识/权限历史做角色提示）与协同过滤（LightGCN）混合，仅采纳高置信 CF 预测（FPR/FNR 均低于 5%），用置信阈值控制覆盖-精度权衡。181 名用户 7,565 条决定、5 折交叉验证：准确率 85.1%、精确率 92.8%，高置信（阈值 0.91）下 94.4%（覆盖 25.9%），冷启动仍有 66.9%。

**与课题关联**：用户侧"授权决策自动化"的首批系统性实证（S&P 2026），过度授权测量与偏好学习-置信度门控机制可作为本课题动态授予/撤销设计的用户行为依据与对照基线。

### P22 · Authenticated Delegation

**标题/载体**：*Position: AI Agents Need Authenticated Delegation*，South 等（MIT / 牛津 / UC Berkeley / 斯坦福），**ICML 2025**（PMLR 267，立场论文）。

它论证：第三方（数字服务、其他 agent、人类）与 AI agent 交互时必须能同时验证"谁在授权"与"代理权限的精确范围"，否则提示注入、越权、冒充与问责断裂不可避免。技术路线是扩展 OpenID Connect 与 OAuth 2.0：人类用户先向 OpenID Provider 注册 agent 并签发**委托令牌**——令牌引用用户 ID-token 与 Agent-ID token、携带范围限制、可嵌入 W3C 可验证凭证；借鉴 UMA 实现策略向多个 agent 传播。权限界定主张"结构化资源范围 + LLM 把自然语言约束翻译成 XACML 类策略 + 人类审核"的混合机制，并给出网页浏览、API 数据聚合、SSH 远程环境、agent 间协作四个用例与代理法/UETA 法律分析。全文是路线图而非实验或形式化证明。

**与课题关联**：与本课题同构的委托凭证框架（签发、验证、过期、跨 agent 传递），标准兼容路线（OIDC/OAuth/VC）清晰，适合作为委托机制章节的理论框架引用。

### P27 · 临床超图委托

**标题/载体**：实际标题为 *Securing Autonomous Clinical Agents: Time-Scoped Hypergraph Delegation for Controlling Patient Data Access*，Karimi 等（Zetafence / Texas A&M-Commerce / Howard 大学），**IEEE ICDH 2026**（pp. 352–358）。

它解决多 agent 临床系统中的"委托链失控"：嵌入化验报告的注入载荷可在任何人审之前贯通整个委托层级，RBAC 角色继承与 Macaroons 凭证链都不能从结构上保证子 agent 权限严格有界于父级。机制是 NGAC-超图委托：每条委托边是带时间窗的超边（委托方、能力、对象、资源、起止时间），子 agent 权限集是父集的**真子集**——衰减由图构造可证明而非依赖模型行为；执行点在工具调用层，到期即拒绝越权操作。SEPI 方法论实验（50 名合成患者、39 个临床扎根注入载荷 × 3 种失陷位置 × 4 种架构）：加权爆炸半径较 Flat RBAC 降 75%、较 Macaroon 链降 65%；消融证明去掉时间过期使爆炸半径增 75%——时间域是独立贡献。Claude Sonnet 4.6 行为层主动检测全部 39 个载荷而小模型不稳定，支持"授权层承担隔离责任、不依赖模型行为"。

**与课题关联**：带时间窗的超图委托 = 多跳委托凭证的"颁发—衰减—过期"生命周期设计，是委托凭证时间域控制的已发表实现参照。

### P28 · APEX

**标题/载体**：实际标题为 *Protocols and Formal Models for Delegated Authorisation with Server-Side Secrecy*，Snyman 等（Surrey / Castellan /墨尔本大学 / TII），**ASIACCS 2025**（pp. 1372–1393）。APEX 是文中协议套件名。

它解决 OAuth 委托授权中"资源在服务器端明文存放，服务器与被授权第三方都能读"的问题：提出 APEX 协议套件，实现"受限委托授权 + 服务器端保密"——资源加密存放于服务器，只有运行在用户设备上的软件代理能触碰明文与密钥。机制包括一次性码（OTC）在不可信服务器中介下绑定双方 agent 身份、双中介授权授予协议、资源注册/检索、密钥重封装与承诺/删除协议（服务器只存密文与 wrapped key）。形式化提出 **RAD（受限授权委托）模型**——Bellare–Rogaway 风格的通用委托授权形式模型，定义授权授予安全与加密资源授权安全两类性质，并证明 APEX 全部满足而 **OAuth 2.0 本身不满足**。原型实测注册约 9 倍、检索约 10.8 倍于普通 OAuth 的延迟。

**与课题关联**：把"委托第三方只能访问被授权资源"形式化为 RAD 模型，并给出加密资源及其密钥的注册/检索/重封装/删除完整生命周期——授权协议形式化与凭证保密的直接参照。

### P35 · AGentVLM

**标题/载体**：*AGentVLM: Access control policy generation and verification framework with language models*，Jayasundara 等（奥克兰大学 / RMIT），**Journal of Information Security and Applications（Elsevier）** 第 98 卷，2026。

它解决"从自然语言高层需求手工生成访问控制策略费时易错、且缺少验证"的问题：四阶段框架——微调 BERT 识别自然语言策略文本；LoRA 微调 LLaMA 3 8B，借结构化信息抽取同时捕捉显式 token 与**语义级隐含规则**，生成含主体/动作/资源/目的/条件五要素的中间表示（可模板化为 XACML）；微调 BART 构建 12 类序列对分类验证器，判断策略正误并定位 11 类错误，用积分梯度归因给出可操作反馈。策略生成 F1 80.6%（较现有框架相对提升至少 34.4%，超 GPT-4o 的 59.9%），验证 F1 94.4%；经提示注入红队微调增强对抗鲁棒性，本地部署小模型保护需求机密性。

**与课题关联**：自动化了"授权策略的生成—验证—修正"生命周期环节（部署前错误检测 + 可解释反馈），与 P21 同属"LLM 代做授权决策"一族；注意其对象是组织级访问控制策略而非 agent 委托凭证。

### P37 · CapChain

**标题/载体**：*CapChain: A Capability-Token Access Control Architecture with Verifiable Provenance for Multi-Agent LLM Systems*，Choong 等（台湾科技大学 / 嘉义大学），**Applied Sciences**（MDPI）16 卷 7776，2026-08。

它针对 LangGraph 类多智能体系统共享同一个无加密、无字段级读控的状态存储（以 langgraph-checkpoint-sqlite 的 CVE-2025-6764 为现实动机），在状态合并（reducer）处部署三个原语：**CapTok**——HMAC 签名的七元组能力令牌，支持签发/收窄/验证，**委托只能收窄不能扩权**（EUF-CMA 不可伪造论证）；**ProvChain**——Ed25519 签名 + Merkle 链的溯源日志，O(log N) 审计；**CAR**——能力感知 reducer，合并前过三道门（令牌有效性、溯源完整性、属性-目的集合交集），拒绝即写审计日志。150 条件的事后推导评估 + 18 条件运行时可行性检查：属性-目的门在 4.67% 的代理间消息上触发裁剪，单次写入门开销合计约 6.8 微秒。

**与课题关联**：代理间授权与委托链（令牌签发→收窄→防重放→审计）在编排器状态转移层的密码学实现，是委托链凭证化的直接对标工作。

## 2. 运行时强制与工具最小权限

### P23 · Task Shield

**标题/载体**：实际标题为 *The Task Shield: Enforcing Task Alignment to Defend Against Indirect Prompt Injection in LLM Agents*，Jia 等（宾州州立 / 普林斯顿），**ACL 2025**（pp. 29680–29697）。

它提出"任务对齐"新视角防间接提示注入：不判断指令内容是否有害，而是校验每条指令**是否服务于用户目标**。形式化定义任务指令、ContributesTo 贡献关系、对齐条件与任务对齐，沿用系统>用户>助手>工具的指令特权层级。运行时防御系统三组件：保守提取嵌套/隐式指令构建用户任务集；对齐检查用 LLM 对每条指令相对每个用户任务打贡献分并聚合（总分归零即判失配）；失配时生成反馈（告警+风险说明+重申用户任务）让 agent 自我修正。AgentDojo 上对 GPT-4o：最强攻击的成功率从 47.69% 压到 2.07%，受攻击效用（69.79%）反而超过无防御基线（50.08%）；轻量版 Input Shield 以约 19 秒中位延迟（完整版 62.56 秒）做到 4.76% 成功率；防御器换 GPT-3.5-turbo 仍能把成功率降约一个数量级。

**与课题关联**：给"agent 每个动作必须对齐用户授权意图"提供了形式化定义与拦截-反馈执行机制，可与凭证层互补构成"意图授权 + 凭证"双层设计。

### P25 · Prompts Don't Protect  

**标题/载体**：*Prompts Don't Protect: Architectural Enforcement via MCP Proxy for LLM Tool Access Control*，Uppala（独立研究者），**EMNLP 2026 Industry Track**（pp. 43–49），代码开源。CCF B

它实证"提示词层面的工具访问控制在对抗下不可靠"：未授权工具出现在上下文中时，即使系统提示明令禁止，前沿模型仍以 48%–68.5% 的比率选择它们（角色提升攻击最高 96%）；显式 per-tool 白名单也只降到 4%–37% 且跨模型不可预测。机制是"受治理的 MCP 代理"：工具发现（tools/list）时做 JWT 验证 + 基于属性的访问控制（ABAC）过滤，**未授权工具根本不进入模型上下文**；调用（tools/call）时再做第二次校验，堵幻觉/注入的工具名。注册表含 507 个真实服务的 MCP 工具，200 个对抗任务（直接注入/间接指令/角色提升/多步欺骗）× 三模型：治理条件下未授权调用率全部精确为 0%，代理 p50 延迟仅 1.52ms。

**与课题关联**："执行点应放在基础设施层而非提示词层"的实证依据——把工具授权做进 MCP 发现/调用链路。

### P26 · Verifiably Safe Tool Use

**标题/载体**：*Towards Verifiably Safe Tool Use for LLM Agents*，Doshi 等（Georgia Tech / CMU / HKUST / NC State），**ICSE-NIER 2026**（愿景短文，5 页）。注意：PDF 页眉年份/DOI 为未替换的 ACM 模板占位符，引用以 ACM Reference Format 块为准。  ICSE 是CCF A

核心思想：将Agent安全从依赖大模型判断的概率性防护，推进到由独立安全策略和形式化验证支撑的可验证安全约束。它主张从"概率性防护栏"转向"可验证保证"：模型封装类防护（GuardAgent、LLM-judge、模式过滤）只能提升可靠性不能保证安全，而传统信息流控制标签依赖昂贵且不可靠的人工标注。三步路线：借航空/汽车安全工程的 STPA 方法识别直接/间接利益相关者并推导安全需求，形式化为时序逻辑流约束；提出带结构化标签的能力增强 MCP 框架——能力（read-only/write/execute）、数据保密级（public/private）、信任级（trusted/untrusted），配四级执行结构（自动阻断/强制必做/安全流免确认/高风险需用户确认）；用 Alloy 对增强版 MCP 形式建模，穷举有界执行轨迹验证"私密数据到达未授权工具"等危险谓词不可能发生。愿景阶段，初步结果仅验证可行性，未来才做外部策略引擎与真实部署。

**与课题关联**：把工具授权形式化为"能力标签 + 信任级别 + 可验证数据流约束"的方法论参照；其未来工作明确点名过度委托，与课题直接相关。

### P29 · AgentBound（重要）

**标题/载体**：*AgentBound: Securing Execution Boundaries of AI Agents*，Bühler 等（圣加仑大学），**FSE 2026**（PACMSE Vol.3, FSE096）。 CCF A

它针对 MCP 服务器在主机上"隐式完全信任"运行、继承 agent 的操作系统权限的问题，给出首个面向 MCP 服务器的访问控制框架：**AgentManifest**——借鉴 Android 权限模型，从 19 篇文献与 16 个用例提炼出 16 项平台无关的 MCP 服务器能力词汇（文件系统读写删、环境变量、进程执行、网络客户端/服务端、外设等五大类）；**AgentBox**——用 Docker 容器沙箱封装 MCP 服务器（零默认权限），mounts 限定文件系统、iptables 出站白名单限定网络，运行时把通用能力细化为具体权限（目录、URL）经用户同意授予；另有两阶段 LLM 流水线自动从代码生成 manifest。评估：296 个热门 MCP 服务器数据集，96 份自动生成 manifest 提交开发者评审 80.9% 判正确、能力词汇覆盖真实需求 100%；48 台服务器人工细粒度对比准确率 96.5%；运行时开销平均 0.6ms，仅容器启动多花约 150–400ms。

**与课题关联**：MCP 服务器"权限声明—同意—授予—沙箱执行"环节的工程化落地——把凭证（如环境变量中的 API key）的访问需求显式化并默认拒绝。

### P30 · Tracked Capabilities

**标题/载体**：*Securing Agents With Tracked Capabilities*，Odersky 等（EPFL LAMP 实验室，Scala 语言创始团队），**CAIS 2026**（ACM Conference on AI and Agentic Systems，pp. 812–838），实现开源（TACIT）。ACM 新会，主要研究AI 智能体、复合 AI 系统、系统优化、安全性与工程化，水平较高。

它把 agent 置于基于编程语言的"安全挽具"中：agent 不直接发工具调用，而是生成表达意图的 Scala 3 代码，由**捕获检查（capture checking）在静态类型中追踪能力**，local purity 保证机密数据（包在 Classified[T] 容器中）只能经纯函数变换、永不泄露；能力经作用域块授予并在**块结束时自动失效**——生命周期控制做进了类型系统；配合"不可信云端 LLM + 可信本地 LLM"双模型架构与双重输出通道。实现为开源 MCP 服务器 TACIT，兼容 OpenCode、Claude Code 等标准 MCP 客户端。实验：AgentDojo 注入攻击下 classified 模式对 Claude Sonnet 4.6 与 MiniMax M2.5 均 **100% 拦截**、效用保持 99.2%/90.9%；τ²-bench 与 SWE-Bench Lite 上性能与标准工具调用持平甚至略优，编译重试率仅 0.32%–2.93%。附录与 CaMeL 逐点对比：静态追踪代码上的能力 vs 运行时追踪数据上的污点。

**与课题关联**：把"能力"作为授权凭证并在类型系统里静态追踪其授予、传递、捕获与作用域到期失效——凭证生命周期的语言级实现路线，生产级语言特性背书。

### P31 · 过度特权工具选择

**标题/载体**：*When Lower Privileges Suffice: Investigating Over-Privileged Tool Selection in LLM Agents*，Yang 等（中科院信工所目前国内互联网中心一把手 / BAAI / 港中文 / 北大），**EMNLP 2026 Findings**（pp. 43846–43867）。CCF B

它研究 agent 的"过度特权工具选择"：存在足够低特权替代工具时，仍直接选高特权工具（激进选择），或在短暂、与特权无关的失败后立即升级特权（过早升级）。构建 ToolPrivBench：8 个应用领域 × 5 类风险（权限提升、范围扩张、时间持久性、安全绕过、数据过度暴露），每场景 3 低特权 + 3 高特权工具且全部能独立完成任务；双 LLM 评审加人工专家审计。11 个主流模型评测：Qwen3-8B 过度特权使用率高达 64.9%，Claude 4.6 Sonnet 仅 2.6%；瞬时失败显著放大升级；安全对齐与三种编码脚手架都不能消除该行为。缓解：特权感知后训练（SFT + GRPO，奖励"标准工具优先完成、升级仅作最后手段"），把三个 Qwen 变体的过度特权使用率从 39.7%–70.0% 降到 18.9%–38.4%，必要高特权场景保留 90%+，通用能力基本无损。

**与课题关联**："agent 侧最小权限行为"的首个系统基准与训练缓解——最小权限不只靠授权层强制，还可以训练进 agent 行为本身。

### P32 · AgentSpec

**标题/载体**：*AgentSpec: Customizable Runtime Enforcement for Safe and Reliable LLM Agents*，Wang 等（新加坡管理大学），**ICSE 2026**，代码开源。 CCF A

它提出运行时强制的领域特定语言（DSL）：规则由触发（state_change/before_action/agent_finish 及领域事件）—检查（谓词条件）—强制（stop/user_inspection/invoke_action/llm_self_examine）三段组成，论文给出规则-轨迹的形式化语义。实现基于 LangChain（拦截行动决策点，行动前评估约束），规则用 ANTLR 解析，可扩展至 AutoGen 与自动驾驶栈。结果：阻止 25 类风险中 24 类的 >90% 不安全代码执行，10 类具身危险动作全部归零，自动驾驶场景 100% 合规；开销毫秒级。LLM 自动生成规则实验（OpenAI o1）精确率 95.6%、召回 71.0%，拦截 87.3% 风险代码。

**与课题关联**："策略即代码"式的运行时授权/行为约束强制（触发-检查-强制三段式），是权限边界与凭证使用策略的落地组件参照——P06 速览里它就是对比基线之一。

### P39 · ProbGuard（拉完了）

**标题/载体**：*ProbGuard: Proactive Runtime Monitoring for LLM Agent Safety via Probabilistic Prediction*，Wang 等（新加坡管理大学 / 西安交大），**ASE 2026**。CCF A

它把运行时监控从"违规已发生才被动响应"推进到主动预测：离线对执行轨迹做谓词抽象并学习离散时间马尔可夫链（DTMC）刻画行为动态，用 PAC 分析刻画学习模型与真实系统的偏差；运行时用 PRISM 做 PCTL 模型检测，计算"从当前状态出发安全性质保持"的概率，低于阈值即向 agent 提示风险上下文（advisory 式干预，不覆盖控制流）。自动驾驶域最早可提前 15.8–38.7 秒预警，阈值 0.3 时 4 条法规 0% 误报、100% 检出，开销约 100ms；具身任务中 re-prompt 干预使不安全行为降 65.4%、保留 80.4% 完成率。与 AgentSpec、REDriver 对比：概率分数可解释且预警更早。

## 3. MCP 生态威胁与实证测量

### P36 · GrantBox

**标题/载体**：实际标题为 *Evaluating Privilege Usage of Agents with Real-World Tools*，Zhang 等（华东师大 / 新疆大学 / 清华），**FSE 2026 Companion**（5 页）。GrantBox 是文中系统名。 CCF A

它针对现有 agent 安全基准只用预编码工具/模拟环境、无法评估真实特权使用的问题，构建基于**真实 MCP 服务**的特权使用评估沙箱：10 个真实 MCP server、122 个特权敏感服务（云运维、数据库、邮件、文件系统），容器隔离 + 请求记录 + 监控；LLM 驱动生成 100 条良性请求与 90 个特权劫持用例（基础设施破坏、数据外泄、数据销毁、工作区篡改、资源耗尽五类）。对 GPT-5、Gemini-3 Flash、Qwen3-Max、DeepSeek-v3 在 ReAct 与 Plan-and-Execute 模式各测 500 次：ReAct 平均攻击成功率 90.6%、Plan-and-Execute 79.1%，八种设置总平均 84.8%——LLM 只有基础安全意识，挡 得住部分直接攻击、防不了精心构造的特权劫持。

**与课题关联**：专门量化"agent 持有真实凭证时的特权滥用与凭证劫持后果"（重置密码、删库、外发数据），其真实服务+容器隔离+攻击成功率的评测框架可直接借鉴为毕业设计实验方法学。

### P38 · MCPTox

**标题/载体**：*MCPTox: A Benchmark for Tool Poisoning Attack on Real-World MCP Servers*，Wang 等（中科大 / 北航），**AAAI 2026**（pp. 35811–35819）。 CCF A

如果攻击者在MCP工具的描述信息中植入恶意指令，即使Agent从未调用过这个恶意工具，是否仍然能够被诱导去调用其他合法工具，执行用户没有授权的操作。它是首个真实世界 MCP 工具投毒攻击基准：覆盖 45 个真实在线 MCP 服务器的 353 个真实认证工具，按三种攻击范式（显式触发-函数劫持、隐式触发-函数劫持、隐式触发-参数篡改）半自动生成并人工校验出 1348 个恶意用例；关键设计约束是恶意动作必须由服务器上**已有的合法工具**完成、被投毒工具本身从不执行——恶意指令藏在工具描述/元数据里，不执行即生效。对 20 个主流模型配置评测：平均攻击成功率 36.6%，最高 72.8%，存在"反向缩放"（模型越强越易受攻击，开推理使 Qwen3-32b 上升 27.8 个百分点）；拒绝率最高的 Claude-3.7-Sonnet 也低于 3%——现有内容安全对齐基本失效。另证把 InjecAgent 的载荷改成工具描述投毒后成功率近 0%，说明该攻击面需要专门基准。

**与课题关联**：证明 MCP 工具元数据是不可信的"信任面"——agent 对工具可信度的自查完全不可依赖，为"工具接入与调用前的授权校验"提供威胁模型与可复用基准。

## 4. OAuth / 账号生态：实证漏洞与形式化建模

### P20 · Universal Cross-app Attacks

**标题/载体**：*Universal Cross-app Attacks: Exploiting and Securing OAuth 2.0 in Integration Platforms*，Luo 等（香港中文大学 / Samsung Research America），**USENIX Security 2025**（pp. 3221–3238，Artifact Evaluated）。与 P07 OASIS 出自同一研究组，是其在集成平台上的前作。  CCF A

当一个平台同时替用户管理多个第三方应用的OAuth授权时，如何保证某次授权从发起、重定向、授权码兑换到令牌保存，始终属于同一个应用和同一个用户授权会话？它研究集成平台（工作流自动化如 Zapier/IFTTT、虚拟助手如 Alexa/Google Assistant、智能家居）中 OAuth 的**角色反转**：平台自身充当统一 OAuth client，而授权服务器反而由开放市场里不受信的第三方应用运营；平台在多应用架构下无法可靠追踪"活跃应用"，由此产生两类平台级跨应用攻击：**COAT**（跨应用 OAuth 账号接管——恶意应用让受害者的授权重定向到良性应用的授权服务器，却在自己的令牌端点收到对方的授权码，进而接管受害者账号）与 **CORF**（跨应用 OAuth 请求伪造），且都有"单击"变体（一条 crafted 链接即可，可借 prompt=none 绕过授权确认）。自研黑盒扫描器 COVScan 实测 18 个平台：**16 个存在跨应用漏洞**，含 Microsoft Power Automate（CVE-2023-36019，CVSS 9.6，单击可接管任意 Microsoft 365 账户）、Google Assistant（5 亿月活）等。修复方案是应用级绑定（全局唯一 per-app ID 嵌入 state + 专用 redirect_uri 双重确认），并指出 PKCE 并非有效防御。负责任披露 9 家修复、赏金 3.5 万美元，推动 OAuth 2.1 规范讨论。

**与课题关联**：揭示 agent 类平台（虚拟助手/插件正是其研究对象）代用户委托 OAuth 时，授权码从重定向到兑换的整个生命周期可被跨应用劫持——与 P07 构成同一攻击面的两代证据链。

### P08 · RAG

**标题/载体**：*Verifying Account Ecosystems With Graph Transformations*，Murphy & Radomirović（Surrey / Heriot-Watt），IEEE EuroS&P 2026。RAG（Resource Access Graph）是文中形式模型名。 CCF C

它解决静态账号生态分析无法建模"生态随时间演化"的问题：将账号、设备、凭据以及它们之间的访问关系构建成一张能够随时间变化的图，再通过形式化模型检测，自动找到可能导致账号接管、权限失控或用户失去访问能力的操作序列。生态演化是图重写转移系统，用户行为与攻击者规则统一为图变换规则，安全性质用 CTL 表达（资源完整性、可用性），用图重写模型检测器 GROOVE 自动验证。运行实例是 Apple 账号生态与 iOS 的失窃设备保护（SDP）：无 SDP 时自动重发现已知账号接管攻击（完整性与可用性均被违反）；开 SDP 后可用性恢复但完整性**仍违反**；进而提出"从受信设备访问 Apple 账号强制二因素"的改进并在模型中验证通过。

**与课题关联**：提供了形式化验证凭证/账号依赖生态的完整方法论，可迁移到 Agent 凭证生命周期策略的自动验证。



## 5. 撤销与凭证基础设施

### P24 · PRC

**标题/载体**：实际标题为 *Do You Need a Receipt? Anonymous Credential Revocation at Continental Scale via Private Record Certification*，EdalatNejad 等（达姆施塔特工业大学），**USENIX Security 2026**（正式发表，Artifact Evaluated）。文件简称取自其核心原语 PRC。  CCF A

它攻匿名凭证系统的"撤销"难题：现有累加器、黑名单、epoch 型方案普遍开销大、撤销生效延迟、需向全体用户推送更新。论文提出新密码学原语 **Private Record Certification（PRC）**：客户端从 n 个撤销机构秘密共享维护的状态数据库中，**不泄露所查索引**地拿到记录的签名证书（非撤销令牌），再以零知识证明向验证者出示。技术上把多服务器 PIR 与 GMW 安全多方计算结合，关键贡献是布尔秘密分享到 One-Hot 编码的转换 Bin2OHE（乘法深度 O(lg N)），配合 Pedersen 同态承诺与门限签名，使客户端通信只取决于索引位数。Rust 原型在 10 亿凭证规模下实现亚秒级（<400ms）实时撤销，单服务器处理百万请求运维成本约 2.5 美元；较 ALLOSAUR 快逾 20,000 倍，较 PIR 基线节省 900–2700 倍服务器计算。

**与课题关联**：凭证生命周期"撤销/失效"环节的规模化隐私保护基础设施，可迁移到 Agent 持有的匿名凭证/VC 的撤销与状态校验设计——撤销环节的材料由此从协议层延伸到基础设施层。

## 6. 凭证使用可验证化与隐私策略求值

### P14 · DECO

**标题/载体**：*DECO: Liberating Web Data Using Decentralized Oracles for TLS*，Zhang 等（Cornell Tech），arXiv 2020 扩展版（DECO 原文发表于 CCS 2020）。 CCF A

它解决"用户无法向第三方证明经 TLS 取回的网页数据确实来自某网站"的问题，且不依赖可信硬件（TEE）或服务器端改造。协议三方为证明者、验证者与 TLS 服务器：三方握手中对 MAC 密钥做加性秘密共享（证明者提交会话密文后才拿到验证者份额，会话承诺不可伪造）；查询用定制 2PC-HMAC；证明阶段支持选择性打开/隐去子串；形式化为理想功能并给出 UC 安全证明。应用包括保密金融合约、把遗留凭证转匿名凭证（年龄证明）等，端到端约十几秒。

**与课题关联**：把 Web 账号已有凭证/数据转化为**可验证凭证**的奠基工作，对应凭证出处证明与隐私化出示环节。

## 8. 授权与委托机制：意图、最小权限、委托语义

### P01 · SUDP

**标题/载体**：*SUDP: Secret-Use Delegation Protocol for Agentic Systems*，Yu 等（帝国理工/牛津/斯坦福），arXiv 预印本（2026-10，v4）。

它针对的是"授权即暴露"：今天的 agent 运行时要启用动作，就得把可复用密钥（API key、OAuth token）放进运行时，一次瞬时提示注入就升级为持久账号失陷。论文把这件事形式化为 Agent Secret Use（ASU）问题，定义了 7 条安全性质（授权完整性 + 秘密保密性），并提出 SUDP 协议：请求方提议一个规范化操作，用户在一次认证器仪式里对**这一具体操作**签发一次性 grant，托管方（本地代理、HSM/TEE 等）验证 grant 后代为执行，可复用权限从不进入请求方边界。主定理证明 7 条性质中 6 条在标准密码假设下原生成立，参考实现每次受代理调用仅增加约 0.76ms 开销。

**与课题关联**：凭证"交付即失陷"问题的首要对标协议——把授权从"给 agent 凭证"改为"对单次操作签发一次性、操作绑定的许可"。

### P02 · PAuth

**标题/载体**：*Beyond OAuth: Task-Scoped Authorization for AI Agents via Natural Language Slices*，Sharma 等（UW/俄亥俄州立/微软研究院），arXiv 预印本（2026-08）。文件简称 PAuth 取自其机制名（Precise Task-Scoped Implicit Authorization）。

它指出 OAuth 的结构性错配：scope 只管"操作符"（如转账权限）不管"操作"（操作符+操作数），而"转账 Citi 余额的四分之一"这类操作数依赖运行时计算，任何静态 scope 都表达不了，agent 因此被结构性过度授权。PAuth 让用户签名的自然语言任务本身成为授权依据：每个 MCP 服务器用 LLM 按受限语法生成代码，再经**确定性**切片编译得到逐工具授权规则；运行时用服务器签名的 envelope 把具体操作数绑定到任务蕴含的计算，不一致就升级为用户弹窗。在自建基准 AuthBench 上，100 个良性任务全部放行、634 个对抗调用全部阻断。

**与课题关联**：论证"OAuth/MCP 授权过权"、设计最小充分委托时的直接参照，附带可复用基准。

### P40 · ASTRA

**标题/载体**：实际标题为 *Delegated Authorization for Agents Constrained to Semantic Task-to-Scope Matching*，El Helou 等（Cisco Systems 瑞士），arXiv 预印本（2025-10）。ASTRA 是文中基准数据集名。

它解决 OAuth 委托授权流"只认显式 scope 请求、不感知自然语言任务意图"的失配：agent 可在令牌中夹带超出任务范围的写权限。机制：授权服务器侧加入可信代理转发全部委托授权流并附加原始 prompt 元数据，AS 内置可信 LLM 语义匹配模块，把任务描述与所请求工具/资源做语义比对，**只发放与任务最小 scope 对应、任务完成即自动回收**的即时最小权限令牌，并将授权基础设施分割为轻量虚拟化实例以收敛爆炸半径。评估：自建 ASTRA 数据集管线（12 个企业级 MCP Server）+ Toucan 公开数据集；单工具任务 LLM 判断准确率 0.84–0.96 优于嵌入相似度（0.77–0.86），3 工具任务召回降至 0.57——过度放行与误拒绝的权衡说明语义匹配必要但有局限。数据集开源。

**与课题关联**：与 P02 同族但落在 OAuth 授权服务器侧——按任务语义发放最小 scope 并任务完成即回收，是签发环节的凭证生命周期约束。

### P41 · CASA

**标题/载体**：实际标题为 *Hybrid Inspection and Task-Based Access Control in Zero-Trust Agentic AI*，El Helou 等（Cisco，与 P40 同组），arXiv 预印本（2026-05）。CASA 是文中框架名（Continuous Agent Semantic Authorization）。

它面向多轮、多 agent 协作场景（工具定义篡改、调用伪造、参数与返回数据篡改、诱导越范围调用），在零信任拦截层部署两类互补控制：**五项确定性检查**（工具定义完整性、请求授权验证、动作对齐、参数完整性、数据保真度）用二元逻辑捕获结构性违规；**语义控制层**把 P40 的单任务匹配分解为"会话任务抽取 + 任务-工具匹配"两阶段，逐工具做二元判定支撑 TBAC（基于任务的访问控制）。数据：扩展 ASTRA 数据集生成 3,524 条会话-工具测试样本与含恶意 agent 的多智能体测试集 3,242 条；GPT-5.4/5.2、Claude Sonnet/Opus 4.6 四模型评测单轮 F1 0.93–0.98、多轮 0.90–0.98，多智能体场景最难（FPR 升至 0.15–0.20）。附录案例表明恶意系统提示注入可绕过全部五项确定性检查、必须依赖语义层。

**与课题关联**：零信任拦截层上"确定性结构检查 + 语义意图-工具匹配"双层防线，逐调用发放/校验令牌的 TBAC——与 P02/P45 同一问题族的多轮扩展。

### P42 · 弹性最小特权

**标题/载体**：*Towards Elastic Least Privilege for Agent Planning*，Parkinson 等（曼彻斯特城市大学 / 曼彻斯特大学），arXiv 预印本（2026-10-29，BlueSky 立场/议程论文，无实现）。

它针对"agent 所需权限随任务与执行动态变化、静态宽授权造成过度赋权"（447,000 个 GitHub CI 工作流 99.8% 过度赋权；GitHub MCP 编码代理拿 repo-scope 令牌即获得约 40 个工具且 16 个可全仓写入），提出弹性最小特权概念模型：agent 静止时只持基线 B(a)，可在所有者定义的包络 V(a) 内申请提升；每次扩展产生随功率与重复请求**超可加增长**的成本率，受组织级天花板约束（含"不可信输入、敏感数据、外传通道不可同时持有"类不变量，会话属性有粘性）；提升一律以**租约**授予，到期/主动释放/预算耗尽即回弹到基线；跨任务经 grant 日志审计"可塑性"重定基线。形式化给出四条由签发方强制、与 planner 行为无关的保证：天花板、有界提升暴露、回收、独立性。

**与课题关联**：凭证/权限动态生命周期最直接的概念框架——基线/包络/租约到期/回收/预算/跨任务重定基线，适合作为机制设计章节的概念底座（注意尚无实现与实证）。

### P43 · Progent

**标题/载体**：*Progent: Securing AI Agents with Privilege Control*，Shi 等（UC Berkeley / UCSB / 新加坡国立大学），arXiv 预印本（2025-04 首版，2026-05 v3）。

它提出工具调用级权限控制框架：权限策略由针对工具名与参数的符号化规则（allow/forbid + fallback 动作）组成，由 LLM 从用户任务自动生成初始策略并随执行动态更新；每次更新经确定性 SMT 求解器（Z3）判定为"收窄"（自动应用）或"扩张"（需显式批准），从而保证**单调约束**性质——无显式批准时 agent 的有效动作空间只能缩小，对抗性输入也无法静默提权。AgentDojo 与 ASB 基准上攻击成功率从 39.9%→约 1.0%、70.3%→3.9%，效用基本不变；仅约 6% 的策略更新需人工批准；已集成 LangChain、OpenAI Agents SDK、OpenHands 与 AutoGen；三类自适应攻击下成功率仅升至 0.5–1.4%。

**与课题关联**：以"策略生成—SMT 判定—批准"实现 agent 权限的动态授予与最小权限收敛，是权限/凭证运行时生命周期管控的直接代表作（P06 的对比基线之一）。

### P45 · 意图凭证

**标题/载体**：实际标题为 *Intent-Governed Tool Authorization for AI Agents*，Zhu & Wang（Accentrust / Georgia Tech / UIUC——与 P03 同一作者对），arXiv 预印本（2026-09）。

它指出凭证中心授权只回答"应用被允许调用什么"，而 agent 工具使用还须回答"该调用是否被用户当前请求正当化"——**意图-工具失配**。机制：**意图凭证（intent certificate）**授权层——服务器端从可信用户请求派生短生命周期策略断言（请求哈希、主体/租户/会话绑定、意图类别、资源与效果边界、置信度、过期与撤销状态），据此单调收窄静态工具清单，经一致性门检查调用-载荷-效果一致，按置信度路由到拒绝/澄清/草拟/预检/确认/执行六种结果（fail-closed：低置信度、冲突意图、高风险均不得直接执行）。形式化给出清单单调性、静态策略不扩张、高风险 fail-closed、请求封闭合同四个命题。评估：复合暴露指标从 1.0000 降至 0、零起不安全执行完成；但严格良性完成率仅 0/108——**凭证的精确资源/效果边界归一化是主要剩余瓶颈**。

**与课题关联**：与课题核心几乎完全重合——在静态凭证之上引入请求级最小特权层，"意图凭证"本身就是带签发、过期、撤销、版本绑定的短时授权凭证；且与 P03 出自同一作者对，两篇合读可见"请求级签发"与"生命周期终点"的成对设计。

## 9. 运行时强制与效果闭环

### P05 · AID-Guard

**标题/载体**：*AID-Guard: Stateful Authorization for Delegated Agent Effects*，佟英哲等（信息工程大学），arXiv 预印本（2026-08）。

它针对"授权-效果鸿沟"：授权检查止步于准入，而之后请求可被篡改、响应可能丢失、重试与恢复可能让一次批准产生**第二个**效果。AID-Guard 是从批准到效果落地的有状态闭环：provider 提交处重验证与批准完全一致的请求和当前状态；结果歧义时保留原 reservation、绝不铸造替代授权；只有终态结果或"经认证的无效果证书"才能释放配额或转移给唯一后继。实验里 13 次活体变异全部拦截、AgentDojo 保护臂 0 个不安全效果，代价是保护路径中位延迟约 2.35 倍。核心论断："重试与恢复是权威转移，而非传输细节。"

**与课题关联**：覆盖"准入之后、效果落地之前"这段最容易被忽视的生命周期，与本课题实现层高度相关。

### P06 · ACG

**标题/载体**：*Authorization Closure Graph: Minimal Repair for LLM Agents with Evolving User Instructions*，Wang 等（同济大学），arXiv 预印本（2026-09）。

用户改口之后，先前的授权如何**选择性**更新？现有方法要么不维护授权状态（只查单次调用），要么整单重新授权。ACG 把授权状态做成版本化有向无环图：节点分 Authority（用户授权）/ Evidence（权威环境证据）/ Derived（派生后果）三类，用 COMMIT、REVOKE、REVISE 等六种认证操作更新；检查候选动作时输出 AUTHORIZE / BLOCK / MINIMAL REPAIR 三种决策——最后一种会返回"依赖最小修复集"，只重授权真正受影响的部分；执行前对记录的节点版本做重验证，防止用过期授权。在 τ²-bench 两个域、三个模型上动作安全性全部最高，不安全写任务从 75 降到 8。

**与课题关联**：把授权变成"可版本化、可选择性失效、可最小修复"的图状态，是授权修订/失效环节的运行时 guard 机制。

### P13 · CaMeL

**标题/载体**：*Defeating Prompt Injections by Design*，Debenedetti 等（Google DeepMind & ETH Zurich），arXiv 2025（2025-06 v2）；系统名 CaMeL，代码开源。

它针对的是提示注入里最棘手的一类：攻击者不劫持控制流，只污染数据流（篡改工具调用参数）就能实现数据外泄。CaMeL 不改模型，而是在模型外建保护层：特权 LLM 只看用户查询、生成计划代码；隔离 LLM 无工具权限、只负责把非结构化数据解析成结构化输出；每个值带能力标签（来源 provenance + 允许读者）；自定义解释器维护数据流依赖并在每次工具调用前强制执行策略。论文把威胁形式化为 PI-SEC 安全博弈，CaMeL **按构造**满足。AgentDojo 上以可证明安全性解决 77% 任务（未防御 84%），949 个攻击下多数模型成功攻击数降为 0，代价约 2.7–2.8 倍 token。作者坦承钓鱼展示、侧信道等仍不可防。

**与课题关联**：能力标签 + 信息流/控制流强制是"凭证与敏感数据不越权流动"的最直接系统范本。

### P44 · Irreversibility Budget

**标题/载体**：实际标题为 *The Irreversibility Budget: Fleet-Level Risk Accounting and Admission Control for Agent Operating Systems*，Mohammadi & Bindschaedler（MPI-SWS），**Agentic OS Workshop 2026**（2026-09-29，布拉格）+ arXiv 预印本。

它指出 agent 舰队的不可逆效应（转账、部署代码、删数据、泄露信息）只有逐笔检查、没有跨 agent/工作流/租户的累积核算：个体均被授权的动作在共享触发（供应商涨价警报、提示注入）下会集体突破主体风险限额（模拟中最多超支租户限额 48 倍）。机制：把**不可逆性视为一等资源**——可信运行时在每个主体的提交边界维护"剩余风险价值"累积账户，按各效应的剩余损失定价收费，边际收费会超出授权预算即拒绝该效应；配套风险类型化效应声明（工具规范声明效应类别、暴露上界、可逆/补偿路径）、层级账本与预留-确认-取消（防双花）、基于风险压力的准入控制。控制模拟与真实 trace（τ-bench 38,452 条轨迹）表明预算每次运行都守住限额、单笔局部闸门超支 2.4–48 倍；账本开销约 2.6 微秒/预留。

**与课题关联**：把授权从"单笔是否允许"扩展到"委托额度的跨主体累积核算与提交前准入"——凭证/权限的量化生命周期管理（预算、预留、冻结）的 OS 层抽象，与 P05 的配额预留、P11 的代价有界验证同族。

## 10. 撤销、残留权威与凭证托管

### P03 · Root-Scoped Quiescence

**标题/载体**：*Authorization Revocation for Long-Running AI Agents: Root-Scoped Quiescence under Delegation and Asynchronous Execution*，Zhu & Wang（Accentrust / Georgia Tech / UIUC），arXiv 预印本（2026-09）。

它解决长期运行 agent 的"停不下来"问题：单点取消（MCP 取消、OAuth 令牌吊销、进程退出）各自只关掉一个本地对象，已入队消息、衍生凭证、cron/webhook 触发器、provider 侧预留操作仍能在**已被退役的授权根**下产生效果；而盲目级联吊销又会误杀独立授权的共享工作。论文定义"根域授权静止"，给出协议：持久 root-epoch 原子冻结签发；各 provider 装本地 fence，栅栏后的旧提交一律拒绝；跨根存续必须经 rebind 到独立见证（防"根洗白"）；用 channel-token 收支核对跨 provider 传递，最终输出 Quiescent / Not-Quiescent / Indeterminate 三值判定（超时或缺证据绝不升级为成功）。全文 3 引理 6 定理共 9 条结果，17 个晚效应用例全部通过。

**与课题关联**：给"吊销 ≠ 停止"的残留权威问题提供了可验证的收尾协议蓝本。

### P04 · ResidualAuth

**标题/载体**：*ResidualAuth: What Authorization State Must Agent Systems Preserve Under Revocable Delegation?*，Choi 等（首尔国立大学），arXiv 预印本（2026-09）。

它回答"可撤销委托下系统必须保存什么授权状态"。核心观察：两条授权历史可以有完全相同的当前权限，但同一次撤销之后，一个该拦、一个该放——差别在**授权来源**。论文用 Myhill–Nerode 等价定义"残余授权状态"，证明精确在线监控器所需的状态数与比特数（冗余-记忆律：无撤销 Θ(rN) 比特、级联撤销 Θ(rN²)），以及信息预算下的决策错误率下界（追加推理也绕不过）。实验很说明问题：LLM 仅凭 256-token 摘要几乎做不对配对判断（0–2/16），但给它一个可信的"当前授权查询"就升到 15–16/16——失败在"信息获取"，不在推理。

**与课题关联**：从信息论下界刻画撤销后"必须对可信机制持续可用的授权信息"，是残余权威问题的理论奠基。

### P17 · HBHC

**标题/载体**：*Heartbeat-Bound Hierarchical Credentials: Cryptographic Revocation for AI Agent Swarms*，Deochake（SentinelOne），arXiv 预印本（2026-05）。

它解决"僵尸 agent"问题：父 agent 被关停后，子 agent 凭现有令牌还能继续执行特权操作几分钟到几小时——因为 OAuth 内省、OCSP、W3C Status List 这些撤销机制都要在线连接中心权威。HBHC 把凭证有效性绑定到父 agent 的**周期性签名心跳**：子 agent 在每次认证中纳入新鲜心跳，验证方只用缓存公钥和本地时钟就能**离线**校验新鲜度，撤销窗口有确定上界；结合 BIP-32 分层密钥派生，给出形式化证明与 OAuth 2.0 / W3C VC 集成方案。实验：僵尸窗口较 OAuth 缩短 90 倍（约 40 秒），认证 0.26ms，工具调用端到端开销仅 0.71%。

**与课题关联**：撤销传播/确定性终止这一核心缺口的离线密码学路线，是撤销机制设计的关键对照方案。

### P18 · Vault 中介执行边界

**标题/载体**：*API Secrets Should Never Become Tokens in the LLM's Vocabulary: A Threat Analysis of API Credential Handling in LLM Agent Systems and an Empirical Evaluation of a Vault-Mediated Execution Boundary*，Kenney 等（Corvic AI），arXiv 预印本（2026-09，7 页）。文件简称取自副标题概念。

它指出工具型 agent 把"凭证卫生"从存储问题变成了执行安全问题：API 密钥会进入对话历史、日志、记忆/向量库、生成代码和错误载荷这些"复制点"，提示注入可把被动泄露转化为未授权操作。论文四项贡献：形式化五阶段暴露链（引入→传播→触发→执行→持久化）；综合 2024 年 Hugging Face 密钥事件、GitGuardian 2377 万硬编码密钥测量与 OWASP/NIST 指南三类证据；描述 vault 中介执行边界——agent 只拿连接器标识符，可信边界按配置注入认证头，凭证**从不是 agent 持有的值**；16 个黑盒探针验证不可观测性、源绑定、集中生命周期等性质，并报告阴性结果：集中托管不等于配置正确。

**与课题关联**：从"凭证不进模型上下文"的保管/注入/轮换视角补充生命周期，作者明确 vault 是必要而非充分条件。

## 11. OAuth 与 MCP 生态威胁

### P07 · OASIS

**标题/载体**：*Demystifying the (In)Security of OAuth-based Account Linking in Connector Ecosystems*，Luo 等（香港中文大学 / Samsung Research America），2026（文内未标注正式出处，USENIX 风格稿）。OASIS 是文中扫描工具名；与 P20 出自同一研究组，是其在 connector/Agentic AI 生态上的后作。

它首次系统研究 connector 生态（连接器应用、集成平台、Agentic AI 基础设施）中基于 OAuth 的账号链接——作者称之为"二阶 OAuth"，是 RFC 6749 未建模的维度。核心发现：当应用业务逻辑与 OAuth client 解耦（跨 origin 回调、或外包给 OAuth-as-a-Service 的中央令牌保管）时，回调落在"未认证空间"，会话可被固定，由此提出新攻击类 **COSF（跨用户 OAuth 会话固定）**：受害者点一下攻击者的链接、静默授权后，自己的 connector 账号被绑到攻击者应用账号上，形成一键账号接管；OaaS 多租户下还有跨租户 client_id 混淆等 confused-deputy 攻击。实测 46 家厂商中 42 家有错链风险（含 Slack、Alexa、n8n、IFTTT、Perplexity、Manus 等）；负责任披露获 20 家确认、15+ 家修复、赏金 35,850 美元，作者撰写的 IETF 草案已被 OAuth 工作组采纳。

**与课题关联**：给出 Agent/连接器**获取凭证环节**的真实攻击面，以及授权上下文绑定 `<user, tenant, connector>` 的规范级防御。

### P33 · Audience Injection

**标题/载体**：*Audience Injection Attacks: A New Class of Attacks on Web-Based Authorization and Authentication Standards*，Hosseyni 等（斯图加特大学信息安全研究所），文内未标注出处（披露时间线 2024-09 至 2025，与 OIDF/IETF 协同披露中）。

它提出**受众注入攻击**——针对签名式客户端认证的一类新漏洞，波及作者所称 OMAA 协议族：OAuth 2.0、OIDC、FAPI 1.0/2.0 高安全 profile、CIBA、设备授权，以及 PAR、令牌吊销/内省、OpenID Federation 等十余项标准与扩展。核心弱点是 Private Key JWT 等 client assertion 的 aud 声明：标准允许（且常推荐）取 token endpoint URL 作受众值，而客户端无法外部校验其真伪。两阶段攻击：恶意授权服务器伪造配置文档把自己的端点列为 token endpoint，诱使诚实客户端发出 aud 指向诚实 AS 的有效 client assertion；攻击者重放该断言冒充客户端向诚实 AS 换取受害者资源令牌——**同时破坏授权与认证两大安全目标**，FAPI 2.0 的 PKCE 也无法阻止。负责任披露推动十多项标准及 Microsoft、Okta、Authlete 等大量实现协调修复：将 aud 强制限定为 AS issuer identifier。

**与课题关联**：攻击对象是授权协议栈的核心（客户端认证与受众绑定）——agent 使用的 OAuth/OIDC 凭证签发环节的协议层威胁来源与标准修复依据。

### P34 · MCP Landscape

**标题/载体**：实际标题为 *Model Context Protocol (MCP): Landscape, Security Threats, and Future Research Directions*，Hou 等（华中科技大学），ACM 格式排版预印本（2025-10，DOI 占位，自标 vision paper，在投状态）。

它是 MCP 生态的首个系统性安全分析：定义 MCP server 四阶段生命周期（创建、部署、运营、维护）细分 16 项关键活动；以攻击者类型为轴构建威胁分类法——恶意开发者、外部攻击者、恶意用户、安全缺陷四大类 **16 个威胁场景**（命名空间抢注、工具投毒、rug pull、跨服务器 shadowing、安装器欺骗、间接提示注入、凭证窃取、沙箱逃逸、越权访问、漏洞版本重部署、升级后权限残留、配置漂移等）；用官方 SDK 自建 host 与 16 个 PoC server 在隔离环境真实验证。同时测量生态现状（26 个 server 市场，实测某市场抽样 300 个 server 中 30 个名不副实、18 个失效），给出三个产业案例研究与按生命周期阶段的细粒度安全加固建议。

**与课题关联**：课题的背景威胁图——其中"明文凭证窃取""升级后权限残留""越权访问"等场景直接对应凭证生命周期主题；引用时注明在投/vision 属性。

# 第三部分 · 标准草案（IETF Internet-Draft，8 份）

### D1 · draft-chen-oauth-agent-revocation-01

**标题/状态**：*OAuth 2.0 Agent Authorization Explicit Revocation*，Meiling Chen、Li Su（中国移动），OAuth 工作组个人提交，-01 版，2026-10-30，2027-05-03 过期，work in progress。

它标准化 **agent 粒度的显式撤销**，弥补 RFC 7009 只能按单令牌撤销的缺陷（无按 agent 批量撤销、上游撤销后下游子 agent 令牌仍有效、无审计上下文、不支持挂起/部分撤销）。核心机制：新增 `POST /agent/revoke` 端点，JSON 请求体含 agent_id、原因、`cascade_depth`（-1 无限级联 / 0 仅本 agent）、操作者上下文，以及临时挂起（按秒）、scope 保留/裁剪等参数；响应返回事务号、撤销统计（直接/级联撤销数、令牌数、失败明细）与审计引用。安全考虑要求专门的 `agent.revoke` 特权 scope、级联限流防 DoS、关键 agent 多方审批。整体仍是偏接口描述的早期草案。

**与课题关联**：撤销环节的"在线中心式"标准化路线；D8 显式把自己定位为它的"传播后完成条件"补充。

### D2 · draft-asor-wimse-agent-delegation-chain-03

**标题/状态**：*Verifiable Attenuated Delegation for AI Agent Chains*，Rafael Asor（Attenu），**WIMSE 工作组**文件，-03 版，2026-10-27，2027-04-30 过期；已有 Python/TypeScript 参考实现与 36 个测试向量。

它标准化 **agent 委托链**：解决 RFC 8693 Token Exchange 的 `act` 声明只是审计信息、无法在两跳以上强制衰减、且每跳需在线访问授权服务器的问题。核心机制：定义 Delegation Token（RFC 9068 JWT 访问令牌的 profile），权限用 RFC 9396 RAR 的 `agent_delegation` 明细承载（scope 支持 literal/wildcard/opaque 三种语法加约束词表：按次数、按生命周期、按子树上限等）；每跳以 `client_id` 命名执行 agent、`sub` 保持不变以绑定同一可问责主体；子令牌用 `par_hash`（父令牌签名输入的哈希承诺）链接父令牌防链拼接；`del_depth` 约束深度，DPoP 做持有者绑定。第 6 节规定 **8 步确定性离线验证算法**（验签、链形与深度检查、逐跳权限包含、单调过期、撤销状态检查——unknown 即拒绝）与 16 种标准化拒绝结果。

**与课题关联**：委托衰减/链式凭证/离线撤销最直接的标准化草案；D6 原样采用它的令牌格式做互操作——事实上的委托链格式锚点。

### D3 · draft-mcguinness-oauth-mission-02

**标题/状态**：*Mission-Bound Authorization for OAuth 2.0*，Karl McGuinness（独立提交），-02 版，2026-11-02，2027-05-06 过期；个人草案（非工作组采纳），自建"Mission 家族"配套草案群覆盖运行时强制、跨域投影、安全模型等。

它为 OAuth 2.0 补上此前缺失的标准化对象——**Mission（任务）**：一个持久授权对象，把披露的任务意图（目标、目标资源、边界、用途、过期时间）与授权服务器**机械派生**的 Authority Set（RFC 9396 条目集合）绑定；批准者对派生权限集本身（而非任务文字）作出同意，内容用 JCS+SHA-256 完整性锚固定。此后每次发令牌（码兑换、刷新、Token Exchange、委派）都门控于：Mission 必须为 active、结果必须是已批准集合的子集、令牌携带 mission 声明且 exp 不超过 Mission 过期；按 mission_id 撤销阻断后续签发（但不召回已发令牌）；可选支持代理间委派策略与降权自交换。显式处理的威胁包括：批准后注入的文本无法扩权、委派链破解、降权遗漏。

**与课题关联**："任务绑定授权"路线的代表作——一次用户批准变成可审计、可撤销的持久授权对象，把签发层治理与运行时逐动作执行明确分层；是八份草案中协议栈最完整的一份。

### D4 · draft-liu-oauth-authorization-evidence-02

**标题/状态**：*Authorization Evidence and Audit Trail for OAuth 2.0 Access Tokens*，Dapeng Liu、Hongru Zhu（阿里巴巴）、Suresh Krishnan（Cisco）、Aaron Parecki（Okta），OAuth 工作组范畴，-02 版，2026-11-02，2027-05-06 过期，Standards Track 意向。

它利用 RFC 9396 的 enriched response 机制定义新的 authorization details 类型 `authorization_evidence`：AS 在批准时把**批准记录**（approved/narrowed/declined 三值、批准者、确认动作、时间戳）与结构化**披露对象**（摘要、权限依据、风险提示——即批准者当时看到了什么）一并写入证据对象，JCS 规范化后以分离式 JWS（强制 ES256）签名，附内容哈希与权限边界哈希；证据可嵌入令牌或以"引用投影"（id+哈希，经 RFC 7662 内省取回）放入。同时定义撤销机制：AS 端授权记录 + 撤销句柄，治理授权有 withdrawn/completed/terminated/expired 四种终态。核心不变式：**"证据不证明当前权限"**。附录含可验证的签名工作示例（相当于测试向量）。

**与课题关联**：把 agent 授权的"批准—披露—撤销"闭环做成可审计、可问责的标准化证据机制，是授权可问责性方向规范性最强的草案（作者阵容含 Okta/Cisco/阿里）。

### D5 · draft-thaha-wimse-agent-evidence-binding-03

**标题/状态**：*Evidence Binding for AI Agent Credentials*，Thaha、Shamsudeen（个人提交），-03 版，2026-11，2027-05-05 过期，Informational；WIMSE AIMS 的伴生文档。

它补 AIMS（防篡改 agent 审计）未定的格式与发现机制：把 AIMS 最小审计字段逐项映射到 SCITT 执行证据档案的 Execution Receipt（agent_id、principal/actor 链、决策、时间戳/序号、策略包摘要、撤销语句等）；定义 JWT/CWT 新声明 `aee_evidence`（证据服务、策略包摘要、did:web 持久 agent 身份、保障级别与状态缓存）；定义服务方每次调用的 **7 步准入门**（令牌+持有证明验证、状态新鲜度、注册与保障检查、Principal 与当前 actor 核对、自算调用摘要拒绝重放、出具准入回执）；定义 HTTP 头绑定单次调用，actor 链用 RFC 8693 嵌套 act 声明承载。成熟度：有完整示例、无测试向量与参考实现，依赖 SCITT 系列伴生草案。

**与课题关联**：解决 agent 凭证与执行证据之间的"发现—绑定—准入"，覆盖委托链记录与按调用准入——凭证生命周期与可验证审计方向的配套机制。

### D6 · draft-sweeney-wimse-credential-delegation-02

**标题/状态**：*Credential Delegation Protocol for AI Agents in Multi-System Environments*，Kieran Sweeney（个人提交，WIMSE 语境），-02 版，2026-10-30，2027-05-03 过期，Standards Track 意向；有 RFC 7942 实现状态章节（作者自有 TypeScript SDK）。

它把 RFC 8693 + DPoP + RAR + OIDC CIBA 组合成面向 agent 的凭证委托框架，补七个缺口（无 agent 身份原语、无链衰减强制、无凭证包裹、无细粒度授权、无同步级联撤销、无异步同意、无审计链）。核心：agent 用临时密钥派生 did:key 身份向委托服务器（DS）认证；DS 签发能力形委托令牌（八类委托约束上限、DPoP 绑定、回执链），**底层 OAuth 凭证存于 DS 凭证保险库、绝不交付给 agent**，agent 经 /exercise 端点由 DS 代理行使；每跳 DS 签名回执以 prf 串联、逐跳重验父链并强制权限单调收窄（修复 RFC 8693 委托链拼接漏洞）；撤销 SLA 单令牌 1 秒、级联 5 秒；超范围委托经 CIBA 后信道向用户征求同意，同意记录不可变、保留至少 90 天。5.5 节"链可验证 profile"原样采用 D2（ASOR）令牌格式供 DS 之外验证者离线校验；原生验证器通过 ASOR -03 全部 36 条互操作测试向量。

**与课题关联**：覆盖凭证全生命周期（身份引导→委托签发→行使→子委托→撤销→审计）的最完整标准化文本，且与 D2 显式互操作——课题标准化对象与对比基线的首选。

### D7 · draft-reddy-wimse-oauth-dialog-binding-00

**标题/状态**：*Binding Agent Dialogs to WIMSE and OAuth Credentials*，Tirumaleswar Reddy、Zaheduzzaman Sarker（Nokia），-00 首版，2026-10-30，2027-05-03 过期，Standards Track 意向，WIMSE 语境。

**与课题关联**：从"会话/对话维度"补充授权边界——把授权限定到具体对话、防令牌跨对话重放，是凭证使用场景约束的对话级粒度标准素材。

### D8 · draft-watts-oauth-agent-revocation-closure-03

**标题/状态**：*Revocation Closure and Authority Epochs for Agent Delegation*，Deonté O'dell Watts（GoodShyt Group），个人提交，-03 版，2026-10-30，2027-05-03 过期，Informational。

它的核心论点是三者区分：**撤销请求 ≠ 令牌失效 ≠ 委托权限闭环**——令牌失效后，被交换（RFC 8693）、委托给子 agent、缓存、附于事务上下文或已入队的异步工作仍可能产生新后果性操作。定义：**authority epoch**（一次授权事件根生的权限有界生命周期的不透明标识，派生权限除非独立再授权否则留在原 epoch 闭环内）；委托谱系确定性归属（换格式/签发者/受众不切断谱系）；准入/队列围栏（闭环开始后禁止新入队）；未决后果性操作四选一（取消/围栏/已提交/再授权）；**闭环评估算法**（形式化谓词 CLOSED：覆盖已知、每条 root-to-sink 路径被 barrier 阻断、无未决操作、无未知状态、无绕行后代，并要求正常路径见证防"空洞 CLOSED"）；闭环状态机 REQUESTED→PROPAGATING→CLOSED/PARTIAL/FAILED/UNKNOWN 刻意 fail-closed；完整性保护的非 bearer 型闭环回执。与 RFC 7009/8693/7662/9449、Transaction Tokens、WIMSE 逐项给出组合规则；显式把自己定位为 D1（chen 撤销端点）的"传播后完成条件"补充而非竞争。

**与课题关联**：正面回答"撤销之后何时才能宣称委托权限真正闭环"——与 P03 的静止证明几乎同题（epoch、barrier、闭环谓词、fail-closed 判定），是标准侧与论文侧互证的难得对照。
