# 强成熟组合的逐步覆盖检验

## 1. 比较对象与同条件

定义G：线性化权威库＋当前准入监督器＋持久工作流/义务台账＋任务级断言/证书检查＋标准有限安全规划。它取得与候选相同的G1合同、K/原生证据、身份/审批/密钥信任、部署覆盖、预算、缓存、图结构、索引和持久化能力。

人工合同和已证frame对双方同价。G可预建动作依赖、复用证书证明、只在相关变更后失效，允许标准数据库/认证数据结构/增量维护；不要求它反复扫描完整K，也不禁止同条件预处理。实际源前提缺失同时约束双方。

## 2. 完整编译

候选Σ=(D_v,K,O,E,P,C,Budget,H)编译到G的记录：

| 候选对象 | G对应 | 保持关系 |
|---|---|---|
| AuthorityTransition | 串行事务中的grant状态/请求队列/消费 | 精确身份、inactive、线性化版本与旧请求 |
| LocalSafetyGuard | 当前策略参考监视器＋声明frame/全部相容状态检查 | 同样前置与微步骤后继不变量 |
| O_global | durable pending/work-item表＋来源/结清tombstone | 同一风险/容量/执行责任投影 |

| dependency reuse | 版本依赖缓存/动作闭包及变更索引 | 同充分依赖与projection包含规则 |

给每个事件一个G转移：CommitRevoke→事务更新/幂等记录；Claim/Release→预留/消费/持久pending；NativeOutcome→原来源登记/隔离；LateEvidence→可信事实更新和责任转换；CheckCert→当前依赖验证；Recover→从当前权威恢复pending。转换函数、原生调用顺序及允许故障后继与候选逐项相同。

## 3. 双向逐步关系与费用

令Φ只重命名上述记录。初态Φ(Σ)相同。候选每个被允许事件e在G上执行同一前提/记录变更，得到Φ(Σ')；G按该配置允许的同类转移也回到候选关系。因此，在已声明模型内两者的可见观察、局部证书性质、K和O及预算轨迹相同。没有调用候选独享oracle。

固定原语费用（事务/读取、原生请求、证据检查、证书字节/签名、依赖维护、恢复），G可用同实现/表示和同缓存，逐事件费用相等；求和给C_G(Φ(trace))=C_candidate(trace)。这个构造已提供同级保证和可达费用的成熟基线，足以排除本轮仅凭架构分工/证书命名主张严格优势。

Φ是组件解释的对应，实际序列化字段/字节可以保持相同，避免用忽略消息长度的重命名得到费用等式。

它不声称任意程序自动生成正确Γ/依赖或所有算法都等价；真实源映射仍是G1责任。最强G还可更快，候选没有取得其必须支付更高代价的证明。

本轮没有提出新的SafeLocal判定或依赖提取算法，G使用相同已给谓词、frame和标准检查原语。若以后提出隐式状态上的新算法，该算法与完整费用需单独检验；本轮等式不把尚未建立的新引理免费交给G，也不预判其增量。

## 4. 用户要求的逐项对应

| 环节 | G如何复现 | 费用与边界 |
|---|---|---|
| 用户撤回 | 当前事务设inactive，签发指定C_local收据 | 同身份/对象、数据库和版本条件，无W先决 |
| 已放行旧请求 | durable outbox/pending保留原origin/消费 | 同单发送/单效果源前提，不能靠幂等键推AS已终止 |
| 甲未知责任 | pending＋容量/来源＋补偿/对账工作项 | 同源完整性与持久空间成本 |
| 乙安全准入 | 同当前grant/source/预算/影响域/窗口和重核 | 相关共享资源照查；不承诺调用成功 |
| 原生关闭 | 同I/U/E/D/F、H_T和路径/后代证据 | 未满足时同样PENDING/UNKNOWN |
| 迟到证据 | 同原请求匹配、隔离、残余风险转换 | 新证据不能把旧甲重新批准 |
| 权威恢复 | 同当前状态/密钥，恢复pending与tombstone | 旧cache不赋权，权威丢失/回滚另证 |
| 证书有效性 | 同依赖缓存/过期/单次请求消费 | 证据缺失/陈旧拒绝，全部维护计费 |
| 完整费用 | 同前期取证/索引/缓存、原生、全状态读写、证书/恢复 | 不把检查/补偿/失败当免费 |

裁决：COVERED_BY_MATURE_COMPOSITION，限定本轮组合逻辑、三类证书及明确费用模型；工程实现价值保留。

## 6. 当前源码落地限制

逻辑证书不自动添加原生能力。现有make_receipt/save_reconciliation要求B在最后处置后有成功UserInfo等具体条件。若B已经在甲处置之前完成唯一操作，纸面证据可按独立frame另证A材料scope，但它不会直接把当前窗口置CLOSED/解禁新创建。要用现有CLOSED路径，额外B检查及其批准/请求费用要计入；要改变窗口条件，需另做接口/正确性审查。

逻辑依赖缩小也不自动减少现有存储成本：当前每次事务读取/加密完整状态。若双方改用标准索引/细粒度版本，也应对G开放相同改造和维护预算。

因此，“成熟组合覆盖逻辑”和“当前原型全部证书已上线”分别成立/待补。没有将工程缺项或更名包装为算法创新。
