# 三个最小实例与强基线逐步处理

版本：COST-SCREEN-1，2026-11-05。全部为纸面轨迹。未运行证明器、服务或候选机制。`AUTHOR_REPORTED`表示Vega论文表值，`DERIVED`表示本轮计算，`SYNTHETIC`表示合成数学对象/费用。原文定位见[sources/READING_LOG.md](sources/READING_LOG.md)。

每项对照均获得相同依赖信息、兼容类、合法预计算路径、缓存预算和未来信息。在线与离线结果分别说明。端到端费用分为已知小计与符号余项，避免把零缺项假设写成实测结果。

## C1：变化处于合法在线兼容域

**输入。** 一份1920-byte MSO，固定配置、凭据内容、issuer签名、查找位置及活动step public values。连续三次合法展示，仅改变论文划入在线段的nonce/设备签名或当前日期，均满足原凭据有效期及同一谓词。共享key及在线工作区已预留，缓存容纳一份prep。[SOURCE：V-PAPER §1.2、§8.1；MODEL]

**强基线轨迹。**

|步|请求|Landlord/离线最优动作|产生的合法状态|计费|
|---|---|---|---|---|
|0|固定配置|setup，保留共享keys|配置可用|S及其加载/分发|
|1|A，动态输入d1|缺页，执行一次`prep_prove`，随后`prove`|返回A的prep|P_A+O_1+V_1+通信/核验|
|2|A，d2|命中，使用返回prep并重随机化|兼容类仍为A|O_2+V_2+通信/核验|
|3|A，d3|命中，同上|兼容类仍为A|O_3+V_3+通信/核验|

空缓存且唯一请求对象要求至少一次准备，后续可直接复用。因此缺页费下界和可达到值均为P_A。在线算法在该实例取得离线最优。[DERIVED；V-CODE 1614–1620、2107]

若采用论文MC/16线程表值：S=51 ms、P=65 ms、O=92 ms、V=23 ms，已知串行小计为`51+65+3×(92+23)=461 ms`。这是作者数据的条件性组合，完整费用为`461 ms + key/credential I/O + 兼容检查 + 策略管理 + 通信 + 表外输出核验 + 失败费用`。表中O已包含当次原实现重随机化，重复加收会双计。[AUTHOR_REPORTED/DERIVED：V-PAPER Figure10]

**裁决。** 合法动态输入并未产生新的prep失效问题。以每次全量准备为对照所获得的节省，属于现有接口已实现的复用。

## C2：某个预计算依赖确实变化

**输入。** 使用教科书级合法关系`R(y;w): w²=y`，合成MC配置含两个同形step，无挑战及rest witness，w放在precommitted段，y为step public value。第一次step1取(w,y)=(1,1)，第二个step保持(3,9)；后续step1合法更新为(2,4)。这只定义数学输入与Vega trait划分，不编写电路或运行程序。[SYNTHETIC；SOURCE：V-TRAIT 19–52、V-CODE 1526–1541]

依赖变化同时涉及step1的precommitted witness及public value。原prep缓存含旧y；其活动matvec校验会拒绝y=4的调用。新输入仍有合法见证；现有高层恢复路径为对新step数组执行`prep_prove`，兼容setup/keys可保留。该例具有真实接口依赖，费用采用符号，独立于1920-byte凭据性能表。[SOURCE/DERIVED：V-CODE 1649–1670、1482–1607]

请求为A、A、A′。双方都获知版本变化，专用缓存容纳一份state。

|步|强基线动作|加载/重建费|每次费用|
|---|---|---|---|
|1|加载A的整份prep|c_A|b_1|
|2|命中并使用返回state|0|b_2|
|3|版本通知将请求标为A′；逐出A，重建A′|c_A′|b_3|

在同一高层原子对象profile且无现成后备副本时，冷请求A和A′各要求一次prepare，强基线加载费为`c_A+c_A′`。完整成本为`I+D+c_A+c_A′+b_1+b_2+b_3+A_π`。如果有已付费后备副本，则按对应固定加载费改写，所有方法均享有该机会。[DERIVED]

若故意先把A的prep与A′输入交给`prove`，增加失败前工作`F_stale`及重新取得state费用；因校验发生在重随机化之后，`F_stale`可以大于零。强基线可使用共同的可信版本信息预先避免这条可预测失败路径，比较依赖分析的费用仍计D。[SOURCE/DERIVED：V-CODE 1620–1670]

**裁决。** 同一兼容配置下确有合法输入改变预计算依赖。当前高层API的已有全量恢复给出正确上界，局部重建的计算下界与公开操作粒度尚无新增结果。这个实例未展示最强通用方法被迫支付可避免的额外费用。

## C3：共享初始化与驻留预算发生冲突

**对象与费用。** 下表全部为合成费用单位CU，内存单位MU；用于检验共享对象计费。它将Q1-F的共享key固定驻留条件扩展为可管理对象，并非Vega具体内存测量。[SYNTHETIC]

|对象|大小MU|加载/生成费CU|所需依赖|
|---|---:|---:|---|
|共享K|2|5|固定外部输入|
|A的prep|2|4|K|
|B的prep|2|4|K|
|服务A或B|额外工作区已预留|每次1|对应prep与K同时驻留|

可管理总容量为4 MU。请求顺序A、B、A，合法服务顺序固定。逐出免费，无预先ready副本；生成输出时依赖与输出均计内存。

**共享DAG/精确状态对照。**

|事件|动作后驻留|费用CU|理由|
|---|---|---:|---|
|载入K|{K}|5|所有服务共同依赖|
|构建A，服务A|{K,A}|4+1|容量恰为4|
|逐出A，构建B，服务B|{K,B}|4+1|K与A、B三者共6，超预算|
|逐出B，构建A，服务A|{K,A}|4+1|再次服务A需要恢复A|

合计`5+3×4+3×1=20 CU`，已包含这个合成模型定义的全部生成、服务费用。另计实际求解/管理开销`A_π`、依赖描述建立D及固定工作区费用。论文MILP求解和在线启发式的计算开销需分别报告，无法填为0。[DERIVED]

**手工最优性。** 至少加载K一次，费用>=5；首次A、首次B各需要4。服务B时必须驻留K和B，容量已满，A无法同时保留；随后服务A至少再付4。三次服务固定费3。故任何同模型方法的原语成本>=20，表中轨迹达到该值。逐出K只会增加费用；后台预取在纯加法目标下也不能减去强制生成次数。[DERIVED]

把K分别重复计入A/B并在三次调用中重复加载会得到`3×(5+4+1)=30 CU`，该对照遗漏共享驻留机会。现有依赖图/状态基线已取得20，节省10 CU尚不足以支持新机制。[DERIVED]

## 汇总

|实例|强基线|结果|能够排除的弱比较|
|---|---|---|---|
|C1合法动态域|原有prep复用；Landlord|只准备一次|逐次完整重算|
|C2真正版本/依赖变化|版本化文件缓存，高层合法重建|每个首次有效版本准备一次；费用符号|忽略版本，先失败再重试|
|C3共享冲突|依赖图精确状态优化/重物化方法|原语成本最优20 CU|重复收费共享K，忽略依赖|

三项均未提供相同信息和合法功能下的严格新方法差距。C1使用论文数据的条件性小计；C2、C3仅为合成数学轨迹。它们支持限定模型裁决，性能采样和部署效果保持各自待测状态。
