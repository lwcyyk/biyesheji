# 精确问题及成熟模型归约

版本：COST-SCREEN-1，2026-11-05。`SOURCE`表示原文，`MODEL`表示本轮条件，`DERIVED`表示纸面推导。所有引用定位见[sources/READING_LOG.md](sources/READING_LOG.md)。候选机制实现保持未开始。

## 1. Q1-F：整份prepared state驻留

### 1.1 输入、状态与可行域

给定有限对象集`F`，对象`f`的标签为“凭据版本、证明配置、shared/precommitted静态输入及活动缓存所依赖的step public values”的兼容标识。标识由可信输入及实际依赖信息形成；它在模型中是输入，建立和比较成本记为`D`。标签可采用保守版本划分，精确的字节级等价判定尚无免费接口。[MODEL；接口依据DEPENDENCY_AND_INVALIDATION.md]

每对象有固定正整数大小`s_f`、固定非负重建/加载费`c_f`。执行的物理内存预算为`M`，固定驻留共享对象占`K`，预留在线及构建工作区`W`，缓存管理元数据占`H`，故专用缓存预算`B=M-K-W-H`。要求`B>0`、`s_f<=B`。`W`需覆盖源码中的临时缓存复制及合法构建峰值；数值保留符号。[MODEL]

请求序列`σ=((f_t,d_t))_{t=1}^m`，其中`d_t`只在对应兼容类允许的在线域内变化。服务`t`要求`f_t`已驻留；随后执行原有`prove`、验证、公开IO比对及通信。成功返回的state替换原state，兼容标签和尺寸保持。一次调用占用一个state，当前模型采用串行服务。[MODEL；SOURCE：V-CODE 1614–1620、1770–1784、2107]

冷缺页有两种独立profile：

|profile|对象在缓存外的来源|`c_f`及一次性费用|
|---|---|---|
|F-rebuild|原始合法凭据及共享keys可获得，ready prep副本未额外储存|读取凭据、执行`prep_prove`及核验的固定费；构建工作区由W预留|
|F-backed|全部ready副本已合法生成，存在可信兼容的固定后备存储|读取、反序列化和核验的固定费；原始预计算与后备存储建立费计入公共初始化I|

两种来源同时可免费取得且每次费用固定时，可令`c_f`等于两条合法路径费用的较小值。若后备副本需首次使用后付费创建、写回或按使用次数改变，则需扩大状态模型；这些费用无法通过预先取最小值消除。[MODEL/DERIVED]

初始缓存双方相同，以下定理采用空缓存。逐出费用在Q1-F中为0。缓存内每个prep均有效；并发、异常与恶意输入排除在这个成功合法请求profile外。全模型若纳入这些事件，须另附原有接口可行转移、检测与恢复费用。[MODEL]

### 1.2 决策、信息与目标

输出为每次请求前后的加载、保留、逐出及合法展示决策。在线算法只知道前缀、当前请求、依赖标签、`s_f,c_f`及预算；离线算法取得完整请求序列，双方获得相同的依赖图和预计算能力。[MODEL]

Q1-F的优化目标固定为加载/重建费用L。选择算法后，同时报告以固定单位表示的完整可加资源账本：

\[
C(\pi,\sigma)=I+D+\sum_t b_t+\underbrace{\sum_{\text{loads of }f}c_f}_{L(\pi,\sigma)}+A_\pi+F_\pi.
\]

`b_t`包括成功在线证明、验证/预期语句核验和约定通信；`A_π`为策略计算与缓存管理，`F_π`为失败、重试、清理及对应重建。上述Q1-F成功profile中`F_π=0`，其余成本保持记账。若度量为墙钟时延，加法要求所计阶段串行且无重叠；吞吐量、能耗和峰值内存需要独立目标。[MODEL]

缓存优化的变动项为`L`。初始化及同功能服务项保持相同后，最小化L的缓存决策由已有文件缓存决定；管理运行时间的差异仍保留`A_π`，既有检索竞争比只约束`L`。若进一步以含算法自身运行时间的C为唯一目标，需要实例化并计量管理开销；本轮未把该扩展宣称为端到端竞争性定理。[DERIVED]

## 2. 与Young文件缓存的双向归约

### 2.1 原文模型与算法

Young，*On-Line File Caching*，Algorithmica，2002，§1：缓存容量为正整数`k`；每文件有正整数size和非负固定retrieval cost。缺页时加载请求文件、支付其费用并逐出其他文件，使总size<=k。在线决策不依赖未来请求。Figure1给出Landlord，Theorem1证明容量k的Landlord相对于容量h<=k的离线最优达到`k/(k-h+1)`竞争比。[SOURCE：YOUNG PDF pp1–4、§2证明]

Landlord为驻留对象维护credit。缺页且空间不足时，按size比例降低credit，直到至少一个对象credit为0；逐出足够的零credit对象后加载新对象，令credit=其cost。命中时可把credit提高到原cost以内。该算法允许异质大小及异质加载费，已强于只采用LRU或完整重算的对照。[SOURCE：YOUNG p3 Figure1]

### 2.2 对应表

|Q1-F|Young|
|---|---|
|兼容类f及其整份prep|文件f|
|prep逻辑大小s_f|文件size|
|固定加载/重建费用c_f|retrieval cost|
|专用预算B|k|
|请求中的f_t|文件请求序列|
|返回同兼容类prep|命中后仍保留相同文件|
|逐出后从合法来源恢复|缺页加载|
|在线仅知前缀/离线知全序列|同一信息条件|
|Σ加载费用L|total retrieval cost|

**命题QF（成本保持归约）。** 对任意满足§1前提的Q1-F实例，忽略与策略无关的服务项，存在相同容量的文件缓存实例，使双方每条可行缓存轨迹一一对应且加载费完全相同。[DERIVED，领域实例化]

**证明。** 给每个兼容标签建立一个文件，size与cost分别赋为`s_f,c_f`，请求顺序保持。任意Q1-F轨迹的驻留集合满足同一容量式，每次缺失都执行同一固定成本恢复；返回状态在同一兼容类内。故该轨迹给出同价文件轨迹。反向按文件保留/逐出动作调用原有整份加载及成功`prove`接口，W已预留使动作内存可行，每次成功仍有合法返回对象。两方向均保留服务可行性及加载费用。证毕。

在无并行收益、无失效期限、固定费用和纯可加总成本条件下，提前加载可以延迟至首次实际服务，期间只会减少占用；因此允许双方预取也不会降低这个profile的最优总加载费用。若存在后台并行、deadline或费用随时间变化，此交换论证前提需重审。[DERIVED]

**继承结论。** 选择共同整数内存单位，令B=k，比较容量h的可行离线最优，并要求对象能在比较容量下服务，则

\[
L_{\mathrm{Landlord},k}(\sigma)\le {k\over k-h+1}L_{\mathrm{OPT},h}(\sigma).
\]

相同容量时h=k，因子为k。Young同时说明其确定性最坏情形保证的紧性；该结论的容量单位和范围须保留，实际系统中巨大字节数的k给出的最坏界可能很宽。本文没有将检索界转写为管理CPU或端到端时延的同一竞争比。[SOURCE/DERIVED：YOUNG Theorem1]

版本变化可作为新文件身份。Young p3脚注1已明确说明这一处理需有变化通知，并将时间变化费用与一致性获取排除在原模型外。本轮输入中含可信版本信息；获取通知的代价计入D。由此得到的覆盖充分性限于列明profile。[SOURCE/DERIVED]

## 3. 离线强基线与复杂度记账

对于已知序列，一个透明的通用精确对照为驻留集合状态最短路：节点`(t,S)`表示已完成t次服务且当前合法集合为S。加载边增加f并支付c_f，逐出边免费，服务边要求`f_{t+1}∈S`并支付公共服务费。所有中间集合满足容量式，状态数至多`(m+1)2^|F|`，边数按对象操作计为指数规模乘多项式。[DERIVED：标准有限状态最短路表示，纸面使用]

该表示完整保留提前加载、版本和不同合法初始集合的选择。将常见精确优化模型落实为可审查对照，有助于在小实例上确定最优；指数规划成本必须计入`A_π`。本文未提出其为高效新算法，也未实现该求解器。大规模应用可直接评估成熟文件缓存算法。[DERIVED]
