## 2. 三种工件分列

1. clean source build：固定commit和配方，记录工作树/生成物/工具链/flags/依赖及二进制摘要。
2. barrier build：从该清洁基线仅加受控调度/观测hook，保留完整diff、hook授权、线程/事务位置和二进制摘要；hook只暂停/放行，禁止更改原业务分支或数据库原子性。
3. 现存release binary：单列`vcs.modified=true`和本地ZIP对应；若dirty差异及精确构建尚未还原，barrier结果只归于对应源码构建。普通发行物的自然并发结果需另获执行范围，当前计划不自动扩展。

hook/DB真值只供私有scorer控制和评分。候选/G运行方法只取得其合同允许的HTTP结果/证据权限，避免把测量特权转成算法观察。双方使用相同入口、权限、故障/时序包络、计费及配置。

## 3. 四条预登记轨迹

|轨迹|控制顺序|预期可检验结果|失败/替代解释|
|---|---|---|---|
|T1 串行负控制|先revoke父并取得ACK/提交证据，再允许refresh首次读取|fresh父读取拒绝；无该次refresh子行|若有子行，排查撤销范围、存储GrantType、缓存/其他创建者及构建差异|
|T2 NC1|refresh完成父读取/校验/生成，停在子Insert之前；另一请求revoke父并ACK；再放Insert/父Delete/返回|子Insert提交在revoke ACK之后；可取得一个子行/响应；fresh子AT是否接受另测|锁/事务阻止ACK或Insert时保留阻塞/错误；ACK发生前Insert不算命中|
|T3 NC2|两handler都完成同父校验/生成，分别停在各自子Insert前；先完成第一个，再完成第二个|两个不同子ID可提交；第二次父Delete可能0行，原返回是否报冲突如实记录|子ID冲突、事务回滚或入口串行化如实保留；命中要求两个提交成功|
|T4 串行轮换控制|第一个refresh完整返回后，再用旧RT发第二次|第一子行存在，第二请求拒绝，未新增第二子|若第二次接受，核rotation/缓存/实际入口/父状态|

每条使用独立合成父材料，禁止上一条的RT/DB结果污染下一条。T2/T3 barrier位置须在ORM写事务开始前；停在持有写锁的位置会人为阻止并发撤销。T3保持原随机/ID生成语义，记录两次ID，避免用强制唯一ID修改被审程序。

T2的必要因果链是`validated → scorer收到ready → revoke请求 → 收到ACK → release barrier → Insert提交`。采用事件ID、单调时钟与hook握手，跨主机墙钟只作辅助。T3保存两个validation、两次Insert提交及父Delete影响行数。记录写入观测hook本身的额外IO/延迟，禁止其扩大事务边界。

## 4. 证据与实际接受测量

- 原始请求/响应、入口、来源r/a/o、父/子材料指纹、开始/ACK/提交/返回顺序、HTTP码及错误均封存；日志公开投影移除Token、密码和cookie。
- 数据库事实通过scorer的只读一致快照/备份取得；SQLite WAL存在时使用合适备份/事务快照并记录watermark。直接复制main文件或分别读取不同时刻行只能作局部线索。离线IO单独计量，不充任免费方法查询。
- 子创建需HTTP发行结果与数据库提交/ID证据分列；handler生成但未提交为另一结果。实际接受以新请求fresh UserInfo验证，父/子分别测；AT/RT使用只读内省并标明其范围。RT内省结果与能否refresh分开。
- RT refresh会产生新材料，主测量禁止以它探测RT有效性。若未来确需此探针，单列业务attempt/预算/副作用/清理并重新审查本计划。
- revoke ACK只证明所调用接口报告成功。登记原生范围、父/子/同cohort变化和fresh接受证据；对任意RP、已缓存handler及未来异步效果均限于实际测得范围。
- 候选/G的对账状态与scorer真值分离。方法输出UNKNOWN、错误/超时或反例也保存；无法定位ACK/Insert顺序时该轨迹为INCONCLUSIVE。

## 5. 尝试次数、环境与停止规则

首批仅四条轨迹，各执行一次。拟议上界：setup≤30、方法≤16（每条≤4）、测量≤28（每条≤7）、cleanup≤40（每条≤10），合计≤114次native尝试。setup含合成组织/用户/app、初始材料及必要配置检查；方法含预登记refresh/revoke；测量含最多三材料的fresh AT/RT检查及最多一次完整合成范围核对；cleanup含已知行/合成资源处置与验证。每个HTTP尝试含失败、超时都计费，DB读另列IO。

114是拟议封顶，授权前需给出逐端点调用清单和依赖闭包，确认能够在这些阶段上界内完成；无法满足则先修订计划。没有自动补跑、扩大调用、随机压力试验或切换历史实例分支。达到任一上界、出现非合成数据/错误issuer、身份范围越界、hook破坏事务边界时停止；保留UNKNOWN和未完成清理，报告下一步所需范围。

cleanup预算预先保留且与方法/测量分账；全部派生材料按已知ID及完整授权范围核对。清理失败保留隔离环境和责任清单，避免删除原始证据或宣称CLOSED。合成账户环境隔离与退出前材料清点均需未来验收。
