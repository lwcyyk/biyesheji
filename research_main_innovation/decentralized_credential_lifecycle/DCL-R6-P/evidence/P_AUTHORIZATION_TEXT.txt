此次接受的合同变化包括：

1. 内存指标由 Windows 进程 Working Set 总和，调整为 Linux payload 的普通用户映射驻留页总和，特殊映射仍需单独审查。

## 四、需要取得的真实平台证据

### P01：实际 Linux 运行环境

取得：

- 实际 kernel release。
- CPU 架构。
- PID 1 可执行文件。
- systemd 版本。

重点判断：

1. 发行版是否实际运行 WSL2 内核。
2. PID 1 是否为 systemd。
3. 当前 systemd 版本是否支持拟议的服务资源合同。
4. 与先前通过公开文档建立的静态假设有何差异。

注意，`systemctl --version` 返回版本信息，仅说明相关程序存在；PID 1 的实际身份需要独立判断。

### P02：cgroup v2 能力

取得：

- cgroup 文件系统类型。
- 实际挂载信息。
- 当前进程所属 cgroup。
- 可用 controller。
- 当前 subtree_control。

重点判断：

- 是否使用统一 cgroup v2。
- memory controller 是否存在。
- pids controller 是否存在。
- 当前层级对未来父 slice 有何限制。
- 哪些条件需要进一步查询或配置才能确认。

当前仅观察，不创建 cgroup。

### P03：身份与权限

取得当前身份及用户组信息。

评估未来执行：

- systemd 系统 service。
- 专用非特权用户。
- 父 slice。
- TasksMax。
- LimitAS。
- 受限日志目录。

所需的管理权限。

只读身份信息不能直接证明创建服务、修改单位属性或隔离权限已经具备。

如需要 sudo、root、Polkit 或新建用户，明确记录具体操作，留待下一次授权。

### P04：原生 Python 环境

检查：

- `/usr/bin/python3.14`
- `/usr/local/bin/python3.14`

若存在，记录实际路径及文件元数据。

如果缺失：

`NATIVE_PYTHON314_UNAVAILABLE`

不得自动：

- 安装 Python。
- 下载运行时。
- 编译 Python。
- 回退到其他版本。
- 使用 Windows Python。
- 采用额外虚拟环境。

原生 Python 的版本执行、SHA-256、标准库和动态链接依赖核验，留给下一阶段经过批准的具体检查。

### P05：资源执行资格

根据 P01–P04 的实际结果，初步审查以下条件：

- systemd 能否作为未来的服务管理入口。
- cgroup v2 是否具有需要的控制器。
- RLIMIT_AS 是否具备对应的平台接口。
- pids.max 是否可用于拟议父 slice。
- 当前身份是否满足后续资源部署需求。
- 原生 Python 是否具备初步可用条件。
- 是否需要专用身份、权限或文件系统配置。

这些判断属于平台资格分析。

本轮不得直接设置 RLIMIT_AS、TasksMax、MemoryMax 或其他资源限制。
