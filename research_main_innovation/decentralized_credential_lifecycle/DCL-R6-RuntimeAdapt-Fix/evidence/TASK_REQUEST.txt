## 三、第一阶段：明确运行时版本变更的真实含义

首先核实：

`8.9 → 8.12`

究竟对应：

- GNU libc 上游版本。
- Ubuntu 软件包版本中的发行版修订。
- 项目自定义的运行时版本标记。
- 其他实际环境字段。

使用原始日志和软件包元数据确定。

不得仅凭报告中的版本字符串认定系统已经升级到某个 GNU libc 上游版本。

### 3.1 当前运行时只读取证

允许在 Ubuntu-24.04 中执行必要的只读命令。

可根据实际环境使用：

```bash
getconf GNU_LIBC_VERSION
ldd --version
dpkg-query -W libc6 libc-bin
dpkg -V libc6 libc-bin
```

对于真实 ELF 文件：

```bash
readlink -f <实际文件路径>
stat <实际文件路径>
sha256sum <实际文件路径>
readelf -n <实际文件路径>
readelf -V <实际文件路径>
```

上述路径必须由当前文件系统、冻结锁和实际软件包信息确定。

禁止使用猜测路径更新执行锁。

优先使用 `readelf` 分析 ELF 依赖。避免通过不可信 ELF 的 `ldd` 检查引入执行风险。

同时核查已有的：

- dpkg 历史日志。
- apt 历史日志。
- 软件包归属。
- 已安装的软件包版本。
- 已有的软件包签名与来源证据。
- 当前系统架构。
- 当前发行版身份。

不得为补充来源信息而自动联网下载或安装软件包。

### 3.2 变更来源裁决

分别判断：

**RTA-1：正常软件包变更**

文件来源、软件包身份及已知更新记录相互吻合。

**RTA-2：可解释的本地环境变化**

文件变化真实存在，但来源证明仍需限定条件。

**RTA-3：来源不明**

无法证明新文件的可信来源。

**RTA-4：异常替换**

观察到与可信软件包或冻结环境合同不一致的变化。

必须保留原始证据。

如果来源无法建立可信关系，停止重冻结，输出：

`RUNTIME_PROVENANCE_UNRESOLVED`

禁止通过直接接受新摘要绕过阻断。

### 4.1 兼容性审查

重点检查：

- 三个文件是否属于兼容的运行时组合。
- 动态加载器和 libc 是否具有一致的软件包来源。
- Python 3.12.3 的 ELF 依赖是否满足。
- 所有冻结本地二进制的必要符号版本是否可用。
- 现有 CPython 执行环境是否发生变化。
- 关键动态库搜索路径是否发生变化。
- 是否引入未审查的库覆盖或预加载。
- 原资源限制接口是否仍可使用。
- 原 native seal 和 finalizer 的依赖是否变化。

只读 ELF 检查能够提供静态 ABI 证据。

后续原生动态兼容性仍需单独验证。

禁止将 `readelf` 成功直接解释为全部运行行为兼容。

## 六、第四阶段：审查运行时更新对安全性质的影响

建立影响矩阵。

至少覆盖：

**RT-1：RuntimeIdentity**

实际加载的运行时组件必须与获批准的摘要锁一致。

**RT-2：LoaderConsistency**

动态加载器与实际加载的 libc、libm 来源一致且可验证。

**RT-3：PythonCompatibility**

当前 CPython 及其必要原生依赖满足已审查的 ABI 条件。

**RT-4：ResourceEnforcement**

原 RLIMIT_AS、TasksMax 和 cgroup 约束的实现依赖得到核查。

**RT-5：NoSilentRelock**

运行时文件变化不能自动刷新可信摘要。

**RT-6：NoCrossBatchReuse**

新运行时执行资格不能继承历史批次的动态收据。

**RT-7：PreflightFailClosed**

当前运行时与新冻结锁发生差异时仍立即拒绝启动。

**RT-8：ExecutionTimeRecheck**

后续 Launcher 或 Guard 必须按照冻结合同重新核验实际运行时身份。

**RT-9：TerminalCompatibility**

TerminalRead、native seal 和自动行政 finalizer 的相关运行时依赖保持明确。

**RT-10：EvidenceProvenance**

新基线具有真实文件摘要、软件包归属及原始审查记录。

逐项给出：

- 现有证据。
- 新运行时可能产生的影响。
- 需要的静态检查。
- 需要的动态验证。
- 当前结论。

## 九、第七阶段：兼容性与回归测试准备

新增范围明确的测试。

### A. 正常运行时

- libc、libm 的来源一致。
- Python 依赖条件满足。

### B. 异常运行时

- 旧加载器与新 libc 混用。

- 软件包版本与文件摘要不对应。
- ELF Build-ID 异常。
- 加载路径改变。
- 来源证据缺失。
- 文件读取失败。
- 执行时再次变化。

### C. 安全边界

- 自动更新摘要锁。
- 缺少摘要仍允许执行。
- 运行时身份只比较版本字符串。
- 预检通过后更换运行时文件。
- 跨批次复用运行资格。
- CLOSED 后重新申请工作。

根据实际代码建立最小变异测试。

所有变异使用隔离副本。

不得修改系统真实 libc、libm 或动态加载器制造故障。

本轮仅运行无业务启动副作用的静态和只读检查。
