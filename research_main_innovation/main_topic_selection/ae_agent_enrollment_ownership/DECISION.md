# 裁决：新路线的选择、资格与下一步

ENO-1；2026-11-07。当前对话内知情模型辅助公开文档与纸面研究。

## 1. 选定新问题线

**AI自主开户中的用户控制权保持与跨服务安全接管。**

技术中心：注册、身份供应与初始信任协议。用户让代理代为开通服务，要求独立接管，不依赖代理进程或原运行商，并可按明确合同终结旧代理访问。

上一轮的合约验证、偏好预测、授权图压缩本轮暂放；T3、统一计数和低环数没有被调用为机制。本轮没有引出新指数猜想或继续原数学审查。

## 3. 本轮实质新增

1. 直接找到并读取自主开户、inbox领取、第三方应用开户的官方文档。
2. 固定用户独立接管、代理权限退出、创建期间控制与证据范围等属性。
3. 完成两服务纸面轨迹及具体错误推理的排除，并明确强基线的原生修复方式。
4. 将SCIM、企业provisioning、OAuth动态注册与BRSKI纳入覆盖责任，避免只和手工裸注册比较。
5. 对普通honeytoken候选完成近邻初筛，发现两篇直接相关预印本，未将其保留为主创新。

检索的无命中和TLS失败均不承担不存在先例的证明。

## 4. 何时足以成为两年主课题

至少取得以下两类证据：

- 一项新协议或可核验接口条件：在明确服务域内保持用户控制，允许不可信代理执行开户任务，完整处理创建/交接故障，且具有超出现有标准组合的命题。
- 一组真实、独立核查的工作流证据：问题频率或后果值得研究，强基线的代价/能力缺口有明确来源。

工作量由协议、证明、恢复、费用、真实互操作与公平验证构成。单纯实现更多signup插件、创建邮箱、导出账户清单或增加signed owner字段，贡献仍不足。

## 5. 严格实现门

当前缺少：真实的具体输入族X_k、冻结的比较度量、完整最强G、G的必要代价依据、候选上界及严格差距实例。NEW_RESEARCH_LINE.md第9节逐项列出。

本轮仅执行公开内容获取、文字提取、摘要/章节核读、文件取证与纸面推导；没有账户开通和机制代码。

## 6. 唯一下一步

**对AgentPass/AgentID/Notte与标准provisioning做一次E1–E5的完整覆盖核验。**

输入对象与主要度量先固定在一个有真实需求的服务子域。复用本轮已读内容，优先补齐AgentPass的Authority/自动signup及Notte Persona/持权管理原文；来源受阻时保留限制，继续完成已读标准的组合映射。

- 若已有组合满足完整合同及同级成本：收缩基础机制的原创性，停止把“自主开户＋领取”当主创新。
- 若保留具体接口/协议责任，且用户确有需求：据该责任构造同条件输入族，完成可证伪分离声明后再评价新协议与实现。
- 若所需保证依赖服务无法提供的事实，而候选也无额外证据：记录能力边界，及时关闭对应主张。

这一步可直接改变新路线的贡献裁决。后续不以增加名称、产品数量或重新包装已证数学来代替。
