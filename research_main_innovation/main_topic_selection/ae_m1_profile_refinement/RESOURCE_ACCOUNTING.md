# 空备用根、完整费用与三种G

MR-1，2026-11-07。本稿是账本核对，不是M₁迁移实验或性能比较。新增原生调用/重放/实验0；历史账本以immutable只读方式查看，未打开在线AS数据库。

## 1. 三种G分开

|量|定义|本case能否代入|
|---|---|---|
|G_B(C)|与固定config所选路径授权相交的效果域数量|现有B的配置资源函数；不额外计未选路径/未准备根|
|G_M₁|全部预建独立根数量，包括空备用根|需要完整根库存/资格/准备账本；当前未实现这个库存合同|
|G_trace|初始/最终采样映射的AS记录单位并集|M2-03为3，含动态刷新单位；不是某时刻库存或静态预建根数|

M2-03初始映射A0/B0两个单位；最终映射A1/B0两个单位；合并为3。六个AT/RT字符串引用没有变成六根，本地两个批准也没有变成整个轨迹的两条固定原生世系根。B_use结果引用已有B0材料，不增加原生单位。

材料/native-unit映射由原始摘要与评分观察支持，不将评分者的完整单位信息免费交给运行算法。未知A1意味着运行者目录尚未完整，不能简单把G_trace=3当作T+输入w。

## 2. 同一个M₁小例的并列账本

模型例：任务a/b初始都在j，k为空但已预建；停止a、保留b。选δ_j=1、δ_k=0，Hamming错配只有b。M₁允许move(b,j,k)一次，再撤销j，G_M₁=2。

当前B若固定C只有a→j、b→j，则G_B(C)=1，setup只取得j使用的授权。k不在resources/setup/stop菜单中。这个G=1初态没有免费目的根或迁移能力。

|账目|M₁抽象/完整费用责任|当前B固定C|P203历史观察的对应范围|
|---|---|---|---|
|预建/发行j|计一个独立根及Q_prep(j)、批准/持久材料|已选路径使用j才issue并计费|A0或B0各有一次方法issue，不是共享j实验|
|预建/发行空k|G再加1，并计Q_prep(k)、批准、材料保管|未选k不会由setup准备，也不能假定它存在|没有空备用根或其准备费用样本|
|保留空根|资源占用及必要持久/期限维护，H_k|原G未定义这个额外项|NOT_MEASURED；不得填0|
|迁移b及其授权|抽象重绑数1；原生Q_move、真实批准A_move、状态操作另记|没有这个动作|NOT_RUN/NOT_MEASURED|
|撤销j|root处置费用Q_stop(j)，实际批准和步数|可按已核实效果revoke；保留b仍共j时不合法|known A0 dispose用了3个方法HTTP，不能当作完整世系关闭费|
|失败/重试|所有已发请求计费，未知不返预算；另有恢复/义务费|按登记操作费用和H检查|丢响应A1仍计一次原生refresh；没有自动重发|
|清理/恢复|Q_cleanup、Q_recovery、可信持久状态、时间|源模型外生命周期须另给合同|本case清理和恢复有记录，未获得move完成收据|
|总原生请求|Q_prep(j)+Q_prep(k)+Q_move+Q_stop+Q_failure/recovery+Q_cleanup|由实际已执行接口算，不等于抽象重绑次数|下节只给原case的历史分项|
|决策步|1次move和所选根处置；物理微步/时长另记|每个B登记停止动作消耗一个H|P203没有M₁步计数，不能把RPC数或SQL数改名为重绑次数|

若用fresh password发行，一个已登记issue调用有一次AS HTTP，但这只是一项子操作，不代表完整空根准备、批准和托管已实现。完整缺失项目使用符号或NOT_MEASURED。

这张表说明成本函数/能力不相同，不能用G_M₁=2与G_B=1宣称优势。B也可在setup为保留任务选择k路径，或使用其原有多路径配置；那会改变初态、批准和支持结构，须真实计费。对于单个已知请求，静态直接分开a/b本来可能完成，示例不承担算法分离。

## 3. 精确选定的历史账本范围

原批次RESULTS在停止时记录HTTP序号前缀≤88；之后原预算账本又被另行授权的M2-04续行使用。本轮仅以序号63对应账户作为内部过滤条件，并限制seq≤88，输出账户别名U0。未复制账户值或凭据。

历史P203可直接归属U0的请求为：

|类别|次数|定位/说明|
|---|---:|---|
|环境/建户|3|序号60–62，用户预查/建立/核对|
|方法|7|63/64发行；67刷新；68保留任务UserInfo；69撤销；70/71该known处置的验证|
|独立测量|9|65/66初始接受；72–78最终UserInfo/RT拒绝/内省|
|清理|9|79–87，三次材料处置、账户收尾及三次最终接受检查|
|直接归属合计|28|原始账本只读重数；包含401/400等失败/拒绝的已发请求|

共同环境登录/配置/发现等没有强行摊为本case的0成本。完整前缀88覆盖其他两个账户和共有开销，其类别为环境14、方法23、测量26、清理25；它不等于P203成本。四case最终114的汇总也不被用于本case迁移比较。

逐序号仅保存类别/操作/状态/长度的索引于sources/COST_INDEX.json，原文数据库未复制。所有请求发送前占槽，失败/查询同样计费。前置本地拒绝不产生原生HTTP，但仍有RPC/权威事务成本；丢响应的已发A1不能退款。

## 4. 批准、持久状态和恢复成本

初始有两个本地批准P_A/P_B，各自限额8。最终P_A spent=2、P_B spent=2、reserved均0，合计4次已放行perform：两次issue、一次A刷新、一次B UserInfo。其余3个方法HTTP属于known材料处置，另由全局原生预算计费，不能漏掉或与grant.spent重复当作相同指标。

批准成员资格由可信实验身份夹具给出；两个批准记录不是两次已测真实用户同意UI。生产批准身份/新批准成本为NOT_MEASURED，不能把控制器有grant接口等同于有权自行批准所有迁移。

原COST_AND_RESULTS的M2-03条目还记载：权威SQL语句104、提交17、完整逻辑快照累计394129字节。物理WAL写入量和fsync次数未测。这些是该历史原型状态维护代价，当前没有测得M₁协议或算法开销。

初始/最终/清理三份原生观察各登记1次限定AS只读SQL，合计3次历史测量访问，另计于HTTP。提供方内部数据库工作、网络头/TCP费用及空根持有期限费用没有据此变成0。本轮只读检索的是归档预算SQLite，未访问在线AS数据库。

R持有SingleActive锁、可信SQLite权威、加密状态及角色能力。M2-03的operational inbox关闭；PRIVATE评分响应不能代替运行收件箱。增加终态查询、持久收件箱、任务绑定事务或排他锁都需要明确能力/信任/存储和故障合同，向候选与最强G同等开放。

恢复时A1保持UNKNOWN而不自动重发，保留原请求/预算/来源义务。清理方之后使用额外真值收尾，不能把这部分能力回填给运行者并宣称恢复已解决。

## 5. 与M₁距离等式和实现门的关系

Hamming错配数只有在完整迁移资格、静态独立根、原子旧支持退役、充分预算及保留条件成立时，才等于最少抽象重绑数。当前完整move尚未精化，不能把它直接换算成最少原生HTTP、批准或SQL次数。

本轮没有修改任何历史G/惩罚/预算函数或结果。备用根、额外接口、锁、材料托管与新鲜持久状态都没有被计作候选独享的免费能力。不存在本轮可交付的严格同能力成本差距实例；机制实现门保持关闭。
