# 纸面检查与强基线

2026-11-07。当前对话内模型辅助推导。所有例子均为明确受限合同下的纸面材料。

## 1. 多路径撤销的完整小例

所有边针对同一资源、账户和动作 \(a\)，各边作用域均允许 \(a\)。取唯一授权根 \(u\)，顶点集合

\[
V=\{u,A,B,C,D,E\}
\]

及边集合

\[
E_G=\{u\to A,u\to B,A\to C,B\to C,C\to D,A\to E\}.
\]

所有边最初均有效。撤销 \(u\to A\) 后，\(B,C,D\) 仍经 \(u\to B\to C\to D\) 授权，\(A,E\) 失去全部根路径。以 A 为根的普通子树删除会同时影响 C、D。

VERA Definition 4 与 Lemma 1，PDF 第 3 页，对 OR 授权给出

\[
T=\operatorname{reach}(G)\setminus\operatorname{reach}(G\setminus\{e\}).
\]

因此这个例子的撤销目标已由现有图语义覆盖。VERA 还明确区分已观察签名图上的目标正确性与传播新鲜度，后者需要另外的交付层。[VERA](https://arxiv.org/abs/2608.30091)

## 2. 隐藏路径的标准零知识组合

### 2.1 适用前提

有一份被授权登记规则认可的当前状态承诺 \(c_e\)。它绑定根集合、签名委托、作用域、期限与撤销状态。登记本身的有效性和状态来源需要检查，不能由不受信任申请方任意指定。

请求者已经取得有效路径及其状态认证见证。采用满足所需健全性与零知识性质的证明系统，所有路径字段长度和最大路径深度有明确编码界。

### 2.2 证明的关系

公开输入包括 \(c_e\)、资源/动作合同、请求 nonce，以及合同选择公开的请求者或绑定标识。私有见证包括路径、签名、作用域字段和当前状态的成员认证材料。验证关系检查

1. 路径从认可的授权根开始并终止于请求者。
2. 每条边签名正确，作用域与当前请求一致，并满足沿途收缩规则。
3. 路径所有边在 \(c_e\) 中有效，期限覆盖当前认可的执行版本。
4. nonce 和请求绑定正确。

在这些前提下，健全性使通过的请求具有一条有效路径，完备性使已持有合法见证的请求者能够证明。零知识隐藏关系中的私有见证，公共输入及网络、交易元数据仍按明确的泄漏函数处理。

资源端需要在实际授权生效点核对所接受的版本。链上验证可在单一状态转换中检查版本与凭证消耗。链外调用要另行说明检查与效果之间的并发边界。

这条构造是通用零知识与认证数据结构的标准组合。它提供条件化的功能可实现性。具体证明系统、设置假设、匿名性合成和性能仍需完整选型。

### 2.3 完整费用表达

设授权边数为 \(M\)，路径长度为 \(d\)，安全参数为 \(\lambda\)。若状态成员认证采用 Merkle 结构，明确展开路径的关系规模可写为

\[
S=O\!\left(d\left(C_{\rm sig}+\log(M+2)C_{\rm hash}+C_{\rm scope}\right)\right),
\]

其中各项均是指定算术电路中实际签名、哈希和作用域检查成本。应另计解析、整数范围检查与填充。此式只描述关系的显式构造规模。

总成本包括

\[
C_{\rm register}+C_{\rm maintain}+C_{\rm discover}
+P_{\rm ZK}(S,\lambda)+V_{\rm ZK}(S,\lambda)
+C_{\rm transport}+C_{\rm enforce}.
\]

递归证明可能缩短证明或验证成本。源定理的适用条件、证明更新与生成费用均需代入。只给出短证明长度，会留下证据发现和维护两项费用。

### 2.4 候选剩余责任

当 D 只保存经过 A 的旧见证时，图上另一条路径的存在还需要转化为 D 实际可获得的当前见证。强基线可以提前发放两条路径、缓存替代凭证、按需联系 C 或 B、查询授权服务，或使用安全多方计算完成发现。

本例只有两条候选路径，预存两条见证已经形成简单可行基线。它不能承担严格代价分离。主要研究对象是一般图上的隐私、故障可用性与完整维护成本。

## 3. 一个明确的观察信息限制

设请求者在截止时间前可获得的全部视图为 \(\mathsf{View}\)，包括其凭证、公共检查点、缓存、消息和可调用接口结果。考虑两个合约允许的世界，当前请求在世界 0 无有效路径，在世界 1 有有效路径。

若两世界的 \(\mathsf{View}\) 计算不可区分，则只根据该视图运行的多项式时间算法无法在世界 0 以 \(1-\epsilon\) 的概率拒绝、同时在世界 1 以 \(1-\epsilon\) 的概率接受，其中 \(\epsilon\) 为可忽略量。否则用其接受位即可区分两世界。

该命题的结论依赖明确的不可区分前提。对于具体协议，备用凭证、公开状态查询或新的消息可能使前提失效。它是经典不可区分论证在本接口上的应用。

因此，授权图保密和自动恢复之间需要明确定义哪些查询、交互和元数据是允许的。仅把图改成隐藏承诺，提供的是状态绑定，证据发现仍需接口。

## 4. 撤销后清理的小例

令状态 \((b,o,c)\) 分别表示正常任务授权、临时公开链接存在、预先批准的清理授权，三者取值为 0 或 1。

正常任务的 CreateLink 在 \(b=1\) 时把 \(o\) 设为 1。DeleteLink 需要合法的删除授权，成功后把 \(o\) 设为 0。

初始执行到 \((1,1,0)\)。若撤销操作只把正常授权置为 0，且此模型内所有删除接口均依赖 \(b=1\)，状态 \((0,1,0)\) 中没有能关闭链接的获准转换。要求“撤销正常任务后自动关闭已有链接”时，合同需要另一个已认可的恢复机制。

标准处理方式是在原始批准阶段建立只针对该链接的清理能力 \(c=1\)，在撤销后让独立清理执行器调用 DeleteLink。能力绑定对象 ID、版本及允许动作。清理成功后消耗能力，重复请求依照幂等结果处理。

这个简单例子由窄能力与持久工作流组合覆盖。候选的新增责任必须体现在更复杂的并发权利、跨组织接替、隐私或成本界上。能力生成还需要资源端支持相应约束，或由可信网关保管较宽凭证。

已有 Cordon §3–4 和 Atomix §1–3 提供任务效果、可恢复状态、补偿和适配器合同。本文复用这些来源作为强基线，并保留其接口假设。[Cordon](https://arxiv.org/abs/2606.17573) [Atomix](https://arxiv.org/abs/2602.14849)

## 5. 共同错误的纸面检查与先例归属

三个验证者各有边际错误率 \(p\)。若独立，简单多数出错率为

\[
3p^2(1-p)+p^3.
\]

若三者的错误变量完全相同，则多数出错率为 \(p\)。当 \(p=0.1\) 时，二者分别为 0.028 与 0.1。不同链上地址与正确签名均可出现在这两类分布中。

这个例子体现共同错误对风险判断的影响。*The Honest Quorum Problem* 已直接研究同一问题，Theorem 5.3 给出共因事件形成的错误概率下界，Theorem 6.1–6.4 给出带语义错误预算、活性预算与 Byzantine 上界的阈值条件，§10.2–10.6 讨论分布变化、隐含共因及自适应对手。

本轮将“给 AI 验证者增加共因风险模型”归入已有直接先例，退出主候选。签名、押金和链上多数只能在相应协议假设内承担保证。[EBFT 原文](https://arxiv.org/abs/2607.16109)
