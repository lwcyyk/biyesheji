原观察：

- Payload 在约 T0+20.928 秒退出。
- Root 最终约 T0+300 秒结束。

- CLOSED 发布时间。
- Root 首次观察停止状态的时间。

- Root 清理开始时间。

### 6.1 必须验证的行为

- STOP_REQUEST 到达后停止继续发放工作。
- CLOSED 后不能继续交接。
- 等待循环能够观察最新状态。
- RPC 阻塞能够按照冻结合同取消。
- 父 waitpid 等待具有明确终止条件。
- 重复停止请求只形成合法的终态处理。
- Root 能够完成有限清理。
- 迟到 ACK 无法恢复 CLOSED。
- 停止期间预算和 deadline 保持不变。

### 6.2 停止延迟

必须测量实际延迟。

若静态合同已规定数值上限，按照该上限验收。

若合同只有有限退出要求，则报告实际耗时及条件，不能补造新的硬实时保证。

Root 在合法停止请求后仍等待到整个 300 秒软窗口的情况，应重新检查停止逻辑。

不能通过忽略 STOP_REQUEST 获得正常交接结果。
